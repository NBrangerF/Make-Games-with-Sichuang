# 文字改完以后，为什么编辑还不能离场？Paul Grogan 的规则书交接判断

## 这篇案例要看什么

一份规则书在文字文档里已经没有明显错字，送去排版以后，是不是就可以结束编辑？职业规则编辑 Paul Grogan 的回答是否定的。他把规则书看成帮助陌生玩家学会并查询游戏的完整产品；标题层级、例图位置、箭头指向、分栏顺序和分页，都可能改变玩家实际读到的规则。

这篇案例关注的不是某一种字体，也不是“编辑必须领导美术”。它要拆开三个更基本的决定：

1. 你究竟只在校对文字，还是在验证玩家能否使用整份规则书？
2. 文本交给排版后，哪些规则关系可能被重新打断？
3. 团队怎样定义一个可检查的交接，而不是把文件“扔过墙”？

不需要认识访谈中提到的游戏。第一次写规则的人可以只读“关系图”“问题”“决定”和“迁移动作”；已经和编辑、插画师或排版师合作的人，再补读角色边界与证据限制。

## 先看一张关系图

```text
规则事实与教学顺序
        ↓ 写成文字
标题、例子、图示与交叉引用
        ↓ 进入排版
分页、分栏、位置与视觉层级重新组织阅读路径
        ↓
陌生玩家实际看见并执行的规则
```

如果团队只检查第一层和第二层，最终产品仍可能在第三层制造新的歧义。

## 先认识五个词

- **教学路径**：第一次学习时，读者按什么顺序获得目标、动作、代价和结束条件。
- **查询路径**：游戏进行中，读者怎样从一个问题找到准确答案。
- **信息前置**：在读者还用不到某项信息时，就一次塞入大量细节。
- **视觉层级**：标题、正文、提示、例子与图注在页面上被区分的方式。
- **交接检查**：文件进入下一位协作者手中后，用明确清单确认意义、位置和关联没有被改变。

这些中文解释是本站为本案例建立的阅读脚手架，不表示受访者使用了同一套固定术语。

## 1. 语境：规则书不是一个人的文字成品

2021 年，游戏设计师 James Naylor 在《Producing Fun》访谈中邀请 Paul Grogan 讨论规则编辑。Grogan 报告自己参与过数十份规则书：有的只是十几个小时的局部工作，有的从结构到最终版持续一百小时以上。他强调，成品往往由写作者、编辑、图形设计师、出版方和其他协作者共同完成，不能只从署名推断工作过程。

他的出发点也不是保存某位作者的文学表达，而是让拿到规则书的人能够理解并开始游玩。这一点会改变编辑介入的时间。若版面已经锁定、团队只要求检查拼写，而真正的问题是教学顺序，编辑即使发现结构错误也很难移动整段内容。

访谈给出两种极端输入。某些文件只需要少量语法修订；另一些看似已经有 PDF、图片和版式，正文却只是给“已经会玩的人”看的速记，连移动几格、能否穿过其他棋子等执行条件都没有写全。它们外观同样接近成品，使用状态却完全不同。

因此案例中的第一项判断不是“句子好不好看”，而是：这份文件目前服务的是设计者记忆、首次教学、游玩查询，还是其中几项？

## 2. 问题：排版会改变规则关系

Grogan 说，自己通常先在文字协作文档中处理正文、图片位置、备注和评论，再交给图形设计师。但他希望在后续阶段继续参与，因为页面安排本身会传达结构。

访谈中的风险包括：

- 一个重要提示框被放到错误页面或错误章节。
- 主章节因为标题样式过弱，看起来像上一节的子内容。
- 为了腾出页面，把一条紧邻例子的规则移到很远的位置。
- 图中箭头方向含糊，使文字正确但例图指向错误对象。
- 双栏页面没有足够分隔，读者不知道应该先向下还是向右继续。

这些不是装饰偏好。玩家在桌边不会先读取纯文本，再独立读取版式；他们接触到的是两者合成后的阅读路径。若一个例子和它要解释的规则被拆开，或标题暗示了错误从属关系，规则意义就可能在交接中发生变化。

问题可以写成一句话：

> 当规则从可编辑文字变成最终页面时，谁负责验证玩家实际看见的顺序仍然可教、可查、可执行？

## 3. 选项：一次交付、全面接管，还是带检查点协作

从访谈描述的工作条件，可以整理出三条路径。

### 路径 A：文字完成后一次性交付

编辑确认文本，图形设计师独立完成版面。这条路角色清楚、沟通成本低，适合结构很短、模板稳定或团队已经建立成熟规范的项目。风险是前一阶段的关系没有人继续负责；排版为了空间作出的局部移动，可能没人从教学角度复核。

### 路径 B：让编辑控制全部视觉决定

这样可以保持单一责任，却可能把字体、美术、印刷和品牌判断交给未必具备全部相关能力的人。访谈者问“理想情况下”是否应由 Grogan 管理规则书图形设计师时，他先保留式地回答“大概是”。但他紧接着说明，现实工作里自己通常不管理图形设计师，也不能仅因个人不喜欢就更换字体；他要求的是继续参与，并能指出影响理解的问题。

### 路径 C：保留分工，并设置往返检查

文字和排版仍由相应角色完成，但交付不是终点。排版稿需要回到规则责任人手中，逐项检查标题、分页、例图、箭头、交叉引用和阅读顺序；发现问题后再与图形设计师协商调整。

Grogan 描述的现实工作更接近第三种方向。他对理想责任关系的回答保留了更多控制的可能，却没有把它写成普遍组织方案；实际协作中，他不决定所有字体，但要求能够对“箭头是否清楚”“提示是否在正确页”“章节是否被误读”等使用问题反馈。

## 4. 决定：把“规则书”定义为完整使用界面

这项决定包含两层。

### 决定一：结构问题要在版面锁定前处理

如果一份规则书的材料组织错误，末期校对无法修好它。访谈中有项目请 Grogan 先做一天诊断，他建议从空白文档重新开始；也有一份文件在解释设置前先放了十二页细节，他把必须提前知道的内容压缩到约两页，其余移到读者真正需要的位置。

这里的动作不是机械删页。先要确认哪些概念若不提前说明，后续动作就无法理解；其余内容才能转移到对应步骤、附录或查询区域。页数变化是结果，信息时机才是决定对象。

### 决定二：排版稿必须回到规则验证循环

在文字阶段，团队检查“规则有没有写”；在排版阶段，还要检查“玩家能否在正确时刻找到它”。Grogan 因此希望继续看到完整页面，并把图示与例子视为规则产品的一部分。

这并不意味着某一个人永远拥有最终决定。更可迁移的做法是为交接建立职责：

```text
规则负责人：确认事实、顺序和交叉引用
图形负责人：确认层级、可读性、空间与制作要求
陌生玩家：用盲测暴露两者合成后的使用问题
```

三者回答不同问题，不能互相替代。

## 5. 证据：访谈究竟能支持什么

| 证据 | 可以支持的判断 | 不能支持的判断 |
| --- | --- | --- |
| 受访者参与过工作量差异很大的多份规则书 | “编辑”可能从校对到重构，项目应先定义工作范围 | 参与数量自动证明每项建议都适合所有游戏 |
| 有版面完整的 PDF 仍缺少移动等执行条件 | 接近成品的外观不能证明陌生人可以执行规则 | 所有简短写法都会造成误解 |
| 双栏与章节分隔的实例让阅读顺序失效 | 视觉组织可以改变文本的实际使用路径 | 双栏版式普遍不可用 |
| 十二页前置信息被重组为更短的必要引导 | 信息时机是结构性编辑对象 | 规则书开头最多只能有两页概念 |
| 受访者希望排版后继续检查箭头、标题与位置 | 文字—版面往返是其实际工作方法 | 编辑应拥有所有图形设计决定权 |
| 听众反馈使受访者重新考虑索引 | 专业实践会因目标用户反馈而改变 | 每本规则书都必须设置索引 |

访谈是职业实践记录，不是受控研究。它没有提供统一任务、成功率、阅读时间或不同版式的对照数据。本站据此建立检查问题，而不把个人流程包装成效果定律。

## 6. 结果：责任链更完整，但仍需要玩家验证

受访者报告，这种从结构到页面的参与方式让他能够在成品前指出位置、箭头和层级问题。他也以多个项目说明，规则编辑的工作量不能只根据字数预估：有的文本能局部修订，有的需要重新建立教学路径。

访谈还显示，他的判断会变化。例如，他原本不常使用索引，后来因为听到更多玩家说索引有帮助，开始在具体项目中重新评估是否值得加入；同时他仍担心索引收录过多会失去查询功能。这不是一条完成标准，而是“用户任务—制作成本—信息选择”的权衡。

本站从中推断：保留排版后的复核，可以减少规则关系在交接时无人负责的空档。这个推断不能代替盲测。编辑和设计师都已经知道游戏，仍可能自动补全缺失信息；只有陌生玩家实际设置、学习和查询，才能暴露最终页面的使用问题。

还要注意，“玩家最后做对了”不是唯一结果。若玩家先翻过许多页、依赖同桌提示、误读后靠常识修正，规则书仍然制造了额外负担。回归记录应同时保存寻找路径、停顿位置、自我修正和口头求助，才能判断问题来自文本、版面还是规则本身。

## 7. 仍未知：这次访谈没有回答什么

- 访谈没有给出各项目排版前后的盲测成功率。
- 没有比较“编辑继续参与”和“一次性交付”在相同团队、相同游戏中的差异。
- 双栏失败案例没有公开具体规则书名称和完整页面，无法复现。
- 十二页改为两页后的玩家表现没有量化报告。
- 受访者主要处理商业项目，其时间、预算和协作角色不等于学生或个人设计者的条件。
- 规则复杂度、读者年龄、语言能力、视觉能力和既有桌游经验会改变适合的教学路径。
- 索引、教程、附录和例图都会增加制作与维护工作；访谈没有给出通用投入阈值。
- 一份容易学的规则书仍可能难以在游玩中查询；两项任务需要分别观察。

## 8. 迁移动作：做一次“排版后规则回归”

你不需要专业排版软件。把当前规则放进任何会改变分页的工具，再完成下面六步。

### 第一步：写两种用户任务

```text
首次学习：玩家必须依次知道______、______、______。
游玩查询：玩家最可能查找______、______、______。
```

不要只写“读懂规则”。教学和查询使用不同路径。

### 第二步：冻结一份文字基线

给文字版本命名，例如 `rules-v0.4-text`。列出本轮不能丢失的五项关系：胜利目标、一个回合、一次代价、一个例外、结束条件。

### 第三步：只改变页面表达

做成两到四页，不顺便重写机制。加入标题、分栏、表格、例子或图示时，记录它们对应哪一条规则任务。

### 第四步：逐项检查交接风险

| 检查项 | 要问的问题 |
| --- | --- |
| 标题 | 主步骤是否被误看成可选提示？ |
| 分页 | 规则和必要例子是否被拆开？ |
| 图示 | 箭头、颜色、编号是否只靠一种信号？ |
| 分栏 | 阅读顺序是否无需猜测？ |
| 引用 | “见下页”与页码是否仍正确？ |
| 重复 | 两处规则是否在改版后互相矛盾？ |

### 第五步：让陌生玩家完成三个任务

1. 不经口头帮助完成设置。
2. 说出第一个回合可以做什么以及为什么。
3. 在模拟争议中找到一条具体例外。

只记录玩家在哪里找、找了多久、先读到什么和最终执行了什么，不要立即替他解释。

### 第六步：把问题交回正确层

- 找不到内容：先检查标题、位置与索引词。
- 找到却读不懂：检查句子、术语、图例与前置知识。
- 读懂却无法执行：检查规则本身是否缺少状态或条件。
- 两个人得到不同答案：检查例外、冲突优先级与重复文本。

每轮只修最能阻断任务的问题，再生成新版本。不要把玩家失败一律归因于“没有认真读”。

## 三种背景，三条读法

- **第一次写规则**：先画教学顺序，只做两页并找一名不知道游戏的人设置。
- **已经有完整原型**：增加查询任务，分别记录首次学习和游玩中断。
- **带领学生或儿童**：每页只给一个明确任务，用实物指向代替抽象页码；测试时允许说“我找不到”，不要把阅读速度当能力评分。

## 作者报告、本站推断、仍不知道

### 作者报告

规则书可能需要从局部校对到彻底重构；文字进入排版后，标题、位置、图示和分栏仍会影响使用；受访者希望继续参与最终页面复核。

### 本站推断

规则书应被当作“文字、图示、版面与查询路径”的整体界面。一次性交付容易形成责任空档；用版本、检查点和陌生玩家任务可以让问题回到可诊断层。

### 仍不知道

这套协作在不同规模项目中的成本与效果，以及哪种版式、索引或教程对你的具体读者最有效，必须由本项目自己的可用性测试回答。
