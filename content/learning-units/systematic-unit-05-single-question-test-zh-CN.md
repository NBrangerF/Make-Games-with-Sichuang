# 单元 5：单问题测试

## 读完以后，你会得到什么

你会把单元 4 的《小动物过河》最小原型，变成一场真的能够执行、观察、停下并交给下一轮的测试。

你会完成九样东西，而且顺序很重要：

1. 一句单问题。
2. 一条行为预测。
3. 一组反驳信号。
4. 一份版本与参与范围。
5. 一句无引导测试任务。
6. 一张分层观察表。
7. 一组停止条件。
8. 一次简短复盘。
9. 一份下一步移交。

这里的“单问题”不是说一款游戏只有一个问题。它的意思是：这一次短测试只让一个问题负责带路。其他有趣发现可以记下来，留给以后，但不在结束时偷偷变成本轮已经回答的问题。

## 先接住上一单元的桌面

单元 4 留下的是这个版本：

> 小动物过河_工具交接_v0.1_2026-08-22

桌面上有两条各含一个障碍的河道。松鼠需要绳索才能越过急流，却拿着木板；水獭需要木板才能越过断桥，却拿着绳索。两枚棋子在同一列时，发起者可以花掉本回合行动，交换两人手中的工具。每名玩家每回合只能前进一格或发起交接。两人都行动后，水位上升一格。两只动物都越过障碍，或水位到达第三格，本段立即停止。

这份原型已经能运行。现在不要加新角色、事件牌、计分或第二段河道。单元 5 的工作不是把它继续做大，而是让它回答一个小而清楚的问题。

## 先记住：一次测试不是证明

如果一对玩家主动商量了工具交接，我们可以写：

> 在 v0.1、这对参与者和这段设置中，出现了预测的讨论行为。

我们不能写：

> 这个机制已经证明能够让所有玩家合作。

如果一对玩家完全没有商量，我们可以写：

> 在这次条件中，预测行为没有出现；记录显示他们直到被障碍挡住才注意到对方工具。

我们不能写：

> 玩家永远不会合作，这个设计一定失败。

一场测试像是在桌面上打开一扇小窗。你能看见这扇窗框住的行为，却看不见所有年龄、所有经验、所有玩家关系、所有版本和所有游玩时刻。测试的价值是让下一步比猜测更有根据，而不是替未来盖章。

**来源事实：** Lim、Stolterman 与 Tenenberg 的原始研究把原型描述为有选择的过滤器，也明确讨论原型用于发现问题与探索设计方向，而不只是证明成败。Denisova 等人的游戏用户研究则区分行为资料与态度资料，并明确说明参与者与研究语境会限制外推。

**本站教学综合：** 本单元因此只使用“暂时支持”“暂时不支持”“无法判断”三种结论，不使用“通过”“不及格”或“已证明”。这三种名称是本站为了帮助新手保留证据边界而设计的记录方法。

## 三种话要分开写

一张可靠的测试记录，至少分得开下面三种东西。

### 可见行为

这是坐在旁边的人或摄像机能够看到、听到并指出时间点的事情。

- 水獭把绳索卡拿起来，看向松鼠面前的木板。
- 松鼠在选择行动前指了指水位第二格。
- 两人都前进以后停在障碍前。

### 玩家原话

这是玩家真的说出来的话。能逐字写就加引号；只能记住大意，就加“约”或“近似”，不要把大意装成逐字引文。

- “如果现在换，我这一轮就不能走，对吗？”
- 约：“我刚才没发现绳索在你那里。”

### 设计者解释

这是你根据行为与原话提出的原因猜想。它可以指导下一轮，但它还不是事实。

- 交接的机会代价可能已经进入玩家判断。
- 工具归属可能不够醒目。
- 玩家也可能看见了工具，只是当时认为先前进更划算。

不要把“玩家沉默三十秒”直接写成“玩家很无聊”。沉默是行为；无聊是可能解释，也可能不是。不要把“玩家说很喜欢”改写成“机制平衡”。喜欢是这名玩家在这个时点的自我报告；平衡需要另一种问题、范围和证据。

为了让这三层不在忙乱时混在一起，本单元规定：测试进行时先写行为、原话、桌面状态和主持介入；设计者解释等这一段停止以后再填。

## 一眼看懂整条路

```text
原型版本
  ↓
一句单问题
  ↓
行为预测 → 反驳信号
  ↓
参与范围 → 无引导任务
  ↓
观察记录 → 停止
  ↓
简短复盘
  ↓
暂时支持 / 暂时不支持 / 无法判断
  ↓
只交出一个下一步
```

下面按这个顺序完成九项产物。不要先看到喜欢的结果，再回头替它补一条预测。

## 第一步：写一句单问题

先用一个句号结束问题。不要用三句话把“是否看见、是否喜欢、是否平衡、是否想再玩”全部绑在一起。

可以使用这个句式：

> 在〔版本与局面〕中，当〔关键条件〕发生时，〔哪类参与者〕会不会在〔时间边界〕以前出现〔可见行为〕？

《小动物过河》本轮填写为：

> 在 v0.1 的开局切片中，当工具交接会占用发起者本回合的前进机会时，两名第一次接触此版本的玩家会不会在任一只动物被障碍挡住以前，主动查看对方工具并商量至少一次交接时机？

这句话长一点，但每个部分都有工作：

| 部分 | 本例写了什么 | 为什么需要 |
| --- | --- | --- |
| 版本与局面 | v0.1 的开局切片 | 防止把后来改过的牌混进来 |
| 关键条件 | 交接占用发起者本回合前进机会 | 指出本轮关心的机会代价 |
| 参与者 | 第一次接触此版本的两名玩家 | 限定这次证据来自谁 |
| 时间边界 | 任一只动物被障碍挡住以前 | 让“什么时候算发生”可判断 |
| 可见行为 | 查看对方工具并商量交接时机 | 不用猜玩家心里有没有合作意愿 |

“这游戏好玩吗？”不是坏问题，只是对当前五分钟切片太宽。玩家可能喜欢动物主题，却没看见交接；也可能看见了决定，却不喜欢纸卡外观。一个回答混进太多原因，就很难知道下一版该改什么。

“玩家会不会理解我的聪明机制？”也不合适。“聪明”在替答案叫好，“理解”又藏在脑中。把它改成能看见的动作：玩家是否查看、指向、复述、选择、放弃、询问或在错误后恢复。

### 第一步的小检查

- [ ] 只有一个问号或一句完整疑问。
- [ ] 写了当前版本或可辨认的局面。
- [ ] 写了具体的人，而不是模糊的“玩家都”。
- [ ] 写了时间边界。
- [ ] 答案可以从桌面行为中取得，而不是只靠“你喜欢吗”。
- [ ] 即使答案不是设计者想要的，问题仍然有用。

**机构观点：** TTGDA 的官方测试资源建议设计者带着想回答的问题进入测试，并举出理解机制、是否使用某选项等具体方向。

**本站教学综合：** 把它压成上述五部分的一句话，是本站给初学者的脚手架，不是 TTGDA 的原表格。

## 第二步：把希望改成行为预测

问题问“会不会”，预测要写“如果暂时会，我预计先后看见什么”。预测不是愿望，也不是对玩家下命令。

本轮预测写成一个短序列：

> 如果工具归属与交接代价已经形成可见决定，那么在任一只动物被障碍挡住以前，至少一名玩家会先查看或指向同伴持有的工具，随后两人会用自己的话比较“前进”和“交接”，最后提出交接、执行交接，或明确说出暂不交接的理由。

这条预测包含三个层级：

1. **注意到信息**：看向、拿起或指向对方工具。
2. **比较选择**：说出前进与交接之间的一项取舍。
3. **作出行动**：交接，或明确拒绝交接并说明眼前理由。

为什么“明确拒绝交接”也能进入预测？因为本轮问题不是“玩家是否一定交换”，而是“交接机会是否进入讨论”。玩家看见了选择，仍然认为先走更好，说明这个选择进入了判断；这和完全没看见工具不是同一种结果。

预测不要写成：

> 玩家会感觉到合作很有趣。

“感觉到”“有趣”需要自我报告，而且没有指出哪一刻、哪件事。可以把它留到以后专门研究体验。本轮先预测可见序列。

预测也不要写成：

> 玩家会做出正确决定。

这会把测试变成考试。对本轮来说，玩家先走、先换或晚一点换都可能是合理策略。我们观察的是他们有没有看见并处理取舍，不是他们有没有猜中设计者的答案。

### 预测卡

| 要写的格子 | 《小动物过河》填写 |
| --- | --- |
| 触发以前 | 任一只动物被障碍挡住以前 |
| 第一件可见事 | 至少一人查看、拿起或指向同伴的工具 |
| 第二件可见事 | 两人用自己的话比较前进与交接 |
| 可能的行动 | 发起交接，或明确说出暂不交接的理由 |
| 不预测什么 | 是否喜欢整款游戏、是否长期平衡、是否想购买 |

这里没有设置“百分之多少才算成功”。本轮只是一对参与者的形成性小测试。数字看起来很客观，但一对玩家不能变成有意义的总体百分比。

## 第三步：先写反驳信号

如果只写自己想看到的现象，结束时很容易忽略相反证据。反驳信号是在测试开始前告诉自己：什么出现时，我必须放下原来的解释，或至少承认当前资料不支持它。

本轮分成两组。

### A. 预测没有得到支持的信号

- 两名玩家都没有看、拿或指向对方工具，直接各自前进并停在障碍前。
- 玩家看见对方工具，但直到被挡住以前都没有比较前进与交接，也没有说明暂缓理由。
- 玩家多次把工具当成只属于自己的能力，行动中完全没有把它看成可交接对象。
- 玩家知道规则允许交接，却一致表示在当前水位与距离中根本没有需要讨论的取舍，并立即采用同一行动路线。

这些现象不自动告诉我们“为什么”。它们只让“当前表达与代价会在障碍前引出讨论”暂时没有得到支持。原因可能是归属不清、交接规则不清、水位压力太弱、设置太显然、玩家已有默契，或别的事情。原因要结合原话和下一轮比较再判断。

### B. 本轮无法判断的信号

- 主持人在玩家注意工具以前说出“你们可以交换”。
- 河道、工具或水位摆错，导致目标局面没有出现。
- 当前提示条漏写合法行动，或两条规则互相冲突到无法继续。
- 参与者之前看过这个版本的完整解法，却被记录成第一次接触。
- 一名参与者需要的文字、语言或操作支持没有准备，困难主要来自无法读取或拿取，而不是本轮机制。
- 参与者不舒服、想退出，或测试因安全原因提前结束。

“无法判断”不是失败，也不是丢脸。它是在保护下一步。如果主持已经泄露答案，却仍把玩家的交换写成机制证据，记录会显得漂亮，却不能帮助设计。

### 反驳信号的句式

> 如果在______以前出现______，而且没有发生______类测试破损，我就把本轮记为“预测暂时不支持”；如果发生______类破损，我记为“无法判断并重跑同一问题”。

本例可以写：

> 如果在任一只动物被障碍挡住以前，两人都未查看同伴工具，也没有比较或提出交接，而且设置、规则和主持都按计划运行，我就记为“预测暂时不支持”；如果主持提前提醒交换、组件摆错或参与者无法读取提示，我记为“无法判断并重跑同一问题”。

## 第四步：锁定版本与参与范围

同一个问题换了版本、换了人、换了媒介，答案可能改变。测试前用两小块把范围钉住。

### 版本范围

| 字段 | 本轮记录 |
| --- | --- |
| 版本名 | 小动物过河_工具交接_v0.1_2026-08-22 |
| 组件 | 河道纸 1、纸棋子 2、工具卡 2、水位代币与三格轨、回合提示条 |
| 开始状态 | 松鼠拿木板，水獭拿绳索；两者在起点；水位为 0 |
| 合法行动 | 前进一格，或同列时由发起者花掉行动交换两张工具 |
| 自然停止 | 两只动物都越过障碍，或水位到 3 |
| 本轮冻结 | 河道、行动数、工具作用、交接代价、水位速度、提示文字 |
| 允许的现场修复 | 只补回掉落或损坏组件；修复要记录，不临时改数值与规则 |

“冻结”不是说永远不改，而是说这一段运行时不悄悄改。若一开始就发现设置错误，可以停止、改正、重新标记一次运行。不要把错误设置的前半段和修正后的后半段拼成同一场证据。

### 参与范围

本轮只需要记录与问题有关的信息，不需要收集真实姓名、住址或无关资料。

| 字段 | 怎样写 |
| --- | --- |
| 参与人数与座位 | 两人；面对同一桌面，工具公开可见 |
| 与版本的关系 | 两人都是第一次接触 v0.1 |
| 与设计者的关系 | 同学、朋友、家人或不熟悉的参与者，如实选一项 |
| 桌游经验 | 很少、偶尔、经常；由参与者自述，不当作能力评分 |
| 语言与读取支持 | 当前提示条使用什么语言；是否需要朗读、大字或其他支持 |
| 年龄范围 | 只记与教学和同意有关的宽范围，不公开可识别信息 |
| 测试媒介 | 实体桌面；若改线上，必须另记版本条件 |
| 关系语境 | 两人是否本来就常合作、是否师生/亲子等；只记与互动解释有关的部分 |

如果两名参与者是好朋友，他们可能几乎不用说话就理解彼此；如果彼此陌生，他们可能因礼貌少提建议。两种资料都可以有用，但不能假装关系没有影响。

如果参与者是儿童，要先用能理解的语言说明：测试的是纸上的游戏，不是在考他们；可以不回答、可以暂停、可以退出。根据学校、机构和所在地要求取得适当的监护或组织同意。不要把课堂分数绑在“有没有做出设计者想要的行动”上。

**研究事实：** Denisova 等人的访谈研究报告了找到合适参与者、处理资料和取得研究专长的现实困难，并明确指出其自身样本地区、语言与招募方式限制外推。

**本站教学综合：** 上述参与范围表为轻量记录，不是人口统计调查，也不能代替正式研究的招募、同意与资料治理流程。

## 第五步：给出无引导测试任务

这里的“无引导”不是把人丢在桌边不管，也不是完整规则盲测。它只表示：任务不说出本轮期待的策略，主持不在关键时刻把答案递给玩家。

本轮任务卡只写：

> 请从现在的设置开始，按照桌面提示条行动，让松鼠和水獭尽量越过各自的障碍。请像平常一起玩一样决定行动。你们认为已经完成、无法继续，或想停止时，请告诉我。

任务卡没有写：

- “记得查看对方的工具。”
- “请在障碍前交换。”
- “你们应该讨论怎样合作。”
- “最聪明的做法是先换工具。”

这些句子会把我们想观察的行为直接教给玩家。玩家照做以后，我们只知道他们能照着提示行动，不知道当前桌面是否自己暴露了这个取舍。

### 开始前的固定说明

主持可以说：

> 今天测试的是这个纸面版本，不是在测试你。规则或组件让你困惑，也是对原型有用的信息。你可以随时提问、暂停或停止。我会记下桌面上发生的事；如果要录音或拍照，我会先另外征得你的同意。现在请先读任务卡和回合提示条。

固定说明提供安全和必要语境，但不解释设计意图。若参与者问“我们是不是应该交换”，主持不要回答“对”。可以使用事先写好的中立回应：

> 请先按照你对提示条的理解作决定。我会记下这个问题，结束后再一起看。

如果问题涉及安全、退出、资料使用或组件损坏，主持必须直接处理，不能拿“无引导”当作不帮助人的理由。

### 哪些介入必须记录

- 重新读了一遍提示条原文。
- 指出了某张卡放在哪里。
- 确认一个行动是否合法。
- 纠正了漏涨水或棋子放错格。
- 提醒了交换选项、障碍需求或停止条件。
- 回答了关于设计意图的问题。

前四项也可能改变行为，后两项更可能直接影响本轮问题。不要凭感觉把“只是小提醒”删掉。记录时间点、主持原话和介入后的下一步动作。

**专业实践观点：** Games User Research 的作者指出，任务措辞若说出玩家本应自己发现的路径，就会遮住对应的可用性问题；主持的确认、否定和个人意见也会影响资料。Stanford d.school 的官方教学材料建议只给基本语境，让使用者操作并先观察，不立即纠正。

**边界：** 这些资料主要来自数字游戏研究或通用人本设计。本单元把它们迁移到实体两人桌面，迁移本身是本站判断，不声称原来源直接验证《小动物过河》。

## 第六步：用一张表观察，不急着解释

测试时把纸横放。前三栏边看边写；最后一栏等停止后再填。

| 时间/回合 | 可见行为与桌面状态 | 玩家原话 | 主持介入 | 设计者解释（停止后填） |
| --- | --- | --- | --- | --- |
| 00:18，第一轮松鼠行动前 | 松鼠看自己的木板，再看水獭面前的绳索；手指停在两张卡之间 | “你的才是我过急流要的。” | 无 | 工具需求与归属在第一次行动前被看见 |
| 00:31，第一轮讨论 | 水獭指向水位轨；两人轮流指河道第一格 | “现在换的话，你就不能走了吧？” | 无 | 交接的机会代价进入讨论；还不能推出它是否平衡 |
| 00:45，松鼠行动 | 松鼠前进一格，没有交换；水獭点头 | “先一起走一格，到障碍前再换。” | 无 | 两人看见交接但选择延后；这仍符合“讨论时机”的预测 |
| 01:24，第二轮开始 | 两人到障碍前；水獭拿起绳索卡 | 约：“那现在换。” | 主持重新读“同列”规则原句 | 发生过介入；需判断它是否只确认同列，还是推动了交换 |
|  |  |  |  |  |

上表只是示范怎样分栏，不是已经发生的测试结果。真正测试时必须填写真实发生的事情，不能把示范行复制成证据。

### 写可见行为的四个问题

1. **谁**做了什么？
2. **什么时候**做？
3. 当时桌面上**看得见什么状态**？
4. 这个动作以后，系统或同伴**怎样回应**？

“玩家很困惑”太像解释。可以改成：

> 水獭连续读提示条两遍，拿起绳索又放下，问“交换以后谁拿哪张？”

“合作顺利”也太大。可以改成：

> 两人在第一次行动前分别指向两处障碍；松鼠说先走一格，水獭复述并同意；第二轮由水獭提出交换。

### 写原话的两个标记

- 确定逐字：用引号。
- 只能回忆大意：写“约：”或“近似：”，不加逐字引号。

如果来不及完整记录，可以先写时间点和关键词，结束后立即补全，并标记“会后补记”。不要在几天后凭印象重写成流畅故事。

### 解释要能回到证据

停止后写解释时，每一句前面都问：

> 哪一行行为或原话让我这样想？还有没有别的解释？

例如，“机会代价进入讨论”可以指向玩家关于“这一轮不能走”的原话。可是“机会代价刚好平衡”仍然超过证据，因为一段短局没有比较其他代价，也没有观察多种策略和重复游玩。

若一个人同时主持和记录，宁可少写解释，也不要错过时间、动作和原话。取得同意后可以录音辅助回看，但录音不是默认权利；要说明保存位置、用途、谁能访问和如何撤回。对儿童和课堂尤其要遵守学校、机构及所在地规则。

## 第七步：在开始前写好停止条件

没有停止条件，短测试很容易变成一边玩、一边加规则、一边把后半款游戏临时做完。本轮使用三层停止。

### 1. 自然停止

- 两只动物都越过自己的障碍；或
- 水位到达第三格。

触发以后立即停下，拍下或画下最终桌面状态。即使刚好想到第二段河道，也不要现场续写。

### 2. 时间停止

如果五分钟仍未触发自然停止，就在当前行动完成后停下，记录桌面状态与未完成原因。五分钟是这份课堂切片的预设，不是适用于所有桌游的标准。

### 3. 安全与有效性停止

出现以下任一情况，可以立刻停止：

- 参与者说想停、显得明显不适，或需要休息。
- 组件损坏、缺失或摆错到目标局面不再存在。
- 规则冲突使行动无法继续。
- 主持提前泄露目标策略，无法再观察自然发现。
- 记录或录制发生未经同意的问题。
- 测试环境出现安全风险。

预测行为一出现，不要马上喊停。让当前切片走到自然或时间停止，才能看到玩家是否真的执行、延后、放弃，或在后续又改变理解。反过来，预测行为没出现，也不要偷偷延长河道，等待它终于发生。

停止条件的任务是让不同结果都能被完整留下，而不是替设计者追到喜欢的答案。

## 第八步：做一次简短复盘

先停止、保存桌面、补全行为记录，然后再问。不要边玩边进行长访谈，因为谈话本身可能改变后续行动。

本轮最多问三个短问题：

1. 你第一次注意到同伴手里的工具是在什么时候？请指一下当时的桌面位置。
2. 当你比较前进和交接时，你觉得两种选择各会失去什么？
3. 有哪一句提示或哪个桌面状态让你不确定自己能做什么？

第一问帮助把回忆接回时点；第二问询问玩家自己的理解；第三问寻找规则或信息问题。它们都没有问“你是不是觉得这个合作机制很棒”，也没有要求玩家替设计者修游戏。

如果玩家主动提出修改建议，可以写进“意外停车区”，并保留为玩家原话。不要立刻答辩，也不要因为建议具体就自动采用。玩家最了解自己的经历，设计者仍要负责判断问题属于哪一层、下一版改什么以及改动会牵动什么。

### 十行以内的复盘

复盘可以很短：

1. 本轮问题是什么？
2. 最关键的两条可见行为是什么？
3. 最关键的一句玩家原话是什么？
4. 主持介入过什么？
5. 哪条替代解释仍然可能？
6. 本轮是暂时支持、暂时不支持，还是无法判断？
7. 结论只适用于什么版本和参与范围？
8. 意外发现放在哪里？
9. 下一轮只改什么，或为什么先不改？
10. 哪些内容继续保持不变？

复盘不是把所有笔记写成漂亮故事。宁可留下“还不知道”，也不要用玩家一句称赞填补没有观察到的行为。

## 第九步：把证据交给下一步

移交不是只写“继续优化”。下一位设计者，或明天的你，应该能从一页纸知道发生了什么、为什么作出下一步决定，以及哪些话仍只是解释。

### 三种结论出口

#### 暂时支持

在约定时间边界内出现了预测序列，而且没有足以改变答案的主持泄露或设置错误。

可以写：

> v0.1、这对第一次接触版本的参与者、实体桌面条件下，在障碍以前出现了查看对方工具、比较前进与交接、明确延后交接的行为。该结果暂时支持“交接取舍能够在这段强制设置中进入讨论”。它不证明自然开局、其他参与者或完整游戏也会如此。

下一步不是立刻宣布机制完成。可以保持规则不变，换一对符合范围的新参与者重复；也可以在更自然但仍可控的设置中检查强制分配是否夸大讨论。一次只选择一个方向。

#### 暂时不支持

目标局面按计划发生，但预测行为没有出现，或出现了预写的相反信号。

可以写：

> v0.1 的运行完整结束，两人直到被障碍挡住才注意到对方工具；无主持提示与设置错误。本轮暂时不支持“当前表达会在障碍前引出交接讨论”。原话显示两人都把工具当成个人能力，但这只是原因线索。

下一步可只改变工具归属的可见表达，例如固定摆放位置或增加持有者标记，然后保留河道、交接代价与水位不变，再问同一个问题。这里的具体改法仍是设计决定，不是玩家资料自动下的命令。

#### 无法判断

目标局面没有按计划出现，或帮助、错误、范围不符让证据无法回答原问题。

可以写：

> 主持在第一轮以前提醒“你们可以交换”，目标行为随后出现。因为答案被任务外提示泄露，本轮无法判断当前桌面能否自己引出讨论。修正主持脚本后，用同一 v0.1 与新的第一次接触参与者重跑。

“无法判断”通常不需要改机制。先修测试，再给原版本一次公平机会。

### 最短移交包

| 移交字段 | 必须写什么 |
| --- | --- |
| 来源版本 | 完整版本名与日期 |
| 单问题 | 原句，不在结束后改写 |
| 范围 | 参与人数、是否首次接触、关系/经验/语言中与解释有关的部分、媒介 |
| 关键行为 | 带时间或回合的两至四条记录 |
| 关键原话 | 逐字或明确标为近似 |
| 主持与破损 | 所有介入、设置错误、中断 |
| 设计者解释 | 与事实分开，并写至少一个替代解释 |
| 结论状态 | 暂时支持 / 暂时不支持 / 无法判断 |
| 下一步 | 重复、只改一项，或暂停此问题；三选一并说明 |
| 保持不变 | 下一轮明确冻结什么 |

### 意外停车区

测试可能同时出现别的问题，例如水位格难看清、玩家拿错棋子或停止时不知道谁先说话。全部可以记，但写在单独区域：

| 意外观察 | 是否影响本轮有效性 | 以后交给哪个问题 |
| --- | --- | --- |
|  | 是 / 否 / 不确定 | 规则表达、组件操作、节奏或其他 |

如果意外问题让目标局面无法运行，本轮应进入“无法判断”。如果它没有改变目标证据，就留给未来，不要在同一版同时修改五件事。

## 把九步完整走一遍

下面不是一份虚构的测试结果，而是一份可直接执行的测试计划。

### 1. 一句单问题

在 v0.1 的开局切片中，当工具交接会占用发起者本回合的前进机会时，两名第一次接触此版本的玩家会不会在任一只动物被障碍挡住以前，主动查看对方工具并商量至少一次交接时机？

### 2. 行为预测

至少一人先查看、拿起或指向同伴工具；两人随后比较前进与交接；最后发起交接，或说出暂不交接的眼前理由。

### 3. 反驳信号

两人都未查看同伴工具，也未比较交接，直接被障碍挡住；或者他们虽然看见工具，却认为当前局面不存在任何需要讨论的取舍。若主持提示交换、设置错误或规则断裂，则不是反驳，而是无法判断。

### 4. 版本与参与范围

使用 `小动物过河_工具交接_v0.1_2026-08-22` 的同一套实体组件。两名参与者第一次接触该版本；记录他们彼此关系、桌游经验与读取支持。测试只外推到这次两人、这一版本和实体桌面切片。

### 5. 无引导测试任务

“请从现在的设置开始，按照桌面提示条行动，让松鼠和水獭尽量越过各自的障碍。请像平常一起玩一样决定行动。你们认为已经完成、无法继续，或想停止时，请告诉我。”

### 6. 观察表

准备“时间/回合、可见行为与状态、玩家原话、主持介入、停止后解释”五栏。运行中不填原因猜想。

### 7. 停止条件

两只动物都越过障碍、水位到 3，或五分钟到时；参与者退出、安全问题、组件/规则破损或目标答案被主持泄露时提前停止并标记原因。

### 8. 简短复盘

停止后问第一次注意工具的时点、前进与交接各自的损失、让人不确定的提示或状态。最多三个问题，先听经历，不争辩。

### 9. 下一步移交

选择暂时支持、暂时不支持或无法判断；附关键行为、原话、介入与替代解释；只交出“重复”“只改一项”“暂停此问题”中的一个下一步。

## 十五分钟可执行练习

这个练习假定单元 4 的纸面原型已经摆好，并有两名愿意参与的人。十五分钟是学习流程的时间盒，不是行业规定，也不是充分测试的保证。

### 0:00—2:00　写一句问题

抄下版本名，用本单元句式写一个问题。把“喜欢、好玩、平衡、所有玩家”划掉，改成能在五分钟内看到的动作与时间边界。

### 2:00—3:30　写预测

只写三步：先注意什么，再比较什么，最后可能做什么。允许玩家明确拒绝目标行动，只要他们已经看见并处理取舍。

### 3:30—4:30　写反驳与无法判断

各写一条：什么行为会让预测暂时不支持；什么测试破损会让本轮无法判断。

### 4:30—5:30　锁定范围

圈出 v0.1，写两名参与者是否第一次接触、彼此关系和需要的读取支持。说明不录音，或先取得明确同意。

### 5:30—6:00　读任务

只读固定说明和无引导任务，不说“交换”“合作”或设计者期待的路线。把观察表放在自己面前。

### 6:00—11:00　运行并记录

让两人行动。记录时间、行为、状态、原话与自己的介入。设计者解释栏保持空白。自然停止先到就提前结束；出现安全或有效性停止立即停。

### 11:00—12:30　问两个短问题

优先问“第一次注意工具是在什么时候”和“前进与交接各会失去什么”。若本轮主要卡在提示，再把第二问换成不确定之处。

### 12:30—14:00　分开事实与解释

给两条行为画线，圈出一句原话。现在才填设计者解释，并写一个可能的替代解释。

### 14:00—15:00　移交

圈选暂时支持、暂时不支持或无法判断。写下一轮只做一件事：保持版本换人重复、只改一个可见表达，或先修测试再重跑。把其他发现放进停车区。

时间到了仍不知道，不要补猜。写“目前不知道，需要下一轮”。这也是完整结果。

## 常见错误，以及怎样修正

### 错误一：一个问题里塞进四个问题

“玩家会不会看见交换、觉得合作好玩、认为水位平衡并愿意再玩？”任何答案都不知道在回答哪一段。

修正：本轮只留“障碍前是否主动查看工具并讨论交接”。其他问题进入停车区。

### 错误二：预测的是感受，不是行为

“玩家会感到紧张”无法只靠观察确认。皱眉、停顿或笑都可能有多种原因。

修正：预测查看水位、比较行动损失、改变行动顺序等可见行为；若以后要研究紧张体验，另建自我报告问题。

### 错误三：反驳永远不会发生

“只要玩家做任何事，就说明机制引发了思考”让所有结果都支持设计者。

修正：在开测前写明相反序列，例如直到被障碍挡住仍未查看同伴工具。

### 错误四：把测试坏掉写成机制失败

工具放反、提示漏印、主持泄露答案后，直接下结论说机制有效或无效。

修正：把这些情况放进“无法判断”，修测试后重跑原问题。

### 错误五：任务句直接告诉玩家答案

“请使用交换帮助彼此过河”会制造目标行为。

修正：只说目标与必要语境，让当前规则和桌面自己暴露选项。

### 错误六：每次犹豫都立刻教学

主持一看玩家停顿，就指出工具、复述策略或解释意图。这样看到的是“得到帮助后的行为”。

修正：预写允许回应；不影响安全时先观察。确实介入就逐次记录，不要假装它没发生。

### 错误七：把行为、原话与解释写成一句

“玩家因为没看懂工具所以很挫败。”这里混了至少两个未经区分的解释。

修正：行为写“连续读卡两遍并拿错工具”；原话写“我不知道这张是谁的”；解释另写“归属表达可能不清楚”。

### 错误八：只记支持自己的片段

记录玩家成功交换，却漏掉主持刚刚提醒过交换，也漏掉另一人一直看错障碍。

修正：按时间记录关键事件和所有介入。分析放到停止以后。

### 错误九：看到预测行为就立刻结束

玩家刚说“也许交换”，主持就停表，没看到他们是否执行、延后或放弃。

修正：走到预写的自然或时间停止，除非发生安全或有效性停止。

### 错误十：没看到预测就无限延长

设计者加水位、加河道、加提醒，直到玩家终于交换。

修正：原停止条件到达就停。没有出现也是证据。

### 错误十一：把一对玩家变成“所有玩家”

朋友、亲子、同学、陌生人、常玩桌游的人和第一次接触桌游的人可能以不同方式交流。

修正：每次都写参与范围，结论用“这次”“这对”“这个版本”。需要扩大范围时另行招募和重复。

### 错误十二：一次改很多，再比较结果

同时改变工具图标、水位速度、河道长度和交接代价，即使行为改变，也不知道由什么造成。

修正：下一轮优先只改一项；若为了修复崩溃必须同时改，完整列出，并把它视为新版本而非单变量比较。

### 错误十三：要求玩家替设计者给答案

“你觉得我该把交接改成免费吗？”可能得到具体建议，却没有说明问题来自可见度、代价还是节奏。

修正：先问玩家何时注意、当时理解和担心什么。建议可记录，但修改责任留给设计者。

### 错误十四：用分数代替证据

给“合作出现”打八分、给“好玩”打七分，看起来整齐，却丢掉何时、谁、做了什么。

修正：早期先保留事件、原话、介入、范围和版本。若未来使用量表，必须为量表另写用途与解释边界。

## 给不同背景学习者的脚手架

### 如果你第一次做设计

只做最小版：一句问题、一条预测、一条反驳、两名参与者、一句任务、四行观察、一个停止、两个复盘问题、一个下一步。空白不是错误；不知道就写不知道。

### 如果你还在小学

可以把三个证据栏记成：

- **我看见**：桌面上真的发生了什么。
- **我听见**：玩家真的说了什么。
- **我猜想**：我觉得为什么会这样。

测试前告诉同伴：不是考他们，随时能停。不要因为同伴没做出你希望的行动而责怪他。原型让人看不懂，是纸和规则给你的线索。

### 如果你已经有很多桌游经验

不要把自己熟悉的策略当作参与者一定会想到的东西。记录他们当时可见的信息与自己的所有提示。区分“玩家没看见选项”和“玩家看见后认为不值得”。前者可能是表达或规则问题，后者才更接近代价判断。

### 如果参与者和你经验差很多

在范围里写清楚，但不要把经验当作高低能力分。当前问题若关心第一次发现，就需要新接触者；若以后关心高手策略，就需要另一个问题和参与范围。不要用一组人替另一组人发言。

### 如果一个人既主持又记录

先保证安全与流程，再抓时间点、关键动作、原话和介入。解释可以稍后补。若有第二位记录者，事先分工：一人只读固定脚本与处理安全，另一人只观察；两人都不要在局中讨论设计。

### 如果需要读取或操作支持

大字、朗读、图形加文字、稳定的卡位和可抓取组件都可以是必要条件。把支持写进版本与范围，不把它当成参与者的“特殊失败”。如果支持会直接揭示本轮答案，就承认条件改变，并为新条件重新定义问题。

## 适用与不适用边界

这套单问题流程适合早期形成性测试：你已经有一段可执行原型，想观察一个局部关系有没有进入玩家的注意、比较与行动。

它尤其适合《小动物过河》这样的短切片，因为目标局面很快出现，桌面状态公开，停止条件明确，版本改动便宜。

它不能单独完成下面这些任务：

- 证明整款游戏好玩、平衡、耐玩或适合发行。
- 证明一种机制导致某种情绪或社交结果。
- 推算所有目标玩家的比例或市场规模。
- 检查长期经济、完整牌库概率、重复游玩、剧情承诺或战役记忆。
- 替代陌生玩家依靠完整规则书学习的正式盲测。
- 替代针对视觉、听觉、动作、认知、语言或其他可及性条件的专门研究。
- 替代未成年人参与、敏感主题、录音录像或个人资料处理所需的正式同意与组织规范。

若测试转到线上，手的移动、卡牌触感、座位距离、指向和目光可能不可见；这应成为新的媒介范围。若游戏依赖秘密信息，不要为了方便观察而把秘密全部公开，否则原型已经过滤掉了要研究的关系。若游戏依赖长时间累积，不要把五分钟没有出现写成永远不会出现。

一场小测试可以发现很重要的问题，但“小”描述的是范围，不是对参与者的尊重，也不是证据边界可以被缩小。

## 完成本单元的信号

- 你能一口气读完本轮单问题，而且它只有一个主方向。
- 预测写的是时间边界内的可见动作，不是“玩家会觉得很好玩”。
- 你在开始前写下了相反信号，也写了无法判断的破损条件。
- 原型版本、冻结内容和开始状态能被另一人重新摆回。
- 参与范围写明谁参与、是否第一次接触、媒介与必要支持，没有收集无关个人资料。
- 无引导任务没有说出查看工具、交换或合作的目标策略。
- 观察表分开可见行为、玩家原话、主持介入与设计者解释。
- 设计者解释在停止后填写，并能指回具体记录，也承认替代解释。
- 自然、时间、安全和有效性停止都已预写。
- 复盘最多使用三个中立短问题，先问经历与理解，不要求玩家替你修游戏。
- 移交使用暂时支持、暂时不支持或无法判断，不使用一次测试通过分。
- 下一步只选择重复、只改一项或暂停此问题，并写明保持不变的内容。
- 意外发现有停车区，不会抢走本轮问题。
- 你的结论包含“在这个版本、这组参与者和这段任务中”。
- 你不会把一次出现写成证明，也不会把一次没出现写成永远不可能。

## 来源与形成方式

本单元是本站原创中文学习内容，不是任何外文文章、课程、论文或表格的翻译，也没有复现外部材料的章节结构。检索与正文级核验于 2026-08-22 完成；更详细的来源用途、权利状态与证据缺口见 `docs/research/SYSTEMATIC_UNIT_05_SOURCE_AUDIT_2026-08-22.md`。

- [Tabletop Game Designers Association, In-person Playtesting](https://www.ttgda.org/in-person-playtesting)：行业协会官方资源，支持测试前带着问题、自测先检查流程、区分亲友/外部/盲测、保持材料可用、不在局中叫好或争辩，以及由设计者负责修改。该页是行业建议，不提供统一样本量或通过线。
- [Kathleen Mercury, Providing Feedback on Prototypes: The WINQ](https://www.kathleenmercury.com/providing-feedback-on-prototypes-the-winq.html)：教师与桌游设计者的一手课堂方法，支持具体、尊重地反馈，并把局中书面记录与设计者收到反馈后的反思分开。她的课堂评价分类和问题数量不被写成通用研究标准；本站没有复刻 WINQ 表格。
- [Kathleen Mercury, Playtesting](https://www.kathleenmercury.com/playtesting.html)：支持教师先建立测试活动的行为期待和安全框架。页面正文较短，因此不承担九步流程的详细依据。
- [Ian Schreiber, Game Design Concepts Level 2](https://gamedesignconcepts.wordpress.com/2009/07/02/level-2-game-design-iteration-and-rapid-prototyping/)：作者公开课程，支持设计、实现、评价、修改和再次测试的循环，以及纸面原型降低早期迭代成本。原课使用简化的“证明或证伪”类比；本站明确收窄为“一次测试只提供受范围限制的形成性证据”。课程本身为 CC BY 3.0，本单元仍采用原创综合而非翻译。
- [Steve Bromley, Running a Games User Research Study](https://gamesuserresearch.com/running-a-games-user-research-study/)：专业游戏用户研究实践，支持任务不泄露路径、主持保持中立、观察与访谈互补、记录参与者与时间点，以及在开始时说明资料与同意。来源主要是数字游戏和专业设施，本单元迁移到实体桌面时保留了这一限制。
- [Alena Denisova、Steve Bromley、Pejman Mirza-Babaei、Elisa Mekler, Towards Democratisation of Games User Research](https://eprints.whiterose.ac.uk/id/eprint/216480/)：2024 年同行评审原始访谈研究，支持以明确研究问题选择行为与态度资料，并提醒招募、资料处理、资源和研究能力是现实约束。研究对象为 13 名独立数字游戏从业者，地区与语言样本有限，不能替桌游规定人数或外推总体。
- [Youn-Kyung Lim、Erik Stolterman、Josh Tenenberg, The Anatomy of Prototypes](https://faculty.washington.edu/jtenenbg/publications/limAnatomyOfPrototypes-tochi2008.pdf)：HCI 原始研究，支持原型会选择性地放大某些设计面向、测试条件会影响所得，以及原型用于发现与探索而非只证明成功或失败。该研究不直接验证桌游九步测试法。
- [Stanford d.school, How to Test with Users](https://dschool.stanford.edu/s/dschool_testing.pdf)：官方通用原型测试教学材料，支持只给必要语境、让参与者操作、主动观察、不立即纠正并在操作后追问。它不是桌游专用协议。

本单元的一句话式、预测三层、反驳/无法判断分流、版本与参与范围表、无引导任务、《小动物过河》观察表、三层停止、十行复盘、三出口移交、十五分钟练习、一页模板、常见错误与完成信号均为本站教学综合。没有任何来源证明这套流程适合所有游戏或所有人；它的用途是让第一场短测试更清楚、更诚实，也更容易交给下一轮。
