# 单元 3：机制、信息与互动

## 读完以后，你会得到什么

你会把一项规则写成一条可以在桌面上观察和测试的因果关系：

> 规则怎样规定信息与行动 → 一名玩家怎样改变桌面状态 → 其他玩家的判断或可行选择怎样改变 → 对方何时可以回应 → 结果怎样被看见

本单元的最终作品不是“机制清单”，也不是给互动打分。你会得到一张**机制—信息—互动因果卡**，它能直接带进下一次纸片测试。

如果你年纪较小，先跟着“小动物过河”的例子填空即可；如果你已经做过游戏，可以把例子换成自己游戏中最常重复的一次决定。

## 先看桌面上的三个版本

继续使用前两个单元的“小动物过河”。四名玩家要在河水上涨前一起过河。每人有一张工具牌；工具可以铺桥、挡水或救回落水的同伴。

### 版本 A：工具全部公开

所有工具正面朝上。轮到你时，每个人都知道谁能做什么。讨论很容易，但也可能出现一个人替全桌算出行动顺序。

### 版本 B：工具各自保密，但可以随意说

工具放在手中，其他人看不见；玩家却可以随时完整说出牌名和效果。卡牌在物理上是隐藏的，信息在交流中却可能很快重新公开。这个版本是否仍有“不确定性”，要看玩家实际上说了什么，而不能只看牌背。

### 版本 C：工具各自保密，每轮只能给一个信号

玩家不能报出牌名，只能在自己回合开始时说一次“我能铺路”“我能挡水”或“我能救援”。现在，选择信号、理解信号和保留信息本身都可能影响后续行动。

这三个版本没有自动的优劣顺序。A 可能适合公开规划和低门槛合作；B 可能适合轻松交谈；C 可能适合需要推理与协调的合作。设计问题不是“隐藏得越多越好吗”，而是：**你改变了哪一条信息规则，它又怎样改变了玩家的决定与回应？**

## 一分钟理解：机制不是标签，而是一条会运行的关系

“工人放置”“手牌管理”“竞拍”“合作”“隐藏身份”是查找相似游戏时很好用的标签，但它们没有完整说明桌面上发生了什么。

在本单元里，“机制”先按普通语言理解：

> 当某件事发生时，规则允许或要求谁做什么，付出什么，并把游戏从一种状态变成另一种状态。

这里的“状态”就是某一刻桌面的快照，例如：棋子在哪里、谁拥有什么牌、水位多高、轮到谁、哪些承诺已经公开。

Ian Schreiber 的课程把规则、信息和玩家互动都列为可分析的正式要素，并提醒游戏是系统：改动一个要素，其他部分可能一起变化。这是**来源中的教学主张**。本单元据此再做一步**本站教学综合**：分析一项机制时，不停在“规则改变了状态”，还要继续追问“谁知道这次变化，以及它怎样改变别人的问题”。

最短因果链可以写成：

> 触发 → 行动权限与代价 → 信息可见性 → 状态变化 → 他人的选项或判断变化 → 回应窗口 → 可见反馈

后面的步骤会把这条长句拆开。

## 先学会区分三种话

设计资料里常把事实、经验和建议写在一起。为了不把某位作者的偏好当作定律，本单元使用三个标签：

| 标签 | 它表示什么 | 例子 |
| --- | --- | --- |
| **规则事实** | 正式规则或来源明确写出的做法 | 某游戏规定玩家每项任务只能通信一次 |
| **作者观点或报告** | 设计师怎样理解自己的设计，或报告某个版本出现了什么 | 作者认为某种共享资源未必构成有意义的互动 |
| **本站教学综合** | 本站把多个来源整理成的学习工具 | 用“触发—权限—信息—影响—回应”记录一项机制 |

规则事实可以证明某款游戏“怎样规定”，不能单独证明这项规定对所有游戏都有效。设计师报告可以提供很好的假设，也不能替代你对自己原型的测试。本站表格是帮助观察的脚手架，不是学术上唯一正确的机制模型。

## 第一步：从单元 2 圈出一个决定

先不要分析整款游戏。拿出单元 2 的核心循环，只圈住一次会重复发生的决定。

小动物过河可以圈住：

> 轮到我时，我要自己前进、使用工具，还是帮助同伴？

然后写下四项：

1. **决定者**：现在是谁在选？
2. **决定时刻**：在回合的哪一个窗口？
3. **合法行动**：规则允许哪些行动？
4. **实际考虑的选项**：玩家真的在比较哪些行动？

第四项必须从测试中观察，不能只从规则书推断。规则允许三个行动，不代表玩家能看见它们，也不代表三个行动此刻都有意义。

如果你还没有单元 2 的循环，可以先用这句：

> 当轮到______时，他看见______，在______和______之间选择；选择后______改变。

只填一个决定，就足够进入下一步。

## 第二步：把机制写成“触发—权限—成本—变化”

现在暂时不写机制名称，改写一条可以执行的规则：

> 当______发生时，______可以／必须______；需要付出或放弃______；于是______状态从______变成______。

小动物过河中的一条规则可以写成：

> 当玩家选择“帮助”时，他可以把自己的工具交给相邻同伴；需要放弃本回合移动；于是工具所有者从自己变成同伴，而自己的位置不变。

这句话比“这是交易机制”更有用，因为它暴露了至少四个可测试字段：何时发生、谁有权做、代价是什么、什么真的改变。

### 一个适合拆机制的五格检查

5-Part Model 的作者用呈现、操控物、资源、决定和目标描述机制。这是一个**学术作者提出的分析模型**；论文也明确把真实环境中的进一步测试留给未来工作。因此本站只把它当检查镜头，不把它当已经验证的普遍定律。

你可以用普通语言检查：

| 检查格 | 问题 | 小动物过河 |
| --- | --- | --- |
| 桌面呈现 | 玩家能看见和理解什么？ | 河道、水位、棋子、部分工具信息 |
| 可操控物 | 玩家直接拿、移、翻什么？ | 棋子、工具牌、信号标记 |
| 稀缺资源 | 什么会用完、被占用或失去？ | 回合、工具、水位余量、通信机会 |
| 决定 | 玩家此刻比较什么？ | 前进、使用工具或帮助 |
| 目标 | 眼前与整局分别要完成什么？ | 越过下一格；最终让全队过河 |

五格不需要全部做成组件。例如“信任”可能影响决定，却未必需要变成一枚信任标记。这个检查只帮助你发现规则句中漏掉的关系。

## 第三步：画一张信息权限表

“公开信息”和“隐藏信息”通常太粗。真正需要记录的是：**哪一项信息，在什么时候，由谁知道，能否说明、询问、验证，以及何时会过时。**

先区分六件事：

- **真实状态**：牌或标记在规则上到底是什么。
- **可见**：玩家能直接看见。
- **已知**：玩家根据先前信息能够确定，但此刻未必看见。
- **推测**：玩家只能猜测。
- **可声明**：规则允许玩家用语言或信号表达。
- **可验证**：其他人能否立即检查声明是否正确。

用下面的表记录一项关键对象：

| 字段 | 要填什么 | 例：阿鹿的工具 |
| --- | --- | --- |
| 真实状态 | 此刻真实内容 | 挡水工具，可用一次 |
| 谁直接看见 | 无需推理就能读取的人 | 阿鹿本人 |
| 谁可能知道 | 从旧信息或规则能确定的人 | 暂时只有阿鹿 |
| 何时更新 | 信息在什么窗口变化 | 工具被使用、交换或弃掉时 |
| 可说什么 | 允许的语言、手势或标记 | 每轮可说一次“我能挡水” |
| 可问什么 | 他人能否主动查询 | 不能问牌名；可问“现在能否帮忙” |
| 能否验证 | 声明能否立刻检查 | 使用前不能；打出后可以 |
| 何时过时 | 旧声明何时不再可靠 | 工具交换后，旧信号仍在桌上则会过时 |

最后一行很容易漏掉。一项信息以前真实，不等于现在仍真实。

《The Crew》的正式规则给了一个清楚的商业游戏实例：通信机会有次数和时间窗口；玩家用牌与标记表达受限制的信息；而先前正确的标记不会随着手牌状态自动更新。这是**规则事实**，它证明规则可以把“说什么、何时说、旧信息是否更新”写得非常具体。它不证明每款合作游戏都应限制通信一次。

《Decrypto》的正式规则展示了另一种信息关系：线索既要让己队理解，又可能被对手跨轮记录并用于拦截。这也是**规则事实**。这里重要的不是照搬线索规则，而是看见同一条消息可以同时面对两个受众，并对两边产生不同价值。

### 公开不等于容易读取

一张牌正面朝上，只能说明它在规则上公开。文字太小、组件分散、信息没有分组、玩家不能方便回看，都可能让“公开信息”在实际决定中消失。

Daniel Thurot 在自己的设计实践文章中主张逐步增加信息、把相似信息分组并简化布局。这是**设计师的个人实践观点**，不是“超过几张牌就一定过载”的实验阈值。本站把它转成一个测试问题：

> 玩家在决定窗口内，能否不用翻找和背诵，就找到这次选择所需的两三项关键信息？

如果答案是否定的，先记录玩家漏看了什么，再决定是改显示、改时机，还是减少信息。

## 第四步：画出互动影响路径

“玩家可以攻击别人”当然是一种互动，但不是唯一一种。帮助、交换、阻挡、竞价、留下线索、占用公共位置、改变共同危险，也都可能改变别人的处境。

先画这条路径：

> A 的行动 → 哪个共享状态或他人状态改变 → B 的哪些可行选项或判断改变 → B 何时能回应 → 回应结果怎样被看见

小动物过河的例子：

> 阿鹿交出挡水工具 → 阿兔现在拥有挡水能力、阿鹿失去该能力 → 阿兔下回合可以挡水，阿鹿不能再把挡水作为自己的计划 → 阿兔在下回合开始时回应 → 工具位置和水位变化让全桌看见结果

### 不要急着给“直接”或“间接”贴好坏标签

Gil Hova 在一场面向三人以上竞争游戏的演讲中，把互动操作性地理解为改变另一名玩家游戏状态的能力，并讨论个人、全局和相邻等作用范围。他也明确提醒，直接不自动等于坏，间接不自动等于好。这是**演讲者为特定讨论设定的定义与范围**。

Bruno Faidutti 在自己的文章中提出更尖锐的**设计师观点**：如果所有人只是分别利用同一个随机结果，他不愿把它称作有意义的互动；共享空间真正影响了后手的选择时，关系才更值得关注。他也认为“间接互动”这个标签有时会掩盖不同现象。

两位设计师并没有给出一个统一评分表。本站因此不问“互动强度是几分”，先问三个更可观察的问题：

1. A 到底改变了哪个状态？
2. B 因此少了、增加了或重新理解了哪个选项？
3. B 是否有一个能被看见的回应机会？

如果你只能写“B 感到被影响”，因果链还不够清楚。继续找棋子位置、资源数量、行动权限、公开信号、顺序、风险或预期收益中的具体变化。

### 六种常见影响路径

下面不是完整分类，只是一组找路提示：

| 路径 | A 改变什么 | B 可能怎样回应 |
| --- | --- | --- |
| 转移 | 给、换、偷走资源或权限 | 接受、拒绝、回赠、改计划 |
| 占用 | 先拿公共位置、骰子或卡槽 | 改走其他路线、提高出价、等待 |
| 改写共同状态 | 推高水位、移动公共标记 | 补救、加速、放弃某目标 |
| 改变信息 | 揭示、隐藏、暗示或制造噪声 | 查询、推理、试探、保留判断 |
| 改变顺序 | 插入、延迟、交换行动次序 | 抢先、预留、承担晚动风险 |
| 提供能力 | 让别人获得行动、折扣或保护 | 接住组合、回报、选择不使用 |

同一项规则可以同时走两条路径。例如交出工具既转移能力，也公开了“阿鹿原来持有挡水工具”这一信息。

## 第五步：把信息与互动接成一条因果关系

现在把前两张表接起来。不要跳过中间环节直接写“所以大家更合作”。

用这个模板：

> 因为规则规定______只能／必须在______时被看见或表达，所以 A 在______之间选择。A 选择______后，______状态改变；这使 B 原本的______变成______。B 可以在______时通过______回应；我们会从______观察这条关系是否真的发生。

版本 C 可以填成：

> 因为规则规定每人每轮只能在自己回合开始时给一个能力信号，所以阿鹿在暴露“能挡水”和保留通信机会之间选择。阿鹿给出“能挡水”后，公开信号状态改变；这使阿兔原本只能猜测的救援选项变成可纳入计划的选项。阿兔可以在自己的回合通过保留移动、等待交接来回应；我们会从阿兔是否提到该信号、是否改变行动，以及工具是否随后交接来观察这条关系。

注意这仍是假设。玩家也可能忽略信号、误解信号，或认为水位根本不值得处理。只有桌面记录能告诉你中间哪一环断了。

### 一则双用途卡案例

Paul Dennen 在《Dune: Imperium》的设计日记中报告：一张牌可以在派遣 Agent 时使用，也可以保留到回合末以 Reveal 方式产生资源；较早使用同一张牌，就会减少回合末可展示的牌。作者把这种双用途关系描述为一个机会成本，并报告它帮助缓和额外 Agent 带来的滚雪球优势。

这是**设计师对自己项目的报告**，不是对所有“双用途卡”都成立的因果定律。本站可以从中迁移一个测试问题：

> 同一组件在两个时机有不同用途时，玩家是否看得见“现在用掉会失去什么”，而其他玩家又能否从这次使用更新自己的判断？

## 第六步：检查对方是否真的能回应

有影响，不一定有可玩的回应。如果 A 的行动彻底决定 B 的结果，而 B 既无法预防、转向，也无法把信息带进未来决定，B 可能只是在接收结果。

逐项检查：

1. **看得见**：B 知道什么发生了吗？
2. **来得及**：B 得知后还有行动窗口吗？
3. **做得到**：至少有一个可行回应吗？
4. **有代价**：回应是否需要真实取舍，而非总是免费正确？
5. **有反馈**：A 与 B 能否看见回应造成的结果？
6. **能延续**：结果会进入之后的决定，还是立即消失？

“回应”不只等于反击。合作游戏中，回应可能是接住同伴的铺垫；竞价中可能是退出；推理游戏中可能是保留怀疑；空间游戏中可能是换路；儿童游戏中也可以只是从两个清楚选项中选一个。

如果目标体验就是短暂惊喜或不可控风险，回应窗口可以很小。但你仍应知道这是有意选择，而不是因为规则漏写或信息没有传到玩家那里。

## 第七步：只改一个字段，再测试

机制、信息和互动会互相牵动。一次同时改五处，你很难知道哪一处造成变化。先从一条因果卡中选一个字段：

- 把“任何时候都能说”改成“回合开始时能说一次”。
- 把工具效果完全隐藏改成显示一个能力类别。
- 把工具交接立即生效改成接收者下回合生效。
- 把公共水位改成只有当前玩家能查看。
- 把使用工具的代价从放弃移动改成提高水位一格。

改动前先写预测：

> 如果我们把______改成______，那么玩家会更常／更少______；因为______。如果测试中出现______，这个解释就需要被削弱或推翻。

例子：

> 如果把无限交流改成每轮一个能力信号，玩家会更常根据不完整信息保留工具；因为他们不能立即确认所有人的完整手牌。如果玩家仍在开局把全部工具用约定代码公开，或工具信息对决定完全无关，这个解释就需要被推翻。

“没有出现预期结果”不是失败，它告诉你因果链中至少一环不成立。

前两项可以被记录；第三项只是暂时假设。也可能真正的问题是水位反馈不明显，而不是通信限制。

## 现在动手：二十分钟三版纸片实验

### 准备材料

- 四枚代表小动物的棋子。
- 八张手写工具牌，其中至少两种功能相近、两种功能不同。
- 一条六格河道和一个水位标记。
- 三张版本说明：完全公开、隐藏但自由交谈、隐藏且每轮一个能力信号。
- 一张观察表。

### 进行方式

1. 每个版本只玩三到五轮，不必完成整局。
2. 每个版本都观察同一个决定：“现在自己前进、用工具，还是帮助？”
3. 观察者只记录看见和听见的事，不在过程中解释设计目的。
4. 每版结束后问玩家三个短问题：
   - 你刚才以为别人有什么能力？
   - 哪一条信息改变了你的行动？
   - 你希望在什么时候回应别人？
5. 三版结束后，比较因果链中哪一环变化，而不是只问“最喜欢哪版”。

### 小学生友好的简化记录

只画三个格：

> 我看见／听见了______ → 所以我做了______ → 这让另一位玩家______

如果第三格填不出来，再问：“你的行动让别人多了什么、少了什么，或重新想到什么？”

### 给有经验设计者的加做题

选一个版本，保留全部行动不变，只改变信息更新时间。例如把“工具交换后旧信号仍留在桌上”改成“交换时立即移除信号”。预测这会改变错误判断、记忆负担还是交流频率，并写出一个可以推翻预测的现象。

## 常见误用

### 误用一：把机制名称当成原因

“因为这是工人放置，所以会互动”没有写出因果。要继续写：谁占了哪个位置、谁因此失去什么选项、什么时候能回应。

### 误用二：以为隐藏越多，推理就越深

信息完全不可读时，玩家可能只能猜；信息能被自由复述时，物理隐藏也可能没有作用。深度来自可使用的线索、代价和回应，不来自牌背数量。

### 误用三：把共同随机结果自动叫作互动

全桌使用同一颗骰子，不一定改变彼此的选择。要检查玩家能否占用、改写、预测、利用或回应他人造成的状态变化。

### 误用四：把直接和间接当成品质评分

直接影响可以清楚、短促且公平；间接影响也可能晦涩、难以察觉或不可回应。先画影响路径，再判断它是否服务目标体验。

### 误用五：只把攻击当互动

帮助、让位、交换、竞价、公开承诺、占位、给线索和改变共同风险，都可能改变别人的问题。

### 误用六：规则只写“玩家可以讨论”

还要说明讨论发生的时间、可谈内容、可用媒介、是否可展示或验证，以及无障碍协助怎样处理。否则不同桌可能实际玩着完全不同的信息系统。

### 误用七：从规则直接跳到情绪

规则可以改变信息、权限和状态；“紧张”“信任”“满足”是玩家可能产生的体验，不是规则自动保证的结果。需要通过行为、访谈和多次测试连接中间环节。

### 误用八：把曾经公开的信息当成永远可用

旧位置、旧承诺和旧手牌信息可能已经过时。规则应说明玩家能否回看，以及桌面标记是否会更新。

### 误用九：认为选项越多越好

新增一个按钮或行动，可能只是增加阅读负担。检查它是否改变代价、状态、他人回应或未来反馈；如果没有，它可能只是表面选择。

### 误用十：用玩家一句评价替代因果记录

“互动不够”“信息太多”是重要线索，但还不是诊断。追问具体时刻：你漏看了什么？谁的哪个行动改变了你？你当时想回应却为什么不能？

## 适用与不适用边界

这套方法适合检查桌游中一条重复关系，尤其适合原型早期。它不是完整的规则写作、平衡或无障碍标准。

- **单人游戏**：可以把“其他玩家”替换成系统、自动对手或未来的自己，重点记录状态怎样改变下一次选择；不必强行制造玩家互动。
- **纯合作游戏**：私密信息不会自动消除“一个人替大家决定”。还要观察发言顺序、专业知识、社交权力和行动权限。
- **实时、速度或动作游戏**：除了信息内容，还需记录读取时间、身体动作、误触和安全；本单元的回合窗口表不够完整。
- **谈判与社交推理**：语言不仅传递规则事实，也包含承诺、欺骗和关系。不要用游戏表现诊断一个人的真实品格、诚实程度或认知能力。
- **记忆游戏**：不允许回看可能是有意挑战，也可能排除部分玩家。应明确它在考验什么，并考虑替代标记、难度档或协助方式。
- **儿童与混龄桌**：不要把阅读速度、词汇量和成人谈判经验误当策略能力。先提供图标、示范回合和短句信号，再比较决定。
- **无障碍协助**：代读、持牌器、颜色替代和公开辅助可能无意泄露隐藏信息。先定义辅助者能接触与复述什么，目标是提供等价访问，不是替玩家推理或决定。
- **两人、三人以上与队伍游戏**：作用范围和结盟可能完全不同。Gil Hova 的相关演讲明确聚焦三人以上竞争游戏，不能直接外推到所有人数与合作结构。
- **完整商业游戏案例**：一项已出版规则只能说明它怎样运作，不能隔离证明某一个机制独自造成销量、口碑或体验。

没有“最佳隐藏信息量”“最佳互动强度”或适合所有年龄的通信次数。先写目标体验，再检查这条关系是否让目标更可能出现。

## 完成本单元的信号

当下面大部分问题都能用具体桌面证据回答时，你可以进入下一单元：

- 我能不用机制名称，写出一条“触发—权限—代价—状态变化”的规则句。
- 我能说清一项关键信息由谁在何时看见、表达、查询、验证，以及何时过时。
- 我能指出 A 的行动改变了 B 的哪个可行选项、判断或资源，而不是只说“产生互动”。
- 我能指出 B 的回应窗口、回应代价和可见反馈。
- 我能分开记录观察事实、玩家解释和设计者假设。
- 我能为下一版只改一个字段，并写出支持与削弱预测的现象。
- 我能说明这条方法不覆盖的部分，例如社交权力、身体可达性或长期平衡。

你的最终作品应能压缩成这一张卡：

> **当**______发生时，**谁**______可以／必须______，付出______；此时______信息对______可见／不可见／可表达。行动让______状态从______变成______，因此另一名玩家的______选项或判断改变。对方可以在______通过______回应。若测试中观察到______，暂时支持解释；若观察到______，就应修改解释。

卡片可以写不满，但不能用“更有趣”“更有互动”代替中间关系。

## 来源、观点与形成方式

本单元是本站原创中文教学综合，不是任何外部文章、课程或规则书的全文翻译。来源用于确认概念出处、正式规则做法与设计师报告；步骤、因果卡、表格、练习及“小动物过河”案例由本站重新组织和创作。

### 正式框架与课程来源

- [Ian Schreiber：Game Design Concepts，Level 3: Formal Elements of Games](https://gamedesignconcepts.wordpress.com/2009/07/06/level-3-formal-elements-of-games/)：用于核对规则、信息、玩家互动与系统要素的课程表述。课程采用 CC BY 3.0；本单元仅概述相关思想，并未翻译该课全文。
- [Hunicke、LeBlanc 与 Zubek：MDA: A Formal Approach to Game Design and Game Research](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/)：用于延续“规则层、运行中关系与体验结果不可直接画等号”的分析边界。本单元不把 MDA 当作桌游制作配方。
- [Mora-Zamora、Brenes-Villalobos 与 Durán：5-Part Model](https://www.clei.org/cleiej/index.php/cleiej/article/view/473)：用于核对呈现、操控物、资源、决定与目标五部分。论文以电子游戏案例为主，并把真实环境测试列为未来工作，因此本站只把它作为拆解镜头。

### 正式规则来源

- [Thomas Sing / Thames & Kosmos：《The Crew: The Quest for Planet Nine》英文规则](https://www.thamesandkosmos.com/manuals/full/691868_Crew_Manual.pdf)：用于核对限次通信、通信窗口、标记含义与信息过时的具体规则做法。
- [Thomas Dagenais-Lespérance / Le Scorpion Masqué：《Decrypto》英文规则](https://www.scorpionmasque.com/sites/scorpionmasque.com/files/decrypto_en_rules_20sep2019_1.pdf)：用于核对一条线索面对己方与对手两个受众、对手跨轮记录线索的规则关系。

这些规则来源只能支持“该游戏这样规定”，不支持“所有游戏都应这样规定”。

### 设计师实践与带立场的观点

- [Gil Hova：Why Indirect or Zero Player Interaction Can Be Great](https://ubm-twvideo01.s3.amazonaws.com/o1/vault/gdc2019/presentations/Hova_Gil_Why_Indirect_Zero.pdf)：用于核对其对互动、作用范围及讨论边界的演讲定义。该定义服务于作者聚焦的三人以上竞争游戏讨论。
- [Bruno Faidutti：Indirect Interaction](https://faidutti.com/blog/blog/2022/04/27/indirect-interaction/)：作为设计师对“间接互动”标签和共享随机现象的个人批评，不作为统一分类定律。
- [Paul Dennen：Dune: Imperium Designer Diary 1 — Beginnings](https://news.direwolfdigital.com/dune-imperium-designer-diary-1-beginnings/)：用于概述作者报告的 Agent／Reveal 双用途牌及机会成本。案例不能隔离证明单一机制的效果。
- [Daniel Thurot：Information Overload](https://daniel.games/information-overload/)：用于呈现作者关于渐进信息、分组和简化布局的实践建议，不提供普遍的信息量阈值。

### 本站怎样形成这套方法

本站把上述来源与单元 0–2 已建立的“问题—体验—决定循环”串联，形成以下教学顺序：先冻结一次决定，再写可执行规则，接着记录信息权限与他人影响，最后用回应和反馈闭合因果链。这个顺序、术语模板与记录表都是**本站教学综合**，应通过真实课堂、不同年龄与不同背景玩家的使用继续修订。
