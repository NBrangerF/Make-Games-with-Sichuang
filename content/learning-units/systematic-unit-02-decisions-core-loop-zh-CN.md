# 单元 2：决定与核心循环

## 读完以后，你会得到什么

你会画出一条最小核心循环：玩家看见什么、真正比较哪些行动、承担什么代价、游戏状态怎样改变，以及反馈怎样进入下一次决定。

你也会学会区分“规则允许的行动很多”和“玩家真的遇到了有变化的决定”。

## 先看桌面上的例子

小动物过河的版本现在允许每名玩家在回合中做三件事：移动、使用工具或帮助同伴。

只列这三个行动还看不出游戏怎样运行。把一次回合展开：

1. 玩家看见河水位置、自己的工具和同伴位置。
2. 玩家在独自前进、修好前路或把工具交给同伴之间选择。
3. 选择帮助同伴会失去本回合移动；选择独自前进会让共同水位继续上涨。
4. 棋子、工具和河水状态改变。
5. 所有人看见新的危险距离，并据此重新计划。

第五步把结果送回了下一次选择，这才形成循环。

## 一分钟理解：核心不是机制清单

“卡牌驱动、资源管理、合作、可变地图”是分类标签。它们可以帮助找资料，却没有说明玩家在一局中怎样持续作出决定。

核心循环可以先写成：

> 输入 → 有效选项 → 选择与代价 → 状态变化 → 可见反馈 → 新的输入

这里的“核心”不是说一款游戏只能有一个机制，也不是要求所有复杂游戏都缩成五分钟。它指的是：先隔离一条会反复发生、会因状态改变而产生不同答案的关系。

Eric Zimmerman 的 LOOP 案例从最小输入动作开始，逐步加入对象、目标和危险。Daniel Piechnick 强调删去不支持中心活动的内容。Mark Rosewater 则提醒，增加决定不一定总让游戏更好，过多或没有真实取舍的选项也会增加负担。三者是不同语境下的实践观点，不是同一套普遍定律。

## 第一步：找到会重复的决定

问三个问题：

1. 玩家在一局中会多次遇到什么局面？
2. 当前状态变化后，答案会不会不同？
3. 选择之后，玩家能否看见足以调整下一步的结果？

如果一个决定只在开局出现一次，它仍可能很重要，但不一定是你要先测试的短循环。如果每次答案都显然相同，则需要检查代价、信息或后果是否真的发生变化。

## 第二步：区分合法行动和有效选项

规则书可能允许五个行动，但玩家实际只会考虑两个。其余行动可能：

- 因资源不足而不能执行。
- 在当前状态明显更差。
- 玩家不知道它存在。
- 后果与另一个行动几乎相同。
- 因社交压力或默认策略而不被考虑。

因此记录一次决定时，分开写：

| 层次 | 要记录什么 |
| --- | --- |
| 合法行动 | 规则允许玩家做什么 |
| 玩家看见的行动 | 玩家知道哪些选项存在 |
| 实际考虑的行动 | 玩家在比较哪些方案 |
| 最终行动 | 玩家最后做了什么 |

不要因为一个选项没被选择就宣布它无用。先弄清它是否被看见、是否可行，以及玩家怎样理解后果。

## 第三步：为选择补上代价

一个行动有收益，不等于形成取舍。代价可以是：

- 花掉资源。
- 放弃另一项同时发生的行动。
- 暴露信息。
- 改变位置或顺序。
- 承担失败风险。
- 让其他玩家得到回应机会。
- 推迟长期目标。

在小动物过河中，“帮助同伴”如果同时也让自己前进，就可能一直是显然正确的动作。让它占用移动机会，会产生真实代价，但还需要测试这项代价是否过重。

## 第四步：写清状态到底改变了什么

状态不只是分数。它可以包括：

- 资源数量。
- 卡牌或工具所在位置。
- 公共与私人信息。
- 行动顺序和剩余时间。
- 玩家之间的承诺、债务或信任。
- 哪些行动下一轮可用。

使用一句话：

> 因为玩家选择______，所以______从______变成______。

例如：

> 因为玩家把绳索交给同伴，所以绳索从个人工具变成同伴可用资源，自己的独立过河行动暂时不可用。

这比“玩家进行了交易”更能暴露系统关系。

## 第五步：检查反馈是否回到下一次决定

玩家需要在合适的时间看见结果。反馈可以来自棋子位置、翻开的牌、资源减少、他人表情、规则提示或新的可行动作。

检查：

- 谁能看见结果？
- 什么时候看见？
- 能否理解哪项行动造成了它？
- 这份信息会改变下一次考虑的选项吗？

如果结果直到游戏结束才出现，它可能属于长循环。如果反馈出现但玩家无法追溯原因，学习和掌控感可能受影响。隐藏反馈也可以是有意设计，但要说明它制造了什么不确定性。

## 把五段接成一行

使用下面的格式：

> 玩家看见______ → 在______与______之间选择 → 放弃或承担______ → ______状态改变 → 玩家从______看见结果，并据此______。

小动物过河的版本：

> 玩家看见上涨的河水、两人的位置和自己持有的工具 → 在独自前进与把工具交给同伴之间选择 → 帮助会放弃本回合移动 → 工具归属和双方位置改变 → 两人看见距离下一障碍还有几步，并据此重新分工。

如果其中一段写不出来，先不要增加更多内容。缺口本身就是下一轮问题。

## 只改一个轴，再写行为预测

核心循环可以从多个轴被改变：信息、资源、行动顺序、空间、互动、反馈、目标或终局。

一次同时修改全部轴，很难知道什么造成了变化。先写：

- **本轮改变**：帮助同伴后，工具要到下一轮才能取回。
- **保持不变**：地图、河水速度、玩家行动数和胜利条件。
- **行为预测**：玩家会更早讨论工具交接时机，而不是到障碍前才处理。
- **反驳信号**：玩家不再考虑帮助，因为失去工具的代价始终超过共同收益。

“一次只改一个轴”是诊断策略，不是永远只能改一个数字。若多个规则共同造成不可执行状态，可以先修复运行，再重新建立比较版本。

## 常见误用

### 把行动数量当成决定质量

十个名字不同但后果相似的行动，可能只增加查找负担。先看玩家真正比较了什么，以及状态怎样改变其价值。

### 每个循环都必须很短

谈判、长局经济、叙事承诺和跨局成长可能需要更长时间才反馈。短循环适合先检查局部关系，但不能替代完整局验证。

### 核心循环图画得很完整，就认为游戏已经好玩

一条循环能够运行，只证明关系可描述。它不能自动证明体验有价值、数值平衡、规则可学或玩家愿意重复。

### 删除所有不属于核心的内容

题材、呈现、停顿和外围系统可能承担学习、节奏、表达和无障碍功能。删减应作为带版本的实验，不能把个人偏好变成普遍规则。

## 现在动手：画一轮决定

选一款熟悉的游戏或自己的原型，只记录一个回合中的一个决定：

1. 玩家开始时能看见什么？
2. 规则允许哪些行动？玩家实际考虑哪些？
3. 最终选择牺牲了什么机会或资源？
4. 哪些公共、私人或关系状态改变？
5. 谁在什么时候看见反馈？
6. 反馈怎样改变下一次决定？

再删掉一条你以为重要、但无法接入这条关系的规则，写下预计会发生什么。不要直接永久删除，先保存版本并测试。

## 适用与不适用边界

这条五段循环适合检查短时决定、第一份原型、单项机制修改和玩家为什么总做同一选择。

它不能独自描述所有桌游。实时沟通、身体技巧、角色表演、社会契约、长局叙事和局外活动可能需要其他表示方式。Rosewater 的术语来自 Magic 设计实践；LOOP 是数字游戏案例；Daniel Piechnick 的精简倾向也是个人流程。迁移时要保留这些语境。

## 完成本单元的信号

- 你能分开合法行动和玩家真正考虑的选项。
- 至少一个选择包含不能同时保留的代价。
- 状态变化能够用前后差异写清。
- 反馈会进入下一次决定，或你明确知道它属于更长循环。
- 下一版只有一个主要改变轴，并有行为预测与反驳信号。
