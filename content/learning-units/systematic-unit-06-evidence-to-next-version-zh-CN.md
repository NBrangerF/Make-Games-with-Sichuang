# 单元 6：从证据到下一版

## 读完以后，你会得到什么

你已经做出最小原型，也完成了第一场测试。现在最容易发生的事情，是趁记忆还热，一口气改规则、改地图、改卡牌，再告诉自己：“我是在根据反馈迭代。”

本单元会带你慢一步。你将学会把一场测试变成一条可以回看的推理链：

1. 冻结真正被测试的版本，不让下一版覆盖上一版。
2. 把原始观察、玩家原话和设计者解释分开保存。
3. 对同一现象至少写两个备选原因。
4. 说明证据强到哪里、弱在哪里、还有什么不知道。
5. 在保留、修复和继续观察之间做一个清楚决定。
6. 下一版只选择一项主要学习性改动。
7. 在改动前写下行为预测，以及会反驳当前解释的信号。
8. 把暂时不做的好点子放进停车区，而不是偷偷塞进新版本。
9. 生成一页下一版简报和可以追踪的版本号。

这里不会教你从一场小测试“证明”玩家为什么这样做。早期测试通常参与者少、情境具体，而且设计者的教学、座位、材料和临时解释都会影响行为。我们要做的是比凭印象更诚实地前进：知道自己看见了什么，知道自己猜了什么，也知道下一轮要怎样让猜测更容易被挑战。

## 接上同一张桌子

我们继续使用《小动物过河》，不加入第二个贯穿案例。

当前最小原型仍然是两人切片：松鼠面对急流，需要绳索，却开局拿着木板；水獭面对断桥，需要木板，却开局拿着绳索。两只动物在同一列时，玩家可以发起交换双方手中的工具。发起者要用掉本回合行动，所以每回合必须在前进一格与发起交接之间二选一。两人都行动以后，水位上升一格。两只动物都越过障碍，或水位到达第三格，测试立即停止。

单元 4 把它做成了 `小动物过河_工具交接_v0.1_2026-08-22`。单元 5 为这份原型写好了一场可执行的单问题测试计划，并明确说明其中的观察表行是格式示范，不是已经发生的参与者结果。现在我们的工作不是把模板伪装成证据，而是学习：当真实记录到来时，怎样从记录走到下一版。

为了把整条路演示完整，本单元会使用单元 4 已经出现的两行样例记录作为“教学演练数据”，编号 `DEMO-01`。它不是项目真实测试，不代表真的招募过两名参与者，也不能进入项目的实证结论。将来真的运行测试时，应另建 `T01`，只填写现场发生的事情。

## 一分钟理解：证据不是命令，是一条有缺口的路

可以先记住这条短链：

> 冻结版本 → 整理三栏 → 写备选原因 → 标证据与未知 → 决定方向 → 只选一项改动 → 写预测与反驳 → 编下一版号码

每一段回答不同的问题：

| 环节 | 它回答什么 | 它不能替你回答什么 |
| --- | --- | --- |
| 冻结版本 | 当时玩家实际面对什么 | 玩家为什么这样做 |
| 原始观察 | 桌面上发生了什么 | 玩家心里在想什么 |
| 玩家原话 | 玩家怎样描述当时体验 | 这段描述是否就是唯一原因 |
| 设计者解释 | 哪些原因目前看来可能 | 哪个原因已经被证明 |
| 证据强度 | 当前记录能支持到哪一步 | 结果是否适用于所有玩家 |
| 下一版决定 | 下一轮最值得学习什么 | 哪个方案永远正确 |
| 行为预测 | 改动若有效，预计看见什么 | 结果一定会照预测发生 |
| 反驳信号 | 什么结果会让当前解释变弱 | 失败以后要怎样替自己找借口 |

如果把观察直接跳成修改，中间的原因会藏起来。以后版本变好或变坏，你很难知道为什么。把这条路写出来，不会消除不确定，却能让你和同伴看见不确定在哪里。

## 第一步：先把被测试的版本冻住

### “冻结”不是永远不许改

冻结的意思是：从分析开始，保留一份当时版本的快照，不再在这份快照上直接涂改。你当然可以制作下一版，但不能让新卡覆盖旧卡，让修改后的规则冒充测试时的规则。

一份最小冻结包应当能回答五件事：

1. **组件是什么**：河道纸、棋子、工具卡、水位轨和提示条分别是哪一版。
2. **规则是什么**：设置、合法行动、行动代价、状态变化与停止条件。
3. **玩家看见什么**：哪些信息公开，哪些被遮挡，组件放在哪里。
4. **设计者做过什么**：怎样教学，什么时候回答问题，有没有临时提醒或改规则。
5. **这场测试是谁和什么时候**：用匿名场次编号记录人数、相关经验、日期与必要情境，不收集无关个人资料。

可以给示范场次这样命名：

> `小动物过河_工具交接_v0.1_T01_2026-08-22`

`v0.1` 是设计版本，`T01` 是这个版本的第一场记录。版本号与场次号做不同工作：同一版可以有 `T01`、`T02`、`T03`，但只有实际改变原型后才进入 `v0.2`。

版本号没有行业统一写法。儿童课堂也可以写成“过河-工具交换-第 1 版-第 1 场”。重要的不是像软件公司，而是任何一张观察表都能找到对应的规则和组件。

### 测试中途改了怎么办

不要假装整场都在测试同一版。把记录切开：

| 片段 | 实际状态 | 怎样标记 |
| --- | --- | --- |
| A 段 | 使用原始提示条 | `v0.1-T01-A` |
| 介入 | 设计者补充解释或临时改字 | 单独写下时间与内容 |
| B 段 | 玩家已经知道新增信息 | `v0.1-T01-B，含介入` |

B 段仍然有价值，它可以告诉你补充信息以后发生了什么；但 A、B 两段不能混在一起，当作同一条件下的次数统计。若规则崩溃到无法继续，可以停止、修复并另开一个修复版。诚实地结束一场，比用不断变化的规则凑出“完整一局”更有用。

### 冻结检查

- [ ] 旧组件没有被下一版覆盖。
- [ ] 规则、设置和停止条件有可读快照。
- [ ] 教学与测试中介入被记录。
- [ ] 每条笔记带有版本号和场次号。
- [ ] 照片、录音或录像只在获得适当同意后保存。
- [ ] 参与者可以要求停止，并知道资料只会按约定用途使用。

## 第二步：把笔记分成三栏

单元 4 已经用“事实、玩家原话、暂时解释”做过起步记录。现在把它固定成一张不会混淆的证据表。

| 原始观察 | 玩家原话 | 设计者解释 |
| --- | --- | --- |
| 摄像机或录音可以核对的行动、位置、时间点、问题与结果 | 当时确实说出的短句；若不是逐字记录，要标“意译” | 对原因、意义或设计问题的暂时判断，必须使用“可能” |

### 原始观察：写动作，不替玩家读心

较好的观察会包含“什么时候、什么状态、谁做了什么、桌面怎样变化”。例如：

- “松鼠棋子到达急流前一格后停下。”
- “水獭指向自己面前的绳索卡。”
- “设计者再次说明发起交换会用掉本回合行动。”

下面这些句子已经混入解释：

- “玩家很困惑。”
- “他们不喜欢机会代价。”
- “合作机制失败了。”
- “水獭终于理解正确策略。”

你可以观察到玩家停顿、皱眉、查看提示条、提出问题或走了一步后来撤回，却不能只凭一个动作知道内心原因。把“看起来困惑”拆回可见行为，再把“可能没有理解”放到解释栏。

### 玩家原话：保存声音，也保存它的限制

原话能告诉你玩家怎样描述自己的理解、目标或感受，但它不自动成为客观事实。

如果玩家说“我没看见可以换”，这可靠地说明玩家此刻这样描述自己的经历。它不能单独证明卡牌位置就是唯一原因，因为玩家也可能忘记教学、忙着规划移动，或在事后用最顺手的说法解释自己。

记录原话时：

- 用引号标逐字记录，听不清就不要补齐。
- 只记得大意时写“意译”，不要伪装成逐字引语。
- 保留发生时点，例如“第一次移动后”或“看到障碍时”。
- 不用姓名，使用“玩家 A”“玩家 B”或角色名。
- 不把口音、语法、阅读困难或身体反应当笑料。
- 需要录音录像时先取得适当同意，并说明保存与删除方式。

### 设计者解释：写成可以被挑战的猜测

解释栏不是垃圾桶，也不是判决书。每条解释尽量使用这种句式：

> 这可能与______有关，因为观察到______；但也可能是______，目前还缺______。

例如，“玩家可能没有把工具卡看作可交换物，因为行动前没有查看同伴的卡；但也可能已经看见，只是先移动的代价更容易理解。目前缺少他们第一次查看工具的时点，以及作决定时怎样比较水位与行动机会。”

这个句子比“工具不够显眼，下一版放大”更慢，却更有用。它把原因与方案分开，也指出下一轮需要什么证据。

### 三栏之间不能偷渡

常见偷渡有四种：

1. 把“没有交换”写成“没有合作”。前者是动作，后者是对关系的解释。
2. 把“太贵了”写成“行动代价失衡”。前者是原话，后者仍需结合局面判断。
3. 把“把卡放中间”写进原因栏。它是玩家建议或候选方案，不是原因。
4. 把自己的提示漏掉。设计者说过的一句话可能正是玩家后来行动的原因。

## 第三步：同一现象至少写两个备选原因

### 为什么不能只写最顺眼的原因

设计者知道自己想做什么，所以很容易把观察解释成早已相信的故事。若你觉得问题来自卡牌不明显，就会注意玩家没看卡；若你觉得问题来自交换代价太高，就会注意玩家继续前进。两件事可能都发生，也可能另有原因。

至少写两个备选原因，是为了让注意力不只服务第一个想法。对初学者来说，两到四个通常足够开始，不需要列出所有宇宙可能。

可以从四个方向发问：

| 方向 | 要问的问题 | 《小动物过河》中可能检查什么 |
| --- | --- | --- |
| 看见 | 玩家有没有注意到相关信息 | 是否查看同伴工具、障碍需求和水位 |
| 理解 | 看见以后怎样理解规则 | 是否知道同列可换、发起者耗行动、双方卡片互换 |
| 取舍 | 理解以后是否认为值得 | 是否比较先移动、先交换与水位压力 |
| 情境 | 还有什么影响行为 | 教学顺序、座位、角色分工、熟悉度、设计者介入 |

### 备选原因表

| 待解释现象 | 备选原因 | 目前支持它的记录 | 与它冲突或不能解释的记录 | 仍缺什么 |
| --- | --- | --- | --- | --- |
|  | 原因 A： |  |  |  |
|  | 原因 B： |  |  |  |
|  | 原因 C，可选： |  |  |  |

备选原因不需要互相排斥。玩家可能既没有很早注意工具，又觉得交换机会代价太高。下一轮的任务不是一次解决所有原因，而是选择一项改动，让其中某个解释更容易受到检验。

### 玩家建议放在哪里

玩家说“应该让交换免费”，先记录为：

- 原话或建议：玩家提出免费交换。
- 可能暴露的问题：玩家感觉交换失去的行动不值得，或没有感受到水位压力。
- 候选原因：代价过高；收益不清；当下位置不需要交换；玩家还没理解未来障碍。
- 候选方案：免费交换、降低代价、提前显示需求、改变水位、调整位置。

建议很宝贵，因为它指向玩家试图修复的体验。但是建议不是原因，也不是命令。Daniel Solis 和 TTGDA 的设计实践都提醒我们：先理解建议背后的问题，最后由设计者选择符合目标的方案。

## 第四步：标出证据强度，也写下未知

### 一个给初学者的四级标法

这不是学术量表，也不是行业评分。它只是帮助你不把所有笔记写成同样确定。

| 标记 | 目前有什么 | 可以怎样写 | 不能怎样写 |
| --- | --- | --- | --- |
| 线索 | 一条清楚观察或一句相关原话 | “这提示我们检查……” | “原因已经找到” |
| 相互支持 | 行为、原话或桌面状态从不同角度指向同一解释 | “这个解释比以前更可信” | “其他原因已排除” |
| 重复信号 | 同一冻结版本的多个场次或不同参与者出现相近模式 | “这个模式值得优先处理” | “所有玩家都会这样” |
| 比较证据 | 先写预测，只改一项主要因素，再比较相近情境 | “改动与预期行为变化一致” | “改动已经证明是唯一原因” |

“比较证据”仍然不是因果证明。不同玩家、随机结果、教学变化和群体关系都可能影响新旧版本。它只是比“我改了很多，大家说更好”更容易解释。

### 强度不仅看出现次数

次数回答“在这些记录里出现了几次”，不能单独回答“为什么出现”。还要看：

- **与主问题的距离**：这条记录是否直接发生在目标决定上。
- **记录完整度**：是否知道版本、局面、先后顺序和设计者介入。
- **信号是否汇合**：行动、原话和状态是否互相支持。
- **是否有反例**：有没有玩家在相同条件下采取不同路径。
- **是否能区分原因**：同一结果是否也完全符合另一个解释。
- **后果严重度**：一次无法继续的规则断点，可能比多次轻微犹豫更需要先修。

### 四个不能自动升级的东西

#### 出现频率

三个人都在障碍前停顿，说明“停顿”在这几场重复。它不自动证明障碍文字不清，也可能来自需要计算、等待同伴、首次见到选择或设计者教学方式。

#### 多人共识

所有人都说“交换应该免费”，说明这个小组的建议一致。若他们接受了第一位发言者的说法，或都在同一种设置下没看见收益，共识仍不能确定代价就是根因。

#### 好评

“很好玩”“角色很可爱”是体验资料，应该尊重并保存。但它不能证明工具交接规则造成好评，也不能抵消某个玩家无法阅读卡片的事实。

#### 玩家建议

建议是一项待评估方案。设计者需要知道它想解决什么、会改变哪些关系、是否符合体验目标，以及要怎样测试。多人提出同一建议，也仍然不是因果证据。

### 每个判断都带一个“未知盒”

可以写：

> 我们现在较有把握的是：______。  
> 我们现在只能猜的是：______。  
> 这场测试没有回答：______。  
> 下一场若要区分原因，需要记录：______。

未知不是失败。写下未知，会阻止团队在几周以后把“我们当时猜测”记成“我们已经知道”。

## 第五步：决定保留、修复，还是继续观察

整理完一条问题后，只给它一个当前状态。

### 保留

“保留”表示当前版本的这项关系暂时不改，以免破坏已经能运行的部分，或为了在下一场继续比较。它不表示永远完成。

适合保留的情形：

- 目标行为已经出现，记录中没有严重断点。
- 当前疑问与本轮主问题距离很远。
- 改动会同时影响太多关系，而证据尚不足。
- 你需要保持这一项不变，才能观察另一项改动。

### 修复

“修复”表示当前证据足以让你承担修改成本，而且不处理会阻止下一轮学习。

适合修复的情形：

- 规则矛盾、组件缺失或状态无法恢复，导致测试不能继续。
- 文字、尺寸、对比或摆放让参与者无法取得完成目标行动所需的信息。
- 原型触及安全、尊严或参与权问题，不能为了比较而让问题继续。
- 多种记录汇合到一个清楚而可测试的问题，并且下一步改动范围可控。

修复也要写预测。明显的错字可以直接改，但若改变会影响玩家决定，就不再只是排版维护。

### 继续观察

“继续观察”不是拖延，而是有目的地保持当前项不变，并指定下一场要收集什么。

适合继续观察的情形：

- 两个备选原因都能解释现有记录。
- 观察与原话互相不一致。
- 只出现一次，而且不是安全或可执行性断点。
- 当前场次受到教学介入、规则误用或异常设置影响。
- 你还不知道目标玩家是否也会遇到这个现象。

### 决定表

| 记录主题 | 当前决定 | 理由 | 下一场动作 |
| --- | --- | --- | --- |
|  | 保留 / 修复 / 继续观察 | 用一条观察和一个未知说明 | 保持、修改或指定记录点 |

同一场测试可以产生很多主题，但下一版只能选一个主要学习目标。其他主题仍可标状态，然后进入停车区或以后版本。

## 第六步：下一版只选一项主要学习性改动

### “一项”不是只能改一个字

一项主要改动，是一个能用一句话说明目的的改动包。例如：“让两名玩家在第一次行动前更容易比较彼此的工具与障碍需求。”为了让这个改动真正落地，你可能需要同步移动两张工具卡、加一行提示、更新设置图。这些是同一项改动的必要组成，不是三项无关试验。

下面则是多项混在一起：

- 放大工具卡。
- 取消交换的行动代价。
- 把水位从三格改成五格。
- 加入每个角色的特殊能力。

如果下一场行为改变，你无法判断来自信息、代价、时间压力还是能力。Daniel Solis 在《Monsoon Market》的开发记录中把同时测试太多变量视为需要缩减的问题；Garret Rempel 也把小范围修订当作个人流程。本站把它做成初学者护栏，但不把它说成因果保证。

### 用四个问题选择

面对多个候选改动，逐项问：

1. **它能区分哪个备选原因？** 若所有结果都能被你解释成成功，它学不到东西。
2. **它离主问题有多近？** 优先改变直接影响目标决定的信息、规则或反馈。
3. **它会同时扰动多少关系？** 越少越容易比较，但安全与可执行性不能为了“纯净测试”被牺牲。
4. **失败后能否恢复？** 低成本、可逆、可快速重做的改动更适合早期版本。

可以给每个候选方案写一行，不必打复杂分数：

| 候选改动 | 想检验的原因 | 能看见的结果 | 会同时影响什么 | 本轮选择 |
| --- | --- | --- | --- | --- |
|  |  |  |  | 选 / 停车 |

### 流程崩溃时的例外

若测试发现三处规则矛盾，必须一起修才能再次运行，可以做“维护修复版”。把每一处修复列清，并承认它与旧版不能做干净比较。先自测维护版，确认能开始、继续、停止，再围绕一个主问题建立下一份可比较版本。

一次只选一项，是为了学习清楚，不是为了坚持形式而浪费参与者时间。

## 第七步：在制作前写行为预测和反驳信号

### 行为预测要能被桌面记录

不要写：

- “下一版会更好。”
- “玩家会更喜欢合作。”
- “问题应该解决了。”

可以使用这个句式：

> 如果______确实是主要原因，那么把______改成______以后，在______局面，我们预计看见玩家______。

预测至少包含：

- 被检验的原因。
- 本版唯一主要改动。
- 行为发生的时点或局面。
- 观察者能记录的动作、问题或原话。

预测不是愿望。它是在测试前留下的一把尺，防止结果出来以后临时改变成功标准。

### 反驳信号告诉你何时放下心爱的解释

使用这个句式：

> 如果玩家已经______，却仍然______，或出现______，那么“______是主要原因”会变得较不可信；下一步应检查______。

反驳不一定彻底推翻原因。它可能只说明原因不是唯一的，或改动没有真正改变玩家接触到的信息。

举例来说，若你增强了工具与障碍的对应提示，玩家确实在第一步前查看双方工具，却仍然没有讨论交接，那么“完全没看见工具关系”就变弱。此时更值得检查交换代价、对水位压力的理解、行动顺序或玩家是否认为以后仍来得及。不要因为玩家最终完成交换，就删除前面的反驳信号。

### 同时写下保持不变的东西

预测只有在读者知道哪些关系保持不变时才可解释。下一版简报至少列出：

- 河道与障碍位置是否不变。
- 工具效果与初始归属是否不变。
- 交换是否仍需同列，是否仍消耗发起者行动。
- 水位上涨与停止条件是否不变。
- 教学用语、参与者类型和记录方式是否尽量一致。

无法保持一致的地方也要写。例如下一场换了年龄组，不要隐藏，而要把它列为新的情境变量。

## 第八步：把没做的改动放进停车区

停车区不是垃圾桶。它保存那些有价值、但会让本轮失焦的点子。

| 停车项 | 它想解决什么 | 为什么现在不做 | 什么信号会让它回来 | 风险或依赖 |
| --- | --- | --- | --- | --- |
|  |  |  |  |  |

一个合格停车项不能只写“以后看看”。例如：

> “取消交换行动代价”试图解决玩家觉得交换不值得的问题。本轮先不做，因为我们还要区分玩家是否看见工具关系。若下一版玩家已主动查看并讨论，却持续因为失去行动而拒绝交换，再重新评估代价。

这样做有三个好处：

1. 团队不会因为害怕忘记而把所有点子塞进同一版。
2. 提议者能看见自己的想法被保存，而不是被拒绝后消失。
3. 未来有触发信号时，可以知道为什么把它拿回来。

停车区也要定期清理。若游戏目标已经改变，某个点子不再相关，可以标“关闭”并说明原因，不需要永远背着它。

### 下一版简报只写一页

简报不是完整设计文档。它只让制作、测试和观察的人对本轮学习目标达成一致。

### 给版本一个能追踪的号码

若 `v0.1` 已经完成测试，下一份含有主要设计改动的原型可以叫：

> `小动物过河_工具交接_v0.2_2026-08-22`

测试记录再追加场次号：

> `小动物过河_工具交接_v0.2_T01_2026-08-23`

不要把尚未测试的版本写成“有效版”。可以在简报里标状态：

- `v0.1 frozen`：已冻结，有对应测试记录。
- `v0.2 planned`：已决定，尚未制作。
- `v0.2 ready`：已制作并自测，可以邀请参与者。
- `v0.2 tested`：已有场次记录，等待分析。

若只修正不改变玩家获得的信息、合法行动或结果的错别字，可以使用团队自己的小修编号，例如 `v0.1a`。但只要修改可能改变玩家决定，就宁可升成新设计版并写清变化。这里没有唯一正确编号，只有能否找回证据的区别。

## 完整走一遍《小动物过河》

下面完整走例的身份是：

> `小动物过河_工具交接_v0.1_DEMO-01_教学演练`

它只训练整理与决策，不是假装已经完成研究。单元 5 那张包含多个时间点的观察表明确是格式示范，本节不把那些行拿来充当真实结果。这里仅使用单元 4 早已写出的两行样例，并且始终标为演练资料。

### 1. 冻结原型与测试计划

设计版本：`小动物过河_工具交接_v0.1_2026-08-22`。

单元 5 为这个版本写下的主问题是：

> 在 v0.1 的开局切片中，当工具交接会占用发起者本回合的前进机会时，两名第一次接触此版本的玩家会不会在任一只动物被障碍挡住以前，主动查看对方工具并商量至少一次交接时机？

计划中的行为预测分成三层：先注意同伴持有的工具，再比较前进与交接，最后提出交接或明确说出暂不交接的理由。若主持提前提醒交换、组件摆错、规则冲突、参与者并非第一次接触或所需读取支持没有准备，本轮应标“无法判断”，不能硬算成机制结果。

本次教学演练没有真实参与者范围、主持记录、设置照片或停止结果。因此这些字段全部写“演练不适用”，不能从两行样例补出来。

### 2. 把两行样例放回三栏

| 原始观察，演练数据 | 玩家原话，演练数据 | 设计者解释，暂时 |
| --- | --- | --- |
| 开局 20 秒内两人都先移动，没有查看对方工具 | “我以为只能用自己的。” | 工具卡可能被理解为个人能力；也可能是交接规则或工具归属没有在第一步前进入注意 |
| 松鼠停在急流前，水獭指向手里的绳索 | “那我这轮跟你换？” | 障碍可能让工具关系变得可见；交换提议已经出现，但不知道是否执行，也不知道有没有讨论机会代价 |

注意这张表没有写：

- 玩家真的完成了交换。
- 两枚棋子当时处于可以交换的同一列。
- 水位当时是多少。
- 玩家比较过前进与交接各自的损失。
- 测试怎样停止，或总共进行了多久。
- 哪位参与者说了哪一句话。
- 第二行发生在同一真实场次。

两行样例能示范推理，却不能让这些空白自动长出答案。

### 3. 先判断原问题，不急着找原因

若把两行当作一份教学数据集，原计划所说的“在被障碍挡住以前查看并商量”没有出现。第一行写的是两人先移动且未查看，第二行到松鼠停在急流前才出现指向工具和交换提议。

因此教学演练的最窄结论是：

> 这两行样例暂时不支持“交接取舍会在障碍以前进入讨论”；它们只显示在障碍前出现了交换提议。由于资料是演练样例而不是真实测试，不能据此评价 v0.1 的实际表现。

这里没有写“合作失败”。交换提议出现了，可能说明障碍成功暴露了依赖关系；只是出现时点晚于单元 5 预先写下的边界。

### 4. 对同一现象写三个备选原因

待解释现象是：“样例中的工具关系直到急流前才进入可见行动和语言。”

| 备选原因 | 目前支持它的样例 | 与它冲突或不能解释之处 | 未知 |
| --- | --- | --- | --- |
| A. 工具归属与可交接性在开局不够醒目 | 开局未查看工具；原话把工具理解为只能自己使用 | 后来水獭能指向绳索并提出交换，说明信息并非永远不可见 | 卡牌实际位置、字号、提示条是否被读、第一次注意工具的准确时点 |
| B. 玩家看见了信息，但在障碍出现前没有行动理由 | 交换提议恰好在松鼠停到急流前出现 | 第一行写“没有查看”，且原话暗示对工具权限的理解可能有误 | 玩家是否早已用余光看见、是否认为到障碍前再换更划算 |
| C. 交接机会代价或水位压力让玩家先移动 | 两人都先移动；交接会耗掉发起者一次行动 | 样例没有任何关于代价或水位的原话，也没有水位状态 | 玩家是否比较过损失、是否知道水位每轮上涨、是否觉得时间充足 |

三个原因可以同时存在。现有样例无法排除任何一个，所以不能直接把交换改成免费，也不能断言只要放大工具卡就会解决问题。

### 5. 标证据强度与未知

对原因 A，目前只有“一条未查看的行为样例加一句权限理解原话”。在本单元的四级标法里，它最多属于“相互支持的演练线索”：行为与原话方向接近，但没有真实场次、反例、主持介入或独立重复。

对原因 B，目前是一条时序线索：障碍前才出现指向与提议。它不能告诉我们开局是否真的没看见，也不能告诉我们延后是不是合理策略。

对原因 C，目前只有行为结果，没有直接谈论代价的原话，因此仍是较弱线索。

未知盒可以这样写：

> 我们现在较有把握的是：样例把“未早期查看”与“障碍前才提议交换”连在同一条教学推理线上。  
> 我们现在只能猜的是：问题主要来自可见性、理解、当下激励还是机会代价。  
> 这份演练没有回答：真实玩家是否会这样、交换是否执行、代价是否进入判断、完整切片是否可运行。  
> 真正测试时需要记录：工具第一次被看见的时点、提示条是否被读、玩家怎样描述持有与交接、当时位置和水位、主持全部介入。

### 6. 给不同主题不同决定

| 主题 | 当前教学决定 | 理由 |
| --- | --- | --- |
| 河道、障碍、初始工具分配 | 保留 | 它们让目标关系快速出现；本轮没有证据要求改变 |
| 工具归属与可交接性的可见表达 | 修复并检验 | 原因 A 有行为与原话样例共同指向，而且可用低成本信息改动检验 |
| 交换的行动代价 | 继续观察 | 没有关于代价判断的原话或状态，直接取消会混入第二项大改动 |
| 水位长度、角色能力、第二段河道 | 保留或停车 | 它们不是当前问题所需，加入会让比较失焦 |

这里选择“修复”不等于已经确认根因。它表示我们愿意用一个可逆的小改动，让“开局是否看见工具关系”更容易被下一场挑战。

### 7. 只选一个主要改动

本轮唯一主要改动是：

> 强化“谁持有什么，以及工具可以在同列交接”的开局可见表达。

具体制作成一个信息表达包：在每名玩家面前画固定的“当前持有工具”框；两张工具卡保持原效果，但在名称下加入同一句短提示“同列时可交接”；设置图同步标出卡片必须进入哪个持有框。

这三处是同一项信息改动的必要同步，不改变交接的行动代价、工具作用、河道、障碍、水位、停止条件或参与人数。

为什么不只把卡做大？因为卡片大小也许提升视觉注意，却不一定澄清“当前由谁持有”和“可交接”这两个关系。为什么不取消行动代价？因为那会同时测试价值判断，无法区分玩家原先是没看见，还是觉得不值得。

### 8. 在制作前写预测和反驳

行为预测：

> 如果开局可见表达是主要原因，那么在 `v0.2` 中，第一次行动以前至少一人会看向或指向双方的持有框，并用自己的话提到同伴拿着自己障碍需要的工具，或提到同列时可以交接。

反驳信号：

> 如果玩家能正确指出双方工具归属与交接权限，却仍然到障碍前都不比较交接时机，那么“没有看见工具关系”作为主要原因会变弱，下一步应检查他们是否认为提前交换没有收益、机会代价怎样进入判断，以及到障碍前再换是否本来就是合理路径。

还有第二个需要区分的结果：如果新提示存在，玩家仍然完全不看持有框，不能立刻说“信息原因被推翻”。这可能表示本次表达改动没有真的进入注意。下一场要记录目光、指向、读卡和复述，而不是只看最后有没有交换。

### 9. 把其他方案放进停车区

| 停车项 | 想解决什么 | 现在不做的原因 | 重新启用信号 |
| --- | --- | --- | --- |
| 取消或降低交换行动代价 | 玩家可能认为交换不值得 | 会同时改变价值判断，盖住可见性问题 | 玩家已看见并讨论，却持续明确因行动损失拒绝交换 |
| 改变水位速度 | 加强共同时间压力 | 当前没有水位状态或压力原话 | 多场记录显示玩家理解交接但认为永远来得及 |
| 把障碍需求提前印到起点 | 更早暴露未来依赖 | 可能直接提示计划答案，也改变地图信息节奏 | 持有信息已清楚，但玩家仍不知道工具为何重要 |
| 加角色能力或更多工具 | 增加变化 | 不是当前单问题所需，会扩大内容与解释空间 | 核心交接关系在简单切片中已经稳定可读 |

## 15 分钟练习：从一张测试表走到下一版

你可以使用自己的记录，也可以使用本单元的《小动物过河》证据表。定时不是质量标准，只是帮助第一次把整条链走完。

### 第 0–2 分钟：冻结

写下游戏名、设计版本、场次号与主问题。圈出测试中设计者曾经介入的地方。若找不到对应规则或组件，先写“快照缺失”，不要凭记忆补成确定事实。

### 第 2–5 分钟：拆三栏

选择两条最接近主问题的笔记。用不同栏重写：看见或听见的事件、玩家原话、你的解释。删掉观察栏里的“觉得、想要、因为、喜欢、讨厌”等读心词，除非它们来自明确原话。

### 第 5–8 分钟：写两个原因

对最重要的现象写原因 A 和原因 B。每个原因各填一条支持记录，再写一项未知。若想不出第二个原因，从“没看见、没理解、觉得不值得、测试情境影响”四个方向重新看。

### 第 8–10 分钟：标强度并决定

把当前判断标成线索、相互支持、重复信号或比较证据。然后只选保留、修复或继续观察之一。用一句话说明为什么现有证据只够走到这里。

### 第 10–12 分钟：只选一个改动

写三个候选方案，然后问哪个最能区分原因、最接近主问题、同时扰动最少、失败后最好恢复。只圈一个。其他两个进入停车区，并各写一个重新启用的触发信号。

### 第 12–14 分钟：预测与反驳

完成两句：

> 如果原因 A 较重要，改动以后，在______时我们会看见______。  
> 如果玩家已经______却仍然______，原因 A 会变弱，我们要检查______。

若第二句怎么都写不出来，说明原因太模糊，或你还不愿意让它失败。回到上一步缩小主张。

### 第 14–15 分钟：编号并交接

写下一版号码与状态，把简报交给一个没有参加分析的人。请对方只回答三件事：要改什么、什么不改、下一场看什么。若对方答不出来，简报还不够清楚。

## 常见错误

### 修改以后才补写预测

看到结果以后写预测，很容易把已经发生的事包装成“果然如此”。预测必须在下一版测试前冻结，并保留原句。可以在测试后写新解释，但不能覆盖旧预测。

### 把观察词写得像心理诊断

“无聊、困惑、自私、没有策略”都需要证据。先写停顿、查看、提问、选择、交谈与状态变化。若玩家自己说“我无聊”，把它放原话栏，并继续问发生在哪一刻。

### 因为三个人都说一样，就宣布找到原因

共识可以提高处理优先级，却仍可能来自共同情境或彼此影响。记录谁先说、其他人是否在听到以后附和，以及行为是否支持这段说法。

### 因为只有一个人遇到，就当作不重要

一次现象可能只是偶然，也可能是阻止参与、破坏安全或让流程无法继续的严重问题。频率、严重度和与主问题的距离要分开判断。

### 把好评当成机制证明

玩家喜欢角色，不表示交换机制成立；完成挑战，也不表示过程清楚。保存好评，同时继续检查目标行为与反例。

### 直接采用最响亮的建议

先问建议想解决什么。声音大、经验多或说得像设计师，都不让一个方案自动正确。把建议与提出它的人分开评估，也不要要求儿童替你完成设计工作。

### 同时修改信息、代价、地图和时间压力

这可能让游戏突然更顺，却留下无法解释的结果。若必须大改，承认这是探索版或维护版，不要假装它精确验证了某个原因。

### 把未做的点子全塞进“顺便”

每个“顺便”都会增加变化。停车区让好点子有安全位置，也让当前版本保持清楚。

### 版本号变了，组件却混在一起

河道是 `v0.2`、提示条仍是 `v0.1`，得到的是没有名字的混合版。每张容易混淆的组件写版本角标，测试前按清单装袋。

### 反驳出现以后保护原解释

“玩家没按预测做，是因为这批玩家不对”可能有时成立，但必须有独立理由。更诚实的写法是先降低信心，记录参与者差异，再设计能区分两种解释的后续测试。

### 把继续观察当成什么也不做

继续观察必须指定版本、局面和记录点。若只是“再玩几次看看”，下一次仍会得到难以整理的印象。

### 把一场短切片推广到完整游戏

《小动物过河》强制两人拿着对方需要的工具，且只有一个障碍。它适合快速暴露工具交接，却不能证明完整地图、随机分配、更多角色和长局节奏中也会产生相同行为。

## 适用与不适用边界

这套方法适合：

- 纸面原型和局部机制测试后的第一次整理。
- 有明确主问题、能保存版本快照的小规模测试。
- 需要让儿童、成人或跨背景团队共同看见“记录与解释不同”的课堂。
- 想减少下一版同时变化数量的个人或小团队。
- 需要把失败、反例和未知保留下来的早期项目。

它不能替代：

- 用足够样本、随机分配和统计分析回答总体效应的问题。
- 针对长期经济、牌库概率、胜率或平衡性的专门数据设计。
- 对陌生玩家独立学习规则的完整盲测。
- 针对视觉、听觉、动作、语言或认知条件的可访问性研究。
- 儿童参与、录音录像、敏感主题和个人资料所需的机构规定与当地法律判断。
- 专业安全评估、伦理审查或正式因果研究。

一次只改一项主要因素可以提升可解释性，却不能消除玩家差异、随机性、观察者偏差与情境影响。三栏记录也不会让设计者变成完全中立的摄像机。它们的价值是把判断过程留在纸面上，让别人能质疑、让未来的你能复查。

## 完成本单元的信号

- 你能找到测试时实际使用的规则、组件、设置和教学记录。
- 每条关键记录都带设计版本与场次号。
- 你把原始观察、玩家原话和设计者解释放在不同栏。
- 解释使用“可能”，并至少保留两个备选原因。
- 你能说清一条记录支持什么，也能说清它不能证明什么。
- 你没有把频率、共识、好评或玩家建议自动当作因果证据。
- 每个主题已经标为保留、修复或继续观察。
- 下一版只有一个主要学习性改动，必要同步更新被明确列出。
- 你在制作以前写好行为预测和反驳信号。
- 未采用的点子进入停车区，并有重新启用条件。
- 下一版简报能让未参加分析的人说出“改什么、不改什么、看什么”。
- 新版本有可追踪号码，旧版本没有被覆盖。
- 你愿意在反驳出现时降低信心，而不是删除不合心意的记录。

## 来源与形成方式

本单元是本站原创中文学习内容，不是任何外文文章、论文或课程的翻译，也没有复制任一来源的章节结构。来源作用分成三类。

### 游戏设计师与机构的一手实践

- [Ian Schreiber, Game Design Concepts Level 2](https://gamedesignconcepts.wordpress.com/2009/07/02/level-2-game-design-iteration-and-rapid-prototyping/)：作者公开课程支持把设计、实现、评价与再次修改看成循环。课程把游戏测试类比科学方法属于作者的教学表达，本单元不把普通桌游测试写成因果证明。
- [Ian Schreiber, Game Design Concepts Level 14](https://gamedesignconcepts.wordpress.com/2009/08/13/level-14-playing-with-non-designers/)：支持观看实际行动、规则误用与玩家互动，不只问“好不好玩”。身体姿态等观察可能有多种解释，所以本站要求另设解释栏。
- [Kathleen Mercury, Providing Feedback on Prototypes: The WINQ](https://www.kathleenmercury.com/providing-feedback-on-prototypes-the-winq.html)：教师与设计师本人实践支持让不同年龄学习者写具体反馈、问题与新想法，再由设计者反思。本单元没有复制 WINQ 表单。
- [Tabletop Game Designers Association, In-person Playtesting](https://www.ttgda.org/in-person-playtesting)：行业协会页面支持带着问题测试、反复迭代、尊重反馈但由设计者决定修法。
- [Garret Rempel, Playtesting with Purpose](https://www.tricorngames.com/designer-blog/2017/8/26/playtesting-with-purpose)：设计师个人流程支持记录版本、场次、参与者与目的，把笔记转成问题，并缩小修订范围。作者的具体选择规则不被写成行业标准。
- [Daniel Solis, 3 Steps to Interpreting Playtest Feedback](https://danielsolisblog.blogspot.com/2014/03/3-steps-to-intepreting-playtest-feedback.html)：设计师案例支持观察玩家建议试图处理的问题，不直接把建议当修法。
- [Daniel Solis, Revising the Constants and Variables in Monsoon Market](https://danielsolisblog.blogspot.com/2014/05/revising-constants-and-variables-in.html)：作者开发记录支持减少同时变化的变量。它没有证明“一次一项”能建立因果。
- [Nels Anderson, The Proving Ground](https://unwinnable.com/2013/02/11/the-proving-ground/)：设计师本人复盘支持用可评价的问题组织测试、安静观察，并警惕让指标替代设计目标。

### 正式研究与官方方法

- [GOV.UK, Taking notes and recording user research sessions](https://www.gov.uk/service-manual/user-research/taking-notes-and-recording-user-research-sessions)：官方研究方法支持详细记录、区分观察与个人解释、标场次，并在录音录像前取得同意。
- [Michael D. Fetters and Ellen B. Rubinstein, The 3 Cs of Content, Context, and Concepts](https://pmc.ncbi.nlm.nih.gov/articles/PMC6846267/)：原始方法论文支持把发生内容、情境与概念化分开，并保存从观察到分析的轨迹。论文来自医疗田野研究，本站三栏是桌游教学迁移。
- [John R. Platt, Strong Inference](https://pages.cs.wisc.edu/~markhill/science64_strong_inference.pdf)：原始论文支持提出多个工作假设并寻找能够排除某些解释的结果。桌游早期测试通常不具备论文所讨论的受控条件。
- [Judea Pearl, Causal Inference in Statistics: An Overview](https://ftp.cs.ucla.edu/pub/stat_ser/r350-reprint.pdf)：原始研究综述支持关联资料本身不足以建立因果，因果判断还依赖假设与研究设计。本单元不教授其数学模型。
- [Amos Tversky and Daniel Kahneman, Belief in the Law of Small Numbers](https://doi.org/10.1037/h0031322)：原始论文支持警惕把小样本看得过度稳定或具有代表性；它没有为桌游测试规定固定人数。
