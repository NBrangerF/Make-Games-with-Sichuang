# 全站视觉重构：回归与可访问性测试矩阵

- 日期：2026-08-23
- 范围：正式站点的视觉重构，不改变既有信息架构与内容语义
- 目标：保护“资源站优先”的关键路径，并让小学生到成年人都能看懂、选择、返回和继续
- 适用阶段：视觉方案开发中、合并前、发布前、发布后抽查

## 1. 结论先行

视觉重构可以开始，但必须保留四类发布门禁：

1. 首页仍只有三个主要入口，另有一个弱化的“搜索全部资料”入口。
2. 资源目录、资源详情、方法内容和上下文工具都能通过键盘、深链、刷新与浏览器历史完成。
3. 任何选中、成功、警告、错误、可点击状态都不能只靠颜色表达。
4. 自动化通过不等于可访问性完成；至少还要完成键盘、屏幕阅读器、缩放/文字间距和跨年龄任务测试。

当前最大的自动化缺口是：

- 新版浏览器套件没有覆盖 `#resources/all` 的搜索、组合筛选、空结果、重置、详情与返回。
- 现有检查能验证 ARIA 与源代码契约，但不能证明视觉状态“不是只靠颜色”。
- 现有截图是留档，不是稳定的视觉差异基线。
- 旧的 `pnpm qa` 仍依赖已经隐藏的设计路径、独立工具入口等旧界面假设，不能作为当前发布门禁。

### 2.2 浏览器证据的状态

- 当前权威的新版浏览器脚本是 `scripts/qa-resource-v2.cjs`，对应命令 `pnpm qa:resource-v2:browser`。
- 它覆盖桌面、390×844、320×760，包含三入口、若干资源/方法/工具路径、旧深链、横向溢出、移动导航触控尺寸与跳转链接。
- 它目前会把截图写入 `design/qa/`；重构后的新套件应改为带构建编号的独立制品目录，避免覆盖历史证据。
- `scripts/qa-site.cjs` 含有一些有价值的全资料目录断言，但同时依赖旧导航和旧可见入口。应提取断言，不应直接把它当作新版发布门禁。
- 本次规划时应用内浏览器运行时不可用，因此没有生成新的视觉签核。已有浏览器通过记录来自既有进度快照，必须在重构完成后重新取得。

### 2.3 现有规范入口

键盘与屏幕阅读器的详细硬门禁继续以 `docs/product/ACCESSIBILITY_HARD_GATE.md` 为准。本文件不降低该规范，只补充视觉重构所需的回归矩阵。

## 3. 发布门禁分层

| 层级 | 触发时机 | 必须完成 | 阻断条件 |
| --- | --- | --- | --- |
| G0 源代码与内容契约 | 每次提交 | 类型检查、构建、内容检查、静态 QA | 任一命令失败 |
| G1 关键路径浏览器回归 | 合并前 | 下方 F01–F15 的自动化部分 | P0/P1 失败、控制台错误、关键请求失败 |
| G2 响应式与视觉检查 | 合并前和发布前 | 五档视口、200% 缩放、文字间距、无横向阻断 | 主操作不可见/不可达、内容遮挡、信息仅靠颜色 |
| G3 键盘与辅助技术 | 发布前 | 键盘 K1–K8、屏幕阅读器 S1–S8 | 键盘陷阱、焦点丢失、控件无名、状态未播报 |
| G4 跨年龄可理解性 | 视觉方向冻结前 | 至少覆盖 7–9、10–12、青少年、成人新手、成人熟练者 | 三入口无法区分、关键术语无法理解、需持续代操作 |

建议严重度：

- P0：空白页、页面崩溃、数据丢失、关键路由不可进入、键盘陷阱、屏幕阅读器完全无法完成主流程。
- P1：主要入口或返回失效、主要操作被遮挡、320px 出现阻断操作的横向滚动、焦点不可见、信息只靠颜色、筛选结果错误。
- P2：次要对齐、非阻断换行、措辞理解成本、视觉差异但不影响任务。
- P3：装饰性问题或后续优化建议。

P0/P1 必须在发布前清零；P2 需要负责人、处置决定与复测日期。

### 5.2 新版浏览器套件的建议结构

不继续扩写旧 `qa-site.cjs`。建议建立一个 V3 套件，并按页面族拆分：

1. `home-and-entry`：F01–F04。
2. `catalog-and-detail`：F05–F06。
3. `method-and-context-tools`：F07–F09。
4. `compatibility-and-history`：F10–F14。
5. `responsive-and-runtime`：F15、A10–A15。

每条测试都应：

- 从明确 URL 开始，避免依赖上一条测试状态。
- 同时断言可见结果、URL 和页面标题。
- 记录控制台错误、未捕获异常和关键请求失败。
- 使用角色、标签和可见文本定位，避免依赖 CSS 类名。
- 等待语义状态或目标内容，避免固定延时。
- 将截图写入带构建编号的制品目录；失败证据和批准后的基线分开。

| 环境 | 用途 | 必查内容 |
| --- | --- | --- |
| Chromium 1440×1000 | 主视觉与完整信息层级 | 首页三入口、资料/工具主次、长内容宽度、固定/悬浮元素 |
| Chromium 1366×768 | 常见低高度桌面 | 首屏关键入口、标题换行、底部操作是否被截断 |
| 平板 768×1024 | 中间断点 | 卡片列数、筛选布局、导航、正文行宽 |
| 移动 390×844 | 主要移动基线 | 全流程、触控、软键盘、返回、筛选 |
| 移动 375×812 | iPhone 常见宽度 | 中文长词、按钮换行、详情元数据 |
| 窄屏 320×760 | 极限回归 | 无阻断横向溢出、操作不重叠、内容不丢失 |
| 桌面 200% 缩放 | 低视力/放大 | 无内容裁切；仍能完成三入口、筛选、详情、工具 |
| 文字间距覆盖 | 阅读可访问性 | 行高、字距、段距增大后不遮挡、不截断、不丢操作 |

人工视觉检查不要只比较“是否好看”，而要记录：

- 首屏主要选择数量和视觉权重。
- 标题层级能否只靠位置与文字理解，而非颜色。
- 每段长度、行宽、留白是否支持快速浏览。
- 中文长标题、作者名、标签与按钮在窄屏是否自然换行。
- hover、focus、selected、disabled、error、success 是否彼此可区分。
- 页面滚动时是否存在遮挡正文或操作的固定元素。
- 动效关闭后仍能理解状态变化；系统“减少动态效果”设置有效。

模拟器不能替代真机。发布前至少抽查一次 iOS Safari 和 Android Chrome 的触控、软键盘与返回行为。

## 7. 不依赖颜色的专项门禁

### 7.1 可自动检查

对所有状态组件建立清单并执行以下 DOM 断言：

- 当前导航同时有 `aria-current` 或等价语义，以及文字/形状/边框等非颜色差异。
- 筛选或切换按钮使用 `aria-pressed`、选中符号或明确文字，不只改变底色。
- 链接在正文中有下划线、图标或其他非颜色识别方式。
- 表单错误同时有文字说明、与字段的程序化关联和 `alert`/live region，不只显示红框。
- 成功、警告、草稿、已完成等状态包含可见文字或图标并有可访问名称。
- 焦点环在所有交互控件上可见，且与相邻颜色有足够对比。

### 7.2 必须人工检查

1. 将整页转为灰度，仍能分辨可点击、当前、禁用、错误和成功状态。
2. 使用浏览器的色觉缺陷模拟分别检查红绿色觉、蓝黄色觉；这只是启发式检查，不是用户验证。
3. 实测正文和控件的对比度：普通文字至少 4.5:1；大号文字至少 3:1；关键控件边界与焦点指示至少 3:1。
4. 使用键盘逐个聚焦控件，确认焦点不是仅靠轻微色相变化。
5. 至少邀请一位低视力或色觉差异使用者完成主任务，或明确记录本轮尚未覆盖，不能宣称已经全面支持。

截图看起来“有差别”不能代替对比度测量；色觉模拟也不能代替真实用户。

## 8. 不同年龄用户的可读性与脚手架测试

年龄不是阅读能力、经验或障碍的替代指标。招募时还应记录桌游经验、设计经验、中文阅读习惯和是否使用辅助技术，但不在仓库保存未成年人的个人身份信息。

| 用户组 | 代表任务 | 观察重点 | 建议通过标准 |
| --- | --- | --- | --- |
| 7–9 岁，成人陪同 | 看首页并说出三个入口分别能做什么；选一个开始 | 标签是否具体；图标是否误导；是否必须解释术语 | 至多一次中性提示即可指出合适入口；不要求独立阅读长文 |
| 10–12 岁 | 从首页找到“学习”或“分析”；阅读一项“适合谁/不要把它当成” | 分段、句长、术语解释、返回能力 | 2 分钟内到达相关内容，并能用自己的话说明下一步 |
| 13–17 岁 | 按一个设计问题找资料；使用一次情境工具并返回 | 资料与工具主次、任务连续性、是否感到被过度简化 | 无代操作完成主任务，能说明工具为何此时出现 |
| 成人新手 | 选择学习入口；搜索/筛选；打开详情 | 信息焦虑、术语、筛选理解、可信度线索 | 首次使用即可完成，且能说出该资料的用途与限制 |
| 成人熟练设计者 | 快速定位框架/专题/资料；使用旧书签 | 效率、深链兼容、内容密度 | 不被脚手架阻挡；可跳过解释并快速到达目标 |
| 跨年龄访问需求 | 200% 缩放、键盘、屏幕阅读器、色觉差异 | 同一任务是否仍可完成 | 不降低核心任务成功标准；只调整输入/呈现方式 |

每轮至少使用同一组三个核心任务，以便比较版本：

1. “你想系统地学习如何设计桌游，请从首页开始。”
2. “你正在判断一个游戏为什么会拖沓，请找到一份合适资料。”
3. “从一篇资料或指南开始，使用建议的工具，然后回到刚才的位置。”

记录以下证据，而不只问“喜不喜欢”：

- 第一次选择是否正确；犹豫点在哪里。
- 到达目标所需时间、返回次数和中性提示次数。
- 用户如何复述入口、资料适用范围和下一步。
- 是否把工具误认为独立内容库，或把框架名误认为必须先学的前置知识。
- 是否因文字太密、颜色、图标、动效或布局而中断。
- 误操作后能否自行恢复。

涉及未成年人时，需取得监护人同意；不要把姓名、录音、面部影像或联系方式提交到代码仓库。

## 9. 键盘与屏幕阅读器抽查

详细步骤以 `docs/product/ACCESSIBILITY_HARD_GATE.md` 的 K1–K8、S1–S8 为准。视觉重构额外关注：

- 跳转到主要内容的链接在聚焦时可见，并真正移动焦点。
- 首页三个主要入口的读出顺序与视觉顺序一致。
- 筛选控件有可理解名称；结果数量变化会被适度播报，不重复轰炸。
- 打开资源详情或工具后有明确标题；返回后焦点落在原触发点或合理替代位置。
- 选中状态、展开状态和错误状态均会被读出。
- 懒加载时有状态提示；失败时能听到错误并找到重试。
- 弹窗或覆盖层没有焦点逃逸；关闭后焦点回到触发控件。
- 旧深链直接打开时仍有主标题、主区域和明确的返回路径。

最低发布抽查组合：

- macOS Safari + VoiceOver。
- Windows Firefox 或 Chrome + NVDA。

只用一种浏览器/屏幕阅读器组合不能作为广泛兼容结论。

## 10. 视觉基线与证据留存

每次视觉方向冻结时，为下列页面族建立批准后的基线：

- 首页、学习入口、分析入口、问题入口。
- 全资料目录：默认、组合筛选、空结果。
- 资源详情：短文、长文、元数据较多三种代表。
- 方法首页、指南详情、框架详情、概念详情。
- 上下文工具：初始、填写中、结果/完成、错误。
- 旧路径、旧工具直达、隐藏阅读直达。
- 320、390、768、1440 四档关键截图。

每份 QA 记录至少包含：

- 构建编号或提交标识。
- 浏览器、操作系统、视口、缩放和系统动态效果设置。
- 执行的流程 ID 与结果。
- 自动化报告、失败截图、控制台/网络错误。
- 人工检查者、日期、未覆盖项和风险接受人。
- 差异是“批准的新设计”还是“回归缺陷”。

不要用截图差异自动判定所有失败：字体渲染、日期和内容变化可能产生噪声；但所有关键区域差异都必须被人审阅。

## 11. 推荐执行顺序

### 每个视觉重构提交

```bash
pnpm check
pnpm build
pnpm qa:a11y-contract
pnpm qa:url-navigation
pnpm qa:resource-v2
pnpm qa:method-deep-links
pnpm qa:guide-resource-handoff
pnpm qa:concept-actions
```

如果内容数据也有变化，再执行：

```bash
pnpm content:check
```

### 合并前

1. 执行重构后的 V3 浏览器套件，覆盖 F01–F15。
2. 完成 320、375、390、768、1440 的截图和交互检查。
3. 完成 200% 缩放、文字间距、减少动态效果与灰度/色觉模拟。
4. 清零 P0/P1；人工确认所有视觉差异。

### 发布前

1. 完成键盘 K1–K8。
2. 完成屏幕阅读器 S1–S8 的最低组合。
3. 至少进行一轮跨年龄可理解性任务测试；若暂时无法覆盖某组，明确记录为未验证风险。
4. 在真实 iOS Safari 与 Android Chrome 各抽查一次主流程。

## 12. 本轮重构的验收定义

只有同时满足以下条件，才可称为“视觉重构完成”：

- 三个首页主要入口的含义和权重没有被视觉装饰稀释。
- 全资料目录的搜索、组合筛选、空状态、详情和返回均有新版浏览器回归。
- 资料始终是主内容；工具只在相关学习/分析语境中作为下一步出现。
- 所有现行和兼容深链在刷新、后退、前进后仍可用。
- 320px 到桌面、200% 缩放和文字间距覆盖下，主流程都可完成。
- 状态不只靠颜色，键盘焦点始终可见。
- 自动化门禁通过，且键盘、屏幕阅读器、跨年龄任务测试均有证据或明确未验证风险。
- 没有把旧 `pnpm qa` 的结果误当作新版站点的发布签核。
