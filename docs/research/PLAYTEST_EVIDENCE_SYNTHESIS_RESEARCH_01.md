# 测试证据综合与版本决定研究 01

更新：2026-08-21  
范围：把一场已完成的桌游测试，从逐事件记录整理为有来源的发现，再形成可复测的下一版变更简报。

## 1. 本轮问题

1. 原始观察、发现、解决方案与项目行动怎样保持不同层？
2. 小规模质性测试中的重复次数、分组和严重度分别能说明什么？
3. 从发现进入版本改动时，怎样避免玩家建议自动成为待办？
4. 来源会话被撤回后，派生复盘怎样处理？

## 2. 检索方法与边界

- 搜索了 15 个以上组合：`game user research analyse study`、`tabletop playtest synthesize notes`、`board game playtest review results`、`observation finding action user research`、`rainbow spreadsheet frequency`、`affinity diagram one observation per note`、`usability severity frequency impact` 等。
- 深读 8 份可访问全文：Games User Research 的分析与复盘、Tricorn Games、Daniel Woodard、GOV.UK 会话分析与笔记指南、GDS Rainbow Spreadsheet、IxDF 亲和图、Boardssey 测试结果复核。
- MeasuringU 正文访问受限，只按公开摘要收录为 `catalogued`，不据此扩展具体量表。
- Firecrawl 与 Exa 在当前工具环境不可用；本轮使用网页搜索与页面全文打开，并逐条记录可迁移结论和限制。
- 搜索结果中的 BGG 设计日志与 Tablehop 页面没有取得足够正文，未作为核心论据。

## 3. 证据矩阵

| 来源 | 可迁移动作 | 不能推出 |
|---|---|---|
| Games User Research：分析研究 | 复核笔记；描述问题；只在约定的可用性标准下谈严重度；小样本频次不可靠 | 自动严重度、总体比例、桌游平衡结论 |
| Games User Research：复盘研究 | 先沟通目标、方法、对象、版本、任务与发现；解决方案先发散再收敛；安排复测 | 团队会议能保证方案正确 |
| Tricorn Games | 从笔记回到潜在问题；一个版本只改一个问题轴；记录版本与任务 | 重复提问次数等于严重度 |
| Daniel Woodard | 沿整局和多场资料综合；尊重测试者语境；避免随相反口味来回摆动 | 固定聚类或优先级公式 |
| GOV.UK：分析会话 | 一条便签一个观察；观察归组；发现与行动另写 | 政府服务流程直接等于桌游设计流程 |
| GOV.UK：笔记与记录 | 观察、参与者/会话标识和资料范围可回查；观察不等于发现或行动 | 法律或伦理认证 |
| GDS Rainbow Spreadsheet | 用参与者列和观察行回查来源；提醒笔记量会膨胀“重要感” | 颜色和人数证明优先级 |
| IxDF 亲和图 | 一条观察一张便签；人工归组；保留参与者声音 | 聚类证明因果、显著性或唯一主题 |
| Boardssey | 分开有效、无效、想改和未确定；显式连接项目任务 | 商业工具字段自动产生正确结论 |
| MeasuringU | 频率与影响是不同输入；评级需先约定方法 | 乐趣、平衡、文化影响的通用评分 |

## 4. 综合结论

### 4.1 四层资料必须分开

1. **来源资料**：版本、玩家配置、媒介、主持条件、事件与局后原回答。
2. **证据选择**：本轮哪些事件支持、反驳、保持未定或只提供语境。
3. **发现**：资料共同说明什么；只适用于什么条件；还有什么反证、替代解释和缺失。
4. **版本决定**：保护、修改、继续调查、暂存或不改；若修改，要另写候选方案、保持项、单一变化轴、回退信号和下一问题。

这四层之间只能由设计者显式推进。工具可以复制引用和显示计数，但不能自动选择、归因、评分或写回项目。

### 4.2 计数只用于回到证据

出现次数受到任务长度、记录粒度、主持介入、玩家配置和同一根因重复表现的影响。它可以帮助分析者发现“需要再看”的位置，却不能单独代表影响、风险、因果或改动优先级。安全与无障碍停止门是例外：它们应在测试前按风险另行定义，而不是由多数票产生。

### 4.3 发现需要负边界

只有“玩家没看见收益”还不够。可回查发现还要写：发生在哪个版本/人数/媒介/阶段；哪些事件支持；哪些事件反驳；是否也可能来自教学、位置、主持或玩家经验；还缺哪类玩家或局面。负边界防止单场便利样本被扩写成目标受众结论。

### 4.4 玩家建议不是待办

建议可以暴露经历或约束，也可能是好方案，但仍须与其他候选方案比较。选择修改时，本站要求至少两个候选方案、一个暂不采用的方案、一个保持项、一个变化轴、一个具体改动、回退信号和下一场唯一问题。这样才能让下一版仍是可解释实验。

### 4.5 撤回应传播到派生记录

来源会话与复盘记录必须通过会话 ID 关联。撤回本地会话时，本地派生复盘同时清除；浏览器无法追回已经导出或另行复制的文件，因此导出界面与 JSON 必须明确此限制。本站流程不是法律意见，机构保留义务需另行判断。

## 5. 产品决定

- 升级既有 `feedback` 工具为“证据复盘与变更简报”，不新增同义工具。
- 旧版反馈数组迁移到 v2；保留原话和旧判断，但明确标记缺少来源、版本、适用条件与反证。
- 只允许显式承接 `completed` 会话；承接复制快照，不修改原会话。
- 显示支持/反驳/未定/语境计数，但始终标明“数量只用于回到原记录”。
- 不提供自动洞察、自动严重度、频次优先级、自动解决方案、因果证明或静默项目写回。
- “复制为项目下一步”必须在完整保存后由设计者主动触发。

## 6. 尚未解决

- 需要中文完整示例，展示同一事件如何得到两个合理但相反的解释。
- 个人设计师独自主持、记录和分析的工作量仍缺少低负担实测。
- 当前聚焦单会话复盘；跨会话人工聚类、版本比较与重复发现合并尚未设计。
- 安全、无障碍阻断与一般设计适配应使用不同风险标准；本站尚未提供合规量表。
