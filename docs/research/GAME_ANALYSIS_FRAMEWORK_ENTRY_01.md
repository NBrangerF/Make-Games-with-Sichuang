# 从设计师角度分析游戏的资源入口 01

日期：2026-08-21  
状态：规划依据  
范围：第二个资源入口、框架分组、最短分析流程与内容缺口

## 核心判断

“从设计师角度分析一款游戏”应成为独立资源入口，不再只是“体验意图”阶段里的一个子项。它横跨体验、决定、互动、系统、信息、教学、无障碍和测试。

第一版不需要开发一个新的大型工具。入口应先帮助用户提出一个具体问题，再只显示一个分析镜头、一份完整中文说明和一个小动作。

框架名称不能成为第一道门。用户不应先在 MDA、5PM、TAG、Ludii 或几十篇专题中做理论选择，而应先回答：

> 这一局，我想弄懂什么？

## 推荐问题分组

新手首屏只显示五个普通语言问题。形式化分析放在第二层。

| 用户问题 | 起步方法 | 按需展开的镜头 | 本轮产出 |
| --- | --- | --- | --- |
| 为什么会产生这种体验？ | 有目的游玩 + MDA | 体验意图、主题承诺、议题到系统 | 一条规则、动态与体验假设 |
| 玩家真正做了什么决定？ | 5PM + 决定轨迹简版 | 核心循环、计分、平衡、随机 | 一个决定时刻和选择坍缩点 |
| 玩家之间怎样互相影响？ | 互动作用路径 | 共享决定、谈判、拍卖、隐藏信息、人数配置 | 谁经由什么规则改变了谁的选择 |
| 游戏怎样随时间和状态运行？ | 系统路径 | 回合、终局、市场、资源链、牌库、空间 | 一条状态与反馈流 |
| 玩家怎样看见、学会并执行？ | 任务路径 | 盲测、教学、卡文、无障碍、具身动作 | 一条行动、查询与恢复路径 |
| 进阶：我需要形式化或计算比较 | TAG 或 Ludii | AutoBG 只作为辅助校对 | 一个形式模型及其证据边界 |

### 不进入新手首屏的内容

- TAG 与 Ludii：保留为进阶形式化入口。
- AutoBG：移动到 AI 辅助设计专题，不和基础分析框架并列。
- Jesse Schell 的镜片卡：作为未来研究和可能的授权对象。官方产品以百余镜片组织问题，但当前不能复制商业卡面、问题清单或完整翻译书籍。官方入口见 [Schell Games](https://schellgames.com/art-of-game-design)。
- Machinations：适合资源经济和反馈流。可作为“系统怎样运行”的后续候选，但需先完成中文内容和权利核验。原论文见 [AAAI AIIDE](https://ojs.aaai.org/index.php/AIIDE/article/view/12477)，框架文档见 [Machinations Documentation](https://machinations.gitbook.io/docs/getting-started/framework-basics)。
- Formal Abstract Design Tools：意图与可感知后果很适合补充“玩家决定”组，但应先做来源和许可审计。原文见 [Game Developer](https://www.gamedeveloper.com/design/formal-abstract-design-tools)。

## 默认四步分析流程

### 1. 只选一个问题

用户从五组普通问题中选择一组。一次分析不要求覆盖整款游戏，也不要求评价游戏好坏。

### 2. 抓住一个具体时刻

最小记录：

- 游戏版本和玩家人数
- 玩家对游戏的熟悉程度
- 当时任务和可见信息
- 实际行动
- 随后发生的后果
- 玩家当时的感受或说法

不从整局总评开始，不把回忆中的喜欢或不喜欢直接当成系统结论。

### 3. 用一个镜头追关系

所有起步镜头共用一条普通语言链：

```text
规则或组件 → 信息与状态 → 玩家实际选择 → 后果与反馈 → 体验或关系
```

不同镜头只改变要追问的位置，不改变观察与推断分离的原则。

### 4. 写清结论边界

默认只要求五句：

1. 我观察到
2. 我推断
3. 我仍不知道
4. 我想带走的关系
5. 可选：我会怎样在自己的原型中测试

“迁移到自己的设计”是可选步骤。只想学习分析的读者不应被迫先有自己的原型。

## 内容单元，而不是框架卡片

每个分析问题需要一套完整中文内容：

1. 一篇问题导论：这个问题在分析什么，不分析什么。
2. 一个起步框架：用普通语言解释来源、步骤、产出和限制。
3. 一个完整桌游案例：从具体时刻走完观察、推断和边界。
4. 一张轻量工作单：只包含四步，不保存、不打分。
5. 三份延伸资料：站内可直接读，清楚标明内容状态。
6. 一个进阶入口：只在用户主动选择时展示更细的专题或工具。

框架页不能只有定义和步骤。完整中文教学模块至少包含：

- 先看一个桌面例子
- 这个框架要解决的问题
- 逐步示范
- 常见误用
- 何时换另一个镜头
- 一次小练习
- 证据与适用边界
- 来源、权利和版本记录

## 首批内容范围

第一批只做三组，验证入口逻辑：

1. 体验：有目的游玩 + MDA
2. 决定：5PM + 决定轨迹简版
3. 互动：互动作用路径

第二批再补：

1. 状态与反馈流
2. 教学、查询与无障碍任务

第三批才加入：

1. TAG
2. Ludii
3. Machinations
4. 其他经过权利与内容审计的进阶方法

MDA 原论文见 [Hunicke、LeBlanc 与 Zubek](https://www.cs.northwestern.edu/~hunicke/MDA.pdf)。5PM 的项目来源记录见 [CLEI Electronic Journal](https://www.clei.org/cleiej/index.php/cleiej/article/view/473)。MDA 可以连接机制、动态与体验，但不应被宣传为通用配方。5PM 可以拆开呈现、操控物、资源、决定和目标，但原论文也不能替代桌游案例和真人观察。

## 交互边界

第一版明确不做：

- 新增第二十个正式工具
- 总分、星级、雷达图或游戏质量判决
- 策略深度分、体验分或框架完成度
- 自动从一次记录生成因果结论
- 一次展示全部框架和全部专题
- 强制保存、账号或仪表盘

只保留：

- 问题选择
- 一个镜头的渐进式阅读
- 四步临时分析笔记
- 三份站内中文资料
- 明确的来源与内容状态

## 验收条件

- 分析入口首屏最多显示 5 个普通语言问题。
- 首屏不出现 framework 名称、理论流派或工具列表。
- 选择问题后只出现 1 个起步镜头、1 个案例动作和 3 份资料。
- 默认流程正好 4 步，不需要账号或保存。
- 观察、推断和仍不知道必须分开。
- 每组至少有 1 篇完整中文导论和 1 个完整桌游案例后，才可以上线。
- 任何框架都必须显示适用边界，不生成质量分。
- TAG、Ludii 和其他形式化内容只能从进阶入口访问。
- 至少使用同一款游戏完成 3 个不同镜头的示例，证明框架会提出不同问题，而不是重复同一套评价词。
- 不解释产品的情况下，不同经验读者能在 30 秒内选到符合意图的分析问题。
