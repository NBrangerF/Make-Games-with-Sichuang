# 新手发现历史与修订交接审计 01

日期：2026-08-21  
对象：`evidence-synthesis` 的历史浏览、只读重开与后继修订

| 新手断点 | 失败后果 | 当前防护 | 仍需验证 |
| --- | --- | --- | --- |
| 以为打开旧记录就能改 | 当时判断被无声覆盖 | 历史详情没有输入控件，明确写“只读” | 用户是否仍会寻找编辑入口 |
| 以为“最新”就是正确答案 | 时间顺序被误读成证据强度 | 历史横幅和旧修订提示均说明最新只表示顺序 | 文案能否阻止质量推断 |
| 不知道为什么要新 ID | 把后继当作普通保存 | “从这份记录创建后继修订”单独动作 | 新手能否预测旧记录仍存在 |
| 后继没有修订理由 | 无法解释变化 | 修订 2+ 保存前强制填写理由 | 用户是否能写新证据/边界而非空泛句 |
| 从旧修订分支造成重复编号 | 沿革列表无法区分 | 修订号取沿革当前最大值加一，父记录保留实际来源 | 分支关系是否足够可读 |
| 旧记录迁移后丢失 | v1 用户历史消失 | v1 保守迁移为 v2；自身 ID 成为沿革 ID | 真实旧数据样本迁移 |
| 已完成草稿重新可编辑 | 固定判断变成草稿 | 迁移时 `completedAt` 草稿被换成新空白草稿 | 异常本地数据恢复提示 |
| 在草稿中直接写回项目 | 未完成判断变成项目决定 | 只有只读打开的已保存记录可显式复制 | 按钮禁用/错误文案是否清楚 |
| 后继继承旧项目动作 | 旧行动被误当成新决定 | 创建后继时清空 `projectNextAction` | 用户是否理解需要重新决定 |
| 会话撤回只删直接记录 | 留下无来源的孤立后继 | 沿 `parentRecordId` 迭代清除全部后继 | 大沿革性能与外部副本说明 |
| 历史列表只显示句子 | 同名发现难区分 | 同时显示修订、生命周期、日期、沿革短 ID | 多沿革时检索和分组需求 |
| 从历史返回丢草稿 | 用户不敢查看旧记录 | 查看历史不替换当前草稿，返回后继续编辑 | 刷新和跨标签页冲突 |
| 把父记录当成来源会话 | 混淆研究来源与修订来源 | 详情分开“来源复盘”和“父记录” | 术语是否需要更通俗说明 |
| 导出只包含当前记录 | 站外无法还原沿革 | schema v2 导出 active、draft 与全部 saved records | 大包可读性与导入需求 |

## 结论

结构层已覆盖不可覆盖、只读重开、显式后继、修订理由、分支编号、v1 迁移和撤回级联。剩余风险主要是文案理解、真实旧数据、长沿革导航、跨标签页冲突与真实辅助技术使用；不能因结构守卫通过而宣称新手可用。
