## 本轮问题

1. 每个框架真正建模的对象是什么？
2. 作者怎样证明或演示它有效？
3. 新手可以拿它回答什么，不能回答什么？

## 结论先行

这五篇文献不构成一条由浅入深、彼此替代的“统一理论”。它们位于不同尺度：

| 当下问题 | 更合适的框架 | 主要产出 | 证据边界 |
|---|---|---|---|
| 规则怎样连接玩家体验？ | MDA | 机制—动态—体验假设链 | 原论文以分析案例论证，未报告对照实验 |
| 一项机制哪里含糊或冲突？ | 5PM | 机制剖面与故障假设 | 作者把真实环境测试列为未来工作 |
| 如何让程序执行现代桌游并测系统指标？ | TAG | 状态机、自动对局、复杂度指标 | 实现与 7 款游戏实验；不验证人类体验 |
| 如何用可组合概念描述并比较规则？ | Ludii | ludemic 游戏描述 | 形式证明 + 推演速度实验，范围偏传统策略游戏 |
| AI 如何参与规则草案迭代？ | AutoBG | 候选规则书与待测问题 | 2026 预印本；模型评测与 30 人单次研究，没有实体游玩 |

## 1. MDA：Mechanics、Dynamics、Aesthetics

来源：Hunicke, LeBlanc & Zubek, 2004，[AAAI 原始出版页](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/)。

### 模型对象

- **Mechanics**：数据、算法、规则、行动和控制机制；
- **Dynamics**：机制在玩家输入与彼此作用下随时间产生的运行行为；
- **Aesthetics**：玩家与系统互动时产生的、设计者希望促成的情绪体验。

设计者通常从 M→D→A 建造，玩家则从 A→D→M 感知。MDA 的价值不是把游戏切成互不相关的三盒，而是迫使设计者在三个抽象层之间往返，解释微小规则怎样级联到桌面行为与体验。

原文列出 sensation、fantasy、narrative、challenge、fellowship、discovery、expression、submission 八种体验词汇，并明确说列表并不穷尽。把它当固定玩家类型或配方会超出原文。

### 作者怎样支撑主张

论文通过 Charades、Quake、The Sims、Final Fantasy、Monopoly 和三版 babysitting/AI 设计案例示范分析。Monopoly 案例展示领先者正反馈怎样损害其他玩家的投入与戏剧张力，并提出落后补贴、领先税或时间压力等候选机制，再明确要求回到 playtesting 和 tuning。

论文没有参与者、对照组或效果量；它是一个由教学与设计实践发展出的概念框架。可说“提供了一套分析语言”，不能说“实验证明使用 MDA 会产生更好的游戏”。

### 对新手的最小练习

1. 写一句可观察的体验目标，不写“好玩”；
2. 写出玩家桌面上应反复出现的行为、互动或反馈循环；
3. 写出支持它的规则、资源和信息；
4. 测试后反向追查：体验出现了吗？动态出现了吗？哪条机制可能阻断它？

### 产品含义

网站不应把 MDA 做成三个定义卡片，而应做成一条可被测试反驳的因果链。Aesthetics 输入允许自定义词，八分类只作为启发。每个箭头都需要记录“这是设计假设还是观察证据”。

## 2. 5PM：5-Part Model

来源：Mora-Zamora, Brenes-Villalobos & Durán, 2020，[CLEI 出版页与开放 PDF](https://www.clei.org/cleiej/index.php/cleiej/article/view/473)，CC BY 4.0。

### 一个来源一致性问题

CLEI 页面标题与摘要仍显示“5PM and DoC”，但当前下载 PDF 的标题是 *5-Part Model: A Formal Approach to Designing Mechanics*，正文只完整定义和演示 5PM。结尾反而说细化难度的 Risk and Reward 模型仍在开发。本项目因此只录入 5PM，不把 DoC 写成已在正文中完整提出的第二模型。

### 五个部件

- **Representation（呈现）**：玩家能直接感知的组件、文字、声音、程序行为与参数；
- **Tokens（操控物）**：呈现中能被玩家直接控制的子集；
- **Resources（资源）**：玩家能花费、承担风险或获得的呈现子集，包括时间和空间；
- **Decisions（决定）**：是否行动、作用于哪个对象、何时做、投入多少；
- **Goals（目标）**：即时、本地和全局三个尺度的收益或进展。

作者用 Prince of Persia 的跳跃呈现问题和 Ark 中两项机制争夺空间、目标互相抵消的问题展示诊断；再用 Plague Inc.、Mortal Kombat 11、The Walking Dead 和 Gone Home 把五部分连接到不同体验目标。

### 证据与边界

这篇论文提出两项“hypothesis”，但没有参与者实验或项目对照。讨论部分仍以作者对案例的解释支持主张；Future Work 明确说下一步是在课程和独立游戏中真实测试模型。因此“5PM 已经被验证能预测玩家反应”是不成立的。

“每项机制应该消耗/风险至少一种资源并奖励另一种”是作者的规范主张。它对诊断权衡很有启发，但不能自动套到自由表达、仪式、谈判或无需显性成本的动作上。网站应把它写成检查问题，而非必过规则。

### 产品含义

用五个字段审查一项足够具体的行动，并增加两类交叉检查：

- 两项机制是否争夺同一资源；
- 它们的即时/本地/全局目标是否互相抵消。

最终产出必须是一条“下一版要验证的故障假设”，不能自动给出最佳修复。

## 3. TAG：Tabletop Games Framework

来源：Gaina et al., 2020，[arXiv 原始论文](https://arxiv.org/abs/2009.12065)。本轮阅读 v1，24 页；论文自称 living documentation，后续引用应记录版本。

### 模型对象与实现结构

TAG 是 Java 桌游 AI 研究框架，重点是现代桌游的隐藏信息、多玩家、合作/竞争混合与组件丰富度。核心抽象包括：

- `GameState`：任一时刻的状态、组件、部分可观察副本和评价函数；
- `ForwardModel`：设置、合法行动、行动效果、回合顺序和终局；
- Actions：改变状态的独立逻辑单位；
- Rules / Turn Order / Phases：限制流程与行动窗口；
- Cards、dice、tokens、counters、decks、areas、grid/graph boards 等通用组件。

### 能产生什么证据

论文对 7 款已实现游戏——Tic-Tac-Toe、Love Letter、Colt Express、Uno、Virus!、Exploding Kittens、Pandemic——按每种玩家人数用随机代理运行 1000 局，报告：

- 行动空间；
- 分支因子；
- 状态组件数量；
- 隐藏信息比例；
- setup/next/actions/copy 执行速度；
- 决定数、tick、回合和每回合行动数；
- 启发式奖励的范围与稀疏度。

作者也提醒平均值会隐藏游戏过程中的大幅变化，例如 Uno 的行动空间随手牌数量变化。未来方向包括参数优化、规则变化、内容生成和可迁移 AI。

### 对设计者的正确用途

TAG 适合问“游戏在形式系统层面有多复杂、参数变化造成什么结果、某策略是否可能存在”。随机代理并不等于合理玩家，平均长度不等于体感节奏，隐藏信息百分比也不等于推理乐趣。程序无法从这些指标推出规则是否好教、组件是否好拿、玩家是否感到紧张或一名玩家是否压制他人。

### 产品含义

长期可以建立“计算测试实验单”：待测参数、代理策略、运行次数、随机种子、指标、解释边界和必须进行的真人复核。MVP 只提供概念卡，不在浏览器里承诺执行 TAG。

## 4. Ludii：Ludemic General Game System

来源：Piette et al., 2019，[arXiv 原始论文](https://arxiv.org/abs/1905.05013)。

### 模型对象

Ludii 用 ludeme——高层、可理解、可组合的游戏概念——描述游戏。一个游戏大体被组织为 Players、Equipment 和 Rules；Rules 再分 Start、Play、End。它以 class grammar 把 Java 类库自动变成描述语法，目标包含 generality、extensibility、clarity、efficiency、evolvability 和文化/历史分析。

论文证明 Ludii 对“有限、确定、完美信息游戏”具有通用表示能力：可把完整游戏树映射成图上的单一 token 移动。该构造证明可表示性，不代表是每款游戏最高效或最易理解的实际编码。

### 实验

作者比较 Ludii、GDL propnet 与 RBG interpreter/compiler 每秒随机推演数。Ludii 在所有纳入的 Tiltyard/GDL 游戏上快于 GDL；与 RBG 相比，通常快于解释器、慢于编译器，但 Hex 和 Gomoku 等例外。作者公开说明清晰度、可演化性和性能之间存在权衡。

### 边界

论文虽称支持随机、隐藏信息、同时行动并包含实时 proof-of-concept，但形式通用性证明只覆盖有限确定完美信息博弈，性能表以棋类和传统策略游戏为主。不能据此声称谈判、角色扮演、Legacy、肢体表演、主题阅读或开放社交规则都已获得同等覆盖。

### 产品含义

Ludii 对本项目最有价值的不是让每个新手立刻学语法，而是提醒知识库把机制存成“可组合、有参数、有语义的动作关系”，而非无上下文标签。后期可用它支持传统机制谱系和变体实验。

## 5. AutoBG：AI 辅助的端到端设计流程

来源：Li et al., 2026，[arXiv v2 预印本](https://arxiv.org/abs/2606.01976)。当前日期下尚不能视为同行评审定稿。

### 系统结构

- **BG-Ideator**：多轮对话，把模糊想法收敛为结构化草案；
- **BG-Realizer**：生成七段式完整规则书；
- **BG-Critic**：按 MDA 链进行评分、缺陷定位和版本比较；
- **BG-Persona**：基于 150 名真实评论者的评论历史模拟个体偏好反馈；
- **Verifier-Gated Iteration**：只有独立比较器偏好新版本才接受修订；无缺陷或无候选更好时停止。

数据基础报告为 2.2K 结构化规则书和 180K 过滤评论。训练样本大量使用 GPT-5.4 生成/改写，并用其他模型辅助验证，因此“真实数据基础”不等于每条训练监督都由人类直接标注。

### 评测与用户研究

- 207 款与训练集分离的留出游戏；
- BG-Critic 的诊断质量仍由 Gemini-3.1-Pro 根据标注评分；
- 规则生成与迭代的多个指标由 BG-Critic 本身评估，存在评价器—生成器闭环的解释风险；
- Persona 测试含 50 名玩家、210 个实例，以留出的真实评论和评分比较；
- 30 人完成一次 45–60 分钟端到端任务：10 名设计者、15 名爱好者、5 名新手；没有随机对照，通用 LLM 对比是 22 人的回顾性自评。

论文报告所有群组的六项 Likert 均值都高于 5/7；设计者最看重 critic，爱好者整体推荐最高。新手只有 5 人，完成率 80%，并且觉得诊断较不容易行动（4.8/7）。这些是有价值的可用性信号，不足以证明长期设计质量或出版成功。

### 作者明确承认的三项限制

1. **没有实体测试**：人体工学、真实节奏和涌现策略只能通过实体/真人游玩发现；
2. **纯文字**：未评估图形、图标、桌面布局、组件和主题沉浸；
3. **画像深度不足**：不包含团体互动、游玩频率和随时间变化的品味。

### 产品含义

最值得迁移的是“生成者与评价者分离 + 版本比较门控 + 明确停止条件”，而不是复制一个自动给分机器人。网站里的 AI 输出都要落成：原文位置、疑点、改动理由、替代方案和真人测试问题。画像模拟永远标为 audience hypothesis。

## 跨框架组合：一轮设计怎样使用

1. 用 MDA 写清本轮体验假设；
2. 用 5PM 拆开最关键的一项玩家行动；
3. 做最小实体原型并收集观察；
4. 当规则已足够无歧义、且问题适合计算时，再用 TAG/Ludii 形式化；
5. AI 可以整理和比较候选版本，但任何动态与体验结论都回到真人、实体游玩。

顺序不是强制瀑布流程。若项目从一个有趣机制开始，可以先用 5PM 描述，再用 MDA 追问它可能支持什么体验；若形式化暴露了规则歧义，也应回到纸面原型，而不是继续增加模拟次数。

## 下一轮研究缺口

- MDA 的批评与替代模型（如 DDE）需要用原文而非二手摘要比较；
- 规则书可理解性与视觉人体工学仍缺开放全文研究；
- TAG/Ludii 需要用同一款小型桌游做一次实际编码，才能估算新手成本；
- AutoBG 是新预印本，需追踪版本、代码/数据开放、同行评审和独立复现；
- 本轮不再把 DoC 当作已读完整模型，需另找准确的原始定义或作者后续成果。
