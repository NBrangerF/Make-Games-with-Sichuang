# 新手交接审计：从测试计划到现场证据

日期：2026-08-21  
状态：implemented / participant-validation-pending

## 审计问题

现有“单问题测试计划”能定义要看什么，但用户到桌边后没有正式位置记录时间、玩家别名、可见状态、随后结果、主持介入、实际停止和撤回。旧“反馈整理器”只能事后整理文字，无法恢复事件发生时的版本与语境。

## 断点

```text
测试计划完成
  → 靠纸片或记忆主持
  → 反馈脱离时间与状态
  → 玩家建议、观察和解释混在一起
  → 下一版决定无法回到证据
```

风险不是“少一个表单”，而是计划中的证据边界在现场丢失：同一次主持提示既可能被忘记，也可能被当成机制自己产生的结果。

## 修复原则

- 用户必须显式点击“保存并开始主持”；记录器只读取最近计划并冻结快照。
- 同一份刚保存计划不重复写历史；改过字段才形成新快照。
- 开场先填实际发生的参与、配置、媒介、观察角色、捕捉方式和同意范围。
- 每条事件把观察与可见状态、后续结果、介入影响连起来；允许事后修正并保留 `revisedAt`。
- 局后回答单独保存，不回填成局中事实。
- 支持/反驳/未定分组不自动计算严重度、因果、代表性或通过率。
- 撤回会删除当前本地草稿和同会话历史，但明确提醒外部录音/共享副本另行处理。

## 已修复的路径

```text
原型范围
  → 单问题测试计划
  → 保存并开始主持
  → 开场与同意
  → 局中逐事件记录
  → 结束与追问
  → 证据与下一版
  → 项目完整包 playtest_sessions
```

## 仍需真人确认

- 一人同时主持和记录时，右栏事件表是否过重；
- 多人快速对话中，别名与阶段选择是否足够快；
- 暂停、停止、撤回和开始新会话的文字是否不会误导；
- 新手是否把“与主问题关系”误读为严重度或结论；
- 375px 手机宽度是否适合桌边快速记录。
