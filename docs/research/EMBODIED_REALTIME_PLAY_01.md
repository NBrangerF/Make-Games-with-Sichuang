# 专项研究 12：实时、灵巧动作与具身桌面体验

状态：review  
日期：2026-08-19  
深读来源：12（学术/研究 6，一手规则或设计实践 5，残障玩家博客 1）

## 研究问题

1. 当抓取、悬停、摆放、堆叠、弹射、画线、说话或同时行动决定结果时，身体动作在系统里承担什么功能？
2. 实时和同时行动怎样改变注意、信息、协作、错误修复与决定权，而不只是缩短时长？
3. 组件、桌面、座位、光线、噪声和媒介为什么必须进入原型与测试记录？
4. 怎样提供节奏或输入替代，而不假定替代版本与原体验完全等价？
5. 新手设计师应记录什么，才能区分“有意的身体挑战”和“无意的使用摩擦”？

## 方法与证据边界

检索使用 `tabletop embodied play`、`dexterity board game design`、`real-time board game designer diary`、`board game bodily action repair`、`physical disability dexterity board game` 及中文近义词。优先深读可取得全文的方法论文、官方规则、设计者一手复盘与残障玩家第一人称文章；商业介绍和玩家讨论只用于发现候选症状。

这个交叉领域没有一套已经在多类实体桌游和多样玩家中验证的统一理论。有关身体互动的系统综述主要来自屏幕式全身游戏；有关桌游身体互动的研究多是会话分析、理论设计空间或单一原型。本站因此只提取可观察问题和版本化测试方法，不把相邻研究写成实体桌游的通用效果定律。

## 综合结论

### 1. 身体动作是规则的一部分

实体桌游不只要求玩家“决定移动到哪里”，还要求他用某种姿势、距离、手、速度、力量和精度改变共享状态。弹射的力量和角度、堆叠的接触点、画线的速度、悬停棋子的犹豫，都会成为系统输入或同桌信息。只把规则写成结果，会漏掉真正被玩家执行的动作契约。

**产品转译**：每个身体动作至少记录起点、目标、身体/工具、允许姿势、距离、精度、力量、速度、重复次数、失败后状态和能否重置。

### 2. 组件、桌面与座位共同生成结果

圆片与板面摩擦、木块的重量和重心、桌面稳定度、玩家能否转动棋盘或绕桌、光线和噪声都会改变可行动空间。Carrooka 的旋转底座不是外观升级，而是改变玩家从座位到目标角度的路径。Crokinole 技术概念验证则显示，即使把动作数字化，光照、颜色、相机距离、延迟和实体状态回写仍会进入系统。

**产品转译**：身体动作原型不能只在线上验证。测试计划要保存表面、桌高/尺寸、座位、触达、照明、噪声、组件批次和媒介；更换材料或桌面后应视为新版本。

### 3. 实时是一套注意与权限结构

计时器只是一个部件。实时或同时行动会决定谁能等待别人、谁必须持续听、谁能发言、谁负责确认、错误什么时候可见，以及一人停顿是否拖住全队。Captain Sonar 让角色按各自职责同时处理信息；Magic Maze 把动作权限拆给不同玩家并限制沟通。它们的体验来自时间、信息、权限、身体动作和修复规则的组合。

**产品转译**：不要只写“60 秒”。要画出每个角色在同一时间窗里必须读取、决定、操作、发言、确认和恢复什么，并标出最早出现排队、遗漏、代办或互相等待的位置。

### 4. 紧张与共同成就是条件性结果

Space Alert 的案例分析把共同敌人、有限行动、沟通、时间压力和同时挑战连接到共同成就与难忘失败，也指出平衡失调时可能出现过度紧张和替罪羊。设计师不能从“大家很吵/很激动”直接推断沉浸或合作；同一现象也可能是信息丢失、职责不清或某人被排除。

**产品转译**：观察中分开生理/情绪自述、可见协调、任务完成、错误修复和关系后果；不把音量、速度、笑声或失败记忆合成“投入度”。

### 5. 桌面上的“无动作”也可能有信息

悬停棋子、反复整理资源、身体前倾/后退和非词汇声音可能向别人展示思考、犹豫、准备或退出。远程化、自动整理或强制倒计时会删除或改变这些信号。它们不一定都应保留，但设计者需要知道自己删掉了什么信息通道。

**产品转译**：比较实体/线上、回合/实时或自动/手动版本时，记录哪些身体信号变得不可见，哪些隐私反而增加，以及策略推断和主持人介入怎样变化。

### 6. 错误修复本身也是玩法与社交事件

动作放错位置、抢先操作、没有及时回应或碰倒共享结构，可以由别人直接扶正、口头提醒，或边示范边责备。不同修复方式会改变信息、羞耻、教学、责任和游戏状态。只记录“出现一次误操作”不足以指导下一版。

**产品转译**：记录谁发现、谁修复、是否先征得同意、用了身体/语言/系统哪种方式、是否泄露信息或替代决定、状态能否无损恢复，以及玩家随后是否继续自主行动。

### 7. 替代节奏和输入是版本，不是自动等价

Captain Sonar 的规则明确把首局、噪声和少人数导向回合制；残障玩家博客也提出回合制或替代角色能打开参与机会。但实时压力本身可能承担主题、协调或表演功能，因此移除计时可能改变信息优势、策略深度和共同节奏。替代输入也可能损失触觉、引入设备或协助劳动。

**产品转译**：同时保留原版本与替代版本的体验承诺；分别测试玩家任务、贡献权、身体/认知负担、设置劳动和社会后果，不用“无障碍模式”四个字宣称等价或通过。

## 新手可执行路径：一轮身体—时间观察

1. **冻结体验承诺**：这轮身体动作或时间压力究竟要带来紧张、熟练、混乱、协作、表演还是空间判断？
2. **冻结一个动作窗口**：写清谁在何时、从哪里、用什么动作改变哪一状态；不要观察整局所有动作。
3. **画注意与权限链**：同时标出必须看、听、触摸、决定、发言、确认和等待的内容。
4. **记录第一次偏离与修复**：观察动作没发生、发生太晚、精度不足、信息漏掉或别人代办时，桌面怎样恢复。
5. **只改一个条件复测**：计时长度、暂停点、组件、表面、座位、角色或替代输入一次只改一项，并记录失去与新增的体验。

贯穿例：四人合作修理飞艇，玩家要在 45 秒内把不同形状零件放进公共仪表盘。第一次测试只追“导航员听到故障后把三角零件放到红区”这一动作：记录他同时要听几条指令、从座位能否够到、放错能否自己复原、谁代为纠正，以及改为 60 秒后协调和紧张分别怎样变化。

## 不应产品化成总分的内容

- 不计算“身体参与度”“紧张度”“沉浸度”或“无障碍分”；
- 不用完成速度代表动作质量或玩家价值；
- 不把他人代为操作自动记成参与成功；
- 不把线上模拟、技术概念验证或设计者自测当作真实材料与玩家任务证据；
- 不把一种替代模式标为所有玩家通用的无障碍版本。

## 仍缺证据

- 缺少中文灵巧/实时桌游设计师的逐版本长日志，而不是宣传访谈；
- 缺少中国身体障碍玩家对实时与灵巧桌游的第一人称任务记录；
- 缺少同一实体游戏在不同桌面、材料批次、座位与替代输入间的比较数据；
- 缺少长期身体技能学习曲线、疲劳、疼痛与退出选择的纵向研究；
- 缺少实时桌游中噪声、听觉处理、语言差异与团队责任分配的交叉研究。

## 产品决定

1. 新增一篇专题指南“别只计秒，追一次身体—时间窗口”，复用现有决定轨迹、共享决定、任务无障碍与测试计划工具，不新增第十三个正式工具。
2. 新增四个概念：具身动作、时间契约、动作修复、身体技能曲线。
3. 新增六条可追溯 Claim，均保留媒介、样本与迁移边界。
4. 资源库暂不新增第十个入口；九个入口已经接近移动端发现负担上限。新来源进入“边玩边学设计”“把玩家抱怨变成可测试问题”和“让更多玩家真正参与”所支持的逐条搜索，但等待真实用户验证后再决定是否增加独立入口。
