# 桌游设计能力怎样长期形成：第一轮证据综述

更新：2026-08-19  
状态：可用于内容化；仍需更多中文纵向个案与桌游设计师多年同期日志

## 研究问题

这一轮不问“怎样做完一个游戏”，而问三个更难的问题：

1. 做过更多项目，是否就等于设计能力提高？
2. 日志、比赛、Game Jam 和限时挑战怎样才会产生可迁移的学习？
3. 网站应记录什么，才能帮助新手看见自己的判断变化，而不是制造新的等级焦虑？

结论先行：**项目、工时、原型数、比赛名次都只是练习发生过的痕迹，不是能力增长的直接证据。** 更有用的最小记录单位是：一次具体判断在什么情境下形成，遇到了什么证据，怎样修订，后来能否在一个有所改变的新情境中继续成立。

## 检索范围与方法

- 学术线：设计专长、设计教育阶段、职业游戏设计实践、设计日志、Game Jam 学习、桌游 Jam。
- 实践线：商业桌游设计师复盘、个人设计挑战、比赛日记、中文赛事观察。
- 优先级：全文或机构仓储 > 出版商摘要 > 设计师本人文章 > 二手转述。
- 使用方式：每条结论同时记录“它支持什么”和“它不能支持什么”。
- 工具限制：本轮环境没有可调用的 Exa / Firecrawl；改用网页检索、机构仓储与可访问 PDF 逐条核验。没有把搜索摘要当作全文证据。

## 核心发现

### 1. “做了很久”与“判断发生了质变”是两件事

Nigel Cross 对设计专长研究的综述指出，熟练设计师往往更快地界定问题、设定优先级、形成暂定方案并在实施前作初步评价；他们也更常把问题与方案共同推进，而不是先把问题完全分析完再寻找答案。综述中提到的学生纵向材料尤其重要：有些学生的行为发生了变化，有些没有；也有人投入更多时间，却没有出现相应的质性改变。项目类型本身也会影响表现。

因此，网站不能把“第几个作品”“投入多少小时”直接转译为能力等级。它们可以作为背景字段，但学习证据需要继续追问：原来的判断是什么？哪条观察使它失效？新判断在哪个边界内成立？

来源：[Cross, Expertise in Design: an overview](https://oro.open.ac.uk/3271/)，[全文 PDF](https://scispace.com/pdf/expertise-in-design-an-overview-5wb49muh62.pdf)。

边界：这是跨设计领域综述，不是桌游设计的效果实验；协议分析也难以捕捉非语言、情境化和长期工作中的全部知识。

### 2. 专长不是贴在整个人身上的单一等级

Dorst 与 Reymen 把 Dreyfus 模型带入设计教育，提出从依赖规则到情境化判断的不同表现，但他们明确把研究称为初步探索：材料来自一名工业设计学生三年中的自我评价，而且同一个项目里可以同时出现不同层次的行为。

这意味着网站不应给用户发“新手 / 中级 / 专家”总等级徽章。更稳妥的做法是追踪一个局部判断，例如“什么时候应该隐藏信息”“怎样缩小测试问题”“何时停止补规则”。一个人在概率估算上可能很熟练，在无障碍测试上仍是新手；这种并存是正常状态。

来源：[Dorst & Reymen, Levels of Expertise in Design Education](https://northamericanchapter.designsociety.org/publication/19588/LEVELS%2BOF%2BEXPERTISE%2BIN%2BDESIGN%2BEDUCATION)，[全文 PDF](https://scispace.com/pdf/levels-of-expertise-in-design-education-1q4c44vo9b.pdf)。

边界：单个学生、回顾性自评，不能据此建立经过验证的能力量表。文中讨论的“专长反转”也提醒我们：对新手有帮助的脚手架，可能会干扰熟练者，但这不是为用户贴标签的理由。

### 3. 能迁移的不是固定配方，而是带边界的判断

Cross 的综述把专家表现与抽取底层原则、重构问题、在活动模式之间切换联系起来。Cormio 等人对 11 位职业游戏设计师的扎根理论访谈又提出“在恒定与变化之间平衡”：设计师既维护框架与一致性，也通过协作和迭代保留对约束的适应能力。

对桌游学习工具的直接含义是：每次迁移只改变一个重要情境变量，例如玩家年龄、信息结构、合作关系、材料限制或游戏时长。随后观察原判断是继续成立、需要适配，还是应被搁置。原样复制同一配方，最多证明记住了步骤；在新情境中能说明适用边界，才更接近可迁移能力。

来源：[Cormio et al., Exploring game design approaches through conversations with designers](https://u-pad.unimc.it/handle/11393/332510)，[DOI](https://doi.org/10.1016/j.destud.2024.101253)。

边界：11 人访谈主要面向职业电子游戏设计；作者也要求未来跨类型、跨文化检验。这里把“恒定与变化”转为桌游学习活动，属于有标注的产品推论。

### 4. 日志的价值在于连接决定，而不是堆积文字

Gestwicki、Coy 与 Largent 对本科生游戏设计日志的研究，把日志用途归纳到行动项、活动、决定、测试、缺陷、研究、规则与课程笔记等类别。它说明日志可以成为工作记忆和设计轨迹，但日志形式高度个体化，研究也没有证明“写得多”会自动带来长期专长。

设计师日记还存在时间偏差。Scott Almes 对《Cosmic Colonies》的六年回顾，清楚展示了一个核心选取机制长期保留、外围系统与主题反复舍弃、签约后继续开发；Quinn Brander 对《Rebuilding Seattle》的访谈则把一个失败项目与后来反向选择新约束联系起来。这些材料对理解真实取舍很有价值，但它们都是围绕已出版作品压缩过的成功叙事，不能还原当时全部不确定性，也不能直接推广为普遍规律。

来源：[The Forms and Uses of Undergraduate Student Game Design Logs](https://cardinalscholar.bsu.edu/items/37ebe8e8-c964-4019-b72a-36fb6073a315)，[Cosmic Colonies 设计日记](https://floodgate.games/blogs/news/designer-diary-making-a-good-game-great)，[Rebuilding Seattle 设计日记](https://wizkids.com/2022/11/28/designer-diary-for-rebuilding-seattle/)。

产品要求：区分三种材料——当场记录、测试后复盘、数月后的作品叙事；不要把后来讲得通的故事冒充当时就知道的因果。

### 5. Jam、比赛和限时挑战是“练习容器”，不是成长计分器

Aurava 与 Sormunen 的系统综述纳入 2010–2022 年的 25 篇研究，报告 Game Jam 可能促进跨学科、程序性、认知、元认知、社会与情绪技能，但结果依赖任务、角色，以及活动是否真正安全、包容。原研究多是描述性单案例，通常没有对照组，也无法把 Game Jam 与其他学习方式比较。

Hautopp 等人的 7 小时教育桌游 Jam 试点更接近本项目主题：30 名教育工作者组成小组，经历构思、制作和测试；不同小组在明确视角、共享领域与游戏知识、控制机制与学习内容的复杂度上表现不同。研究者同时是组织者与观察者，结论来自四组过程，作者要求在新场景继续验证。

个人挑战也显示同样边界。Matteo Menapace 的“十周改造十个游戏”给出了重复实验协议，但公开页面只呈现到八个成品；Wannabe Board Game Designer 的 54 张卡比赛日记细致记录版本、测试、投稿与赛后不确定性，却也显示截止日期可以交付作品，却未必自动带来高质量反馈。

来源：[Game Jam 学习系统综述](https://doi.org/10.1016/j.caeo.2023.100129)，[全文 PDF](https://trepo.tuni.fi/bitstream/10024/209142/1/Future-oriented_skills.pdf)，[教育桌游 Jam 研究](https://doi.org/10.34190/ecgbl.17.1.1759)，[十周十个游戏改造](https://medium.com/10-game-hacks-in-10-weeks/10-game-hacks-in-10-weeks-68d0255e3a52)，[54 张卡比赛日记](https://wannabeboardgamedesigner.com/diary/)。

中文侧补充：[WODC 评委复盘](https://www.sohu.com/a/552916676_99978201)提到较长赛程给参赛者留下沟通、测试和修改规则的时间；它是赛事参与者视角与宣传语境，不是参赛者长期能力的追踪研究。

## 给网站的可执行模型

### 最小学习单元：判断迁移记录

每一条记录只追一个判断，包含八个字段：

1. **情境**：项目、玩家、阶段与约束。
2. **设计锚点**：这次不轻易改变的体验意图或责任边界。
3. **原判断**：行动前认为“在什么情况下，什么做法会产生什么结果”。
4. **行动**：实际做了什么版本或测试。
5. **证据**：可观察到的行为、版本差异或反例。
6. **修订判断**：保留、缩小、扩大、反转或搁置。
7. **新情境**：下一次只改变一个关键变量的迁移任务。
8. **迁移结果**：原判断继续成立、需要适配，还是失效；同时记录反向信号。

这不是评分表。网站不把它汇总为“设计师等级”，而是形成一组可检索的判断谱系。

### 三层记录，避免事后故事覆盖现场

| 时间 | 记录什么 | 不记录什么 |
| --- | --- | --- |
| 设计中 | 当前目标、暂定判断、刚发生的意外 | 后见之明式结论 |
| 测试后 | 行为证据、版本差异、下一决定 | “大家很开心”式无对象总结 |
| 跨项目 | 迁移任务、适用边界、反例 | 把一次成功包装成普遍法则 |

### 学习循环

`选择一个判断 → 留下行动前版本 → 获取证据 → 修订并写边界 → 改变一个情境变量 → 再测试迁移`

循环允许三种健康出口：继续、改写、搁置。基于证据停止一个机制或项目，也是一项设计判断；“永远打磨同一个作品”不比“不断开新坑”天然更专业。

## 明确不做

- 不根据工时、项目数、比赛排名或出版状态生成能力分数。
- 不把探索性的阶段模型包装成经过验证的晋级阶梯。
- 不要求每个休闲设计项目都承担作品集或职业训练目标。
- 不把商业成功日记当成方法有效性的因果证明。
- 不用一次 Jam 的完成度替代活动安全、角色分工、反馈质量和后续迁移。
- 不把 AI 转录或整理后的日志默认为设计师原始记录；如使用，应保留生成方式与本人校订状态。

## 证据缺口与下一轮问题

1. 缺少公开、同期记录、跨多年的桌游设计师日志，尤其是未出版与主动放弃项目。
2. 中文公开材料多为课程、赛事介绍或作品复盘，缺少同一设计师跨项目判断变化的可核验记录。
3. 现有 Game Jam 研究偏短期、教育或数字游戏情境，不能回答能力是否在数月后保留。
4. 需要用户访谈检验“判断迁移记录”是否足够轻量，以及新手能否区分证据、解释与决定。
5. 后续可研究同一位设计师在机制、测试、规则写作、无障碍与生产约束上的局部能力如何不均衡发展。

## 本轮内容化决定

- 新增专题指南：**别数做了几个，追一个判断怎样迁移**。
- 新增术语：问题框架、学习提取、迁移测试、练习容器。
- 新增主张：练习需要学习提取；专长具有任务特异性；迁移需要改变情境；设计要平衡恒定与变化；日志要连接决定；挑战只是练习容器。
- 指南复用现有“体验意图、版本、假设、观察、设计决定、测试计划、决定轨迹”能力，不另造一个重型工具。
