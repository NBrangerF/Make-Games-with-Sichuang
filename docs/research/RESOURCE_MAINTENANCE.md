# 资源维护与链接巡检

最后更新：2026-08-21  
状态：review

## 两种“核验”必须分开

`content/resources.json` 的 `lastCheckedAt` 是人工内容审阅日期：审阅者检查作者/发布者、正文或元数据、适用阶段、用途与局限。它不是实时链接可用性承诺。

`docs/research/resource-health.json` 是自动网络巡检快照：它只能说明自动请求当时得到什么响应，不能证明正文未改、本站摘要仍准确、许可未变或用户浏览器一定能打开。

## 运行方式

```bash
pnpm resources:health
```

默认无论发现什么状态都生成报告并以成功状态结束，防止暂时限流阻断内容工作。维护门禁可显式使用：

```bash
pnpm resources:health -- --fail-on-dead
```

## 状态解释

| 状态 | 自动判断 | 人工动作 |
|---|---|---|
| `reachable` | HTTP 200–399 | 仍按资源的时效风险检查正文与许可 |
| `blocked` | 401、403、429 | 用普通浏览器打开；检查登录、地区、机器人拦截或限流 |
| `dead` | 404、410 | 保留来源记录；寻找作者新址、DOI、出版社页或可信网页归档 |
| `error` | 超时、网络错误、5xx 等 | 稍后重试并人工检查，不能自动判死 |

脚本先发 `HEAD`；若得到任何 4xx/5xx 状态，再用 `GET` 复核，减少站点不支持 `HEAD` 造成的假阳性。并发为 6，每条超时 15 秒。脚本不会更改或删除 `content/resources.json`。

## 建议节奏

- `currencyRisk: high`：每月或发布前；
- `currencyRisk: medium`：每季度；
- `currencyRisk: low`：每半年；
- 每次新增资源后：运行一次完整巡检；
- 用户报告失效后：立即人工复核，不等待计划任务。

修复链接时保持资源 `id` 不变，更新 `href`、`lastCheckedAt`、人工审阅记录和来源台账。若原文彻底消失，优先记录新位置与迁移理由；不要静默替换成论证不同的相似文章。
