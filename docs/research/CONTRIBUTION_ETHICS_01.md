# 玩家经验与设计案例贡献：同意、权利和撤回研究

状态：review  
日期：2026-08-19  
范围：为未来征集玩家第一人称经验、设计日志、课程反思、无障碍任务记录、生产案例与资源纠错建立治理基础；本轮不开放在线投稿。

## 研究问题

1. 怎样让“愿意参与讨论”不被误写成“同意公开”？
2. 怎样承认玩家、翻译者、分析者与编辑者的不同劳动，而不把所有人压成匿名素材来源？
3. 贡献者要求停止、撤回或修改时，网站需要保存什么映射才能执行？
4. 开放许可、匿名和公开引语各自有哪些不可逆或难以逆转的后果？
5. 涉及残障、儿童、健康、场地与商业数据时，哪些条件必须阻止自动发布？

本轮检索了参与式研究、残障用户研究、知情同意、研究资料管理、公众参与付费、贡献者角色、Creative Commons 许可、儿童参与和设计正义等主题。深读九项官方或原始机构资料；不把任何一份境外指南写成中国法律意见。

## 1. 一次参与需要四个独立决定

“我愿意讲述经历”不能同时代表以下四件事：

1. **参与**：愿意完成访谈、填写记录或共同分析；
2. **保存**：允许本站在明确期限内保存哪些原始资料；
3. **引用与公开**：允许公开匿名摘要、逐字引语、署名内容或媒体；
4. **再许可**：允许其他人按某个公共许可继续复制、改编或传播。

这四项必须分别选择，默认都是最窄范围。W3C 与 GOV.UK 的共同边界是：材料格式和沟通方式本身必须可访问，同意还需要在过程中继续核对，而不是只取得一次签名。

项目推断：贡献包默认 `review_only`，不能默认匿名公开。匿名化降低识别风险，却不等于取得公开许可；公开许可也不等于允许展示姓名、照片或健康资料。

## 2. 公开副本和开放许可存在不可逆边界

CC BY-SA 4.0 明确将公共许可描述为不可撤销；授权者可以停止继续分发，但已经获得许可的人仍保有相应权利。公开网页也可能被搜索缓存、截图、下载或引用。

因此本项目不得：

- 在投稿表中预选 CC 许可；
- 用“方便传播”诱导贡献者选择开放许可；
- 承诺公开后能从全网彻底删除；
- 把停止本站展示写成终止所有既有副本的权利。

若未来提供 CC 选项，必须在最终公开文本确定后再次确认，并用普通语言说明不可撤销性。`review_only`、`link_and_summary`、`approved_excerpt` 与 `cc_by_4_0` 是不同发布模式，不能只用一个“同意条款”。

## 3. 撤回能力依赖可定位的数据结构

只写“可以随时撤回”不够。资料必须能通过一个非公开贡献 ID 定位到：同意记录、原始资料、编辑稿、公开稿、引用它的 Claim、页面和缓存处理记录。

撤回流程分三个阶段：

| 阶段 | 本站能够承诺 | 不能承诺 |
|---|---|---|
| 未公开 | 停止审阅，删除原始资料、工作副本和同意映射，保留最小删除完成记录 | 无法删除贡献者自行保留或发送给第三方的副本 |
| 已公开但未开放许可 | 下架本站页面/引语，更新引用与 Claim，说明是否保留匿名事实摘要 | 无法保证搜索缓存、截图或他人合法引用立即消失 |
| 已使用 CC 公开 | 停止本站未来分发，按许可要求尽可能移除署名信息，更新本站引用 | 不能撤销他人已获得的 CC 权利或回收全部副本 |

这不是法律保证，而是本站可执行的运营边界。涉及争议、违法内容、儿童安全或其他高风险情况时，应停止流程并取得相应专业审查。

## 4. 贡献劳动需要角色、决定权与反馈

CRediT 说明单一“作者”标签会隐藏概念、调查、资料整理、分析、验证与写作等不同贡献。桌游资源网站还需要补充：生活经验、设计实践、翻译/沟通支持和社群联络。

贡献包至少记录：

- 谁提供生活经验或设计记录；
- 谁决定研究问题和字段；
- 谁收集、翻译、摘要或分析；
- 谁验证事实与版本；
- 谁审阅最终公开稿；
- 哪些人希望实名、化名、集体署名或不公开身份；
- 贡献如何改变网站内容，以及哪些建议没有采用、为什么。

NIHR 的公众参与资料支持把准备、参与和后续反馈都视为贡献劳动，并另外考虑参与开支。本站不能用“曝光”“帮助社群”替代事先说明的补偿方案；具体金额和税务必须在实际地区另行核验。

## 5. 第一人称不等于代表整个群体

生活经验具有知识价值，但一位玩家不能代表同一诊断、障碍、地区或社群。W3C 要求报告样本与任务范围，并把用户参与和标准检查结合；Design Justice Network 则强调直接受影响者和社群控制。

本站公开材料需要同时显示：

- 这是第一人称、共同分析、机构转述还是编辑推断；
- 游戏、版本、地点、日期、任务和协助条件；
- 贡献者是否参与最终分析和文案批准；
- 结论只覆盖什么，不覆盖什么；
- 是否有相反经验或未采用意见。

公开一段经历的价值不是把它升级成总体规律，而是让此前不可见的任务、代价和设计问题进入下一轮验证。

## 6. 儿童与高敏感资料不是普通投稿分支

UNICEF 将儿童最佳利益、伦理审查、安全保障、风险管理、有意义的同意/同意表达、隐私和资料管理列为全生命周期要求。项目因此不允许普通贡献包直接进入涉及儿童或需要额外保护参与者的公开候选状态。

最低门槛包括：

- 先完成专业的安全保障与风险审查；
- 分开记录监护人许可与儿童/参与者本人的同意表达；
- 提供适龄、可访问的信息和停止方式；
- 不把监护人同意写成儿童必须参加；
- 对照片、录音、逐字引语和作品使用分别确认；
- 明确出现不适、披露风险或退出信号时由谁负责。

本站目前没有相应人员、流程和法律审查能力，所以模板默认阻止这类贡献进入发布候选。

## 产品决定

1. 不上线公开投稿表或审核后台，保持 MVP 的 local-first 边界。
2. 提供离线贡献包模板；默认私有、默认不录音录像、默认不公开引语、默认未选择公共许可。
3. 数据结构分开参与同意、资料保存、引用/公开与公共许可。
4. 发布前需要贡献者审阅最终公开副本；编辑摘要不得依赖最初的泛化同意。
5. 每个贡献包保留可执行撤回映射，但公开前不把真实联系方式写入可分享 JSON。
6. 涉及儿童、无法完成有意义同意、高风险健康/身份资料或第三方权利不清时，机器状态不得进入 `publication_candidate`。
7. 不生成贡献质量分、代表性分或可信度总分；证据层级与编辑判断继续分别显示。

## 仍待验证

- 中国大陆、港澳台分别适用的个人信息、儿童保护、著作权与合同要求；
- 合适的中文贡献者信息说明、易读版、音频版和辅助沟通方式；
- 残障玩家、儿童权益与社群组织者对撤回、匿名和署名字段的真实理解；
- 补偿金额、支付方式及其可能影响福利或税务的地区化说明；
- 未来公开贡献是否应使用独立内容仓库、加密资料库和审批权限。

这些问题没有完成专业审查前，离线模板只能用于协议测试和内部准备，不是公开征集授权书，也不构成法律、伦理委员会或儿童保护意见。
