# 专项研究 25：一场只回答一个问题的真实测试计划

状态：review  
检索日期：2026-08-21  
范围：原型版本、单一主问题、行为预测、局中观察、主持边界、参与者语境、局后追问、停止与结论规则

## 研究方法

本轮先拆成五个子问题，再使用可用的网页搜索逐项检索并打开正文核验。原计划使用 Firecrawl/Exa 做批量抓取，但当前工作区没有可调用能力，因此改用搜索结果与全文打开；没有把摘要片段当作深读。研究不提供通用样本量、通过分、乐趣分或发行门槛。

## 研究问题

1. 为什么早期原型测试需要一个主问题或假设，而不是并列的愿望清单？
2. 局中可见行为与局后口头解释分别能回答什么？
3. 主持人的说明、提示和纠正怎样改变测试条件？
4. 参与者经验、玩家配置、彼此关系与实体/线上媒介怎样限制结论外推？
5. 怎样预先写反驳、重复、开始/停止和版本边界，避免测试后只挑支持证据？

## 综合结论

### 1. 测试计划应形成一条证据链

新手需要的不是三个同权问题，而是：

```text
来源版本 → 一个主问题 → 可见行为预测 → 反驳信号
→ 目标事件与记录字段 → 重复/开始/停止 → 下一步规则
```

其他好奇可以进入停车区，仍可记录意外，但不能在测试后被悄悄升级为本轮结论。单问题不是宣称复杂游戏只有一个问题，而是约束一次版本比较的解释范围。

### 2. 局中观察和局后追问是不同证据

局中记录发生了什么：何时、谁、做了什么、当时可见什么、系统怎样回应、主持是否介入。局后追问记录玩家怎样描述自己的判断。后者可解释线索与意义，但不能覆盖或改写前者。工具因此先写观察事件与字段，最后才写最多三个开放追问。

### 3. 主持帮助是条件，不是可删噪音

解释规则、提醒选项、纠正操作或透露设计意图都会改变玩家可见信息与可行动范围。计划必须预写“可以做什么”和“绝不能替玩家做什么”；实际介入要带时间点进入事件记录。引导测试仍然有效，但它回答的是“在这些帮助下发生什么”。

### 4. 参与与媒介限定外推

参与者经验、玩家数量/队伍/座位、彼此关系、测试类型、实体/线上/混合媒介共同定义证据语境。线上或混合测试可能弱化触感、触达、距离、身体动作和细微社交线索，因此导出只声明本次语境，不声称样本代表总体。

### 5. 结论规则要容纳支持、反驳和未定

观察到预测行为不等于证明机制导致它，更不等于好玩、平衡或可发行。测试前应写明支持、反驳和未定证据各自怎样进入下一版；停止条件既包括切片结束，也包括安全/主动停止。工具不计算通过率。

## 产品转译

“单问题测试计划”采用四步：

1. 承接范围：显式导入最近原型范围，只复制已有字段；
2. 观察协议：事件、字段、重复、开始/停止、保持不变与单一改动；
3. 参与与主持：参与者、玩家配置、类型、媒介、允许/禁止介入、记录同意、安全停止；
4. 结束与追问：开放追问、支持/反驳/未定后的处理、意外停车区。

底部证据链仅显示字段是否齐全，不生成分数。历史记录继续使用项目包现有 `test_plans` 类别，避免为了升级工具制造第二个同义数据孤岛。

## 新增 Claim

- `claim-test-plan-needs-one-evidence-chain`：一轮形成性测试需要将一个主问题接到预测、反驳、观察与结论规则。
- `claim-play-observation-and-interview-are-different-evidence`：局中行为和局后自我报告应分开记录并互相解释，不能相互覆盖。
- `claim-moderator-help-changes-playtest-evidence`：主持介入会改变测试条件，应预先约束并逐次记录。
- `claim-playtest-context-limits-generalisation`：参与者、配置、关系与媒介限定结论可外推范围。

## 仍待补证

1. 中文桌游设计师公开展示“原型问题—测试记录—下一版决定”的完整案例；
2. 谈判、合作、实时与身体化桌游中，多人事件记录的最低负担格式；
3. 视障、听障、认知差异和动作差异参与者对记录与主持协议的共同修改；
4. 涉及未成年人、敏感主题或公开视频时的地区性同意与数据保管要求；
5. 新手能否稳定区分“行为预测”“反驳信号”和“结论规则”。
