# 专项研究 24：从体验意图到核心循环的证据交接

状态：review  
检索日期：2026-08-21  
范围：核心循环、中心挑战、有意义决定、状态—反馈—下一输入、循环出口与最小交互原型

## 研究问题

1. “核心循环”在新手工具中应记录哪些关系，而不是哪些机制名称？
2. 体验意图里的玩家、重复决定、压力、反馈和预测，哪些能被原样承接，哪些不能自动翻译？
3. 怎样判断反馈真的回到下一次决定，而不只是显示结算结果？
4. 怎样记录一次性事件、终局与换层，避免为了画闭环强行回箭头？
5. 画布完成能证明什么，不能证明什么？

## 综合结论

### 1. 核心循环是作用链，不是机制目录

最低可操作结构为：

```text
当前信息/状态 → 玩家认为可行的选择 → 代价或承诺
→ 系统状态变化 → 玩家能获得的反馈 → 下一次输入/决定
```

“工人放置、卡牌驱动、资源管理”只能说明可能使用的规则家族。新手画布必须追问这些规则在一个具体决定时刻允许谁读取什么、做什么、失去什么、改变什么，以及新状态怎样进入下一次判断。

### 2. 体验意图只能原样承接，不能自动处方

可直接复制并标记来源的字段：项目、版本、玩家语境、重复决定、行为预测、反驳信号和测试问题。不能由系统自动补写的字段：可行选项、结算行动、成本、承诺窗口、状态变化、可见范围、反馈时机、作用路径和循环出口。

因此产品使用显式“导入最近体验意图”，保留来源 ID/时间与只读摘要；导入后仍把规则字段留空。任何自动推荐机制都会把设计者预测误写成事实，并遮蔽其他可能实现。

### 3. 反馈要改变下一次判断条件

分数变化、标记移动或文字提示是反馈载体，但只有当玩家能读取它，并据此重新评价下一次可行行动、风险、价值或关系时，才完成本轮所说的回接。画布分开记录：

- 什么状态改变；
- 谁能看见；
- 何时及通过什么载体看见；
- 它怎样改变下一次输入；
- 这条路径影响当前玩家、对手、共同目标或游戏世界中的谁。

这仍只是一条规则假设。真人可能忽略、误读或利用不同信号。

### 4. 循环必须有出口

一次性揭示、不可逆变化、终局触发或模式切换不必回到同一决定。工具单列“循环何时停止、换层或进入终局”，防止为了图形完整把所有流程强行画成无限回路。

### 5. 闭合不等于有趣、平衡或可用

结构画布只能发现缺失的输入、结算、反馈或出口。它不能证明：

- 选项在真实局面中都有价值；
- 玩家实际看见并理解反馈；
- 代价被认为合理；
- 实体读取、操作和查询可完成；
- 对手或共同决定的社会后果可接受；
- 行为预测或目标体验已经出现。

所以导出固定拒绝循环质量分、最优机制推荐和玩家体验结论，并把第一条问题交给原型范围裁剪器。

## 产品转译

核心循环画布采用五步：

1. **承接意图**：显式导入或手填玩家、决定、预测与反例；
2. **信息与选择**：当前信息、眼前目标、可行选项与状态相关差异；
3. **代价与承诺**：执行、支付/放弃/暴露、锁定与回应窗口；
4. **状态与反馈**：变化、可见对象、时机/载体、下一输入与作用路径；
5. **重复与出口**：下一输入/决定、出口、保持不变、单一改动与原型问题。

完整记录进入 `core_loop_records`。体验意图卡提供“继续到核心循环”，核心循环提供“继续裁剪原型”，原型范围裁剪器则显式导入最近核心循环的原字段。三次跳转都不自动宣称上一步已经验证。

## 新增 Claim

- `claim-core-loop-output-becomes-input`：反馈必须改变下一次能看见、能选择或愿意承担的条件；
- `claim-core-is-not-feature-list`：核心是中心挑战的作用链，不是机制/组件清单；
- `claim-loop-completeness-is-not-quality`：闭合结构不能证明选择、反馈、操作、社交或体验质量。

## 仍待补证

1. 中文桌游设计师公开记录中，完整展示“体验目标 → 核心循环 → 最小原型”字段变化的版本史；
2. 谈判、合作与身体化桌游中，循环边界由多人共同决定而非单人动作的案例；
3. 新手是否把“反馈成为下一输入”误写成奖励，或把循环出口误写成游戏结束；
