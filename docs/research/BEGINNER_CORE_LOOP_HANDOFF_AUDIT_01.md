# 新手路径完成度审计 02：体验意图到核心循环与原型范围

状态：implementation-complete / browser-and-participant-validation-pending  
日期：2026-08-21

## 审计问题

第 16 项“体验意图卡”已经能把模糊点子变成玩家语境、重复决定、压力、可见反馈、预测、反例和测试问题。但原“核心系统”阶段只有决定轨迹、熟悉游戏改造、约束牌和平衡诊断：这些工具都能分析或改造已有规则，却没有承接体验意图并写出“输入—选择—代价—状态—反馈—下一输入”的工具。原型范围裁剪器也只能手工重写问题，无法标记来自哪条核心循环。

因此第二段路径在产品层面断开：用户可以写意图，却没有稳定中间产物来说明哪条规则会反复产生该体验，也无法把这条作用链带入最小原型。

## 结论

新增第 17 项“核心循环画布”，并建立两次显式交接：

1. 体验意图卡只有在字段完整时才允许“继续到核心循环”；
2. 核心循环画布由用户点击后才导入最近体验意图，复制原字段并保存来源，不自动选择机制；
3. 核心循环字段完整后才允许继续到原型范围；
4. 原型范围由用户点击后才导入最近核心循环，复制问题、预测、反例、必要功能、受保护决定、起始状态、重复和出口；
5. 材料、范围、保真度、非目标和开工门槛仍由设计者填写。

## 为什么是六段循环

本轮研究把核心循环写成“当前信息 → 可行选择 → 代价/承诺 → 状态变化 → 可见反馈 → 下一输入/决定”。这比机制清单更适合交给原型：每个字段都能转成一项需要出现的规则、状态或观察任务。循环出口另列，避免把终局、阶段切换或一次性事件硬塞成无限重复。

研究依据与反例见 [核心循环交接研究](CORE_LOOP_HANDOFF_RESEARCH_01.md)。闭环完整只表示规则链可描述，不表示选择有趣、信息被理解、代价公平、反馈可访问或目标体验成立。
