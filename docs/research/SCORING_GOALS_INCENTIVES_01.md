# 计分、目标、奖励与激励错位：研究记录 01

更新：2026-08-20  
状态：review；资源、主张、术语、指南与入口已落盘，待中文用户测试

## 为什么要从终局与平衡中拆出来

站内已经分别说明了目标、结束触发、最后一轮、结束进度、多个目标和单风险平衡，但仍缺一条回答以下问题的连续路径：

- 游戏何时结束、谁获胜、怎样计分，是同一件事还是三个相互作用的规则；
- 分数实际奖励了哪些重复行动、资源持有、关系或结果；
- 玩家在行动前能否理解一项选择怎样影响获胜，以及这种信息何时公开；
- 不同计分来源是否真的产生不同承诺和机会成本，还是只把同一优势重复换算；
- 前置、持续、阶段和终局计分怎样改变进度感、对手回应和领先者压力；
- 非对称角色的计分速度不同，是否会被误读为落后、失控或突然翻盘；
- 加分、奖励、徽章或排名是否把原本的设计、学习、合作或表达任务改造成另一项优化问题；
- 精确的小数、倍率、套装和多级平手规则提供的信息，是否值得其计算、查询与教学成本。

这不是“胜利点好不好”的辩论，而是把计分当成行为激励、信息结构、进度反馈和结果判定来检查。

## 站内已有基础与去重边界

- `goal` 已区分短期、阶段和整局目标，不把目标等同终局胜利条件；
- `end-trigger` 与 `special-ending-contract` 已覆盖结束触发、触发者、剩余行动和结算，不重复做终局模板；
- `progress-legibility` 已覆盖离结束多远，本专项新增的是“当前行动怎样影响胜利与分数”的可读性；
- `claim-objective-structure-shapes-tradeoffs` 已说明多目标只有改变机会成本或路径才丰富决定；
- `special-balance-one-risk` 已要求来源—转换—消耗—计分链和明确基线，本专项不生成综合平衡分；
- 主题复核已经比较作品承诺与被奖励的行动，本专项只在激励诊断中复用，不提供伦理认证；
- 设计辅助工具研究已说明计分和竞争会引入第二套目标，本专项补足一般游戏与学习工具共同适用的记录字段。

## 研究拆分

本轮将大问题拆成五个可独立核验的子问题：

1. 结束条件、胜利条件和计分函数应怎样分开记录？
2. 分数怎样改变玩家实际追求的行动、节奏和长期计划？
3. 公开、隐藏、间歇或延迟计分分别改变了哪些信息与互动？
4. 多路径、非对称和阶段性计分怎样制造可读进展，或产生支配路径与误读？
5. 数学结果、玩家理解、动机与桌上互动需要哪些不同证据？

检索顺序为：站内终局/决定/平衡材料 → 桌游设计师理论 → 商业项目设计日志 → 玩家长评与社区讨论 → 一手实验和学位论文。设计主张保留作者立场；玩家材料只作为症状候选；数字游戏、学习和动机研究只用于反驳简单因果，不直接推导实体桌游配方。

## 明确不做

- 不生成作品的计分、目标、乐趣、动机或公平总分；
- 不计算“最佳”分数区间、公开比例、隐藏目标数量、点沙拉浓度或平手链长度；
- 不把胜利点称为天然抽象、无主题、策略浅或优于二元胜负；
- 不把公开分数自动称为更透明、更互动或更有压力；
- 不把隐藏分数自动称为更悬念、更友善或能阻止围攻；
- 不因有多个得分来源就宣称存在多条获胜路径；
- 不从一次玩家获胜、终局分差或平均得分推断激励已对齐；
- 不把外部奖励对实验表现的结果直接迁移成桌游乐趣规律；
- 不做自动配分、策略推荐、最佳路径求解器或玩家排名工具。

## 第一轮发现

### 1. 先拆三个规则，再谈分值

至少分开：

```text
end_condition       什么时候停止或进入收尾
win_condition       什么状态/比较决定胜负
scoring_function    哪些事件与状态被怎样换算
```

Tom Russell 的阈值例和 *Daybreak* 的最后危机阶段都说明，三者可以错开。达到目标不一定立即结束，结束也不一定立刻判胜；计分则可能只是其中一种比较方式。若把三者写成“先到 50 分获胜”，设计者会看不见检查时点、回应窗口、额外条件和主题后果。

### 2. 计分函数是一套行为激励，不是结算注脚

每个可得分事件都在告诉玩家：这种行动、占有、关系或结果值得追求。最低需要画：

```text
player_action_or_state
immediate_non_score_feedback
score_event_and_amount
when_player_can_predict_it
what_is_sacrificed
what_repeated_behavior_it_selects
theme_or_experience_commitment
```

*Daybreak* 把保住社群写进共同失败阈值，是设计团队对“什么不可被当作可接受代价”的系统承诺。*Sanctuary* 评者的相反症状则是：同一组保育目标同时提供高分和终局触发，使其他动物牌在其多局经验中常像诱饵。两者都不能单独证明机制好坏，却说明“分值是否算对”之前要问“什么行为被选中”。

### 3. 多个计分来源不等于多条路径

路径至少需要不同的承诺、机会成本、信息需求或对手回应。若建造、收集、升级和公开目标都由同一收入引擎同步推进，它们可能只是四个结果栏。最低比较：

```text
path_commitment
required_state_and_timing
opportunity_cost
switching_cost
interaction_surface
failure_signal
score_contribution_by_stage
```

站内多目标研究和 27,000+ 玩家次要目标 A/B 研究共同阻止“更多目标一定更深”的推断。后者仍是数字 Flash 任务，不能用留存直接评价桌游；其价值是迫使每个附加目标先写强化主目标与分散注意两种竞争假设。

### 4. 计分速度和可见性会改变感知进展与互动

*Hegemony* 日志是关键一手案例：资本家早期几乎不前进、末轮爆发，让新手误以为自己做错，也让其他玩家觉得领先被突然夺走；团队改用基于总资本的 Wealth track，让过去积累形成可见进展并可调节计分速度。设计者仍承认角色的得分速度不同且新手仍会困惑，因此案例支持“记录速度与可读性”，不支持所有角色同速。

Gajadhar 的数字多人实验又提供谨慎反例：分数公开影响社会联结/卷入若干量表，但对总体享受与投入量表没有显著简单主效应，并与共同游戏条件交互。公开/隐藏不是视觉开关，而是会改变比较、同理、负面情绪、围攻、阻断与记忆劳动的信息设计。

最低记录：

```text
scoring_timing = immediate / phase / delayed / endgame
visibility = public / private / inferable / trackable-but-hidden
pace_by_stage
what_opponents_can_change
memory_or_calculation_work
perceived_progress
actual_score_state
surprise_at_reveal
```

### 5. 复杂度预算应花在核心决定，不是精确幻觉

Subsurface Games 的一手日志记录，复杂计分一度让计分阶段和行动阶段一样长；最终版本让多数区域即时判断，只在少数区域留下有张力的选择。作者的判断是项目特定的，但给出可测试问题：这项倍率、套装或额外比较是否改变前面的决定，还是只增加结算劳动？

Daniel Piechnick 同样反对用数学精确换复杂度，并建议平手规则沿胜利链向前一层，而非引入随机或无人在意的指标。本站不会把这条偏好写成规则；只要求平手优先级能解释它代表的设计优先级，并允许“平局”作为候选。

### 6. 分数、奖励、表现、动机和乐趣必须分轨

Szulawski 等将 200 名年轻成人随机分到 Boggle 的奖励/无奖励与心理需要支持/受挫条件。外部代金券主效应没有显著提高表现；需要支持影响内在动机，能力感又中介了部分表现关系。实验只有两次三分钟单人新手任务，奖励是外部代金券，不能裁决游戏内 VP；它足以反驳“加奖励必然提高目标行为”。

本站因此至少分开：

- 系统轨：分值、频率、协方差、胜率/分差；
- 决定轨：玩家在行动前理解哪些路径和机会成本；
- 进展轨：玩家何时感到前进、落后或仍可追赶；
- 互动轨：公开/隐藏信息怎样改变阻断、围攻、谈判和记忆劳动；
- 体验轨：能力感、自主、紧张、表达、主题后果与乐趣；
- 归因轨：玩家认为自己为什么领先、落后、赢或输。

这些轨道绑定同一版本、人数、经验和场景，但不合成“计分质量”。

## 候选产品方向

专题指南：`special-scoring-contract` / “先写分数奖励的行为，再调分值”。

候选五步：

1. 分开结束、胜负与计分函数，并写目标体验；
2. 抽取一个关键得分事件，画行动—反馈—分数—下一决定；
3. 比较两条候选路径的承诺、机会成本、切换成本和阶段贡献；
4. 写计分时点、可见性、感知/实际进展和对手可回应动作；
5. 分开系统结果、玩家理解、互动与体验证据，只改一个激励关系。

可复用：`decision-trace`、`balance-pass`、`test-plan`、`feedback`、`playtest-selector`。不新增自动计分推荐器。

## 剩余限制与下一步

- BGG 两篇日志目前通过搜索缓存深读，直接页面受 403；资源审阅必须标明 `article_level`，不冒充稳定全文访问；
- Gajadhar 是 2012 年数字 FPS 学位论文，分数由实验员每 30 秒更新；只支持信息/社会语境问题；
- Boggle 实验测外部代金券与短时表现，不是游戏内积分或持续游玩；
- *Sanctuary*、*Point Salad* 和 Reddit 都不是代表性玩家样本；前两者还存在出版方供样；
- 现有材料仍以英文为主，缺中文设计师完整计分迭代日志；
- 尚未获得真实原型的逐事件计分记录，无法验证表单负担；
- 后续需以中文新手、熟练玩家、两人/多人、公开/隐藏版本和至少一种合作作品执行任务式测试。
