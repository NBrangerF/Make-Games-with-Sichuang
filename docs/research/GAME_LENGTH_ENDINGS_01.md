# 游戏时长、节奏、结束条件与拖尾：专项研究 01

更新：2026-08-20  
状态：review；资源、主张、术语、指南与入口已落盘，待中文用户测试

## 结论先行

“这游戏 60 分钟”不是足够的设计描述。至少要拆成四层：

1. **会话口径**：设置、教学、游玩、查询/纠错、结算与收纳从哪里计到哪里；
2. **节奏形状**：建立、转化、加速、停滞和收束分别发生在什么时候；
3. **终局契约**：谁触发、谁看得见、触发后谁还能行动、是否等回合、玩家是否知道这是最后行动；
4. **结束后的能动性**：胜负高度可预测后还有没有目标体验中的决定；投降、退出或淘汰怎样改变同桌其余人的系统。

因此本站不提供“最佳局长”“拖尾分数”或通用结束条件生成器，而提供一张可测试的结束契约。

## 研究范围

本轮集中回答：

- 固定轮数、资源耗尽、玩家竞速触发、公共时钟与混合结束怎样改变玩家行为？
- 等回合与知道最后一回合是否是同一问题？
- 进度可见性为什么既是界面问题，也是节奏机制？
- 首局、熟练局与不同人数的分钟怎样避免错误比较？
- 何时是有价值的收束，何时只是结果已定后的重复执行？
- 投降、单人退出与玩家淘汰如何改变信息、地图、资源和其他人的胜负？

本轮不做市场推荐、最佳人数、可接受等待秒数、普遍投降礼仪或玩家淘汰接受率。

## 发现一：局长首先是测量口径

盒侧“60–90 分钟”常把不同劳动混在一起：

- 开盒与设置；
- 规则教学、例子和首轮指导；
- 玩家思考、等待与实际操作；
- 查询规则、纠错和恢复共享状态；
- 终局计分、解释结果与收纳。

设计日志和玩家长评都显示，经验会同时改变行动效率、风险承担、进度推进和查询，而不只让每回合更快。Drillers 的作者报告熟练玩家通常 10–12 回合推进到结束，新手可能拉到 17–18 回合；这是同一机制因为完成进度不同而改变**轮数**，不是简单的“新手每回合多想几分钟”。该日志没有样本量，数字只能用于发现变量。

最低记录应为：

```text
version / configuration / experience / support
setup_start → ready_to_teach
teach_start → first_independent_decision
play_start → end_trigger → last_action → scoring_complete
rules_lookup / repair events
```

首局、返回玩家和设计者熟练局必须分轨。跨版本或人数只比较起止口径仍相同的字段。

## 发现二：节奏是形状，不是平均速度

相同 90 分钟可能有完全不同的问题：

- 每轮都新增一种有意义的转化；
- 前 60 分钟建立，后 30 分钟形成高潮；
- 中盘开始安全循环，没人愿意推动高风险结束；
- 玩家回合不长，但共享状态频繁变化使回合外预案失效；
- 胜负已定，仍需逐个把资源换成分数；
- 正向反馈让结尾快速加速，或负向反馈让系统长期停滞。

因此记录开局—中盘—终局的阶段事件，优先问：

- 候选行动和目标何时扩大、收缩或重复？
- 玩家何时第一次只是在执行已决定的计划？
- 谁能加速、拖延或隐藏公共时钟？
- 进度信号何时被玩家实际读取？
- 等待时能否保留预案，还是轮到自己才开始决定？

“一轮太长”只是症状。可能的修订分别是删内容、提前进入核心循环、让安全路径推进时钟、降低共享状态波动、移动结算或改变终局激励；不能用同一个加速补丁覆盖。

## 发现三：结束条件是四变量契约

一个可执行终局至少写：

| 变量 | 要问的问题 |
|---|---|
| 触发 | 固定时间、资源耗尽、目标完成、任一玩家行动、共同决定，还是混合条件？ |
| 所有权与可见性 | 谁能推进/拖延？行动前能否看到离结束多远和谁有触发机会？ |
| 触发后行动 | 立即结束、完成当前回合/轮、最后一圈、所有人再一次，还是独立收尾阶段？ |
| 激励与补偿 | 触发者为什么愿意结束？座位、少行动或多行动如何处理？ |

Jaffee 的框架指出两个常被混淆的变量：

- **等回合**：每位玩家总行动次数是否相等；
- **最后行动确定性**：玩家在作决定时是否知道这次或下一次是最后行动。

“完成当前轮”可以做到等回合，却仍让轮首玩家无法知道自己的跨回合投资是否有回报。反过来，所有人都明确再行动一次也可能让不同座位获得不同总回合数。两者都不是自动公平，需要按作品的计划长度、信息责任和座位结构验证。

## 发现四：进度可见性会改变行为

Drillers 的结束轨道经历四种方案：

1. 统计全桌卖出的矿物：能运行，但难追踪；
2. 数玩家获得地块上的点：仍需反复重数他人状态；
3. 用地块实体尺寸填轨：直观，却允许玩家只建牌组、不拿高价值深层地块而拖长游戏；
4. 让地块与矿物从两端共同填轨：同时覆盖两种行为，并让进度一眼可见。

这个案例说明，可见性不是只加一个进度条：**轨道统计什么，就奖励和约束什么行为**。

Djinn 的日志则从另一方向展示：多个结束途径让部分玩家感到突然，最终改为所有人都能看到剩余数量的单一 Boss Djinn 触发，再给 1–2 次收尾行动。它证明一套项目迭代如何处理意外与计划收束，不证明所有游戏都应完全公开或使用单一触发。

隐藏终局可以是作品承诺。产品问题不是“是否完全可见”，而是玩家在承担风险前拥有哪些信号，以及意外发生后有没有仍然有意义的行动或修复。

## 发现五：拖尾需要两个独立观察

不能只问“第几轮大家知道谁会赢”。至少要同时记录：

1. **结果确信**：每位玩家当时认为冠军、失败或排名已确定到什么程度，以及依据是什么；
2. **剩余决定价值**：之后是否还有策略、表达、学习、排名、叙事或完成承诺中的价值。

四种常见组合：

| 结果确信 | 剩余决定 | 诊断方向 |
|---|---|---|
| 低 | 高 | 正常未决阶段 |
| 高 | 高 | 可能是有效收束、次级目标或完成表达 |
| 低 | 低 | 可能是随机揭晓前的纯维护或等待 |
| 高 | 低 | 强拖尾候选；检查提前结算、加速或正式认输 |

这张表是本站诊断框架，不是经过验证的评分器。竞技排名、锦标赛资格和完整叙事可能让冠军已定后仍有明确目标；这些价值必须写出来，而不是用“有悬念”或“没悬念”代替。

## 发现六：投降、退出与淘汰不是同一件事

- **两人认输**：双方同意时通常没有第三方状态，但仍可能影响比赛积分、学习或复盘；
- **整桌提前结束**：需要决定是否承认当前结果、是否结算排名、隐藏信息何时公开；
- **多人局单人退出**：可能改变邻接、地图空位、资源供给、攻击目标、谈判与其他人的获胜机会；
- **玩家淘汰**：游戏继续，但该玩家永久或暂时失去能动性，可能仍需旁观、保密、答疑或等待下一小局。

Rogerson 等的三页扩展摘要把实体桌游淘汰与数字 permadeath 区分开：同桌玩家可能被迫继续见证过程，并承担信息义务。它也提醒短轮淘汰后快速回桌，与长局永久出局不是同一个体验。由于方法细节有限，本站只用它建立观察字段。

玩家社区讨论进一步暴露多人退出的系统后果，但不能决定礼仪。产品应提前写：

```text
who_may_propose
consent_rule
state_after_exit
hidden_information
remaining_social_duties
rejoin_or_table_stop
result_and_recording
```

退出协议不能替代修复长局，也不能以“社交契约”强迫不适、疲劳或紧急离桌者继续。

## 形成的八条主张

1. 局长必须说明测量区间和群体语境；
2. 终局是触发、可见性、剩余行动与结算的契约；
3. 等回合与最后行动确定性不同；
4. 进度可见性会改变节奏行为；
5. 节奏是阶段形状，不是平均分钟；
6. 拖尾要分开结果确信与剩余决定价值；
7. 投降、退出与淘汰需要状态和同意协议；
8. 首局与熟练局时长需要分轨。

主张已写入 `content/claims.json`，均保留反例与证据类型。

## 明确不做

- 不用平均分钟生成节奏分或质量判断；
- 不把更短自动称为更好，也不把长局自动称为深度；
- 不把设计者熟练局当新手盒侧时长；
- 不把等回合自动称为公平；
- 不把结果可预测自动等同于应强制结束；
- 不把投降、玩家淘汰或提前结束当无代价补丁；
- 不从商业成功日志推导普遍参数；
- 没有真实记录前不新增时长预测器或终局生成器。
