# 新手路径完成度审计 01：从模糊点子到第一条可测试假设

状态：implemented-audit  
日期：2026-08-21

## 审计问题

第一次进入网站、只有模糊题材或感觉的新手，能否从首页完成一条可保存、可导出、能被后续原型反驳的体验意图，而不是只读完一篇文章？

## 证据盘点

| 路径位置 | 现有证据 | 审计结果 |
|---|---|---|
| 首页卡点 | “我只有一个模糊的点子”会选择体验意图阶段 | 有入口 |
| 核心指南 | 5 步把动作、压力、行为、边界和测试问题连起来 | 有解释 |
| 指南练习 | “四句体验意图”有示例产出 | 有纸面练习 |
| 工具 CTA | `guide-experience-intent.toolIds` 原为 `[]` | 缺少可填写产物 |
| 项目护照 | 保存 `experienceIntent`，但只是一段自由文本 | 有结果字段，没有形成过程或反驳门 |
| 下一阶段 | 核心系统、原型范围和测试计划均已有工具 | 下游存在，首段断裂 |

六篇核心指南中，体验意图是唯一没有任何 `toolIds` 的阶段。信息架构自 2026-08-13 已把“体验目标卡”列为首个工具，但实现顺序先完成了测试、反馈、原型、主题、生产与发布等下游工具。因此本轮选择补第一阶段，而不是增加第 32 篇专题或更多资源。

## 现有研究怎样约束工具

- Kathleen Mercury 的课程把实际游玩、机制、主题、原型、反馈和规则连成学习路径；它支持从具体动作进入，而不是从机制百科选择“正确答案”。单项教学材料许可仍需另审。
- MDA 支持把设计规则、运行动态与玩家体验分开；工具因此记录“系统怎样让后果可见”，而不把设计者想要的情绪当成已经发生。
- Elizabeth Hargrave 与 Timothée Decroix 的设计回顾分别展示主题兴趣和媒介/触感问题怎样成为起点；工具允许题材、机制、触感或问题任一入口。
- James Ernest 的访谈强调目标玩家、时长与复杂度会决定反馈是否仍指向同一款游戏；工具因此先写玩家语境，并强制一项本轮非目标。
- 本地《狗头人》笔记 K01–K03 强调整体、动机与体验目标；网站将“动机”改写为可观察行为，不声称读取玩家深层心理。
- 现有 Claim 明确：体验意图用于判断反馈边界；主题与机制可以双向开始；情绪可由触觉、限制、协作与信息结构承载，但不同玩家语境可能产生不同反应。

## 设计决定

新增 `experience-intent` 正式工具，并让核心指南第一顺位直达。它不做以下事情：

- 不生成乐趣、策略性、沉浸或“体验命中率”分数；
- 不从年龄、身份、游戏经历生成玩家画像或偏好；
- 不推荐最佳机制，也不把 A/B 二选一当成所有决定的标准形式；
- 不把设计者预测改写成玩家实际感受；
- 不证明使用工作单会改善设计能力。

## 最小形成链

```mermaid
flowchart LR
  A["题材 / 机制 / 触感 / 问题"] --> B["玩家与语境"]
  B --> C["重复决定与不同后果"]
  C --> D["压力与可见反馈"]
  D --> E["桌面行为预测"]
  E --> F["反驳信号"]
  F --> G["本轮非目标与测试问题"]
  G --> H["核心系统 / 原型范围 / 测试计划"]
```

只有 B–G 全部完成才能保存记录。编译出的体验假设是阅读辅助，不覆盖用户原字段，也不是自动结论。

## 仍待验证

1. 新手是否会把“压力”误写成剧情冲突，而不是实际代价；
2. 是否能区分预测、测试问题和成功标准；
3. “反驳信号”是否被误解为失败或必须删掉游戏；
4. 玩家语境字段是否诱发刻板画像；
5. 五步切换是否比单页八字段更易完成；
6. 375px 下步骤局部滚动、摘要下移和清空确认是否可发现。

这些问题由配套形成性测试处理；结构守卫与构建不能回答。
