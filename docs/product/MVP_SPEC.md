# MVP 产品规格

状态：implementation-ready  
日期：2026-08-13

## 首个可用切片

MVP 不是完整资源库，而是验证核心承诺的一条闭环：

1. 用户选择当前卡点；
2. 界面给出该阶段的下一步与一个核心原则；
3. 用户查看经过解释的资源；
4. 用户填写并保存一次测试计划；
5. 数据保存在本地，可导出 JSON。

## 主屏功能

- 顶部导航切换设计路径、资源库、工具箱、方法；
- 六阶段路径轨道可选；
- 四个常见卡点切换选中状态和下一步说明；
- 当前项目卡显示版本和主问题；
- “记录一次测试”打开测试计划面板；
- 每场测试限定一个主问题，其他好奇进入停车区；同时记录预测/反驳、观察协议、参与者/配置、主持边界、测试类型与媒介盲点；
- 保存到浏览器本地存储；
- 导出当前项目与测试记录为 JSON；
- 资源库最少展示 8 条已研究资源，可按阶段筛选并显示证据类型/限制。

## 内容约束

- 不生成“游戏评分”或自动解决方案；
- 将观察事实、体验反馈、建议和设计决定分开；
- 线上测试必须提示触感、空间、身体动作和细微社交线索可能缺失；
- 资源卡不按“权威分”排序，显示来源类型、为何有用与限制；
- 数据 local-first，不需账号。

## 非本轮范围

- 登录、云同步、多人协作；
- 全文搜索与爬虫更新；
- 卡牌排版、虚拟桌面或自动平衡；
- 发布/众筹完整流程；
- 用户公开投稿与审核后台。

## 验收场景

1. 新手能在 30 秒内选出“规则很多但没有玩过”，看到“裁出今天能上桌的原型”。
2. 用户能创建包含来源版本、一个主问题、预测/反驳、观察事件、参与/主持条件、测试类型、媒介与结论规则的测试计划。
3. 选择线上媒介时出现具体盲点提醒。
4. 刷新后测试计划仍在；导出 JSON 含 schema_version。
5. 键盘可完成导航、选择卡点、打开/填写/关闭测试面板。
6. 375px 宽度无横向溢出，项目面板移到主列表下方。

## 2026-08-21 可分享导航扩展

四个主视图与十九项正式工具使用规范 hash：`#path`、`#resources`、`#method` 与 `#tools/<tool-id>`；全站页脚另提供 `#privacy` 数据与隐私入口。主导航是带 `aria-current` 的真实链接；指南直达与工具标签写入浏览历史，刷新恢复当前工具，未知地址安全回到路径或默认工具。每个路由更新页面标题，并提供指向 `#main-content` 的跳过链接。URL 不携带项目、表单、参与者或筛选数据；local-first 隐私边界不变。详细契约见 [可分享 URL 导航契约](SHAREABLE_URL_NAVIGATION.md)。

同日方法深链增量把 5 个理论框架、32 篇专题指南、287 个概念和 574 份资源审阅接入 `#method/<section>/<item-id>`，合计 898 个可分享条目；`#method/frameworks/<id>` 是框架的显式地址，而无条目的框架分区规范化为 `#method`。筛选导致当前条目不可见时替换当前历史项，不保存检索词。四个内容分片的按需加载保持不变。详细契约见[方法分区与条目深链](METHOD_DEEP_LINKS.md)。

概念行动增量使用已有 `guideIds`、`conceptIds` 和 `toolIds` 生成反向索引：287 个词条全部可进入正式工具，276 个还能进入实际引用它们的专题；核心/专题指南末尾也能返回同一规范词条。关系不计算相关度或质量排序，`test-plan` 抽屉不会被伪装成无效深链。详细契约见[概念—专题—工具双向交接](CONCEPT_ACTION_HANDOFF.md)。

## 2026-08-21 中文新手测试战役扩展

章程验收不再由分散协议或内部走查推断。统一战役先用 2–3 人诊断、修复阻断，再用 5–7 名新用户确认；全部确认参与者完成阶段定位与资源边界，至少 4 人完成意图、循环、原型范围、单问题计划、主持演练记录、刷新与项目包导出。`task_help` 后的完成不计独立成功，虚构演练不计游戏外部证据，虚构 JSON 不计参与者。详见[中文新手首轮可用性测试战役](BEGINNER_USABILITY_CAMPAIGN.md)。

## 2026-08-21 公开试用发布准备扩展

新增 `#privacy` 与全站页脚，明确 localStorage、导出、外部链接、托管日志和二次前缀清理边界；未配置真实托管方、联系人和试用模式的构建会直接显示“不可公开招募”。Vite base、试用期 `noindex`、静态主机/Vercel 安全头、缓存、严格环境门与回滚已形成平台无关发布包。它没有创建外部部署，也没有把 `noindex` 当作访问控制；详见[公开试用发布契约](PUBLIC_TRIAL_RELEASE.md)。

## 2026-08-21 键盘与语义硬门扩展

skip link 现在保留当前 hash 路由并显式聚焦唯一页面 main；工具工作区不再嵌套主地标。构建加入 18 项语义退化守卫，但自动门不等于键盘或屏幕阅读器通过。公开试用前必须执行 K1–K8 与 S1–S8，尤其是抽屉焦点圈定/恢复和中文状态播报；详见[键盘、语义与屏幕阅读器硬门](ACCESSIBILITY_HARD_GATE.md)。

## 2026-08-18 连续性扩展

原静态“当前项目”已替换为本地项目护照。用户可编辑项目名、体验意图、版本、阶段、当前问题和下一步，保存带变化摘要的版本节点；测试计划继承当前项目版本。首页汇总 18 类本地工具记录，并可导出项目护照、版本节点与全部记录。第 18 类为现场测试会话记录；它嵌入测试计划快照，但不静默修改来源计划，也不从事件次数生成严重度、因果或通过结论。

2026-08-21 测试计划 v2 增量：原型范围可在完整校验后继续到抽屉，但来源仍需用户显式导入。测试历史继续使用现有 `test_plans` 类别，不增加同义项目记录类别；独立导出拒绝乐趣分、样本代表性、因果证明、发行认证和静默范围推断。

2026-08-21 现场会话增量：完整测试计划可显式“保存并开始主持”，相同计划复用最近快照；新会话记录进入 `playtest_sessions`。开场同意、局中事件、局后回答和下一版决定分层保存，撤回只删除本站本地会话并提醒另行处理外部录音/副本。

2026-08-21 证据复盘增量：既有 `feedback` 工具升级为 schema v2 的证据复盘与变更简报。它只承接已完成会话，要求用户人工选择原事件/局后回答，先写发现、适用条件、反证和缺失，再决定保护、修改、继续调查、暂存或不改；“修改”还要求至少两个候选方案、保持项、拒绝方案、单一变化轴、回退信号和下一问题。保存不会更新项目，只有显式“复制为项目下一步”才写回；旧数组迁移不会伪造缺失来源。

该扩展仍遵守 local-first 和免账号范围，但首版只维护一个活动项目。旧工具记录没有 `project_id`，因此完整导出前必须提示用户确认记录归属；记录数量不得表述为进度或质量。详细契约见 [本地项目护照与完整导出](PROJECT_WORKSPACE.md)。

## 2026-08-18 资源发现扩展

资源库默认不再直接倾倒 294 条列表，而是提供十三个任务型策展入口，每个入口连接 4–8 条已审阅资源并显示自己的证据边界。第五个入口把玩家的“拖、乱、没参与感、规则难找”转译为带语境的可观察问题；第六个入口把有目的游玩转成自身体验、桌面行为、系统关系、他人语境和迁移假设；第七个入口按想产出原型、建立诊断词汇、比较从业者观点或查找机制来选学习主线；第八个入口先区分词汇参考、随机约束、诊断反思、协作脚手架、闭环练习和原型组件；第九个入口从抵达、设置、读取、操作、决定、沟通、查询到退出选择一个无障碍任务，并分开协助与关系代价；第十个入口把战役、Legacy、永久状态、缺席接续和版本迁移连接到四条历史护照；第十一个入口先写单人承诺并映射互动接口，再比较计分、场景、dummy、自动对手和多手控制；第十二个入口把人数、队伍、角色、模式和座位写成配置，再比较互动拓扑、总行动、密度、功能性 dummy 与同步重构；第十三个入口把会话计时、节奏形状、终局触发与可见性、最后一轮、拖尾、投降和淘汰连接成结束契约。用户也可查看全部资源，并组合设计阶段、受众层级、使用方式、语言、访问方式和关键词。结果行直接显示阅读深度、“最适合”和“不要用来”；零结果说明是筛选交集为空并提供恢复入口。详细契约见 [资源发现、筛选与策展入口](RESOURCE_DISCOVERY.md)。设计辅助闭环仍处于[产品规格](DESIGN_AID_PRACTICE_LOOP.md)和任务测试阶段，不列入已完成工具。

## 2026-08-19 贡献协议准备

“用户公开投稿与审核后台”仍不在 MVP 范围。本轮只增加离线贡献包、数据模型与机器守卫，用于验证未来征集玩家经验、设计日志和案例时需要的参与、保存、公开、许可、署名、撤回和安全保障字段。模板默认 `review_only`、不引用、不使用媒体、不选择 CC，也不允许把儿童或高风险资料直接升级为发布候选；没有新增网络表单、账号、上传、联系人数据库或正式第十三项工具。详见[玩家经验与设计案例贡献包](CONTRIBUTION_PACKAGE.md)。
