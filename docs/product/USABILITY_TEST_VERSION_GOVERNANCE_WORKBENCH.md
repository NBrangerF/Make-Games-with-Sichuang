# 新手可用性测试：内容版本治理工作台

状态：ready / not run  
日期：2026-08-21

## 要验证的判断

用户能否在不把证据状态当质量分的前提下，识别一个旧版内容单元、限定一个完整兼容配置、找到当前事实源、区分三个治理日期，并给旧版持有者写出可执行迁移。

## 参与者

4–6 人：至少 2 名第一次维护扩展或勘误的新手、1 名持有旧印次或多扩展的玩家、1 名做过规则编辑/翻译/社群答疑的人。至少安排一种大字、放大、卡架、键盘输入或代读支持条件。不得以医学诊断替代任务观察。

## 材料

- 一张印刷文字已过时的卡或玩家辅助；
- 一份旧印次基础版、一个扩展和当前规则/FAQ；
- 一个故意保持未知的组合；
- 工作台空草稿；
- [可用性测试记录模板](usability-session-template.json)。

## 任务

### T1：认出内容

建立内容护照，录入稳定 ID、印刷文字、当前文字和稀有度五字段。追问：“哪个字段说明它常不常出现？哪个字段说明怎么拿到？”

观察：是否把稀有度当单一强度等级；是否能从实体材料找到稳定身份；长文字输入是否造成遗漏。

### T2：限定兼容配置

新增两行配置：一行有正式声明但未实测，一行已经用指定任务验证。让参与者选择证据状态并写定位。

观察：是否把“声明支持”误选为“已验证”；是否漏写印次、模式、语言；是否认为一行能代表全部扩展组合。

### T3：指定当前事实源

录入旧规则书、当前 FAQ 和补充数据库，并把事实源从旧规则书切换到 FAQ。

观察：是否发现“当前”自动保持唯一；是否理解历史来源仍被保留；能否在摘要中找到当前来源。

### T4：排治理日期

给出三个不同日期，要求分别填入公告、生效和复查，并写一个回退门。

观察：是否把公告日当立即生效；回退门是否是可观察信号，而不是“情况不好”；键盘和日期输入是否可用。

### T5：写回归与迁移

为旧版持有者写有效配置、回归任务、反驳信号、迁移材料和实际动作。

观察：迁移是否停在“查看公告”；是否考虑打印、替换、套牌、查询恢复与协助代价；回归任务是否仍只验证一个断点。

### T6：保存、恢复与导出

保存记录，刷新后恢复；导出治理包；触发一次清空草稿但在确认前停止，再确认清空并检查已保存记录是否保留。最后从项目护照导出完整项目包。

观察：是否知道草稿与快照不同；是否看到“不代表兼容性认证”；完整项目包是否包含 `version_governance_records`。

## 主持规则

- 不解释“正确状态”，只问参与者当前依据是什么。
- 不把完成时间当质量分；记录第一次猜测、回退、外部协助、未读提示和字段误解。
- 若参与者真实持有旧版，只使用其愿意展示的材料；不要上传或复制购买凭证、个人账号和私密社群记录。
- 代读者不得替参与者选择兼容状态、回退门或迁移动作。

## 形成性通过门

- 5/6 任务中至少 4/6 参与者无需主持人定义即可完成；
- 没有人把“声明支持”稳定误读为“已验证”，或把导出包当认证；
- 所有人能说出公告日与生效日的区别；
- 清空草稿没有误删已保存记录；
- 键盘、375px、至少一种支持条件下没有阻断任务；
- 失败模式形成具体界面或文案修订，而不是计算参与者总分。

通过门只允许说“这些任务在该样本中可完成”，不允许声称工具改善了扩展质量、平衡、购买价值、规则理解或无障碍。
