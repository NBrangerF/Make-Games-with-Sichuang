# 主包与工具加载边界

日期：2026-08-21  
状态：implemented / production build verified / browser intent pending

## 问题

方法与资源数据已按意图分片，但主 JS 仍为 506.47 kB（gzip 154.85）。`App.tsx` 的静态面分析显示，一组只在工具箱选中后才使用的早期工具仍全部进入主包。其中最大的静态消费者是“生产假设账本”，源码函数约 14.5 kB；默认设计路径和默认工具都不需要它。

## 决定

1. 将生产假设账本移入独立 `production-ledger-tool.tsx`，通过 React `lazy` 只在选中该工具时消费。
2. 工具按钮在鼠标悬停和键盘聚焦时对等预取，直接深链打开时立即加载。
3. Suspense fallback 使用真实工具名与 `role=status`，不用空白面板伪装完成。
4. 生产记录的 storage key 移到共享 `storage-keys.ts`；独立工具和主包中的项目导出使用同一 key。
5. 保留原有无价格预测、无制造报价、无合规意见导出字段和本地保存格式。

2026-08-21 后续复核：资源入口深链与六阶段交接使主 JS 变为 491.82 kB（gzip 151.52），比本契约拆分后快照增加 1.28 kB（gzip 0.40），仍低于 500 kB。入口 runtime 为 6.83 kB，34 个入口包与 803.83 kB 完整目录的独立边界仍保持。

## 守卫

`pnpm qa:main-boundaries` 的 12 项守卫检查：

- 工具实现不再内嵌主包；
- 动态导入、React lazy 与辅助技术加载状态；
- 鼠标/键盘预取对等；
- 安全导出字段和本地读写；
- 共享 storage key 与完整项目包汇总；
- 守卫已进入 `content:check`。

## 证据边界

生产构建能证明代码分片和产物大小，不能证明真实用户在弱网、移动网络或辅助技术中感知到改善。浏览器 QA 已增加“意图前未请求、打开后已请求”断言，但本地端口 `EPERM` 使该断言尚未实跑。
