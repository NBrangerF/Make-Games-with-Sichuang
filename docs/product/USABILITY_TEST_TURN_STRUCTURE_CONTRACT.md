# “回合结构与等待契约”新手任务式测试

更新：2026-08-20  
状态：draft；待首轮中文用户测试

## 目的

验证一名没有读过本站研究报告的新手，能否用专题指南和一页模板完成以下真实任务：

1. 找出一个回合窗口中的决定、行动、回应、锁定与交接所有者；
2. 不把行动经济简化为行动点数量；
3. 不把所有非主动时间合成一个 downtime 数；
4. 在删维护或改同步前写出要保留的功能；
5. 只选择一项结构改动，并给出可否定的测试信号。

本测试不评价用户的原型是否“好玩”，也不要求找出最佳回合结构。

## 参与者与材料

- 首轮：4–6 名中文新手设计者；至少 2 名有自己原型，至少 1 名只玩过但未设计过桌游；
- 后续：熟练设计者、混合经验组、至少一名使用不同感官/注意/操作支持的参与者；
- 一份最多三轮的纸面原型或预写案例；
- `special-turn-structure-contract` 页面；
- [回合结构与等待契约](../guides/TURN_STRUCTURE_CONTRACT.md)；
- 计时器、屏幕/桌面录像（需同意）、观察记录纸。

## 固定案例（参与者没有自己的原型时）

> 四人港口游戏。顺时针行动，每回合先从市场买货，再做两次航行/交货/贷款，最后补一张市场牌。任何玩家交货后，其他三人按座位可各打一次拦截牌；没有牌也要口头通过。前一玩家需把船标记交给下一位。测试中常发生：玩家在别人回合计划，但市场被买空；补牌被漏；五个反应窗口无人使用；下一位常在 5–15 秒后才发现轮到自己。

## 主任务

### 任务 A：画一个窗口

提示只说：

> “选择从玩家决定交货到下一位开始行动的这一段，填出谁看、谁决定、谁能回应、何时锁定、谁结算和怎样交接。”

成功动作：

- 至少写出主动玩家、潜在回应者和下一位；
- 交货提交/锁定、回应通过、结算和船标记交接可辨认；
- 不用“所有人参与”代替具体权限。

观察：第一处遗漏、是否能从指南找到修复、是否误把执行者当决定者。

### 任务 B：展开行动经济

提示：

> “只看‘两次行动’这句话还漏掉什么？请补完整。”

成功动作：

- 写出贷款的机会成本和收入后果；
- 把买货、补牌、反应、通过或交接放到槽位外但仍记其成本；
- 至少提出一次行动粒度问题，而非直接加减行动点。

失败信号：只抄动作菜单；把免费动作写成无成本；没有跨窗口资源或维护。

### 任务 C：分解一次等待

给出一段时间线：

```text
00:00 甲开始回合
00:18 丙写下港口 A/B 两个预案
00:43 乙买走市场关键货物，丙的 A 失效
01:12 甲交货；三人依次说无响应
01:31 甲结算完但忘记传标记
01:43 丙发现轮到自己
02:02 丙提交行动
```

成功动作：

- 分开钟表等待、决定开始、预案存活/失效、反应监看、交接和重新扫描；
- 不从“丙有写预案”直接推出其体验良好；
- 至少提出一个需向丙确认的体验问题。

### 任务 D：判断维护功能

要求参与者分别处理“每回合补一张市场牌”和“共同翻开新港口事件”。

成功动作：

- 给两项写状态、信息、纠错、决定或共同注意功能；
- 允许得出不同处理方案；
- 不因都叫维护而一起删掉或自动化。

### 任务 E：只改一项

参与者从以下任选一项：

- 无响应牌者自动通过并显示资格；
- 四人同时锁定买货意向；
- 补市场集中到整轮结束；
- 交货与航行合并成一项行动；
- 用明显标记和口令完成交接。

成功动作：

- 写唯一改动；
- 写预计降低的具体成本；
- 写必须保留的功能和至少一个新增风险；
- 写一个会让自己否定方案的观察。

## 记录表

| 指标 | 记录方式 |
|---|---|
| 首次偏离 | 第一个漏掉、误解或无法继续的字段 |
| 恢复入口 | 页面标题、示例、术语链接、模板提示或主持人 |
| 完成时间 | A–E 分段，不合成质量分 |
| 主持人介入 | 原话、时点、介入后是否能继续 |
| 权限正确性 | 是否区分观察、决定、操作、回应、确认 |
| 行动经济范围 | 是否超出行动点与动作菜单 |
| 等待分解 | 六类中能独立记录几类及遗漏原因 |
| 维护判断 | 是否先写功能再选处理 |
| 可否定性 | 改动是否有明确反驳信号 |
| 主观负担 | 哪一字段最难、最重复、最像术语考试 |

不要合成单一“回合设计能力分”。

## 访谈问题

1. 你刚才认为“等待”最先指哪一种时间？完成后是否改变？
2. 哪个字段让你第一次发现“免费动作”仍有成本？
3. 你在哪里分不清决定者、执行者和确认者？
4. 哪项维护你最想删？写功能后是否改变判断？
5. 如果把案例改成合作或实时游戏，哪一部分最先失效？
6. 哪个示例过于复杂、暗示了答案，或与你的项目无关？

## 通过门槛（首轮形成性）

- 4/5 参与者无需主持人解释即可完成任务 A；
- 4/5 能在任务 B 写出至少一种槽位外成本；
- 4/5 能在任务 C 分开至少四类等待，且包含预案存活或交接之一；
- 4/5 在任务 D 先写功能再决定删除/保留；
- 4/5 的任务 E 含一个可观察反驳信号；
- 没有字段被多数人理解为“数值越低越好”或“同步必然更好”。

未达门槛时，先修页面命名、示例和字段顺序；不要据此改参与者的原型。

## 证据边界

该脚本只验证指南和模板能否帮助中文新手描述并设计下一轮测试，不验证模板能改善局长、乐趣、互动、平衡或可访问性。固定案例是教学构造，不是产品证据。首轮人数小，只用于发现理解和操作故障；结论必须绑定页面版本、参与者经验、所用案例和主持人介入。
