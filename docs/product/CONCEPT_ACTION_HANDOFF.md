# 概念—专题—工具双向交接契约

状态：implemented / browser-pending / newcomer-pending  
日期：2026-08-21

## 要关闭的断点

概念词表原先能解释词义、反例、相关概念、核心路径与来源，但“在哪条路径会用到”只是不可操作的文字。指南末尾的概念也只是标签。新手理解一个词后仍要重新搜索专题和工具，读指南时也不能回到同一份规范定义。

本增量把三类已有关系接成双向路径：

```text
核心/专题指南中的概念
          ↓
#method/glossary/<concept-id>
          ↓
相关专题 #method/guides/<guide-id>
正式工具 #tools/<tool-id>
```

## 唯一关系来源

不在界面中另写推荐清单。`content/concept-action-index.json` 由以下权威字段机械生成：

- `content/glossary.json`：每个词条的 `guideIds`；
- `content/guides.json`：六篇核心指南的 `toolIds`；
- `content/special-guides.json`：32 篇专题的 `conceptIds` 与 `toolIds`。

生成规则：

1. 反向读取每篇专题的 `conceptIds`，得到概念实际出现在哪些专题；
2. 对词条声明的核心指南和反向关联的专题，各取第一个具有可分享地址的正式工具；
3. `test-plan` 目前是抽屉而非正式 hash 页面，因此跳过它并选择该指南后续第一个正式工具；绝不生成无效的 `#tools/test-plan`；
4. 按核心指南、专题内容顺序去重，不计算相关度、质量分或推荐排序；
5. 没有专题关系时保持空列表，不凭关键词猜测关系。

运行 `pnpm concept-actions:index` 重建；`node scripts/generate-concept-action-index.mjs --check` 和 `pnpm qa:concept-actions` 会拒绝过期或被杜撰的索引。

## 界面行为

概念详情新增“把概念带回设计”：

- “在专题里看它怎么用”只显示真实引用该概念的专题；
- “带去一个工作单”打开具有规范地址的正式工具；
- 每个入口使用真实 `<a href>`，复制地址、浏览器菜单和无脚本地址语义仍成立；
- 应用内点击写入浏览历史，后退可回到原概念地址；
- 关系说明明确它们不是自动推荐、质量排名或固定流程。

核心指南和专题指南末尾的概念标签也改为真实词条链接。应用内点击保留当前工具上下文；直接复制的地址使用安全默认工具，但词条目的地不变。

## 加载与包体边界

行动索引与 `glossary.json` 同属 `glossary-catalog` 动态分片。首页、设计路径、资源库、工具箱和方法默认框架不会加载它。概念到专题的点击才加载完整专题分片；仅查看概念不会提前下载 32 篇长指南。

索引原始 JSON 约 80 KB；生产构建应记录压缩后的实际分片变化。原始字节数不能替代网络请求时序验证。

## 证据边界

- “显式关系完整”不等于“教学顺序正确”；
- 一个概念出现在多篇专题中，不表示它更重要；
- 工具入口来自指南声明的首个可分享动作，不表示这是所有项目的最佳下一步；
- 自动守卫不证明新手理解链接标签、能预测落点或能在返回后维持任务上下文；
- 真实浏览器、键盘、屏幕阅读器和真人新手任务仍是发布前硬门。

## 机器验证

`pnpm qa:concept-actions` 当前覆盖 12 项：

1. 权威目录数量；
2. 每个概念恰有一条索引记录；
3. 专题概念外键；
4. 反向专题关系完整且无杜撰；
5. 工具关系完全可由指南字段复算；
6. 每个概念至少有一个可分享正式工具；
7. 专题引用与深链；
8. 非推荐边界与生成规则；
9. 行动索引仍在词表动态分片内；
10. 概念到专题/工具为真实链接；
11. 核心/专题指南能返回概念深链；
12. 浏览器回归脚本包含双向、工具与后退断言。

浏览器脚本中存在断言不等于该脚本已在当前环境执行成功。
