## 0. 这份手册做出的决定

V3 不把网站装饰成某一款桌游。它把桌游最有价值的界面经验转成网站规则：状态留在动作附近、位置承担意义、规则按使用时机分层、组件帮助防错、颜色之外还有形状与文字。

网站的视觉隐喻是“一张正在使用的开放桌面”：

- 资源首页像摊开的行动与参考板。
- 资源条目像可以直接拿起阅读的资料记录。
- 完整长文像规则书加就近玩家辅助。
- 分析方法像可查询的索引，不像软件后台。
- 配套工具像有输入、处理和产出的个人工作区。

这不是产品改名。“开放桌面”只是设计系统的内部名称。

### 0.1 规范优先级

不同类型的决定使用不同真源，发生冲突时先判断它属于哪一类：

1. 已接受的信息架构、路由契约与冻结界面文案：产品行为真源
2. 本手册：视觉语义、组件使用条件与页面模板真源
3. `tabletop-visual-tokens-v3.json`：视觉令牌数值的机器真源
4. 静态界面样板：手册的非规范示例
5. 图像风格板：材质与氛围参考

样板只能解释手册，不能自行增加首页行动、改变品牌、覆盖路由或替换冻结文案。发现冲突时先修低优先级文件，不能把样板中的变化反向当成产品决定。

### 0.2 探索 dial 与生产预算

风格板探索时使用 `6 / 3 / 5`，以便明确测试视觉边界。它不是生产页面的目标值。正式实现按模板预算做减法：

| 模板 | Variance | Motion | Density |
| --- | ---: | ---: | ---: |
| 首页、学习入口、分析入口 | 3 | 1 | 3 |
| 主题、阅读、方法 | 4 | 1 至 2 | 4 |
| 配套工作单 | 5 | 2 | 5 上限 |
| 系统页 | 2 至 3 | 1 | 3 |

全站生产上限为 `5 / 2 / 5`。更深的页面可以承载更多信息，但不能用更高动画或更多装饰补偿结构问题。

### 0.3 成功的视觉印象

读者应当感到：

- 我知道从哪里开始。
- 我可以先做一小步，也能继续深入。
- 这是认真整理过的中文资料，不是课程销售页。
- 工具是资料的一部分，不是突然跳进另一个产品。
- 页面有桌游的结构感和触感，但没有借用任何游戏的品牌外观。

### 0.4 明确不做什么

- 不做游戏商店、社区门户、成就系统或 SaaS 仪表盘。
- 不使用骰子、meeple、棋盘格、木纹桌面或散落组件作为泛化装饰。
- 不做卡片墙、徽章墙、胶囊标签墙和功能货架。
- 不复制经典游戏的地图、插画、卡框、图标、组件剪影、规则文案或整体 trade dress。
- 不按“小学生、成年人、高级玩家”给读者贴身份标签。
- 不为制造移动端简洁而隐藏关键说明或完整资料。

## 1. 读者与产品原则

### 1.1 读者跨度

本站可能被小学生、青少年、成人初学者、教师和有经验的设计师共同使用。视觉系统不尝试用一套“低龄风”服务所有人，而是用按需脚手架服务不同阅读需要。

每一项重要内容提供三种深度，但不必每页都显示三个开关：

1. `先做一步`：一句任务、一个主行动、一个可见产出。
2. `先看例子`：用完整例子展示怎样做。
3. `理解原理`：保留准确术语、完整正文、来源和证据边界。

这三层是内容顺序与按需展开规则，不实现成三个全站模式、三张并列卡片或用户身份开关。

### 1.2 四条产品原则

1. 资源站优先：资源入口始终比功能入口更显眼。
2. 一页一个主要决定：页面可以信息丰富，但首屏不能要求同时做多个决定。
3. 脚手架按需要出现：不按年龄或经验猜测用户能力。
4. 完整内容不离站：中文正文、来源说明和上下文工具都在站内完成。

### 1.3 保留当前 foundation

V3 必须保留以下已经验证的产品契约：

- 顶栏只有 `找资料` 与 `方法与概念` 两个一级入口。
- 资源首页仍从学习、分析、正在解决的问题三个入口开始。
- 学习方式、分析问题和具体设计阶段仍是逐层选择，不回到大目录首屏。
- 工具只在相关资料、学习单元或分析问题附近出现。
- 完整中文资料可以站内直接阅读，阅读中途没有强制外跳。
- `#path`、`#tools/<id>` 和已有资源深链继续兼容。
- 返回操作应回到确切来源，不只是回到资源首页。

### 1.4 需要重构的对象

| 优先级 | 对象 | 当前问题 | V3 决定 |
| --- | --- | --- | --- |
| P0 | 完整阅读 | 超长页面缺少章节定位，治理信息早于正文，页面角色与入口页相同。 | 新建 `ReadingShell`，标题与收益先出现，桌面章节轨，移动目录，来源说明就近但不抢首屏。 |
| P0 | 语境工具 | 双标题、横向步骤轨、边框密集，像另一个产品。 | 新建 `GuidedToolShell`，真实工具名直接做 H1，产出先行，纵向短步骤，来源返回永久可见。 |
| P1 | 方法详情 | 左侧大目录加右侧文章，移动端出现嵌套滚动。 | 改成搜索或问题入口，少量结果，再进入单一正文。 |
| P1 | 全部资料 | 默认筛选、计数、胶囊和结果墙，重新提高首屏负担。 | 定义为进阶查找，默认搜索加推荐，筛选二次展开。 |
| P2 | 学习集合 | 当前单元、完整路线、来源译文同时出现，像多套课程。 | 明确分成“现在开始”“继续选择”“原作者资料”三个区段。 |
| P3 | 四个入口型页面 | 当前结构清楚。 | 冻结信息量，换用 V3 令牌、形状和排版，不增加功能。 |

## 2. 品牌方向

### 2.1 核心概念：开放桌面

开放桌面由三个对象组成：

- `规则书`：负责完整、准确、可持续查阅。
- `玩家辅助板`：负责把当前最需要的信息放在手边。
- `组件托盘`：负责分组、排序、防错和保留状态。

三者共同建立桌游气质，不需要任何具象桌游美术。

### 2.2 品牌性格

| 性格 | 应该如何表现 | 不应如何表现 |
| --- | --- | --- |
| 好奇 | 用问题开启页面，用例子引导观察。 | 用夸张吉祥物或神秘化术语制造兴趣。 |
| 严谨 | 标出来源、译文、边界和版本。 | 把所有信息都做成学术论文式密文。 |
| 慷慨 | 明说读者会得到什么，提供足够上下文。 | 用“了解更多”“立即探索”等空洞动作。 |
| 平静 | 留白、稳定位置、少量动作色。 | 持续动画、闪烁提示、大面积高饱和色。 |
| 可动手 | 每篇资料就近提供一个可完成的小行动。 | 把十九个工具并排陈列。 |

### 2.3 语气词

推荐：清楚、具体、耐心、开放、可验证。  
避免：炫酷、沉浸、史诗、颠覆、全能、一站式、零门槛。

## 3. 从经典桌游研究到原创视觉原语

本节把[经典桌游视觉与信息设计研究](../research/CLASSIC_BOARD_GAME_VISUAL_REFERENCE_2026-08-23.md)转成 V3 可执行的设计约束。研究案例只用于说明灵感来源和功能问题，不提供可复用素材，也不授权复制原作表达。

这里所说的“可用”是本站采取的保守设计政策，不是法律意见，也不是对任何具体使用作出的权利结论。每次实施仍需检查最终组合是否过度接近原作。

### 3.1 抽象迁移方法

每一项研究只能按以下顺序进入设计系统：

1. 记录官方材料中可观察到的信息问题，例如如何显示当前步骤、如何把高频规则放在手边。
2. 用不含游戏名称、角色、主题、组件数量和独特外观的句子写出通用规则。
3. 使用“开放桌面”的颜色、比例、字体、线条和语义重新设计原创表达。
4. 把表达映射到既有语义组件，不因为一个案例新增装饰性组件家族。
5. 逐项检查商标、版权、整体外观、硬件实现与素材许可边界。

来源名称只出现在研究记录、设计决策与必要案例说明中。正式界面组件名、CSS 类名、图形资产名和可见主题名使用中性功能词，不使用第三方游戏名称。

### 3.2 来源到规则、原语与组件的映射

下表中的“允许表达”都必须使用本站令牌重新绘制。“禁用边界”同时约束单个元素和元素组合，不能把多个通用元素按原作的标志性比例与位置重新拼回去。

| 灵感来源 | 官方材料中可观察的问题 | 抽象后的规则 | V3 原语、规则与组件映射 | 允许表达 | 禁用边界 |
| --- | --- | --- | --- | --- | --- |
| Ticket to Ride | 公共关系、目标端点和已完成路线需要同时可见。 | 关系视图只显示起点、终点、连接和当前所处位置。 | `RelationPath`，用于 `ChapterRail` 与局部学习关系。 | 原创直线或折线、文字端点、本站圆点与动作色。 | 不使用真实或虚构地图轮廓、城市布局、列车、车票、原路线组合与品牌色。 |
| Pandemic | 全局风险、当前任务、个人能力和高频动作分布在不同信息层。 | 把全局背景、当前任务与就近速查分开，当前动作附近重复最短必要说明。 | `ContextAid`，用于 `PageIntro`、阅读速查和工具当前步骤。 | 一句当前任务、短边界、进入完整资料的文字动作。 | 不使用世界地图、疾病符号、角色卡结构、原规则文字与整套颜色体系。 |
| Carcassonne | 能否连接由边缘关系判断，较难规则延后加入。 | 连接必须有明确对位提示，非当前任务所需复杂度按需展开。 | `AlignmentCue` 与 `LayeredDisclosure`，用于相关资源、来源关系和进阶说明。 | 1px 关系线、2px 对位短线、文字关系名、原生 `details`。 | 不绘制地块、道路、城堡、田野边缘、棋子方向、计分关系与原组件数量。 |
| Azul | 输入、暂存、转化、产出和无法容纳的内容各有固定位置。 | 工作区按认知顺序排列，并为待处理与不能继续的内容提供明确归属。 | `ProcessLane` 与 `OverflowNotice`，作为 `GuidedToolShell` 的内部语法。 | 纵向步骤区、当前步骤摘要、字段旁错误、可恢复草稿。 | 不使用瓷砖纹样、玩家板网格、原色组、行列数量、工厂布局与计分槽。 |
| Splendor | 累计影响需要持续露出，每回合只执行一个主要动作。 | 累计结果在当前决定附近持续可见，同一视区只有一个主行动。 | `PersistentSummary` 与 `PrimaryActionRule`，用于工具摘要和保存流程。 | 简短定义列表、当前产出、单一实心按钮。 | 不使用宝石、卡牌等级、叠牌露边、贵族、市场排布、原数值与图标。 |
| Codenames | 共享信息与主持信息分层，完成内容被覆盖而不是删除。 | 不同可见范围必须有文字边界，完成痕迹保留并可复核。 | `VisibilityBoundary` 与 `StateTrace`，用于主持工具、已读记录和历史状态。 | 具名区域、完成文字、时间或版本记录、轻边线。 | 不使用词网格、秘密控制卡、5×5 比例、身份颜色、角色命名和覆盖牌外观。 |
| 7 Wonders | 类别由颜色与符号共同表达，规则、效果、依赖和记录按查询任务拆开。 | 颜色必须有第二编码，同一规范内容可以按不同查询任务提供入口。 | `DimensionMark`、`SourceDisclosure` 与 `InlineTerm`。 | 首页专用几何形状加完整文字、独立来源与术语入口。 | 不使用原符号、原颜色对应、卡框、连锁图、计分纸、插画和数值。 |
| Wingspan | 第一次使用有引导流程，高可读版本与标准版本保持机制一致。 | 先让读者完成一次真实操作；可读性变体必须共享同一内容数据。 | `FirstMoveExample` 与阅读排版变体，落在 `ReadingShell` 和工具示例。 | 一步可完成的原创例子、更大字号、更高对比、减少非必要装饰。 | 不复制鸟牌框架、插画、图标、首局脚本、栖息地布局与组件外观。 |
| Root | 带着做、概念教学、精确规则、阵营速查和数据库共享同一规范来源。 | 复杂知识只有一个规范源，再按任务提供不同深度入口。 | `CanonicalContent`，由 `ReadingShell`、`InlineTerm`、方法搜索与速查共同读取。 | 同一中文内容源的摘要、例子、全文和词条视图。 | 不使用阵营、动物美术、阶段名、阵营板、规则原文和卡牌数据库外观。 |
| Turing Machine | 对位组件可以直接检查输入，防错与单一输出靠结构完成。 | 验证应发生在当前步骤，明确指出缺口和下一步，不能只在提交后报错。 | `ValidationGate` 与 `AlignmentCue`，用于工具字段组、保存前检查和产出确认。 | 原创文字检查、边线对位、缺失项列表和一个明确结果。 | 不复制打孔算法、孔位、验证数据、题库、遮挡板或独特硬件实现。 |
| MicroMacro: Crime City | 稳定总览承载大量关系，连续问题逐步控制观察范围。 | 保留可回到的总览，同时一次只提出一个具体观察问题。 | `QuestionLens` 与局部 `RelationPath`，用于方法入口、分析步骤和长文导读。 | 白话问题、局部关系摘要、当前问题与返回总览动作。 | 不使用城市地图、人物、案件、线索、叙事、观看任务与原线描风格。 |

Ahoy 的玩家辅助与易用性设计日志作为 `ContextAid` 的补充证据，只支持“高频信息就近、通过真人任务验证辅助材料”的通用规则，不提供任何视觉素材或组件外观。

表中的命名分成三类，实施时不能把它们都误做成新组件：

- `PrimaryActionRule` 是交互规则，要求同一视区只有一个实心主行动。
- `CanonicalContent` 是内容架构规则，要求摘要、例子、全文与词条读取同一规范中文内容源。
- `FirstMoveExample` 是内容脚手架，使用现有 `ReadingShell`、`ContextAid` 或 `GuidedToolShell` 承载，不建立独立视觉外观。

其余具名表达是下列视觉与信息原语，默认作为既有组件的 anatomy 或 variant。

### 3.3 V3 可复用视觉原语登记

视觉原语是组件内部的最小语义表达，不等于必须新增一个 React 组件。相近表达优先作为既有组件的 anatomy 或 variant，避免把设计系统重新做成工具货架。

| 原语 | 负责什么 | 原创表达规则 | 映射到的组件 | 不能怎样使用 |
| --- | --- | --- | --- | --- |
| `DimensionMark` 维度标记 | 为首页三个顶层入口提供颜色之外的冗余编码。 | 28 至 32px 的方形、圆形或六边形，加完整文字；形状为装饰时使用 `aria-hidden`。 | `TaskChoiceRow` 的首页可选槽。 | 不延伸到学习子入口、资源类型、方法分类或工具步骤。 |
| `SectionTray` 分区托盘 | 用稳定位置说明哪些内容属于同一组。 | 留白、组标题和 1px 线构成开放分区，不画盒底、把手或立体边缘。 | 资源列表、来源列表、方法结果组。 | 不做白色卡片墙、立体收纳盒或拟物塑料托盘。 |
| `RelationPath` 关系路径 | 表达少量起点、终点与当前关系。 | 使用 `rule` 线、`connectionDotPx` 圆点和文字端点；关系必须能用一句话读懂。 | `ChapterRail`、局部学习关系、相关资料连接。 | 不在首页制造路线图，不用装饰性网络，不复制任何地图或标志性节点布局。 |
| `AlignmentCue` 对位提示 | 表达两块内容属于同一来源、步骤或输入输出关系。 | 2px 短线、共用基线或相同文字标签；响应式重排后语义仍成立。 | `ResourceRecord` 相关项、`SourceDisclosure`、工具字段组。 | 不模仿地块边缘、打孔卡、拼图接缝或物理卡槽。 |
| `ContextAid` 就近辅助 | 把当前动作最需要的信息留在动作附近。 | 一个短标题、一至三句说明和一个进入完整资料的动作。 | `PageIntro`、`ContextAction`、`InlineTerm`、工具当前步骤。 | 不重复整篇规则，不长期占据第三栏，不显示无关推荐。 |
| `StateTrace` 状态痕迹 | 让当前、完成、排除和待处理可以复核。 | 2px 状态边线、明确状态文字、版本或时间信息；颜色只是辅助。 | `ResourceRecord` 状态、`ChapterRail` 当前章节、工具保存与历史。 | 不用覆盖牌、翻面动画、身份色或只靠透明度表达。 |
| `LayeredDisclosure` 分层展开 | 按使用时机展示例子、原理、全文与来源。 | 内容顺序优先，必要时使用原生 `details`；所有层读取同一规范内容源。 | `ReadingShell`、方法正文、`SourceDisclosure`、进阶字段。 | 不建立年龄模式，不复制多份正文，不把关键说明藏在 hover。 |
| `QuestionLens` 问题镜头 | 把广泛主题缩成一次可执行观察。 | 一次一个白话问题，紧跟观察对象、期望产出与换问题动作。 | 分析入口、方法搜索、阅读导语。 | 不做测验评分，不连续弹问，不借用案件卡或谜题叙事。 |
| `ProcessLane` 过程区 | 固定输入、整理、决定、产出与边界的认知顺序。 | 纵向区段、当前步骤文字和就近摘要；移动端保持同一阅读顺序。 | `GuidedToolShell`。 | 不使用横向步骤轨、玩家板网格、资源槽或拖放拟物。 |
| `PersistentSummary` 持续摘要 | 让累计输入和当前产出不必反复寻找。 | 桌面可在右侧显示短摘要，移动端放在当前步骤之后；只显示本任务数据。 | `GuidedToolShell` 的摘要区。 | 不变成常驻仪表盘、跨工具统计、分数或成就。 |
| `OverflowNotice` 边界归属 | 说明哪些输入尚未处理、无法继续或需要移回当前步骤。 | 在相关字段之后显示具名状态、原因、保留结果与恢复动作；与字段保持同一阅读流。 | `GuidedToolShell`、`Notice`、字段错误区。 | 不复制玩家板溢出轨、扣分槽、资源格或只靠红色表达。 |
| `VisibilityBoundary` 可见范围边界 | 区分共享、个人、主持或尚未公开的信息。 | 区域开头写明谁能看见、何时公开和当前状态；程序语义与可见文字一致。 | 主持工具区、`Notice`、历史记录。 | 不使用秘密控制卡、身份色、遮挡牌或仅靠模糊与透明度隐藏。 |
| `ValidationGate` 防错门 | 在错误发生处说明缺口、保留内容并给下一步。 | 字段关联错误、缺失项列表、保存状态与可恢复动作。 | 工具表单、`Notice`、完成确认。 | 不复制物理验证器，不用神秘红灯，不自动声称设计正确。 |

这些原语优先复用现有 `color`、`border`、`graphic`、`spacePx` 与 `motionMs` 令牌。本节没有引入新的裸色、阴影、圆角、组件比例或动画时长，因此当前 token JSON 不需要新增值。

### 3.4 五类页面的具体落点

| 页面 | 当前唯一决定 | 使用的原语 | 组件落点 | 硬边界 |
| --- | --- | --- | --- | --- |
| 首页 | 从学习、分析或正在解决的问题中选择一个入口。 | `DimensionMark`、`SectionTray`。 | 三个 `TaskChoiceRow` 组成一列开放列表，形状只作冗余编码，搜索全部资料保持次级文字入口。 | 不增加路线图、资源预览、统计、hero CTA、卡片市场或步骤编号。 |

### 3.5 保守复用与拒绝门

每个受经典桌游启发的新组件、图形或布局必须在设计评审中回答以下问题：

1. 灵感来源是否记录到研究文件，并能指出观察到的是功能问题而不是“看起来很像”？
2. 抽象规则能否在不提游戏名称、主题、角色、组件和独特比例的情况下完整说明？
3. 最终表达是否只使用本站颜色、字体、线条、比例、命名和交互？
4. 是否避开原作的地图、插画、卡框、规则文字、图标、组件轮廓、数量关系和标志性组合？
5. 多个通用元素组合后，是否重新形成了可识别的原作整体外观？
6. 是否存在第三方截图、扫描、裁切、描摹、热链、取色或未登记素材？
7. 如果案例说明必须展示第三方图像，是否已有单独、可验证的权利依据和完整资产记录？
8. 若涉及 Turing Machine 一类独特硬件或功能实现，是否已停止在视觉类比层，没有复制结构或工作方式？

出现以下任一情况即拒绝进入样板或正式构建：

- 删除产品名称后，评审者仍主要靠布局、配色或组件组合认出某款游戏。
- 需要借助原作截图、规则图、卡牌、地图或图标才能让界面成立。
- 使用第三方品牌名称、标志或外观为本站建立来源识别。
- 只有“内部、非营利、教育”这一理由，没有可验证的素材权利依据。
- 无法判断抽象方法与具体表达的边界，且尚未完成进一步权利核验。

通过本门只表示符合本站的保守设计政策，不表示取得授权或完成法律判断。

## 4. 标志与图形语法

### 4.1 基础形状

V3 只在资源首页的三个顶层维度使用三种基础形状：

| 含义 | 形状 | 辅助色 | 必须同时出现的文字 |
| --- | --- | --- | --- |
| 学习 | 方形 | `dimensionMoss` | `学习` 或完整入口名 |
| 分析 | 圆形 | `dimensionBlue` | `分析` 或完整入口名 |
| 解决问题 | 六边形 | `dimensionTerracotta` | `解决问题` 或完整入口名 |

形状是颜色之外的冗余编码，不是新的图标语言。不能单独放一个形状让读者猜测含义。学习方式、分析问题、资源条目与工具步骤默认不继续使用这套形状，避免读者在每一层重新学习编码。

当前状态不使用圆形，避免与“分析”混淆。它统一使用 2px 动作色边线、文字 `当前` 与程序化状态。`TaskChoiceRow` 的形状槽是资源首页专用的可选属性。

### 4.2 线与连接点

- 1px 实线：同一组内容的普通分隔。
- 2px 实线：当前章节或当前行动。
- 点线：可选关系或尚未完成的连接，不能表示不可用。
- 小圆点：只作为关系图中的连接点，不能表示页面当前状态，也不能用于装饰性散落。
- 对位短线：提示两块内容属于同一来源或流程。

### 4.3 品牌记号

站点标记使用原创的“开放桌面”几何构成：两个错位矩形像摊开的纸页，中间留出一条可通过的路径。第一版只用 CSS 或内联 SVG 绘制，不使用任何棋子、骰子或知名组件轮廓。

标记不能替代文字品牌名。移动端仍显示完整中文名称或经过用户验证的短名称。

### 4.4 编号规则

- `01 / 02 / 03` 只用于必须依次完成的步骤、章节或版本。
- 任意选择入口不使用数字序号，改用形状与明确文字。
- 如果一个列表既能任选又有推荐顺序，先写 `任选一项`，再用 `建议从这里开始` 标出一项。

## 6. 字体与排版

### 6.1 字体角色

V3 使用两种声音，不再让宋体、楷体、Georgia 和系统字体按组件各自生长。

1. UI 与正文：`Noto Sans CJK SC / Source Han Sans SC / PingFang SC / Microsoft YaHei / system-ui`。
2. 编辑标题与长文标题：`Noto Serif CJK SC / Source Han Serif SC / STSong / SimSun`。

实施时优先自托管经过许可登记的中文字体子集。引入前必须核验许可、常用与生僻中文字形覆盖、文件体积，以及实际存在的 `400 / 600 / 700` weight；不依赖浏览器合成 `650`。字体尚未进入资产清单前使用系统回退，不从第三方 CDN 加载。楷体不再承担重要信息，只允许作为极少量、短于 12 个汉字的装饰批注，并必须有普通正文等价内容。

### 6.2 排版角色

| 角色 | 桌面 | 移动 | 行高 | 字体 |
| --- | --- | --- | --- | --- |
| Display | 56 至 72px | 44 至 52px | 1.08 | Serif |
| H1 | 44 至 56px | 36 至 44px | 1.14 | Serif |
| H2 | 30 至 38px | 28 至 32px | 1.24 | Serif |
| H3 | 22 至 26px | 21 至 24px | 1.35 | Sans 或 Serif，按模板固定 |
| 正文 | 17px | 16 至 17px | 1.75 | Sans |

| 小字 | 15px | 14 至 15px | 1.6 | Sans |
| 标签 | 15px | 14 至 15px | 1.4 | Sans 600 |

### 6.3 中文排版规则

- 阅读正文一行目标约 32 至 42 个汉字，最大宽度 720px。
- H1 不强制单行，移动端长标题允许自然换行，但首屏必须仍能看到导语开头。
- 段落间距至少 0.9em，不能只依赖首行缩进分段。
- 中文与英文、数字之间由浏览器自然排版，不手工插入大量空格。
- 使用全角中文标点；界面文案不使用长破折号。
- 表单控件使用 `font: inherit`。
- 重要信息字号不得低于 16px；元信息不得低于 14px。

## 7. 空间、网格与表面

### 7.1 间距序列

只使用：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96px`。光学校正值必须在代码旁登记原因。

### 7.2 内容宽度

| 模板 | 最大宽度 |
| --- | ---: |
| 决策入口 | 1120px |
| 资源详情 | 960px |
| 完整阅读壳 | 1040px |
| 阅读正文 | 720px |
| 索引加详情 | 1240px |
| 配套工具 | 1080px |

### 7.3 表面

- 页面使用 `canvas`，正文与输入只在需要区分时使用 `surface`。
- `surface` 与 `canvas` 的明度差不足以单独承担分组。输入区与重要表面必须同时拥有可感知的 `ruleStrong` 边线、标题或明确空间关系。
- 默认无阴影、无渐变。
- 普通分组用留白和 1px 线，不反复制造白色卡片。
- 圆角只有 `0 / 4 / 6px`。关系连接点使用 `50%`，且只用于等宽高元素；当前状态不使用圆形，也不允许胶囊标签。

- 投影只允许在真正覆盖页面的 dialog 上使用。

### 7.4 桌面不是拟物桌面

组件托盘、切线和纸页是结构比喻，不做真实木盒、塑料高光、厚重阴影、翻页音效或拖动组件的强拟物。触感来自细微纸纹、边线、比例和留白。

## 8. 全站结构

### 8.1 顶栏

可见品牌冻结为 `桌游设计工坊`。`开放桌面 Open Table` 只出现在设计手册、样板说明和版本记录中，不替换产品品牌。

桌面：中文品牌左对齐，两个一级入口居中或右侧成组，`仅限内部学习` 保留为低调状态。  
移动：中文品牌与内部状态在第一行，两个一级入口在第二行等宽排列；每个目标至少 44px 高。几何品牌记号在 480px 以下隐藏，不能挤掉中文品牌或内部状态。

当前页面同时使用：

- `aria-current="page"`
- 2px 下边线
- 字重变化

不能只改变颜色。

`#tools/<id>` 与隐藏兼容页 `#path` 不属于两个一级栏目，允许两个导航项都没有 `aria-current="page"`。自动测试必须把这种“无当前一级项”视为正确状态。

顶栏不新增设计路径、工具、收藏、登录或搜索图标。全站搜索只出现在明确的进阶查找入口。

### 8.2 页面头部

标准顺序：

1. 可选返回入口
2. 一行眉题
3. 唯一 H1
4. 一句说明“这一页能帮你做什么”
5. 可选紧凑来源或内容状态
6. 页面主行动

完整阅读页不能在 H1 之前堆叠译者、许可和治理信息。

### 8.3 页尾

页尾继续保留内部学习范围与数据和隐私。内容版本、关于与反馈方式只是预留槽位，不能由视觉重构自动新增。页尾不是第二个导航区，也不列出全部工具或栏目。

### 8.4 hash 路由参数契约

当前应用已经使用 `location.hash` 作为主路由，章节锚点不能再用第二个裸 `#chapter` 覆盖它。V3 冻结以下形式：

```text
#resources/learn/<contentId>?section=<stableSectionId>
#tools/<toolId>?from=<encodedAllowlistedAppRoute>
```

规则：

- `section` 是内容仓库中显式保存的稳定 ID，译文小修不能自动重写。
- `from` 只保存经过序列化和 URL 编码的站内允许路由，不接受协议、域名、脚本或任意外部地址。
- 允许来源至少覆盖资源主题、学习单元、分析问题与方法正文；具体 allowlist 在路由模块中维护。
- 旧的无参数深链继续有效。
- 章节链接、工具进入、返回、刷新、浏览器前进后退与复制链接全部进入 DOM 和浏览器 QA。
- 参数无效时使用安全默认页并显示可恢复说明，不能直接把未经验证的值写入 `location`。

## 9. 七种页面模板

### 9.1 模板 A：资源首页

唯一问题：`你今天想从哪里开始？`

- 首屏主行动只有三条任务选择，搜索为次级文字入口。

### 9.2 模板 B：学习方式与分析入口

唯一问题分别是“你想怎样开始学”和“你想从哪个问题分析”。

学习方式固定为四个入口：

1. 系统性学习
2. 看设计师怎样思考
3. 边玩边学
4. 从一个小练习开始

游戏分析固定先从五个白话问题进入：

1. 为什么会产生这种体验？
2. 玩家真正做了什么决定？
3. 玩家之间怎样互相影响？
4. 游戏怎样随时间和状态运行？
5. 玩家怎样看见、学会并执行？

形式化框架与进阶术语在读者选定问题后出现，不与五个普通问题争夺首屏。

- 继续使用开放选择行。
- 每项先写完成后的产出，再写方法名。
- 对术语提供短解释，例如“形式化分析：用固定维度记录游戏怎样运作”。
- 可以标出一个“建议从这里开始”，但不隐藏其他入口。
- 任选菜单使用形状或短标签，不用步骤数字。

### 9.3 模板 C：资源主题页

一个主题页从上到下只有四段：

1. 当前问题和一句边界
2. `先从这里开始`，最多三份资料
3. `换一种做法`，展示同阶段的不同 approach
4. `做一小步`，只出现与当前主题相关的工作单

资源条目不是卡片。每条包含：

- 中文标题
- 一句“它能帮你完成什么”
- 资料类型与可选的篇幅或内容形式
- 中文完整度状态
- 来源或作者
- 站内阅读动作

每组前三份之后保留次级入口 `查看本主题全部资料`，保证完整资源仍可找到。篇幅只使用 `短 / 中 / 长` 或页数、章节数等可验证信息；不默认给跨年龄读者相同的分钟估算。

### 9.4 模板 D：完整阅读

桌面宽屏布局：

```text
184px 章节轨  |  40px 间隔  |  720px 阅读正文
```

`>=1180px` 使用上述两栏；960 至 1179px 使用约 152px 章节轨、32px 间隔与 660 至 720px 正文；小于 960px 变为单栏，章节轨成为标题后的原生 `details`。速查与相关行动进入导语后或对应小节末尾，不设置第三栏。正文始终完整存在于同一路由。

规则：

- H1 与“这篇能帮你做什么”先于治理信息。
- 目录显示章节名与当前章节，不显示虚假的百分比。
- 每个 H2 都有稳定锚点；路由刷新可恢复章节位置。
- 桌面章节轨可粘性定位，但不遮挡焦点。
- 移动端目录不制造第二个滚动容器。
- 表格在窄屏可局部横滚，并显示文字提示“表格可左右移动查看”。
- 相关工具放在真正相关的小节末尾，不在页尾堆叠工具货架。
- 来源、翻译方式、许可和内部范围保留完整记录，默认位于导语之后的一行展开入口与文末详细区。
- 主阅读动作永远是站内正文。来源记录默认显示可选择、可复制的原始地址；如果保留外部打开动作，必须是明确标注的次级操作，不能代替站内内容。

### 9.5 模板 E：方法与概念

方法首页保留三个任务入口：解决一个具体任务、理解一种分析方法、查一个设计词。

详情页采用“先问或搜索，再读一个结果”：

```text
我想理解： [搜索或选择一个问题]

建议先看
1 个主要结果

其他可能相关
最多 7 个普通结果

选中结果的完整正文
```

- 默认不显示 32 篇专题或 287 个词条的完整内嵌目录。
- 桌面可使用索引加详情两栏，移动端必须顺序浏览。
- 任何列表都不设置独立的 330px 固定高度滚动区。
- 搜索结果标题稳定，页面 H1 不随每次输入改变。

### 9.6 模板 F：配套工作单

工具真实名称直接作为 H1，不再先显示“这一步的练习工具”。H1 下面固定写：

- `做完会得到`：一个具体成品
- `来自`：进入工具的资源或单元
- `预计`：完成时间或步骤数
- `返回`：精确来源

工作区使用纵向顺序：输入 → 整理 → 决定 → 产出 → 边界。桌面可以在右侧持续显示短摘要，移动端则把当前摘要放在当前步骤下方，不推到整张表单末尾。

规则：

- 一次只突出一个主行动。
- 步骤用文字显示“第 2 步，共 4 步”，不依赖横向步骤轨。
- 保存状态明确写“已保存到此设备”或“尚未保存”。
- 刷新后仍能恢复来源路径，不能只依赖 React 内存状态。
- 高级选项默认折叠，并说明为什么可能需要它。
- 完成页显示成品、下一步和边界，不用庆祝动画或积分。

### 9.7 模板 G：系统页

关于、隐私、版本说明使用简洁阅读模板。它们可以降低品牌图形密度，但必须保留相同顶栏、正文宽度、链接、焦点和页尾规则。

## 10. 核心组件

不要建立万能 `Card`。组件名称应说明其语义。

| 组件 | 什么时候使用 | 必须包含 | 禁止 |
| --- | --- | --- | --- |
| `SiteHeader` | 所有页面 | 品牌、两个一级入口、当前页语义 | 工具、设计路径、图标菜单墙 |
| `PageIntro` | 每个页面头部 | H1、收益说明、可选眉题 | 标题前大段治理文本 |
| `TaskChoiceRow` | 少量互斥入口 | 任务、产出、整行目标；首页可选形状 | 用数字伪装成步骤、嵌套按钮 |
| `ResourceRecord` | 资源清单 | 中文题名、收益、类型、完整度、来源、站内动作 | 缩略图墙、评分、彩色胶囊堆叠 |
| `ChapterRail` | 长文桌面端 | 章节名、当前项、锚点 | 百分比伪进度、移动端嵌套滚动 |
| `ReadingShell` | 完整中文正文 | 内容头、正文、目录、来源、行动 | 780px 以上正文、状态块抢 H1 |
| `ContextAction` | 资料附近的工具入口 | 为什么现在用、做完得到什么、进入动作 | 同时展示多个无关工具 |
| `GuidedToolShell` | 配套工作单 | 来源返回、真实 H1、产出、步骤、保存状态 | 双标题、工具货架、隐藏横向步骤 |
| `SourceDisclosure` | 译文与来源 | 原题、作者、链接、翻译方式、许可、范围 | 只写“来自网络” |
| `InlineTerm` | 首次出现的术语 | 术语、白话解释、可选深入入口 | 把专业词全部替换成不准确说法 |
| `Notice` | 边界、错误、保存 | 明确状态与下一步 | 只换颜色、只放图标 |
| `Disclosure` | 进阶细节 | 原生按钮或 details、明确标题、展开状态 | 用 hover 才能看到 |

每个组件必须记录：使用条件、禁止场景、必填内容、默认/hover/focus/pressed/disabled/loading/empty/error/success 状态、移动行为与可访问名称。

### 10.1 首批组件状态矩阵

| 组件 | Default | Hover | Focus | Current / Selected | Disabled / Loading | Error / Empty |
| --- | --- | --- | --- | --- | --- | --- |
| `SiteHeader` | 两项普通文字导航 | 下划线加深 | 3px 实线环 | 2px 下边线、字重、`aria-current`；工具页可无当前项 | 不适用 | 路由失效仍保留顶栏与返回首页 |
| `TaskChoiceRow` | 标题、产出、整行目标；形状仅首页可选 | 标题下划线，边线加深，不位移 | 整行焦点环 | 若需要推荐，使用文字 `建议从这里开始`，不伪装选中 | 未开放项优先隐藏；若显示，必须解释原因 | 列表为空时说明原因并给一个可执行入口 |
| `ResourceRecord` | 题名、收益、形式、完整度、来源 | 站内阅读动作下划线加深 | 动作获得焦点环 | 已读状态用文字与轻边线，不只换色 | 正文加载中保留题名并写 `正在载入` | 说明缺失的是正文、译文还是来源，并给返回或重试 |
| `ChapterRail` | 章节列表与稳定锚点 | 标题下划线 | 单个章节链接有焦点环 | 2px 左线、文字 `当前章节`、`aria-current="location"` | 不适用 | 无章节时不渲染目录，正文仍完整可读 |
| `GuidedToolShell` | 来源、产出、当前步骤、输入与保存状态 | 仅当前动作变化 | 控件与步骤动作各有可见焦点 | 文字 `第 n 步，共 m 步` 加 2px 边线 | 说明为何不可继续；保存时用 `role="status"` | 错误靠近字段，给下一步；无已有记录不冒充错误 |
| `Disclosure` | 标题与展开状态可知 | 标题下划线 | 触发器焦点环 | `aria-expanded` 与可见指示一致 | 不适用 | 内容缺失时解释并隐藏空触发器 |

Phase 2 开始前，代码中的每个核心组件必须把这张矩阵转成可测试的 props、DOM 与 CSS 状态；未定义状态不能由单个页面临时发明。

## 11. 交互状态

### 11.1 链接

- 正文链接默认有下划线，不能只靠绿色。
- 大型任务行用边线变化、文字下划线或方向标共同提示可操作。
- 访问过的链接可以有次级变化，但不能降低到 4.5:1 以下。

### 11.2 按钮

- 主按钮：`action` 底色，白字，最小 48px 高。
- 次按钮：透明底，2px `action` 边线，最小 44px 高。
- 文字行动：仅用于低风险次级动作，点击区域仍至少 44px 高。
- 同一视区最多一个实心主按钮。

### 11.3 焦点

所有交互元素使用 3px `action` 实线焦点环与 3px offset。焦点必须在 `canvas`、`surface` 和所有状态底色上达到至少 3:1，不能被粘性章节轨或顶栏遮挡。

### 11.4 禁用、加载、错误与保存

- `disabled` 必须解释原因，否则优先隐藏尚不可用的动作。
- 短加载显示文字状态，不滥用骨架屏。
- 错误包含发生位置、原因和下一步，并同时使用文字、边线和错误色。
- 保存反馈使用 `role="status"`；破坏性错误使用适当的 `alert`。
- 成功不使用彩纸、分数或徽章；显示产出与下一步即可。

## 12. 响应式规则

### 12.1 内容断点

| 断点 | 变化 |
| --- | --- |
| 1180px | 长文显示章节轨与正文两栏，速查进入正文流。 |
| 960px | 复杂双栏收拢，长文速查进入正文流。 |
| 720px | 所有主要布局单栏，章节目录改为原生展开区。 |
| 480px | 缩小外边距和标题，两个一级导航仍保持等宽目标。 |

### 12.2 必测视口

- 320×568
- 390×844
- 768×1024
- 1024×768
- 1440×900

### 12.3 移动端硬规则

- 页面级 `scrollWidth` 不得大于 `clientWidth`。
- 不用横向滑轨承载关键步骤或主要导航。
- 不在一个纵向页面里再放固定高度的纵向滚动目录。
- 说明文字不因空间不足而隐藏。
- 所有非行内点击目标至少 44×44 CSS 像素。WCAG 2.2 AA 的最低要求是 24×24 或满足间距例外，本站采用更宽松的 44×44 目标作为跨年龄默认，参考 [Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 与 [Target Size Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)。
- 200% 文本缩放时不得丢失内容或功能；400% 页面缩放与 reflow 是发布硬门；320% 单独文本缩放保留为发现长标题、表单和表格脆弱点的额外压力测试，不能替代 400% reflow。

## 13. 动效

动效只解释状态变化：

- hover、press、focus：120ms
- 选择与当前状态：160ms
- disclosure：200ms
- 页面进入、滚动触发、视差、自动播放、无限循环：禁止
- 元素 hover 不发生位移，不造成文字重排
- `prefers-reduced-motion: reduce` 下关闭非必要动画和 smooth scroll

允许的微动效例子：

- 关系图中被选中的连接点从描边变为实心。
- 展开区的边线从 1px 变为 2px。
- 保存文字从“正在保存”切换到“已保存到此设备”。

## 14. 图片、插画与材质

### 14.1 默认少图

图片只在解释原型、流程、组件关系、案例证据或视觉比较时出现。纯文字资源不需要每条配缩略图。

### 14.2 原创插画方向

- 顶视或正投影，像编辑过的原型记录。
- 抽象几何组件、纸张、切线、托盘与连接点。
- 保留真实纸纤维和轻微边缘质感，不做过度 3D。
- 不烘焙中文 UI 文字进图片。
- 站内界面优先使用 CSS 与 SVG，位图主要用于文章证据和品牌氛围。

### 14.3 V3 样板资产

`design/concepts/tabletop-resource-styleboard-v3.png` 是通过图像生成 skill 创建的原创方向样板。它不含可读文字、品牌名或可识别游戏元素，只定义材质、形状、密度和配色。它不是可直接切片复用的 UI 素材。

### 14.4 资产登记

每个非 CSS 素材必须记录：

```text
文件名
创作者或生成方式
来源
许可
允许范围
是否允许修改
裁切或修改记录
替代文字
获取日期
公开或内部
```

不能热链第三方图片。无法确认许可的素材不进入构建。内部、免费、教育用途不等于自动取得复制许可。

## 15. 中文界面与内容写作

### 15.1 入口写法

每个入口回答三件事：

1. 你现在可以做什么
2. 进去后会得到什么
3. 大约需要什么投入

推荐：`做一个只包含本轮测试内容的原型清单`  
避免：`打开原型范围裁剪器`

### 15.2 动词词典

| 意图 | 固定动词 |
| --- | --- |
| 进入完整正文 | 阅读 |
| 进入一组内容 | 查看 |
| 执行练习 | 开始 |
| 恢复来源 | 返回 |
| 暂时保存 | 保存 |
| 生成本地文件 | 导出 |
| 显示隐藏细节 | 展开 / 收起 |

禁止孤立的“点击这里”“了解更多”“探索”“进入”。

### 15.3 术语脚手架

专业词保留准确中文，在第一次出现时使用：

```text
体验意图
也就是：你希望玩家在这个时刻感到什么、做出什么决定。
```

白话解释不替代术语，进阶读者仍能看到框架原名、来源和限制。

### 15.4 译文状态格式

紧凑行：`完整中文阅读 · Codex AI 主译 · 内部学习`  
展开详情：原题、作者、发布日期、来源链接、许可、翻译方式、完整度、修改记录、内部范围和法律边界。

紧凑行不能挡在 H1 前面。

## 16. 无障碍硬门

V3 继承并扩展现有[无障碍硬门](ACCESSIBILITY_HARD_GATE.md)：

- 每个路由恰好一个 `main` 与一个 H1。
- 有可工作的跳到正文链接。
- SPA 路由后焦点移到新 H1 或主区域并宣布页面变化。
- 标题不跳级。
- 所有功能可用键盘完成。
- 当前页使用 `aria-current`，选择状态使用合适的原生控件或 ARIA。
- 表单标签、说明、错误和控件建立程序化关联。
- dialog 约束焦点，Escape 关闭，关闭后焦点回到触发点。
- 表格具有标题关系，窄屏横滚有文字提示。
- 图形状态有文字或形状冗余。
- 正文至少 4.5:1，非正文与焦点至少 3:1。
- 自动扫描零严重错误，但发布仍需纯键盘与真实屏幕阅读器走查。

## 18. 当前基线与技术债

V2-05 的首层资源体验已经成立，但视觉实现无法继续扩张：

- `src/styles.css` 约 1400 行，只有 5 个 CSS 自定义属性。
- 宋体、楷体、Georgia 与系统字体存在大量按组件硬编码的组合。
- 灰色、边线、字号、宽度与圆角存在多套接近但不一致的值。
- 首页与入口页实际密度约 3，方法详情约 6，工具和全部资料约 7 至 8。
- 受检长文页面高度约 20,775px，包含 85 个段落、58 个 H2/H3 与 7 张表，但没有本地章节导航。
- 当前真实工具页包含 7 个字段、11 个按钮与 5 个 section/aside 区域，移动端工作台本身尚未完成完整浏览器 QA。
- 返回入口与部分次级操作尚未统一到 44px 触控目标。
- 工具来源返回只保存在 React state，刷新会丢失精确来源。

V3 的目标不是把这些页面统一画得更漂亮，而是把已经成立的产品逻辑编码成可复用模板，并让不同页面角色真正可辨认。

## 19. 分阶段迁移

### Phase 0：冻结 V2-05 基线

- 保存首页、学习入口、分析入口、方法入口、资源主题、系统学习集合、长文、真实工具、方法详情和全部资料的桌面与移动截图。
- 记录当前深链、返回、焦点与 DOM 合约。
- 补拍 390 和 320 的真实工具页，不把“工具入口”截图当成“工作台”证据。
- 补拍方法详情与全部资料的 320/390 状态。

完成标准分开记录：自动构建与 DOM 合约通过；V2-05 截图基线可复现；真实键盘走查待签收；Safari/VoiceOver 与 Windows/NVDA 等屏幕阅读器组合待签收。前两项不能被表述成“无障碍通过”。

### Phase 1：令牌化，不改变页面结构

- 建立 tokens、foundations、components、templates 与 responsive 五层 CSS。
- 第一轮保留旧 `--ink / --blue / --red` 别名，记录剩余数量。
- 修复未定义令牌与硬编码字体、颜色、宽度。

完成标准：旧页面无有意义布局回归；新 CSS 不再新增裸色值、任意间距或未登记圆角。

### Phase 2：建立 V3 基础件

- 新建 `SiteHeader`、`PageIntro`、`TaskChoiceRow`、`ResourceRecord` 与所有交互状态。
- 把资源首页、学习入口、分析入口和方法入口迁移到同一基础组件。
- 保留当前入口数量与信息架构。
- 新几何品牌标记启用后，单独验证 320×568 顶栏；标记不能挤掉中文品牌或内部状态。

完成标准：入口页在五个视口无溢出，键盘、焦点、对比度和 200% 缩放通过。

### Phase 3：先重构两个高风险模板

1. `ReadingShell`
2. `GuidedToolShell`

先选择一篇最长正文和 `prototype-scope` 作为纵向切片，验证章节导航、来源状态、精确返回、保存反馈和移动端反馈距离。

完成标准：长文可以稳定定位章节，真实工具在 320/390 无隐藏步骤与多向滚动，刷新后能返回来源。

### Phase 4：重构方法详情与全部资料

- 方法详情改为搜索或问题入口加少量结果。
- 全部资料改为进阶查找，筛选二次展开。
- 取消固定高度目录滚动区、默认胶囊堆叠和结果墙。

完成标准：287 词条不会在移动首屏出现；搜索、空状态与恢复深链通过。

### Phase 5：迁移其余页面与工具

- 依次迁移资源主题、学习集合、设计师案例、十九项工作单和系统页。
- 工具共享同一个外壳与步骤语法，业务字段保留各自定义。

完成标准：每类模板通过 DOM、响应式、键盘和截图验收；不再新增工具专属视觉系统。

### Phase 6：素材治理与强制门禁

- 建立资产登记表并移除不明素材。
- 删除旧令牌别名、废弃工作台样式和不可达视觉模式。
- CI 启用视觉系统、响应式、资产版权和中文文案检查。

完成标准：无未登记例外、无废弃令牌、文档与实现版本一致。

## 20. 自动与人工验收

### 20.1 机器检查

`check-visual-system` 首批检查：

- 令牌文件之外新增的十六进制颜色
- 阴影与渐变
- 未登记圆角
- 外部字体与第三方热链
- 缺少 `focus-visible`
- 缺少 `prefers-reduced-motion`
- 固定尺寸小于 44px 的非行内交互
- 页面级横向溢出
- 禁用的旧导航标签
- 工具页双标题
- 入口菜单误用步骤数字

### 20.2 DOM 合约

每种模板验证：

- 唯一 main 与 H1
- 主行动数量
- 返回路径
- 工具来源上下文
- 内容状态位置
- 章节锚点
- 深链刷新
- loading、empty、error 与 saved 状态

### 20.3 浏览器证据

每次视觉发布至少产出：

- 五个验收视口截图
- 溢出结果
- 200% 文本缩放、400% 页面 reflow 与 320% 文本压力测试结果
- 最长中文标题
- 最宽表格
- 键盘路径记录
- 对比度报告
- reduced-motion 结果
- 深链与来源返回
- 与手册的例外清单

视觉差异检查与 DOM 合约并用。中文字体跨环境会造成像素变化，不能只依赖全页像素比对。

### 20.4 人工任务

至少邀请三类读者各完成同一组任务：

- 低阅读经验用户
- 成人初学者
- 有桌游设计经验的用户

不要询问“喜欢这个设计吗”，而观察他们能否：

1. 在 20 秒内选对入口
2. 说出选择后会得到什么
3. 在长文中找到指定章节
4. 从资料进入工作单并返回原处
5. 区分“先做一步”和“完整资料”

## 21. 手册治理

- 每条规则分为 `必须 / 推荐 / 例外`。本手册未特别标注时均按“必须”执行。
- 例外需要记录：页面、原因、责任人、复查日期和截图。
- 每次视觉变更同步更新版本号、受影响模板、桌面与移动证据。
- 设计手册版本与构建标识同步。首个实施构建建议使用 `resource-v3-01`。
- V2 文件保留为历史基线，不继续追加 V3 规则。
