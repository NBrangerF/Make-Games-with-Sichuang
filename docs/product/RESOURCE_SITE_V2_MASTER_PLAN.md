## 0. 一句话决定

网站默认页不再同时展示阶段、处境、问题、路线、筛选和资源列表。它只问一个问题：

> 你今天想完成什么？

用户只看到三个主入口：

1. 开始学习桌游设计
2. 从设计师角度分析一款游戏
3. 按我正在解决的设计问题找资料

“搜索全部资料”是一个次级文字入口。六阶段、34 个策展入口、574 条资源、32 篇专题、287 个概念和 19 项工具都保留在数据层，但不再同时挤进默认页面。

## 1. 本方案解决的五个问题

1. 第一个入口怎样拆成若干小入口，而不是一条假装适合所有人的线性课程？
2. 怎样建立独立的“分析一款游戏”入口，并让 framework 支持用户，而不是制造新的术语墙？
3. “完整中文资料”到底指什么，怎样避免把导读伪装成全文译本？
4. 怎样在小学生、青少年、成人、新手、教师和已有经验设计者之间提供脚手架，又不增加身份选择和功能开关？
5. 怎样大幅删除 UI，同时保留现有研究、深链和内容资产？

## 2. 已确认的现状

### 2.1 内容基础已经足够，不应继续横向扩张

当前资源发现与索引层规模为：

- 574 条资源
- 34 个任务型资源入口
- 6 个设计阶段
- 32 篇专题指南
- 287 个规范概念
- 5 个理论或形式化框架
- 19 项正式工具
- 6 条三份资料的最短学习路线

这已经是一个很好的内容基础。下一阶段的核心不是继续增加数量，而是建立更少的入口、完整中文正文和明确的内容状态。

与发现目录分开计算，当前核心学习正文的显式白名单共有 **16 个 `authoritativeItems`**：8 个 `original_complete`（系统单元 0–6 共 7 个，另有 1 篇“边玩边学”完整脚手架）、3 篇 `authorized_full_translation` 开放许可完整译文、5 篇 `original_case_synthesis` 设计师案例综合。数量增长只发生在既有二级正文层；首页仍保持三个主入口和一个次级搜索入口，第一入口的四种学习方式也不增加。

### 2.2 当前资源页实际有 7 到 9 层

默认资源页依次出现：

1. 页面标题和导语
2. 六阶段选择
3. “我不知道自己在哪一步”处境帮助
4. 当前阶段问题列表
5. 当前入口的问题、结果和证据边界
6. 三份资料学习路线
7. 搜索与五组筛选
8. 结果数量
9. 7 到 8 条完整资源列表

资源列表里的三份资料又与学习路线重复。移动端只是把列变成单列，并没有减少区块或字段。代码证据见 [App.tsx](../../src/App.tsx) 和 [resource-learning-path-view.tsx](../../src/resource-learning-path-view.tsx)。

### 2.3 当前“中文导读”不是完整资料

[资源优先重构 01](RESOURCE_FIRST_REDESIGN_01.md)已经明确：现有 574 条内容是本站原创中文导读，不是逐段完整翻译。18 份核心路线资料的专项审计进一步确认，目前只有 2 份可进入完整译文候选，16 份仍需要授权、原创替代或权利链澄清。详见 [核心 18 份资料中文全文权利审计 01](../research/CORE_18_TRANSLATION_RIGHTS_AUDIT_01.md)。

## 3. 产品原则

### 3.1 资源站第一

- 主页负责把人送到合适的中文内容，不负责展示网站拥有多少功能。
- 工具只在阅读后确实能帮助完成一个动作时出现。
- 任何互动功能都不能阻挡阅读，不要求登录，不生成设计师分数。

### 3.2 从用户任务开始

[GOV.UK 设计原则](https://www.gov.uk/guidance/government-design-principles)强调从用户需要开始、只做不可再减的核心，并承担让复杂系统变简单的工作。本站采用相同方向：入口使用读者会说的话，不先要求理解项目内部阶段和术语。

### 3.3 一页只做一个决定

- 主页：选择任务。
- 学习入口页：选择学习方式。
- 专题入口页：选择一条起步路线。
- 正文页：阅读和完成一个动作。
- 完整目录页：主动搜索和筛选。

[GOV.UK 界面写作指南](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)建议从更少的内容开始；如果必须解释界面怎样使用，应先修界面。本站不再用越来越多的帮助文案解释越来越复杂的页面。

### 3.4 按需要提供脚手架，不按年龄贴标签

不设置“小学生模式”“成人模式”或“初级设计师模式”。年龄不能可靠说明阅读能力、桌游经验、教学支持和当前任务。

每份内容使用同一套渐进结构：

1. 先看桌面例子
2. 一分钟理解核心关系
3. 阅读完整单元
4. 完成一个小动作
5. 需要时再看术语、来源和进阶材料

### 3.5 完整性和权利状态是发布门，不是装饰标签

核心路线中的每一步都必须有可独立读完的中文内容。导读摘要不能进入核心路线冒充课程。完整译文必须先通过许可、正文覆盖、来源和翻译主体记录门。Codex AI 完整译文可直接成为内部学习主版，不以人工双语复核为前置条件；内部与公开状态仍必须分开。

## 5. 第一入口：开始学习桌游设计

第一步最难，所以不再把它写成单一路线。入口页只问：

> 你想用哪种方式开始？

### 5.1 系统性学习

适合希望知道整体路径、愿意逐步学习的人。课程不是书单，而是一组本站原创完整中文学习单元。

建议课程骨架：

| 单元 | 核心问题 | 必须产出的东西 |
| --- | --- | --- |
| 0 从一个具体问题开始 | 桌游设计为什么不是先写完整规则？ | 一句当前问题 |
| 1 玩家体验与设计意图 | 希望玩家反复经历什么？ | 一句体验意图 |
| 2 决定与核心循环 | 玩家反复做什么选择？ | 一条最小循环 |
| 3 机制、信息与互动 | 规则怎样改变可见信息和他人选择？ | 一条因果关系 |
| 4 最小原型 | 这一轮最少要做什么？ | 一个可玩的切片 |
| 5 单问题测试 | 这一场只回答什么？ | 一个预测和反驳信号 |
| 6 从证据到下一版 | 观察、解释和决定怎样分开？ | 一项单变量改动 |
| 7 规则、教学与查询 | 陌生人怎样开始并恢复？ | 一条任务路径 |
| 8 呈现、生产与发布 | 哪些责任和规格必须冻结？ | 一页责任与规格清单 |

页面默认只显示“下一单元”和一句结果。完整目录可展开，但不在首屏展示九张卡片。

### 5.2 看设计师怎样思考

这个入口不按设计师名气或游戏销量组织，而按真实决定组织：

- 怎样从题材收缩为核心问题
- 为什么删除一个喜欢的机制
- 测试后为什么没有照玩家建议修改
- 怎样处理人数、时长或规则负担
- 生产限制怎样反过来改变设计
- 一次失败判断后来怎样被修正

每个中文案例使用统一结构：

1. 项目和版本语境
2. 当时遇到的问题
3. 设计师考虑过的选项
4. 最终决定
5. 使用了什么证据
6. 后来发生了什么
7. 哪些判断不能直接迁移
8. 读者可以带走的一条关系

优先争取设计师博客、开发日记和访谈的具体文章授权。未获全文授权时，发布本站原创、可独立读完的案例综合，不复制原文结构和长段表达。

### 5.3 边玩边学

适合已经玩过一些游戏，但只能写“好玩或不好玩”的读者。

最短路径：

1. 选一个具体问题
2. 抓住一个具体时刻
3. 分开体验、行为和系统推断
4. 写一个可反驳的迁移关系

这个入口与第二入口共享基础方法，但目的不同：第一入口教会怎样学习，第二入口帮助完成一次具体分析。

### 5.4 从一个小练习开始

适合不想先读完整课程、需要马上动手的人。首批只提供三种练习：

1. 改造一个熟悉游戏的一条规则
2. 画出一次决定的输入、选择、后果和反馈
3. 用纸片做一个只回答一个问题的原型

每个练习控制在一次短会话内，不需要先注册项目，也不自动把结果写入工具箱。

### 5.5 第一入口首批内容门

在重新设计 UI 前，先准备：

- 系统路线的单元 0、1、2
- 3 篇设计师决定案例
- 1 篇《怎样边玩边学设计》
- 3 个小练习
- 每项内容的来源、权利、版本和审阅记录

没有完整中文正文时，只展示“内容准备中”，不能用现有导读占位后宣称入口已完成。

当前进度：内容包 02 已完成系统单元 3“机制、信息与互动”、单元 4“最小原型”、无障碍规则书论文完整译文，以及 Paul Grogan 规则书交接与《New Bedford》生产约束两篇第二批设计师案例综合。内容包 03 又完成单元 5“单问题测试”、单元 6“从证据到下一版”和第一篇“边玩边学”完整脚手架。连同既有内容，系统单元达到 0–6 共 7 个，另有 1 篇“边玩边学”、3 篇完整译文和 5 篇案例；机器契约共登记 16 个 `authoritativeItems`（`8 + 3 + 5`）。两个内容包都只补既有入口下的正文，没有扩张首页或一级入口。三个小练习仍未达到本小节的完成门，因此 WP2 仍是部分完成。

## 6. 第二入口：从设计师角度分析一款游戏

第二入口先问“这一局想弄懂什么”，不先展示框架名称。

新手首屏最多显示五项：

1. 为什么会产生这种体验？
2. 玩家真正做了什么决定？
3. 玩家之间怎样互相影响？
4. 游戏怎样随时间和状态运行？
5. 玩家怎样看见、学会并执行？

形式化与计算比较放入进阶入口。

默认分析流程正好四步：

1. 只选一个问题
2. 抓住一个具体时刻
3. 用一个镜头追关系
4. 写清“观察到、推断、仍不知道、可以带走什么”

第一批只实现体验、决定、互动三组，并复用 MDA、5PM、有目的游玩、决定轨迹简版和互动作用路径。TAG、Ludii 退到进阶；AutoBG 移到 AI 辅助专题。完整研究、内容结构和验收条件见 [从设计师角度分析游戏的资源入口 01](../research/GAME_ANALYSIS_FRAMEWORK_ENTRY_01.md)。

## 7. 第三入口：按正在解决的问题找资料

这个入口承接现有六阶段和 34 个任务入口，服务已经在做游戏的人。六阶段仍是重要的资源组织逻辑，但不再是所有读者进入网站时必须理解的第一层。

入口流程：

1. 选择当前阶段
2. 选择一个具体问题
3. 先读三份起步内容
4. 主动选择时再看该问题的完整资料目录

当前实现已经采用二段式：第一段只选六个设计阶段，第二段只显示所选阶段的具体问题。进入具体主题后只显示 3 份起步内容，不自动展开完整资源目录。

现有深链和按入口加载保持兼容。旧地址不能失效，旧入口如果没有完整中文路线，则显示一份明确的策展缺省页，不自动回退到完整长列表。

## 8. 页面契约与 UI 减法

### 8.1 资源首页

只保留：

```text
H1 桌游设计学习资源站
一句说明

开始学习桌游设计
从设计师角度分析一款游戏
按我正在解决的设计问题找资料

搜索全部资料
```

首页不显示：

- 六阶段网格
- 六项处境帮助
- 当前入口详情
- 三份学习路线
- 搜索框和筛选器
- 结果数量
- 任何资源行
- 框架、专题或工具列表

### 8.2 学习方式页

只显示四条普通文字入口。每条由标题和一句结果组成，不使用等权卡片网格，不显示来源数量、标签或审阅元数据。

### 8.3 专题入口页

只显示：

- 返回资源首页
- 入口标题
- 一句结果说明
- 三份起步内容：中文标题、一句用途、内容状态
- “查看这个主题的全部资料”文字入口

不重复显示阶段、处境、完整筛选和完整目录。

该页面契约已经进入当前实现：具体主题默认限制为 3 份起步内容，完整搜索必须由读者主动进入。内容包 02 的桌面、移动、深链、键盘与站内预览浏览器核验记录在[历史进度快照](../PROGRESS_SNAPSHOT_RESOURCE_V2_2026-08-22.md)；内容包 03 不沿用这份历史构建替代当前证据，其本轮结果单独记录在[内容包 03 进度快照](../PROGRESS_SNAPSHOT_RESOURCE_V2_2026-08-22_CONTENT_03.md)和[交接](../handovers/2026-08-22-resource-v2-content-package-03.md)。

### 8.4 资源正文页

建议顺序：

1. 内容状态和中文标题
2. 一个桌面例子
3. 完整中文正文
4. 一个读完动作
5. 可展开的来源、许可、译者、版本与适用边界

正文页不再把“怎么读、阅读重点、适合谁、不要当成什么、限制、来源”拆成七个同等醒目的区块。重要边界留在正文相应位置，元数据收进文末来源记录。

### 8.5 完整目录页

搜索和筛选只在用户主动进入“搜索全部资料”后加载。保留现有按阶段、用途、语言和访问方式的能力，但第一版先评估是否真的需要五组筛选。默认只显示搜索、阶段和用途，其余放入“更多筛选”。

### 8.6 删除矩阵

| 处理 | 内容 |
| --- | --- |
| 保留 | 资源深链、34 个入口、三份起步资料、来源和许可记录、按需加载 |
| 移出首页 | 六阶段、筛选器、完整列表、证据边界、原题名和审阅元数据 |
| 合并 | “你可能在问”“这组资料会带你”和路线导语，合为一句结果 |
| 移到正文末尾 | 作者、原题名、许可、译者、更新时间、适用与不适用边界 |
| 删除展示 | 六项重复处境入口、路线资料在同页重复出现、路线收录标记 |
| 删除视觉 | 连续嵌套边框、圆形步骤号、每行多枚胶囊标签、装饰性提示 |
| 移到隐私页 | 全站页脚的构建版本 |

这里的删除只删除重复 UI，不删除资源数据、研究、深链或审阅记录。

## 9. “完整中文资料”的产品契约

### 9.1 五种内容状态

| 状态 | 含义 | 是否可进入核心路线 |
| --- | --- | --- |
| 本站原创完整学习单元 | 由本站综合多份来源写成，可独立学习和练习 | 可以 |
| 获授权完整中文译本 | 一份原作的完整翻译，许可、来源版本和审阅已通过 | 可以 |
| 已获许可中文原文 | 原作本来是中文，已取得公共网络转载权 | 可以 |
| 中文导读 | 原创用途说明、限制和简短概述，不替代原文 | 不可以作为核心正文 |
| 待授权或受限 | 尚不能公开正文 | 不可以 |

“本站原创完整学习单元”和“完整中文译本”都可以解决用户的完整学习需求，但二者绝不能使用同一个模糊标签。

### 9.2 完整学习单元结构

每篇至少包含：

1. 读完能完成什么
2. 一个贯穿的桌面例子
3. 核心概念和关系
4. 逐步方法
5. 常见误用和反例
6. 一次小练习
7. 适用与不适用边界
8. 来源、权利和更新时间
9. 下一步入口

它必须自洽，不能要求用户离站才能理解正文。来源 URL 仍保留在文末供核验，但不作为完成学习的必经步骤。

### 9.3 完整译本覆盖门

只有同时满足以下条件，才显示“获授权完整中文译本”：

- 翻译与公共网络传播权有一手证据
- 来源版本和快照已冻结
- 正文标题、段落、表格、脚注、图注和必要附录无静默遗漏
- 第三方图片和引用逐项处理
- 术语与本站词表对齐
- 记录 `translationAuthority`；Codex AI 译文明确使用 `codex_ai_complete`
- 完成来源结构、练习、链接、署名和许可的 Codex 核对
- 记录译者/翻译主体、许可、改动说明和人工复核是否必需
- 不声称人工翻译、人工审定、原作者认可或法律审定
- 有更新、撤回和下架联系人

如正文完整但必要图片权利未解决，不得笼统标为完整译本，应继续以原创学习单元方式发布。

## 10. 中文内容生产流程

### 10.1 权利门

1. 确认权利主体
2. 核对准确许可版本和法域
3. 确认翻译、复制、公共网络传播、下载和商业范围
4. 列出第三方素材排除项
5. 保存证据快照

中国著作权法明确列出翻译权和网络传播权；课堂教学例外不等于可以在公共网站出版发行。法律依据和 18 份资料的逐项处理见 [核心权利审计](../research/CORE_18_TRANSLATION_RIGHTS_AUDIT_01.md)。

### 10.2 来源冻结

- 保存原始 URL、发布日期、抓取日期、版本号和文件哈希
- 记录正文、图片、附件和第三方引用的边界
- 对会持续更新的网页标记 `living_source`

### 10.3 翻译与原创写作

当前版权政策：没有开放许可或明确书面授权的外文来源，不制作、保存或接入全文翻译，内部学习也不作为例外。此类来源只能保留必要事实、链接与本站原创综合；取得许可后再另建版本化译文。

完整译本：

1. 提取完整结构
2. 建立术语表
3. 由 Codex AI 产生完整译文
4. 用 Codex 对来源结构、练习、链接、署名和许可做机器化核对
5. 写入 `codex_ai_complete`、`humanReviewStatus: not_required` 和非人工/非法律审定边界
6. 以 `internal-ready` / `authoritative` 进入内部学习主版
7. 完成无障碍和版式检查

原创学习单元：

1. 冻结一个学习问题
2. 选择至少两类不同语境的来源
3. 写本站自己的结构和例子
4. 区分来源主张、本项目推断和练习建议
5. 检查是否实质替代单一受保护原作
6. 完成内容和权利复核

### 10.4 发布与维护

- 每次发布生成内容版本和变更记录
- 来源更新时做差异比较，不自动覆盖译文
- 许可变化、撤回请求或错误会触发下架门
- 所有正文显示最后复核日期

## 15. 总体验收门

### 信息架构

- 首页最多 3 个主选择和 1 个次级搜索入口。
- 首页只有 1 个 H1 和 1 句说明。
- 首页不加载完整资源目录、筛选器或框架库。
- 从首页到首篇正文最多 3 次操作。
- 原有 34 个入口和资源深链保持可访问。

### 内容

- 核心路线中的每一步都有完整中文正文。
- 100% 正文显示准确内容状态。
- 中文导读不被标为完整资料。
- 每篇原创学习单元都有例子、练习、边界和来源。
- 每篇完整译本有来源版本、覆盖检查、翻译主体、内部/公开范围和不伪造人工或法律审定的记录。

### 权利

- 0 项无授权完整译文。
- 0 项把免费访问误当再发布许可。
- 100% 完整译本有一手许可证据或书面授权。
- 第三方图片、引语和附件有明确排除或许可记录。

### 可用性

- 不解释界面的情况下，至少 80% 参与者能在 30 秒内选择预期入口。
- 参与者能区分“完整译本”“原创学习单元”和“中文导读”。
- 分析入口用户能把观察、推断和未知分开。
- 移动端不出现横向滚动，内容量相对桌面有真实减法。
- 键盘、焦点、语义结构和 WCAG AA 对比度不回退。

### 产品边界

- 不新增账号、社交、排名、课程完成度、游戏质量分或设计师等级。
- 不把新的分析入口做成第二十个大型工具。
- 不把 574 条目录当成 574 项立即翻译的待办。
- 不在真人测试前宣称路径提高学习效率或设计质量。

| 为不同人群增加模式开关 | 首页出现年龄或能力选择 | 使用同一渐进内容结构，按任务提供帮助 |
| 删除 UI 后老链接失效 | 旧 hash 无法恢复 | 保留路由兼容和自动化深链检查 |
| 工具再次抢占资源站 | 阅读路径不断导向表单 | 工具只作为读完后的可选动作 |
