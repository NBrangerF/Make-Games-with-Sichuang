状态：测试仪器已就绪，尚未完成真实参与者可用性测试

对应规格：`DESIGN_AID_PRACTICE_LOOP.md`

## 用途与边界

这个原型只用于让 5–7 名中文桌游设计新手执行 T1–T6。它不是已上线工具，也不验证闭环能否提高创意、学习或成品质量。

- 不接入正式网站导航、项目护照或本地存储；
- 不上传、不持久化页面输入，刷新即清空；
- 不生成模拟玩家反馈；
- 不计算设计师分数、通过判断、排名、徽章或连续完成；
- 私有反思不进入分享预览，并可单独删除；
- 四条提示均为本项目独立撰写，不复制商业设计卡组文本。

## 原型入口

将以下三个文件保持在同一目录，直接双击 HTML 即可离线打开：

- `design/prototypes/design-aid-loop.html`
- `design/prototypes/design-aid-loop.css`
- `design/prototypes/design-aid-loop.js`

结构检查：

```bash
pnpm qa:design-aid-prototype
```

该命令只检查 JavaScript 语法、静态 ID 绑定、T1–T6 必需文案/分支、完成页边界和移动端/减弱动态规则。它不是浏览器交互测试，也不能代替主持式可用性测试。

## 屏幕与任务映射

| 屏幕 | 主要交互 | 对应任务 | 最高风险 |
|---|---|---|---|
| 选择本轮产出 | 只显示四种期望产物，不显示内部工具名 | T1 | 把入口误认成工具排行榜 |
| 写边界 | 目标玩家、体验、时限必填；硬边界可选 | T2 | 提示覆盖安全、无障碍或项目约束 |
| 选择提示 | 保留、换一张、自己写；三次换牌后中断抽卡循环 | T2 | 把提示当命令或寻找正确答案 |
| 写规则产物 | 按生成/诊断/原型/闭环显示不同最低字段 | T3、T4 | 只有题材或机制名称也进入测试 |
| 写行为预测 | 支持信号和反例信号都必填 | T3 | 把愿望写成已经发生的观察 |
| 选择证据状态 | 准备、自测、外部测试分开 | T5 | 把自测冒充玩家体验证据 |
| 记录与分享 | 观察、原话、解释、下一改动分栏；反思私有 | T6 | 私密反思意外进入分享内容 |
| 完成 | 只说明记录完成，不给质量结论 | T5 | 把完成流程误读为设计通过 |

## 视觉规范

原型沿用网站“工作坊笔记 + 博物馆导视”的纸面、墨黑、钴蓝、砖红和开放分区，但刻意保持低保真：没有插图、营销首屏、进度奖励、卡片墙或产品化动效。桌面为左侧步骤语境、右侧单一任务面；760px 以下转为单栏。时间盒没有倒计时，`prefers-reduced-motion` 会关闭进度过渡。

这里没有使用图像生成。`imagegen` skill 明确建议简单线框和代码原生界面直接用 HTML/CSS；同时，研究仪器不应以高完成度视觉暗示权威结论。
