# 发现沿革与后继修订可用性测试

日期：2026-08-21  
状态：待真实浏览器与新手执行

## 目标

验证第一次使用者能否在不覆盖旧判断的情况下：找到历史、解释旧记录、创建后继、写明改变理由、再次保存，并理解“最新”不是正确性标签。

## 准备资料

- 同一项目两场已完成复盘；
- 已保存沿革 r1，包含支持与反驳来源；
- 一份新的边界变化说明；
- 另备一个含 r1→r2→r3 的 v2 存储样本和一个 v1 样本；
- 不向参与者预先解释“不可变”“父记录”或“沿革”。

## 任务

1. 从当前空白草稿找到已经保存的 r1。
2. 说出 r1 当时声称什么、适用于谁、哪个反例改变过判断。
3. 尝试修正 r1，观察用户是否预期直接编辑。
4. 使用新证据创建后继，写明为什么改变，并把适用边界收窄。
5. 保存后回到 r1，确认它没有变化；再打开新修订。
6. 从 r1 而非最新修订创建一个分支，预测新编号与父记录。
7. 显式把一份已保存记录复制为项目下一步；尝试从未完成草稿复制。
8. 解释“另有较新的修订”意味着什么、不意味着什么。

## 错误门

- 旧记录出现可编辑字段或保存后内容改变：阻断。
- 后继复用父记录 ID，或保存时删除父记录：阻断。
- 修订 2+ 可在没有理由时保存：阻断。
- 从旧修订分支产生重复修订号：阻断。
- 未完成草稿能写回项目：阻断。
- v1 历史迁移后消失或变成可编辑完成草稿：阻断。
- 撤回来源会话后仍保留任何后继：阻断。
- 用户把“最新”稳定解释为更正确：高优先级文案问题。

## 观察指标（不形成总分）

- 首次找到历史入口的路径与停顿点；
- 是否能在操作前预测旧记录不变；
- 修订理由是否包含新证据、边界或竞争解释；
- 是否区分来源复盘、父记录和项目下一步；
- 从旧修订分支时是否理解编号与父关系；
- 需要主持人解释的术语和时刻。

## 视口与辅助技术

- 1440×900：三栏历史浏览；
- 1000×800：历史检查器降到全宽；
- 390×844：单栏、无页面级水平溢出；
- 键盘：历史记录、父链接、后继和返回动作顺序可达；
- 屏幕阅读器：只读状态、修订号、父记录和状态提示可理解。

## 通过边界

这里没有合格分。只要发生覆盖、ID 复用、无理由保存、断裂撤回或未完成写回，就是产品缺陷；术语误解与路径迷失进入下一轮改稿和复测。
