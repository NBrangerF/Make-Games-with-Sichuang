# 新手可用性测试：体验意图—核心循环—原型范围交接

状态：ready-for-formative-test  
日期：2026-08-21

## 目的与参与者

验证三个工具是否形成可理解的连续路径，而不是验证游戏是否好玩。每轮 3–5 名中文新手，至少覆盖：只有题材点子、已有机制但说不清体验、已有体验意图但原型过大的设计者。另记录桌游经验、视觉/读写/操作支持和测试媒介；小样本不外推总体。

## 简报

使用“港湾议会”或参与者自己的项目。主持人只读任务，不解释“正确机制”，不替参与者填字段。若参与者卡住，按“请指出页面上哪个词不清楚 → 请用自己的话描述一次决定 → 最后才解释字段”分级协助并记录。

## 任务

T1. 完成一条体验意图并说明哪些是预测、哪些是尚未证实。  
T2. 继续到核心循环，决定是否导入来源；说出导入做了什么、没有做什么。  
T3. 写出当前信息、至少两个可行选项、代价/承诺和状态变化。  
T4. 让反馈明确改变下一次输入或决定，并写循环出口。  
T5. 保存、导出，再继续到原型范围并显式导入核心循环。  
T6. 在原型范围中删去至少一项非必要内容，说明哪些字段来自循环、哪些仍由自己判断。  
T7. 刷新页面，核对三类记录与完整项目包中的来源链。

## 观察

逐任务记录：首次偏离、实际查看/恢复路径、主持协助、导入误读、术语替换建议、是否把结算动画当反馈、是否遗漏出口、导入后新增/删除了什么、导出与刷新结果。保存原话时去标识化；不计算理解总分或参与者等级。

## 关键失败

- 以为系统已根据体验意图推荐机制；
- 把“选择”写成设计者可选的机制列表；
- 反馈没有进入下一次决定条件；
- 为了闭环强行重复一次性/终局事件；
- 原型导入后认为所有字段都必须照做；
- 来源 ID/时间存在，但用户无法说出它来自哪条意图；
- 375px 下必须横向滚动整个页面，或键盘无法完成步骤、保存和导入。

## 修订门

若同一误读在 2 名以上参与者出现，先改字段说明或交接文案，再考虑加自动化；若参与者普遍需要主持人发明机制，回退研究核心循环示例，而不是增加推荐器。只有真实浏览器和参与者任务都完成，才能把本工具从“已实现”提升为“形成性可用”。
