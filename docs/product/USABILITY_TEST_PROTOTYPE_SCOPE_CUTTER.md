# 新手可用性测试：原型范围裁剪器

状态：ready / not run  
日期：2026-08-21

## 要验证的判断

中文新手能否把一个想做完整的游戏裁成一轮可制作、可运行、能回答指定问题的原型，同时不把“替代/近似/必须真实”误读成质量等级，也不默认越少越好。

## 参与者与材料

4–6 人：至少 2 名第一次做桌游原型的新手、1 名做过两轮以上原型的人、1 名主要使用数字原型或主持代运转的人。至少安排一种键盘输入、放大、大字、卡架或代读支持条件。

准备三个设计简报：

1. 纯规则循环：资源保留与即时得分；
2. 空间/触感：从远座读取并拿取组件；
3. 长局积累：联盟、叙事或经济后果不能在三回合完整显现。

## 任务

### T1：写问题与非目标

选一个简报，写本轮问题、可推翻信号和至少三个非目标。

观察：问题是否可观察；非目标是否只是模糊的“以后做”；参与者是否先写组件而跳过证据。

### T2：只选两个过滤维度

要求参与者解释为何某两个性质必须被看见，并尝试选择第三项。

观察：上限提示是否可理解；是否把未选维度误解为永远不重要；能否把第三项转成非目标或下一轮问题。

### T3：配置三维保真度

为材料、分辨率、范围分别选择并解释。追问：“为什么材料可以替代，但空间必须真实？”

观察：是否把三个选择当线性等级或成熟度；理由是否指向当前问题；控件在键盘和放大条件下是否可用。

### T4：界定代理运转

允许主持人代结算一个尚未实现的系统，要求写谁代什么、哪些决定不能代做。

观察：代理是否泄密、给策略提示或控制节奏；参与者能否在摘要发现缺失边界。

### T5：裁出可玩切片

写玩家配置、起始状态、重复条件、停止触发和明确不做。对长局简报追问短切片只能支持什么。

观察：是否强行要求完整胜负；重复是否能产生可比较经历；停止条件是否可观察；是否承认短片段盲区。

### T6：开工、保存与恢复

列材料、团队自定时间盒、重做信号和下一次测试；保存范围快照，刷新恢复，导出 JSON；第一次点击清空后停止，再确认并检查历史快照仍在。

观察：是否把时间盒误读为本站推荐；能否区分草稿/快照/验证；导出是否明确含两个 `no_*` 边界；项目包是否含 `prototype_scope_records`。

## 主持规则

- 不告诉参与者哪一维应该“必须真实”，只问它怎样产生目标证据。
- 不用完成时间或字段数量计算总分。
- 记录第一次误读、回退、未读提示、代理介入、外部协助和参与者原话；原话需同意。
- 对长局题，不诱导其把三回合当通用最小值。

## 形成性通过门

- 至少 4/6 参与者能产出问题、1–2 个过滤项、三维理由、代理边界、可玩切片与重做信号；
- 没有人稳定把“必须真实”理解为更高质量或更成熟；
- 至少 5/6 能说明短切片和媒介不能支持的结论；
- 第三过滤项提示、缺失字段定位、清空确认和导出边界均无阻断误解；
- 键盘、375px 与至少一种支持条件没有阻断任务；
- 失败形成具体修订，而不是参与者评分。

通过门只允许说“这些任务在该样本和材料下可完成”，不允许声称工具减少了开发时间、提高了设计质量、找到了最小内容量或适合所有游戏。
