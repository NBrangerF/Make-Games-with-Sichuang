# 可分享 URL 导航契约

状态：implemented / browser-smoke-checked  
日期：2026-08-21

## 为什么这是产品功能

资源网站的页面必须能被刷新、收藏和分享。此前四个主视图与十九项工具只存在于 React 内部状态中：用户虽然能点击切换，但地址不变，刷新会回到默认页面，也无法把某一工具发给别人。本契约把“我正在看的内容”变成公开、稳定且可恢复的 URL 状态；本地项目与工具草稿仍留在设备中，不进入 URL。

## 规范路由

| 目的地 | 规范 hash | 示例标题 |
| --- | --- | --- |
| 设计路径 | `#path` | `设计路径 · 落桌` |
| 资源库 | `#resources` | `落桌 · 桌游设计馆` |
| 指定策展阅读入口 | `#resources/<entry-id>` | `入口名称 · 落桌` |
| 工具箱默认项 | `#tools/redesign` | `单一风险改造器 · 落桌` |
| 指定工具 | `#tools/<tool-id>` | 使用工具的中文名称 |
| 方法 | `#method` | `方法与概念 · 落桌` |
| 方法分区与条目 | `#method/<section>/<item-id>` | 根据分区显示理论框架、专题指南、概念词表或资源阅读说明 |

十九个正式工具 ID 由 `src/url-state.ts` 的 `routableToolIds` 统一约束。空 hash、未知主视图和未知工具不会报错：空或未知主视图回到 `#path`，未知工具回到 `#tools/redesign`，并用 `replaceState` 写回规范地址，避免制造无意义历史节点。

## 交互行为

- 顶部品牌与四个主导航项目是可复制地址的真实链接；活动项使用 `aria-current="page"`。
- 指南中的“打开工具”、工具标签和“保存并开始主持”都写入规范 hash。
- 六阶段核心指南的“继续阅读本阶段精选资源”写入对应入口 hash；资源页切换入口也同步地址。
- 方法页的标签和框架/专题/概念/资源审阅选择同步 hash；搜索词和阶段筛选不进入 URL。
- 站内主动导航使用 `history.pushState`；`hashchange` 与 `popstate` 重新解析 URL，支持刷新与浏览器历史同步。
- 每个路由更新 `document.title`，因此书签与标签页能说明当前内容。
- 页面首个可聚焦元素是“跳到主要内容”，指向每个主视图的 `#main-content`。
- URL 只保存视图和工具身份，不保存表单内容、参与者信息、项目记录、筛选条件或推断结果。

## 数据与部署边界

使用 hash 路由意味着普通静态托管无需服务器回退规则即可打开深链。资源阅读入口选择已进入 URL；组合筛选、搜索词、“查看全部”、工具内部步骤和抽屉开关仍是会话内状态。工具草稿与项目记录继续使用 local-first 存储，因此分享工具或资源入口链接不会分享私人数据，也不会让另一台设备恢复当前草稿。

## 防漂移验证

`pnpm qa:url-navigation` 当前有 10 组守卫：

1. 空值与未知值安全回退；
2. 四个主视图规范往返；
3. 资源入口深链往返；
4. 方法分区与条目深链往返；
5. 十九项工具逐项往返；
6. 未知工具回到默认工具；
7. 路由标题；
8. 应用接入解析、历史、标题、真实链接与活动态；
9. 跳过链接与主内容地标；
10. 浏览器 QA 从权威 JSON 读取资源与入口数量，不保留 549、556 或 31 等旧硬编码。

应用内浏览器已实际检查 `#path`、`#resources` 和 `#tools/core-loop`：深链与刷新保持工具，标题与活动导航同步，资源页显示 574 条；390×844 视口的 `scrollWidth` 与 `innerWidth` 均为 390。跳过链接目标与主地标结构已检查，但键盘焦点移动、浏览器后退/前进、下载和十九项工具完整回归仍没有新的自动化浏览器通过证据。系统 Playwright/Chrome 在当前沙箱于页面创建前 `SIGABRT`，详见 [真实浏览器 QA 环境阻塞记录](BROWSER_QA_BLOCKER.md)。
