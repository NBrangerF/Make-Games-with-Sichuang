# 拍卖协议契约：可用性测试脚本

- 对象：第一次或很少设计拍卖的新手设计者
- 样本建议：先做 3–5 人形成性测试；至少覆盖一次需要算术/记忆/表达或精细操作替代的参与者
- 时长：单人 35–45 分钟，四人原型另加 20–30 分钟
- 原则：测试“能否独立把模糊竞价写成可执行协议”，不测试经济学术语背诵。

## 测试材料

- 一段故意不完整的原型说明：四人竞拍港口牌，出价最高者获得；港口可得分并影响货价。
- 预算筹码、三张港口牌、个人目标卡、报价纸/牌。
- 空白《拍卖协议契约》与观察表。
- 三种可选实现：公开顺序升价、同时暗标、固定筹码一次报价。

## 任务

### T1：找到缺失字段

提示：“请在不开始玩之前，圈出这段规则还缺哪些决定。”

观察：是否主动问拍品价值、信息、竞价顺序、支付对象、落败者、并列、零报价、流拍和反馈；是否只问起价。

成功：能发现价值/信息、竞价、分配/支付、边界、反馈五类中至少四类，不要求术语一致。

### T2：完成一份可执行协议

提示：“选一种竞价方式，把规则写到四名陌生人能从开拍做到交接下一轮。”

观察：是否明确出价资格、合法报价、撤回/退出、赢家、支付、收款、并列和无人出价；主持人只在参与者明确卡住时追问。

成功：观察员不补规则即可演完一次正常拍卖和一次并列/流拍。

### T3：解释一笔高价

给出：甲主观最高价值 8，实际出价 11，支付 11，最终兑现 6；乙在 10 退出。

提示：“这能否证明发生赢家诅咒？你还要知道什么？”

观察：是否区分私人/共同/相互依赖价值，能否提出阻断、预算、抬价、误解、情绪或信息噪声；是否把报价直接当估值。

成功：不武断贴标签，并提出至少两种解释和一条可新增记录。

### T4：只改一个变量

提示：“首轮中两名玩家说暗标太难估，另一名说公开喊价压力大。请做下一版，但只能改变一个协议字段。”

观察：是否保持其他字段冻结；是否写支持、保留功能和反驳信号；是否提供等价提交方式而不是替参与者决定。

成功：改动可精确指向一个字段，含可观察预期与回退条件。

## 观察编码

每个任务记录：

- `independent`：独立完成 / 一次提示 / 多次提示 / 未完成
- `rule_gap`：遗漏字段及其在正常局或边界局首次暴露的时点
- `value_model`：私人 / 共同 / 相互依赖 / 未区分
- `price_trace`：估值、报价、支付、兑现价值是否分开
- `access_load`：感知、算术、记忆、表达、动作、时间、社交压力
- `boundary_state`：并列、零报价、储备未达、流拍、非法报价
- `revision_scope`：一个变量 / 多变量捆绑 / 不可执行
- 原话、犹豫点、寻求帮助和自我修正；不要只写“顺利/不顺利”。

## 通过门槛与反驳条件

形成性通过不是“参与者喜欢工具”，而是：至少 4/5 参与者可在一次以内提示下完成 T1、T2 和 T4；所有参与者都能在 T3 分开报价与价值；正常局与并列/流拍均无需观察员补规则。

任一情况触发修订：多数人仍把拍卖形式当完整规则；边界状态首次出现才临时协商；“成交价=估值”反复出现；术语妨碍而不是帮助写规则；替代提交方式改变了信息或行动时机；下一版仍同时改两项以上变量。
