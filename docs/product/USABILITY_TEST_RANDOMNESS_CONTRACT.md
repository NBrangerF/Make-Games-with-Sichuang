# 可用性测试：随机性契约指南

更新：2026-08-20  
对象：`special-randomness-contract` 与 `docs/guides/RANDOMNESS_CONTRACT.md`  
状态：draft；尚未进行真人测试

## 测试目标

确认中文新手设计师能否在不依赖主持人解释的情况下：

1. 分开不确定性目的与骰子/牌库装置；
2. 把输入/输出标签展开成连续决定循环；
3. 写清风险暴露的所有者、信息和 stakes；
4. 区分重掷、改分布、择果、转换与止损；
5. 分开代理结果、真人体验与玩家归因；
6. 形成一项可反驳的单一修订。

## 招募

- 3–5 名有桌游点子或原型、但没有正式发行经验的中文用户；
- 至少 1 名熟悉高随机轻量游戏，至少 1 名偏好低随机策略游戏；
- 尽量包含概率/数感、视觉读取、精细动作或注意力支持需求不同的参与者；
- 不要求了解 input randomness、seed 或 luck mitigation。

## 材料

- 指南正文与一页模板；
- 一段虚构 push-your-luck 规则：12 枚标记中 3 枚灾难，可继续抽或保存；
- 三种缓解：全体重抽、抽二选一、失败后支付资源撤退；
- 一份代理报告：固定地图后事件牌只小幅改变胜率；
- 一份玩家记录：单次坏抽后报告“我的决定完全没用”；
- 计时器与观察编码表。

## 任务

### 任务 1：写不确定性承诺

要求参与者解释为什么需要未知，并把随机装置、隐藏信息和对手行动分开。

失败信号：只写“骰子增加随机性”或直接选择最佳骰型。

### 任务 2：画连续两轮

参与者从“是否继续抽”开始，画到结果、撤退/保存和下一次抽取。

关键观察：是否认为发生在决定前就是好设计，或漏掉输出成为下一次输入。

### 任务 3：写暴露与 stakes

要求标出谁选择继续、知道剩余几枚灾难、最好/最坏结果、已有收益能否保存和失败是否永久损伤。

失败信号：只写 25% 概率，不写所有者、信息或可恢复性。

### 任务 4：分类缓解动作

让参与者分别解释全体重抽、抽二选一和失败后撤退改变了什么、何时支付以及谁拥有。

失败信号：全部称为“重掷 +1 控制”，或只数动作数量。

### 任务 5：解释两条冲突证据

同时给出代理胜率影响小和玩家感觉决定无效，要求提出下一步。

成功信号：保留两者，检查事件序列、回应窗口、代理/指标与玩家语境；不宣判任一方错误。

### 任务 6：只改一个风险

从公开信息、撤退窗口、失败损失或重试结构中选一项，写反驳信号与保持不变项。

## 观察编码

- `purpose_device_merged`：目的与随机装置混淆；
- `input_output_ranked`：把输入/输出当质量顺序；
- `loop_stops_at_result`：未画结果后的下一决定；
- `exposure_owner_missing`：不知道谁选择承担；
- `stakes_missing`：只写概率，不写损失与恢复；
- `mitigation_collapsed`：不同缓解操作合并成数量；
- `probability_equals_access`：公开数字就假定可理解；
- `simulation_overrules_player`：代理结果否定体验；
- `attribution_equals_cause`：玩家归因直接当真实因果；
- `randomness_score`：试图合成单一随机度；
- `multi_change`：一次修改多个变量。

## 成功标准

- 4/5 用户能写出至少两个不确定性来源和一个目标体验；
- 4/5 用户画出完整的决定—随机—回应—下一决定；
- 4/5 用户写出暴露所有者、事前信息、最坏 stakes 与恢复路径；
- 4/5 用户能说明三种缓解改变的变量不同；
- 所有用户都不把代理胜率与真人控制感互相替代；
- 4/5 用户提出一项修订，并写出反驳与保持不变项。

成功标准是产品门槛，不是研究效果量；小样本只用于发现理解障碍。

## 停止与修复

- 用户不愿讨论赌博、损失或个人“运气”时可跳过且无需解释；
- 主持人不得把高随机或低随机当正确偏好；
- 若两名用户都把 stakes 理解为真实金钱，立即改成“局内得失/后果”；
- 若 probability、seed 或 mitigation 阻断任务，优先显示中文释义并记录术语失败；
- 若数字概率对用户不可读，提供实体组成、图标和自然频率三种表达后重试。
