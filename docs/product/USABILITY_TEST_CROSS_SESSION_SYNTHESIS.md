# 发现演化工具可用性测试脚本

日期：2026-08-21

## 前置资料

准备三份已完成复盘：

- v0.3，新手四人首次局，发现资源转换步骤拖慢节奏；
- v0.4，熟练四人重复局，发现限制后仍保留策略深度；
- v0.5，新手四人首次局，发现新增援助改善落后方但教学时间上升。

三份材料故意不完全可比，并包含一条反例。

## 核心任务

1. 选择你认为能回答“限制资源转换是否改善节奏”的复盘。
2. 写出哪些条件可比、哪些关键差异不能忽略。
3. 为每份复盘选择与当前判断的关系，并说明一条反例怎样改变判断。
4. 将发现处理为“收窄”或“拆分”，写清适用边界。
5. 保存发现沿革，但先不要写入项目。
6. 检查来源证据后，显式复制一个下一轮行动。

## 错误门

- 只选一份复盘后尝试继续；预期被阻止。
- 不写关键差异直接进入矩阵；预期被阻止。
- 把支持数量当作优先级；观察界面是否诱导这种判断。
- 把 v0.4 熟练组称为 v0.3 新手组的复现；追问用户看到哪些差异。
- 选择“拆分”但只填一个分支；预期不能保存。
- 保存综合后检查项目下一步；预期未改变。
- 撤回 v0.4 来源会话；预期关联复盘和综合在本站本地存储中清除。

## 观察问题

- “可比较条件”与“关键差异”是否被理解成统计控制？
- “收窄”关系与“收窄”生命周期是否容易混淆？
- 用户是否能找到直接证据入口，而不只读单轮发现摘要？
- 反例是否真的改变表述，还是只被填进一个形式字段？
- 用户是否明白保存、导出和复制到项目是三个不同动作？

## 视口

- 桌面：1440×900
- 窄桌面：900×900
- 移动：390×844

移动端重点检查：四步轨道横向滚动、矩阵局部横向阅读、拆分分支单栏、底部状态不遮住主要动作。

## 通过条件

- 用户不经提示能说出两份材料为何可比或不可比；
- 能指出至少一个反例或竞争解释；
- 不使用“3 票对 1 票”作为处理理由；
- 生命周期决定能回到具体来源与版本；
- 保存不会被误认为已经改变项目；
- 390×844 下无页面级强制横向溢出，矩阵自身可局部滚动。
