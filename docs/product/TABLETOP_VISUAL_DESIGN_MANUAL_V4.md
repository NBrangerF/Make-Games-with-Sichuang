## 0. 本版结论

V4 手册保留 V3 已经成立的信息架构、中文站内阅读、上下文工具和无障碍基础，但不再把“清晰”误解成“视觉上尽量没有事件”。

V5 的网站必须在五秒内同时传达三件事：

1. 这里是桌游设计学习资源站，不是商店、游戏发布站或通用知识库。
2. 读者可以从学习、分析一款游戏、解决一个设计问题三个入口开始。
3. 经典桌游视觉以有来源的“馆藏标本”出现；网站没有伪装成任何一款游戏的官网。

设计方向从“平静的公共图书馆”转为“整理清楚、可以上手的桌游档案馆”。视觉更强，不意味着增加一级功能、首屏决定或阅读负担。V5 的设计感来自强比例、强字体、实色板件、硬裁图像、页面角色差异和明确状态，而不是堆叠控件。

### 1.1 规范优先级

发生冲突时按以下顺序处理：

1. 内容正确、资源可达、完整中文站内阅读。

## 2. Design Read

### 2.1 产品与读者

产品类型：完整中文桌游设计资源馆，兼有分析方法与紧邻资料的工作单。  
读者：从小学生、青少年到成人初学者、教师和有经验的设计师。  
主要任务：找到下一份合适的资料，读懂它，并把它用于正在解决的问题。  
期望感受：好奇、鲜活、可拿取、可研究；像一张正在布置的游戏展览桌。  
不应像：电商货架、SaaS 控制台、儿童玩具站、论文数据库、某一款桌游的复制品。

### 2.2 必须保留的产品基础

- 可见一级导航只有“找资料”和“方法与概念”。
- 资源站是第一位；资源依照设计阶段与同阶段不同 approach 组织。
- 首页只提出学习、分析、问题三个主要入口。
- 完整资料以中文在站内直接阅读，外部来源不替代站内正文。
- 工具只在相关资料、阶段或方法旁出现，不成为独立货架。
- 旧深链、返回来源、浏览器前进后退和本地草稿继续有效。
- 不创建“小学生版”和“成人版”；通过内容层次和脚手架服务不同背景。

### 2.3 视觉目标

V5 必须同时做到：

- 视觉上明显属于桌游设计领域。
- 不看标题也能分辨首页、资源库、阅读、方法与工具。
- 儿童能凭文字、形状与颜色找到入口；成人不会觉得幼稚。
- 图像和材质增强理解，不削弱资料扫描和长文阅读。
- 移动端保留品牌视觉锚点，不退化成纯文字目录。

## 3. 三个设计旋钮

三个旋钮用于约束页面强度，不是质量评分。

- Design Variance：版式、构图、轮廓、图片和颜色之间的差异程度。
- Motion Intensity：状态改变时可感知的位移与节奏。
- Visual Density：一个视口内同时出现的信息与视觉对象数量。

### 3.1 页面预算

| 页面模板 | Variance | Motion | Density |
| --- | ---: | ---: | ---: |
| 首页与一级入口 | 8 | 5 | 5 |
| 学习、分析、问题入口 | 7 | 4 | 5 |
| 资源库与列表 | 7 | 4 | 6 |
| 主题与资料详情 | 7 | 4 | 5 |
| 完整长文阅读 | 5 | 2 | 4 |
| 方法与概念 | 7 | 4 | 6 |
| 配套工具 | 8 | 5 | 6 |
| 隐私、错误与系统页 | 4 | 1 | 4 |

探索稿可以到 9 / 6 / 6；正式生产上限是 8 / 5 / 6。

### 3.2 单视口预算

每个视口同时只允许：

- 一个主视觉场。
- 最多三个强调色家族。
- 最多两种显著板件轮廓。
- 一种主要动作反馈。
- 一个首要决定。

高 Variance 不等于每个区域都不同。它要求一个页面有明确主构图，并让次级区域安静地支持它。

## 4. 品牌与页面隐喻

### 4.1 名称

用户可见品牌固定为“桌游设计工坊”。“可玩的桌游档案馆 Playable Tabletop Archive”是设计系统名称，不替换品牌，也不成为第三个导航入口。

### 4.2 四种工作对象

1. 展览桌：用于首页与主题开场。大图、标题牌、路线和行动板件帮助选择入口。
2. 资料抽屉：用于资源列表与方法索引。色脊、编号、来源和稳定行帮助扫描。
3. 规则册：用于完整长文。正文最安静，章节轨与少量高强调模块帮助持续阅读。
4. 实验板：用于工具与方法工作面。输入、观察、决定、产出和边界清晰分区。

四种对象共享颜色、字体和边界，但构图不同。不能用同一个“万能卡片模板”同时承担四种角色。

### 4.3 品牌记号

- 使用本站原创 CSS / SVG 骰面或板件堆叠记号，不能使用任何桌游品牌 logo。
- 记号只承担品牌识别，不作装饰性背景平铺。
- 桌面建议 40px，移动建议 32px；360px 以下若空间不足可以隐藏记号，但品牌中文必须保留。
- 骰点、六边形、米宝等符号如果只是装饰，必须 aria-hidden；功能图标必须有可访问名称。

### 4.4 语气

界面语气是“清楚的共同工作者”：直白、具体、尊重读者，不卖萌，不考试，不装作导师。

推荐：

- 先选你现在想解决的问题。
- 做完会得到一份本轮测试清单。
- 不确定也没关系，先看一个桌面上的例子。

避免：

- 解锁下一关。
- 小朋友也能学会。
- 专家模式。
- 点击这里探索更多。

## 5. 颜色系统

### 5.1 中性色

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| Canvas | #F5EEDD | 暖纸页面底。 |
| Surface | #FFFDF6 | 正文、输入和资料面。 |
| Surface Raised | #FFF9EA | 少量抬升板件。 |
| Surface Inverse | #081F33 | 顶栏、工作台外层、强边界。 |
| Ink | #081F33 | 主要文字与结构线。 |
| Muted | #4C5961 | 次级说明；在 Canvas 上对比度 6.24:1。 |
| Rule | #C9BCA8 | 装饰分隔；不单独承担状态。 |
| Rule Strong | #58636A | 次级结构边界。 |

### 5.2 四个记忆色

| 颜色 | 色值 | 主要语义 | 文字搭配 |
| --- | --- | --- | --- |
| 钴蓝 Action | #0B4FA3 | 学习、关系路径、当前主行动。 | 白字，对比度 7.75:1。 |
| 番茄红 Editorial | #B7352E | 分析、冲突、批注、重要转折。 | 白字，对比度 5.79:1。 |
| 藏红黄 Discovery | #D79B00 | 开始、发现、提示、待观察。 | 深墨字，对比度 6.84:1；禁止白字。 |
| 叶绿 Success | #1A7045 | 实践、验证、继续、产出。 | 白字，对比度 5.98:1。 |

紫色 #6539A7 只用于“盲点、媒介限制、不同视角”等辅助语义，不能成为第五个同屏主色。

### 5.3 颜色分配

- 首页三条入口可以分别使用蓝、红、黄；绿色用于下方实践或继续，不与三入口争夺。
- 资源库以当前阶段的一个主色为主，其它颜色只作类型或来源提示。
- 阅读页每篇只选一个章节主色；正文高强调模块最多再使用两种。
- 方法页用蓝作结构、红作“不适合回答”、绿作产出；黄只作准备或提醒。
- 工具页用蓝作当前步骤、绿作建议和产出、红作停止条件；紫色只在确有媒介盲点时出现。

### 5.4 颜色硬规则

- 颜色永远不是当前、完成、错误、未知的唯一信号；必须同时有文字、形状或图标。
- Discovery 黄用于细边时必须加 Ink 外框，不能依赖黄与纸面的低对比。
- 复杂照片上不放文字；所有标题牌和说明都落在接近不透明的本站色面。
- 一屏最多三个强调色家族，照片中的自然颜色不算 UI 状态色，但不能与按钮混淆。
- 错误固定使用 #A22525 和明确错误文字，不借用入口红色的品牌语义。
- 浅色文字、半透明文字和低对比元信息不得低于 WCAG 2.2 AA。

### 5.5 焦点颜色

浅色表面使用 #0068D8 的 3px 实线焦点环；深墨或蓝色表面使用 #FFD53D。复杂背景上增加 #FFFDF6 的外层 halo。焦点不被 hover 阴影、粘性顶栏或章节轨遮挡。

## 6. 字体与中文排版

### 6.1 字体角色

1. UI、导航、按钮、表单、首页 Display：Noto Sans CJK SC / Source Han Sans SC / PingFang SC / Microsoft YaHei / system-ui。
2. 长文标题、规则册引文：Noto Serif CJK SC / Source Han Serif SC / STSong / SimSun。
3. 档案编号：Arial Narrow / Roboto Condensed / DIN Condensed / system-ui，仅用于短数字。

不从第三方 CDN 加载字体。引入自托管字体前必须登记许可、中文覆盖、字重和体积。同一页面最多两个字体家族。

### 6.2 排版角色

| 角色 | 桌面 | 移动 | 行高 | 字重 / 家族 |
| --- | --- | --- | ---: | --- |
| Display | 64–88px | 42–56px | 1.02 | 900 Sans |
| H1 | 48–64px | 34–44px | 1.10 | 900 Sans |
| H2 | 30–40px | 27–32px | 1.20 | 800 Sans；长文可用 Serif |
| H3 | 22–28px | 21–24px | 1.32 | 700 Sans |
| 界面正文 | 17px | 16–17px | 1.70 | 400 Sans |
| 阅读正文 | 18px | 17px | 1.86 | 400 Sans |
| 小字 | 15px | 14–15px | 1.55 | 400 Sans |
| 标签 | 15px | 14–15px | 1.40 | 700 Sans |
| 档案编号 | 32–48px | 26–34px | 1.00 | 900 Condensed |

### 6.3 中文排版规则

- 阅读正文每行目标约 32–42 个汉字，最大宽度 720px。
- 首页 Display 允许两到三行强制构图；移动端必须自然换行，不能用缩小到不可读换取单行。
- 正文不使用全段粗体；强调优先用小标题、短色脊和结构关系。
- 长中文标签不做大字距；档案牌上最多对 2–6 个汉字做轻微字距调整。
- 段落间距至少 0.9em，不只靠首行缩进分段。
- 正文和操作文字不低于 16px；极短元信息最低 14px。
- 表单控件使用 font: inherit；占位文字不能代替标签。

### 6.4 数字不是步骤的条件

首页的 01 / 02 / 03 若保留，只表示固定“档案入口编号”，不能：

- 写成“第 1 步”。
- 用一条进度线串成必经顺序。
- 在屏幕阅读器名称中读作任务次序。
- 让后续入口显得被锁定。

入口组必须有可见说明“任选一个入口”。真正的工具步骤才使用“第 n 步，共 m 步”。

## 7. 图形、板件与材质

### 7.1 六个原创视觉原语

| 原语 | 作用 | 造型 |
| --- | --- | --- |
| ActionBoard 行动板件 | 少量互斥入口或主行动。 | 2px 深墨边、单侧色脊或切角、6px 硬阴影。 |
| ArchiveSpine 资料色脊 | 连续资料记录的扫描定位。 | 桌面 12px、移动 8px；带类型文字或图形冗余。 |
| ChapterTrack 章节轨 | 表示位置和关系，不伪造完成率。 | 实线、节点、当前章节文字；大节点只给当前项。 |
| WorkbenchZone 工作区 | 区分输入、观察、决定、产出。 | 深墨外板与高对比纸面，最多两层抬升。 |
| SpecimenPlate 标本牌 | 承载第三方照片的中文观察标签。 | 图片与文字分离；标签为本站实色板。 |
| ArchiveTape 档案胶带 | 说明“这张图是被固定的展品”。 | 单色短矩形，只作装饰，最多四条 / 拼贴。 |

### 7.2 边界与切角

- 主要可操作面使用 2px 深墨或语义色边线。
- 大型主板允许 3px 边线。
- 圆角只使用 0 / 2 / 4px；不使用连续大圆角。
- 切角建议 12px，通过 clip-path 或伪元素实现；焦点轮廓必须仍完整可见。
- 同一视区最多两类显著轮廓，例如切角板件加方形照片；不能同时出现六边、圆、票根、波浪、拼图等五种造型。

### 7.3 硬阴影

- 小板件：3px 3px 0 Ink。
- 主要行动：6px 6px 0 Ink。
- active：1px 1px 0 Ink。
- 阴影必须是硬边，不使用模糊玻璃阴影、发光或多层柔光。
- 长文正文、普通资料记录和大面积容器默认无阴影。

### 7.4 纸纹与印刷感

- 纸纹透明度上限 0.07，网点上限 0.06，套印偏移最多 2px。
- 纹理只能在页面底、标题牌或档案标签局部出现；关闭纹理后层级仍应成立。
- 不使用全页木纹、毛毡、塑料高光或 3D 棋盒。
- 装饰渐变禁止；只有图片可读性 scrim 允许渐变，而且文字仍优先放独立色面。
- 任何噪点都不能降低正文对比或造成 JPEG 式脏污。

### 7.5 图标

- 使用同一套原创或已登记的简洁实心／线性 SVG，不混用 emoji、照片图标和不同笔画风格。
- 图标只能帮助快速定位，完整文字始终存在。
- 功能图标至少 20px，描边建议 2px；纯装饰图标 aria-hidden。
- 米宝、六角形、列车、花砖等第三方可识别造型不能变成系统状态图标。

## 8. 空间、网格与表面

### 8.1 间距序列

只使用 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96px。光学校正值必须在组件旁说明原因。

### 8.2 内容宽度

| 模板 | 最大宽度 |
| --- | ---: |
| 首页与决策入口 | 1360px |
| 资源详情 | 1120px |

| 系统页 | 960px |

### 8.3 页面层级

一个页面最多三层：

1. Canvas 页面底。
2. 主页面对象：展览桌、抽屉、规则册或实验板。
3. 当前行动、展开内容或输出面。

禁止在 Raised Panel 中继续嵌套多个有阴影的卡片。内容分组优先使用位置、色脊、标题和边线。

### 8.4 图片比例

- 首页拼贴：桌面至少 520px 高；平板至少 320px；移动 168–200px。
- 精选资源裁图：72–112px，不给每条理论资料配图。
- 方法或主题案例：单图优先 3:2 或 1:1。
- 所有图片声明 width / height 或 aspect-ratio，避免布局跳动。

## 9. 全站壳

### 9.1 顶栏

- 深墨 #081F33 实色底，白色品牌与导航。
- 可见导航只有“找资料”和“方法与概念”。
- “仅限内部学习”作为状态文字保留，不做醒目促销徽章。
- 桌面最小高度 72px；移动两行布局最小 108px。
- 当前页同时使用 aria-current、2px 下边线和字重变化。
- 工具深链与兼容页可以没有当前一级导航项，这属于正确状态。
- 顶栏不增加设计路径、工具、收藏、登录、通知或图标菜单墙。

### 9.2 页面头部

标准顺序：

1. 可选返回入口。
2. 眉题或当前阶段。
3. 唯一 H1。
4. 一句“这一页能帮你完成什么”。
5. 可选来源或完成状态。
6. 主页面对象。

首页可以把 H1 与拼贴并置；完整阅读不能在 H1 前堆译者、许可和治理信息。

### 9.3 页尾

页尾保持简洁，保留内部学习范围与数据 / 隐私入口。页尾不是第二导航区，不列全部工具、资源和方法。

### 9.4 路由

视觉重构不得改变现有 hash 深链、section 稳定锚点、工具 from 来源白名单、刷新恢复和浏览器历史。图片标签不得变成外部跳转；来源 URL 在站内来源说明中可复制。

### 11.1 ActionBoard 状态

| 状态 | 视觉与语义 |
| --- | --- |
| Default | 2px 边、色脊、标题和产出，6px 硬阴影。 |
| Hover | 在预留空间内横移 4–6px，阴影缩为 2–3px；信息不变。 |
| Focus | 两层可见焦点环；优先于 hover。 |
| Pressed | 位移回落，1px 硬阴影，保持 aria / 原生按压语义。 |
| Current | 明确文字“当前”、实色区域和形状共同变化。 |
| Disabled | 优先不显示；若必须显示，说明未开放原因。 |

### 11.2 ResourceRecord 状态

- 默认是一条连续抽屉记录，不单独投影。
- 左侧 8–12px 色脊承担扫描定位，同时写资源类型或使用图形。
- 精选 / 案例资源可有 72–112px 图片；普通理论资源保持文字优先。
- hover 只增强站内阅读动作和边线，不抬升整条。
- 已读使用“已读”文字和次级边线；缺正文时说明缺的是正文、译文还是来源。
- 列表重复是资源站所需的稳定性，但每个主题必须有标题、当前问题和分组，不形成无尽灰线墙。

### 11.3 ChapterTrack 状态

- 当前章节：大节点、2px 轨道、文字“当前章节”、aria-current=location。
- 已访问章节：保留文字“已读”或历史样式，不推断读者已经掌握。
- 未访问章节：普通节点，不降低文字对比。
- 没有章节时不渲染空轨，正文仍完整。

### 11.4 WorkbenchZone 状态

- 当前步骤用 36–48px 颜色组件、粗边线和“第 n 步，共 m 步”表达。
- 完成步骤保留“已完成”文字和摘要，不消失。
- 错误靠近字段，写明原因与下一步。
- 保存状态使用 role=status；破坏性错误才使用适当 alert。
- 右侧摘要不是第二表单；它只反映当前输入、建议和边界。

## 12. 页面模板

### 12.1 首页：展览桌

唯一问题：你今天想从哪里开始？

必须：

- 深墨顶栏。
- 左侧或上部超大黑体 H1 与两行以内导语。
- 桌面用不对称构图放置 3–4 张经典桌游视觉标本，图片占首屏约 40%–48%。
- 三条 ActionBoard：开始学习桌游设计、从设计师角度分析一款游戏、按正在解决的设计问题找资料。
- 每条入口同时写任务与完成后产出；整行可点击。
- 搜索全部资料是次级入口，不与三条入口同权。
- 移动端保留 168–200px 的紧凑拼贴，放在导语与入口附近。

禁止：

- 增加推荐资源、统计、收藏、登录或第四个入口。
- 把图片变成轮播。
- 用 01 / 02 / 03 暗示顺序。
- 桌面有主视觉、移动端 display:none。

验收：遮住标题后，仍能从展品拼贴和三条行动板件认出这是桌游资源入口。

### 12.2 学习、分析与问题入口

三个入口页各有自己的主色与对象：

- 学习：连续学习票根或书脊轨，强调“选择学习方式”。
- 分析：问题镜头和观察图形，强调“你想看见哪种关系”。
- 问题：六阶段板条或抽屉，强调“你当前卡在哪个阶段”。

所有页面：

- 一次只要求一个选择。
- 每项先写完成后产出，再写方法或框架名。
- 形式化框架在读者选定白话问题后出现。
- 原生链接 / 按钮保持键盘顺序和 44px 目标。
- 每页只使用一个主色家族；不要三页都同时出现四色。

### 12.3 资源库与主题页：资料抽屉

页面顺序：

1. 选择设计阶段。
2. 明确当前问题。
3. 先从这里开始，最多三份资料。
4. 换一种做法，展示同阶段不同 approach。
5. 做一小步，显示唯一相关工作单。
6. 查看本主题全部资料。

视觉规则：

- 阶段使用 StageBoard，桌面可横向排布但不得要求横向滚动；移动转为可换行或纵向。
- 当前问题使用一条高对比标题板，旁边写“找到 n 份可站内阅读的中文资料”。
- 资源以连续 ResourceRecord 呈现，不拆成悬浮白卡墙。
- 只有精选 / 案例型条目使用经典游戏裁图；普通条目保持文字优先。
- 搜索与筛选是可展开资料抽屉，不使用满屏胶囊标签。
- 上下文工具只有一个，写清“把哪份资料用起来”，不做常驻 AI 助手。

### 12.4 资料预览与详情：资料封套

顶部固定包含：

- 中文标题。
- 读完会得到什么。
- 篇幅或可验证的内容规模。
- 作者 / 来源与中文完整度。
- 站内完整阅读主行动。

“先做一步”使用藏红黄动作条；“理解原理”留在普通纸面；“来源说明”使用低饱和 SourcePlate。工具入口最多一个，其余关联使用普通文字链接。

### 12.5 完整阅读：规则册

长文是全站最安静的模板。

桌面 1280px 以上可以使用：

- 168–208px ChapterTrack。
- 32–40px 间隔。
- 最大 720px 阅读正文。
- 可选 272px 右侧 ContextAction；只有确实存在单一带回行动时出现。

1180–1279px 取消右栏；960px 以下目录改为标题后的原生 details；正文始终完整存在于同一路由。

阅读规则：

- 每篇顶部有一个鲜明但短的章节封面区：主色块、编号、主题图形或一张解释性图。
- H1 和“这篇能帮你做什么”先于来源治理信息。
- 每个 H2 有稳定锚点，不生成虚假阅读百分比。
- 正文只允许三种高强调模块：先做一步、看一个例子、关键边界。
- 表格有粗表头、淡色交替行；窄屏可局部横滚并写“表格可左右移动查看”。
- 图片只在需要观察时出现，不在文末铺图。
- 来源、翻译方式、许可和内部范围位于导语后的展开入口与文末详细区。

### 12.6 方法与概念：分析工作台

方法首页保留三个任务入口：

- 解决一个具体任务。
- 理解一种分析方法。
- 查一个设计词。

详情页：

- 左侧是带色脊的窄索引，右侧是主要工作面；视觉权重明显不同。
- 顶部必须回答“它适合回答什么”“不要拿它回答什么”“开始前准备什么”。
- 方法步骤写清每一步输入、动作和产出。
- 必须有一个解释性关系图、循环、比较表或观察卡，不能放纯装饰插图。
- 当前方法最后有唯一“本轮产出”板件。
- 相关方法最多七个，使用窄目录，不返回卡片墙。
- 移动端先显示当前方法完整内容，再显示相关索引。

### 12.7 配套工具：实验板

工具真实名称直接作为 H1。头部固定写：

- 做完会得到什么。
- 来自哪份资源或单元。
- 步骤数或可验证的投入。
- 返回精确来源。

桌面端左侧是过程区，右侧是持续摘要 / 建议 / 边界。移动端顺序固定为：当前步骤 → 当前输入 → 当前摘要 → 下一步。

工作流：

1. 输入。
2. 整理。
3. 决定。
4. 产出。
5. 边界。

规则：

- 一次只突出一个主行动。
- 标准 label、input、select、textarea、button 语义不被板件造型替代。
- 当前步骤、完成步骤、未知、错误、保存都有文字和图形。
- 主按钮可用压下板件反馈；160–240ms，reduced motion 下关闭位移。
- 刷新后恢复草稿与来源；保存写“已保存到此设备”。
- 完成页显示成品、下一步和不能推断什么；不用积分、徽章或彩纸。
- 相关经典视觉样本只可放在工具头部解释信息组织，不能成为输入背景。

### 12.8 系统页

隐私、错误、关于和版本页只继承深墨顶栏、字体、焦点和粗边线。它们不使用经典游戏图像，不使用高 Motion，不把危险操作做成好玩的游戏按钮。

## 13. 交互与动效

动作感来自状态改变，不来自持续动画。

| 场景 | 推荐反馈 | 时长上限 |
| --- | --- | ---: |
| 链接 / 控件 hover | 下划线、边线或色面增强。 | 120ms |
| ActionBoard hover / focus | 预留空间内横移 4–6px，硬阴影同步缩短。 | 180ms |
| 选择阶段 | 色脊 / 节点进入当前位置，文字状态同步。 | 220ms |
| 展开资料抽屉 | 内容向下展开，标题与来源保持稳定。 | 240ms |
| 工具下一步 | 当前组件移位，上一项留下“已完成”。 | 240ms |
| 保存草稿 | 短暂压下，显示“已保存”。 | 180ms |
| 阅读章节跳转 | 原生滚动；reduced motion 时立即定位。 | 不自动 |

硬规则：

- transform 只能在预留空间内，不引发布局重排或根级横向溢出。
- 不自动播放、不循环、不视差、不滚动触发、不漂浮粒子。
- 键盘与触控不依赖 hover 或动画理解状态。
- prefers-reduced-motion: reduce 下移除位移、翻转和 smooth scroll，只保留瞬时色面 / 边线 / 文字变化。
- 页面进入不播放品牌动画。

## 14. 响应式

### 14.1 断点

| 断点 | 变化 |
| --- | --- |
| 1280px | 方法 / 工具可以显示完整索引或右侧持续摘要。 |
| 1180px | 长文显示章节轨与正文；右侧行动进入正文流。 |
| 960px | 复杂双栏收拢；首页拼贴减少重叠但保留。 |
| 720px | 所有主要布局单栏；阶段板纵向；目录改 details。 |
| 480px | 缩小外边距与标题；顶栏保持两个等宽导航目标。 |

### 14.2 移动端硬规则

- 页面 scrollWidth 不得大于 clientWidth。
- 不用横向滑轨承载主要导航、阶段选择、工具步骤或关键资料。
- 不在页面中嵌固定高度的第二个纵向滚动目录。
- 首页至少保留一张经典桌游视觉标本；可以减少张数、重叠和胶带，但不能删光。
- 非行内交互目标至少 44×44px。
- 表单、摘要、来源、错误和说明不因空间不足隐藏。
- 长标题自然换行；不通过 12–14px 小字塞回一行。
- 200% 文本放大后无内容丢失；400% 页面缩放满足 reflow。

### 14.3 必测视口

- 320×568
- 390×844
- 768×1024
- 1024×768
- 1440×900

## 15. 无障碍与跨背景脚手架

### 15.1 结构

- 每页只有一个 main 和一个 H1。
- 使用原生 nav、button、a、details、label、fieldset、table 等语义。
- 跳到正文、章节锚点、返回来源与浏览器历史可键盘完成。
- 粘性顶栏和章节轨不遮挡焦点或锚点标题。

### 15.2 认知脚手架

每个主要入口回答：

1. 我现在可以做什么。
2. 做完会得到什么。
3. 我需要准备什么或投入多少。

内容使用三层：

- 先做一步：最低进入门槛。
- 看一个例子：通过具体桌面理解。
- 理解原理：需要时深入理论与术语。

不按年龄贴标签，不以“简单 / 高级”评价读者。专业术语首次出现时给白话解释，但保留准确术语。

### 15.3 图像

- 信息图像有准确中文 alt，说明“它帮助看懂什么”，不只写游戏名。
- 重复或纯装饰裁切使用空 alt。
- 图片不承载界面文字；概念图里的生成文字不进入产品。
- 颜色、纹理与照片不替代正文说明。

### 15.4 状态

- 当前、完成、错误、未知、保存至少用文字加颜色或形状。
- 错误靠近字段，包含原因和下一步。
- 保存使用 role=status；加载状态写清正在加载什么。
- disabled 必须解释原因，否则优先隐藏未开放动作。

### 15.5 对比与目标

- 普通文字至少 4.5:1，大文字和非文字边界至少 3:1。
- 触控目标最低 44×44px。
- 正文链接默认有下划线，不能只靠颜色。
- 焦点环在纸面、深墨、蓝、红、黄、绿上均可见。

### 16.1 固定动词

| 意图 | 动词 |
| --- | --- |
| 进入完整正文 | 阅读 |
| 进入一组内容 | 查看 |
| 执行练习 | 开始 |
| 恢复来源 | 返回 |
| 暂存 | 保存 |
| 生成本地文件 | 导出 |
| 显示细节 | 展开 / 收起 |

禁止孤立的“点击这里”“了解更多”“探索”“进入”。

### 16.2 资源记录

每条资源依次显示：

1. 中文标题。
2. 它能帮你完成什么。
3. 类型与篇幅。
4. 中文完整度。
5. 作者 / 来源。
6. 站内阅读动作。

原文标题和原始 URL 进入 SourcePlate，不与中文主标题争夺第一层。

### 16.3 全文与翻译

- 中文全文是主内容，来源链接不是替代品。
- 翻译状态、原作者、原题、许可和内部范围完整保留。
- 不在界面中反复显示“AI 翻译待核验”；以当前项目已经确定的翻译流程为准。
- 任何摘要不能冒充完整资料。

## 17. 禁止项

以下模式不得进入 V5：

- 复制任何单款游戏的整体 trade dress、品牌色组合、logo、卡框、角色或地图。
- 经典桌游照片作为按钮皮肤、表单背景、系统状态或全页壁纸。
- 悬浮白卡墙、满屏胶囊标签、玻璃拟态、发光紫渐变、模糊阴影和通用 AI / SaaS hero。
- 每个区块都使用切角、阴影、胶带和四种颜色。
- 连续多个页面都使用同一种细灰线开放列表。
- 自动轮播、无限滚动、滚动驱动动画、粒子、视差和庆祝动画。
- 文字压在复杂照片上。
- hover 才显示来源、解释或操作。
- 只有图标没有文字的主要入口。
- 把选项编号伪装成步骤，把章节位置伪装成完成百分比。
- 横向滑轨承载关键步骤或主要导航。
- 用年龄模式、积分、锁定或徽章评价学习者。
- 系统错误和危险操作游戏化。
- 未登记的网络图片进入 public 或 dist。
- 生成概念图切片进入生产界面。

## 18. 实现契约

### 18.1 Token

- tabletop-visual-tokens-v4.json 是 V4 数值的唯一源。
- 运行时 CSS 变量必须由该文件生成并在 CI 比对，避免 JSON 与 CSS 漂移。
- 新组件使用语义 token，不在多个选择器重复写十六进制色值。
- V3 变量只能作为迁移兼容层，不得继续定义新视觉。

### 18.2 组件与 DOM

- 组件按语义命名，不建立万能 Card。
- 视觉包装不能改变原生控件、键盘顺序、可访问名称和表单提交。
- 每个组件在代码中覆盖 default、hover、focus、pressed、current、disabled、loading、empty、error、success 中适用的状态。
- 色脊、胶带、装饰路线和编号若无独立信息，使用伪元素或 aria-hidden。

### 18.3 图片

- 不热链；只加载登记过的本地文件。
- 首页上折可预加载首个必要标本，其余图片延迟加载；四张构建 WebP 总体积保持在 600KB 以内。
- 图像声明尺寸，使用 object-fit / object-position 做非破坏性裁切。
- public 中不得出现 internal-reference-only 概念图。
- 视觉来源页从登记数据生成或逐项同步，不能手写后长期漂移。

### 18.4 保留功能

视觉重构不得破坏：

- 资源阶段与问题入口。
- 完整中文正文。
- section 稳定锚点。
- 方法搜索和选择。
- 工具 from 来源返回。
- 本地草稿、导出与清除。
- 刷新、复制深链、前进后退。

## 19. 验收

### 19.1 机器门

- tabletop-visual-tokens-v4.json 可被 JSON 解析。
- 生成 CSS 与 token 文件同步。
- 类型检查、生产构建和现有合同测试通过。
- public / dist 无外部图片 URL、无未登记素材、无概念图。
- 所有信息图像有 alt；装饰图像为空 alt。
- 每个页面只有一个 main 和一个 H1。
- 五个必测视口根级横向溢出为 0。
- reduced motion 媒体查询覆盖位移和 smooth scroll。
- 所有既有深链、section、from 和浏览器历史测试通过。
- Asset Register 中的 SHA-256 与仓库文件一致。

### 19.2 浏览器证据

每轮正式验收至少截图并检查：

1. 首页桌面 1440×900。
2. 首页移动 390×844。
3. 资源库 1024×768。
4. 完整阅读 1440×900 与 390×844。
5. 方法详情 1440×900。
6. 工具 1440×900 与 390×844。

同时检查键盘入口、焦点、阶段选择、资源阅读、章节跳转、方法切换、工具步骤、保存和返回来源。

### 19.3 五秒辨识

首次看到首页五秒后，测试者应能说出：

- 这是桌游设计学习资源站。
- 可以从学习、分析或问题进入。
- 页面使用经典桌游作视觉参考，但不是任何单款游戏的官网。

### 19.4 遮题识别

遮住页面标题后，测试者仍应凭构图辨认：

- 首页是展览桌。
- 资源页是资料抽屉。
- 长文是规则册。
- 方法是分析工作台。
- 工具是实验板。

### 19.5 视觉强度

- 首页首屏至少有一个大色面、一组标本拼贴和三条可区分入口。
- 移动首页保留至少一张视觉标本。
- 页面不再只由米白、深绿和细灰线组成。
- 视觉层更丰富，但首屏决定数量没有增加。
- 一屏不超过三个强调色、两种显著轮廓、一个主动作。
- 不出现通用 AI / SaaS 风格或单款游戏复制。

### 19.6 资源与权利

- 每张第三方图片都有来源、作者、许可、文件、修改、裁切、alt 与 SHA-256。
- CC BY 署名和许可链接完整。
- 站内不暗示出版方背书。
- 从内部转公开前重新审计四张现代桌游摄影。

### 19.7 无障碍

- 键盘可以完成入口、筛选、阅读目录和工具步骤。
- 200% 文本放大和 400% reflow 后内容与功能完整。
- 颜色不是任何关键状态的唯一信号。
- 真实素材不成为文字背景噪音。
- 320 / 390 / 768 / 1024 / 1440px 均无根级横向滚动。

## 20. 手册治理

任何新增视觉原语、颜色、字体、动效或第三方素材，必须同步更新：

1. 本手册。
2. tabletop-visual-tokens-v4.json。
3. VISUAL_ASSET_REGISTER_V4.md（若涉及非 CSS / SVG 自有素材）。
4. 对应组件状态测试与浏览器证据。

下列变化触发 V4.x 评审：

- 新增或改变一级入口。
- 新增页面模板或主视觉对象。
- 修改三旋钮生产上限。
- 引入新字体、插画系统或第三方图库。
- 网站从内部学习转为公开、对外演示或商业分发。

本手册不是“给页面加桌游装饰”的清单。它是用桌游的组件感、路径感、局面感和可拿取性，重新组织资源、阅读与行动的正式规则。
