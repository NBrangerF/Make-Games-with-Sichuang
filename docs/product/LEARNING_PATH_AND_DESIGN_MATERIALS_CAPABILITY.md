# 学习入口与设计材料库能力合同

状态：implementation-ready  
日期：2026-08-26

## CAPABILITY

第一次接触桌游设计的学生，可以按自己当前的真实状态进入合适的活动：先做一个微型游戏、系统练习、推进已有原型，或解决一个具体问题。学生还可以浏览 mechanic 与 theme 设计材料，把一张材料牌转成可观察的玩家动作、桌面变化和一个小型原型问题，而不是停留在名词清单或“最佳组合”推荐。

## CONSTRAINTS

### 固定产品规则

- `Learn` 不再把一条专业迭代流程包装成从零到发布的统一课程。
- 当前 1—5 节保留为“观察实验室”；当前迭代方法重排为“问题—证据—最小原型—执行测试—复盘—改版”的循环。
- 盲测、设计交接、商业发布是后期支线，不是所有学生的必经终点。
- 前台仍然呈现一个个节点、一种思维、一个工具和一次动作；不出现能力等级、能力评分或统一年龄分级。
- mechanic/theme 材料只能生成候选与比较问题，不能宣称某个组合最好、一定有趣或适合某类玩家。
- 机制牌必须说明玩家反复做什么、桌面状态怎样变化、常见风险和一个可落桌练习。
- 主题牌必须说明玩家处在什么位置、会重复做什么、哪些关系进入系统、需要留意哪些省略或伤害风险。
- 学生完成记录区分“已起草、已落桌、已测试、已修订”；非空文本只能证明留下草稿，不能自动证明完成真实测试。
- 内容本地优先，继续使用浏览器存储；不新增账号、云同步、排名或自动评分。
- 新入口必须保留现有节点、工具、资源和方法深链。

### 内容边界

- 材料库是中文教学用设计材料，不复制受版权保护的机制百科或课程正文。
- 分类服务于寻找与比较，不宣称是一套穷尽所有游戏的标准本体。
- 年龄、工具和具体游戏类型可以作为使用语境，但不决定固定学习顺序。
- 主题不等于美术皮肤；若玩家行动、奖励与后果没有承载主题关系，页面必须明确指出这一边界。

## IMPLEMENTATION CONTRACT

### Actors

- 第一次做桌游的学生：需要在 60—90 分钟内留下可运行的微型原型。
- 想系统学习的学生：需要经历观察、多个受限小挑战和一个完整项目。
- 已有点子或原型的设计者：需要进入证据化迭代循环。
- 被具体问题卡住的设计者：需要直接进入现有问题型资源馆。
- 带领者或教师：需要短句、约束题和可以核对的可见产物，而不是代替学生作答。

### Surfaces

1. `#learn`：按四种用户状态分流的学习首页。
2. `#learn/first-tabletop`：第一次落桌挑战，调用 mechanic/theme 材料并生成微型原型简报。
3. `#learn/workshop`：基础设计工作室地图，按“先看—多做—深做”组织活动和产物。
4. `#learn/observe`：观察实验室，明确分析对象是实际玩过的游戏。
5. `#learn/iteration`：原型迭代主线，明确前置条件并呈现循环而非毕业轨道。
6. `#learn/mechanics`、`#learn/themes`：两类设计材料库。
7. 稳定的 `#learn/node-XX` 深链：继续打开单个节点。

### States and transitions

```text
未开始
  → 已起草：已留下当前节点要求的文字或选择
  → 已落桌：已经制作并实际运行相关材料
  → 已测试：已经与本轮问题一起完成一次测试并留下现场记录
  → 已修订：已经根据记录形成下一版本决定
```

- 每个节点声明当前动作至少对应哪一个状态。
- 页面允许用户诚实记录更高状态，但必须解释每种状态代表的真实动作。
- 路线进度展示“留下了什么 / 做到了哪里”，不转译为学习能力或作品质量。

### Mechanic material interface

每条 mechanic 至少包含：

- 名称与一句白话解释；
- 玩家反复动作；
- 直接改变的桌面状态；
- 它常制造的取舍；
- 常见失效方式；
- 一个 10—20 分钟可完成的小练习；
- 材料与互动标签；
- 可与哪些 theme 问题产生比较，但不输出最佳搭配。

### Theme material interface

每条 theme 至少包含：

- 主题起点与玩家位置；
- 玩家会重复执行的动作；
- 值得进入规则的关系或压力；
- 一条避免只换皮的系统问题；
- 研究、协作、内容提示或退出选择方面的注意事项；
- 一个 10—20 分钟可完成的小练习；
- 语境与情绪标签。

### Data and validation

- 权威内容文件：`content/design-materials.json`。
- TypeScript 目录：`src/design-material-catalog.ts`。
- 内容门必须验证唯一 ID、必要字段、最低数量、交叉引用和禁用承诺语。
- 页面必须支持关键字与标签筛选，并在手机端不依赖横向滚动。
- 第一次落桌的选择保存在独立、可迁移的本地 schema 中。

### Failure and recovery

- 没有选择 mechanic/theme 时，挑战页应给出明确的下一动作，不生成空简报。
- 内容加载失败时保留学习首页和已有本地记录，并给出重试入口。
- 旧版节点进度需要读取迁移：旧 `completedNodeIds` 映射为“已起草”，不能自动映射为“已测试”。

## NON-GOALS

- 本轮不建立账号、班级管理、社区互评或导师后台。
- 不声称提供完整的全球机制分类或题材清单。
- 不根据年龄、玩家画像或主题自动推荐“最适合”的机制。
- 不用抽卡代替设计判断；随机功能只能给出待比较的约束。
- 不在第一次落桌路线中要求盲测、出版、制造、合同或众筹。
- 不删除现有长文、资源库、工具工作台或项目护照。

## OPEN QUESTIONS

- 真实课堂测试后，mechanic/theme 首批材料的数量和标签是否过多，需要通过参与者观察决定；自动化检查不能替代这项证据。
- 同伴评议、导师反馈与公开测试活动属于后续独立能力，当前产品架构只保留入口空间。
- 多项目与云端同步需要先完成所有工具记录的 `project_id` 迁移，不能由标题或日期猜测归属。

## HANDOFF

按以下顺序直接实施：

1. 建立 mechanic/theme 内容数据与校验；
2. 新建四状态学习首页与材料库；
3. 新建第一次落桌与基础工作室；
4. 将节点拆成观察实验室和原型迭代循环，调整状态与旧数据迁移；
5. 接入路由、视觉、移动端和无障碍；
6. 执行内容、类型、构建、浏览器与生产发布验证。
