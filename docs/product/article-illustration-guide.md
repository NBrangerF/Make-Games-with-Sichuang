# 文章图解规范

一桌点子 / Make Games with Sichuang · 2026-09-14

用户确认喜欢首页右侧的二十四格棋盘。后续文章尽可能用同类示意图帮助理解。图应解释正文的具体关系，和文章一起编写、核对、维护。

## 何时使用

- 涉及空间、路径、落点、资源流向：画出具体组件和变化。
- 涉及结算时序、中间状态、控制权：用逐步图，显示这一步轮到谁、哪些结果还可改变。
- 比较两条规则：固定局面、骰面和其他条件，允许切换；明确实验版本。
- 讲概率：显示样本空间、分母、成功条件和假设，区分固定枚举与模拟。
- 涉及体验、情绪或测试结论：图只能解释假设或记录方法，不能把示意当作真实玩家证据。

不按“每篇固定几张”配额添加。纯观点、来源评价、邀请或反思段落不必硬做棋盘。案例研究使用按规则关系自行绘制的图，不将原创简图误称完整对局，也不直接复制商业游戏组件。

## 图与文字如何配合

1. 先用一段具体局面引入问题，再让图出现在解释这一关系的小节末尾；之后正文继续推进。
2. 一张图集中回答一个问题。按钮表示预设局面或结果时，明确说明，不能让人误以为可在游戏里自由挑选随机结果。
3. 标明起点、中间落点、最终位置、方向或数量。颜色之外也使用文字、数字、线形与符号。
4. 中英文共用同一套模型，所有标题、标签、按钮、说明和无障碍文本均随阅读语言切换。
5. 采用首页纸面风格、清楚的线条和少量颜色；可操作控件至少 44px，手机上换行；不自动播放。
6. 操作就地显示结果，允许比较或重看，不写入用户的学习进度。没有操作时，正文仍应包含完整解释。

## 维护

`src/article-figure-catalog.ts` 将文章 ID 与中英文准确小节标题对应；文章从课程或独立阅读入口打开时共用插入逻辑。图解位于 `src/article-figures.tsx`，棋盘共用 `src/race-board.tsx` 与既有 `src/race-model.ts`，不添加第三方运行时。

编辑小节标题时同步更新图示定位。运行 `pnpm qa:article-figures`，检查两种语言的正文位置、图示唯一性、练习共存和英文标签。修改规则结果时，再跑 `pnpm qa:race-course`，并用浏览器操作受影响的分支。新增图示应先读两种正文，再选表达方式。
