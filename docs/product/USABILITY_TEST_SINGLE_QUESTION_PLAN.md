# 新手可用性测试：单问题测试计划

状态：protocol-ready / sessions-not-run  
日期：2026-08-21

## 参与者与材料

招募 3–5 名能用中文阅读、做过不超过两个原创原型的新手。使用一份已经保存的原型范围；准备实体版本和一份线上替代版本。形成性测试不做统计外推。

## 主持边界

先让参与者自己操作；除安全、设备故障或任务明确允许外不解释字段。所有帮助记录时间点、触发和影响。参与者可跳过问题、停止录音或退出，不需要说明理由。

## 任务

### T1 承接但不被替代

从原型范围继续，打开抽屉并显式导入。参与者应能指出哪些字段来自上一步，哪些仍要自己决定，并确认页面没有自动推荐参与者或主持方式。

### T2 只留下一个主问题

面对三个想知道的问题，选择一个主问题，把其余放入停车区，写出可见行为预测和反驳信号。观察是否把“玩家觉得有趣”当作事件。

### T3 写成可执行观察协议

让另一位主持人仅凭记录写出：何时开始、记录什么事件、每条写什么、重复到何时、何时停止、哪一项保持不变、哪一项改变。

### T4 声明帮助与证据语境

填写参与者经验、玩家配置/关系、媒介、主持允许与禁止行为、记录同意和安全停止。切换到线上，解释警告意味着哪些实体证据仍待复核。

### T5 从证据到下一步

写一个不带机制答案的开放追问，并分别说明支持、反驳和未定时下一步怎样处理。保存、刷新、导出，再从项目完整包找到 `test_plans`。

## 通过门

- 4/5 参与者能在一次非答案性提示内区分主问题、预测与反驳信号；
- 4/5 能分开局中事件和局后自我报告；
- 所有人都能找到主持允许/禁止和主动停止；
- 导入、刷新、保存、二次清空、下载、项目导出无数据丢失；
- 375px 下无页面级横向溢出，四步轨道可局部滚动；
- 没有人把证据链完成态解释为通过分、因果证明或发行就绪。

这些是本产品的形成性退出条件，不是桌游行业标准。若两名以上参与者把“预测行为”写成感受评分，优先改字段示例；若把“导入”理解为系统结论，必须加强来源只读区和非推断提示。
