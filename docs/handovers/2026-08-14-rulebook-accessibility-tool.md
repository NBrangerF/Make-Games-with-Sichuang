## 产品决定与证据边界

1. **不生成总分**：无障碍是玩家、任务、组件功能、媒介和语境共同产生的结果。总分会丢掉私人信息、自主决策和协助成本。
2. **先写实际动作**：记录停顿、靠近、旋转、误拿、询问、跳过或使用辅助技术，不根据诊断猜需求。
3. **玩家策略与外部协助分开**：如果记录了外部协助，但没有写它是否暴露信息、代替决定、增加时间或改变体验，工具拒绝保存。
4. **只复测一个改变**：产出是“单一改变 + 同一任务的可观察成功信号”，不是“已变得更无障碍”的抽象结论。
5. **不替代共同设计**：当前工具是记录容器，不代表残障玩家经验，也不能代替真实玩家测试。

## 限制与不能声称的结论

- 盲人/低视力研究可以支持当前核心字段，不能代表全部残障或全部地区/游戏类型。
- 还没有真实新手、残障玩家或无障碍专家使用这个工具。不能声称它易用、有效或会改善游戏无障碍。
- 尚未验收 Safari、Firefox、屏幕阅读器、键盘全流程、大字号/高缩放和不同打印条件。
- 应用内浏览器本轮无可靠视口缩放和下载事件接口；移动和导出由仓库独立回归补充。

## 建议的下一工作包

1. 用现有可用性模板进行 3–5 场任务测试：至少包含一名新手设计师，并在获得同意的前提下邀请有相关生活经验的玩家。
2. 按“运动/触达、听觉/沟通、认知/记忆、情绪/安全、社会/经济”分五条研究链扩充来源，不用盲人/低视力样本替代其他经验。
3. 根据真实使用修订字段顺序、必填条件、提示语和导出格式，不在测试前扩充更多标签。
4. 建立失效链接巡检、来源最后核验日期和资源提交/审阅工作流，开始处理内容维护而不只是扩容。
