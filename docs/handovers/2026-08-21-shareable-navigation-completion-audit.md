# 可分享导航与总目标完成度审计交接

日期：2026-08-21  
状态：implemented / partially browser-verified

## 本轮解决的问题

完成度审计发现：网站已有大量内容与工具，但目的地只存在于 React 内部状态。用户无法收藏资源库、分享某个工具或在刷新后继续当前位置；同时浏览器 QA 把 549、556、31 等历史数量硬编码在脚本中，内容增长后会产生假失败。

本轮把最高优先级缺口收敛为“可分享 URL 导航 + 非漂移 QA 契约”，没有新增视觉语言或第二十项工具。

## 实现

- 新增 `src/url-state.ts`，集中解析、序列化四个主视图与十九项工具路由，并提供路由标题。
- 顶部品牌与主导航改为真实链接，活动态使用 `aria-current="page"`。
- 指南工具入口、工具标签与开始主持动作写入规范 hash；刷新保持当前工具。
- 应用监听 `hashchange`/`popstate`，主动导航使用 `pushState`，无效地址用 `replaceState` 规范化。
- 每个主视图都有 `#main-content`，页面增加“跳到主要内容”。
- 浏览器 QA 的资源数与阅读入口数改为从权威 JSON 派生，清除旧硬编码。
- 新增 `pnpm qa:url-navigation` 八组守卫，并在浏览器脚本加入深链、刷新与后退场景。

## 验证结果

- `pnpm qa:url-navigation`：8/8。
- `pnpm check`：通过。
- `node --check scripts/qa-site.cjs`：通过。
- `pnpm build`：通过；内容门禁确认 574 条资源、34 个入口、322 条 Claim、31 篇专题指南、287 个术语与 57 份本地资料。Vite 转换 44 个模块，主包 498.15 kB（gzip 152.22），方法目录 502.51 kB（gzip 166.61），资源目录 803.61 kB（gzip 213.80）；大 chunk 警告仍是性能待办，不是加载失败。
- 应用内浏览器桌面烟测：`#path`、`#resources`、`#tools/core-loop` 均能加载；核心循环刷新保持；标题和活动导航同步；资源页显示 574 条与 34 个入口。
- 应用内浏览器 390×844：`scrollWidth = innerWidth = 390`，工具深链、标题、活动导航和主地标成立。
- 系统 Playwright 完整回归：未通过环境启动门。Chrome 在页面创建前 `SIGABRT`，清理返回 `kill EPERM`；这不是产品断言失败，也不能被写成全套通过。

## 下一工作包

最高价值的下一步是“公开试用与新手形成性测试准备”，不是继续扩资源数量：

1. 用户选择静态托管目标后，建立可回滚的试用地址；
2. 将定位、资源发现、意图→测试记录和导出整理成一场 30–45 分钟主持包；
3. 先用 2–3 人找阻断并修订，再扩到章程要求的 5 名定位与 4 名闭环；
4. 在允许 Chromium 的 CI/外部环境运行完整 `pnpm qa`；
5. 设计辅助 T1–T6 与本地资料公开候选保持独立门禁。

## 不得越界的结论

可分享 URL 已有结构和应用内浏览器证据，但整站端到端、键盘、屏幕阅读器、跨浏览器和真人可用性没有签收。574 条资源表示当前策展库规模，不表示网络已搜尽；十九项工具表示实现数量，不表示它们已改善设计质量。
