# 发现沿革、只读重开与后继修订交接

日期：2026-08-21  
阶段：Phase 1 / 第 19 个正式工具的第二次证据链加固  
状态：实现、内容与静态验证完成；真实浏览器受环境限制

## 本轮完成

“发现演化与版本证据”从一次性保存升级为可复用沿革：

- 已保存记录可以从历史列表只读重开；
- 旧记录不会出现编辑控件，也不会被再次保存覆盖；
- 内容变化必须创建新 UUID 的后继修订；
- 后继保留 `lineageId`、递增 `revision`、直接 `parentRecordId`，并强制填写 `revisionReason`；
- 可以从旧修订创建分支，编号取沿革当前最大值加一，父记录仍指向实际选择；
- “最新”只表示顺序，界面不把它表达为正确、成熟或已批准；
- 项目下一步只能从只读打开的已保存记录显式复制；
- 会话撤回兼容 v1/v2，并沿父记录关系清除所有后继与未完成后继草稿；
- v1 记录保守迁移到 v2，不猜测不存在的父子关系。

## 数据契约

存储键保持 `tabletop-workshop-evidence-syntheses-v1`，内部结构升级为 `schemaVersion: 2`，以便原浏览器数据继续被同一键读取。完成记录字段新增：

```text

```

导出升级为 `schema_version: 2`，并声明 `immutable_completed_records` 与 `explicit_successor_revision`。详细状态转换见 `docs/product/CROSS_SESSION_FINDING_EVOLUTION_CONTRACT.md`。

## 已知限制

1. 当前历史列表按保存时间排列，尚未提供搜索、按沿革折叠或长历史虚拟化。
2. 本地存储没有跨标签页冲突解决、云同步、用户权限或合并分支。
3. 沿革只有直接父记录，不提供自动差异比较或“当前批准版本”。
4. v1 迁移只做保守字段补全，尚未用真实用户旧数据样本执行浏览器迁移测试。
5. 撤回只能控制本站当前浏览器存储；站外 JSON、录音、照片和其他副本需分别处理。

## 下一步建议

优先在允许本地端口的环境执行 `docs/product/USABILITY_TEST_FINDING_LINEAGE.md`：验证只读预期、后继理由、旧修订分支、v1 样本迁移、撤回全后继，以及 1440×900、1000×800、390×844 三个视口。若真实新手能理解沿革，再考虑“同一沿革折叠 + 修订差异摘要”；不要先引入自动合并、批准状态或证据评分。
