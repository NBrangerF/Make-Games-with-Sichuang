# 资源网站 V2 当前进度快照：导航减法与工具入流

日期：2026-08-22  
构建标识：`resource-v2-05`  
阶段状态：已实现并通过静态、类型、桌面与移动浏览器验收  
预览：`http://127.0.0.1:8017/?build=resource-v2-05#resources`

## 1. 本阶段结果

这一轮没有增加首页功能，而是把现有基础继续做减法：

- 顶栏从四个入口减为两个：`找资料`、`方法与概念`。
- `设计路径` 暂时从可见导航隐藏；旧 `#path` 深链继续有效。
- `中文知识` 更名为 `方法与概念`，并先让读者按任务选择，而不是先面对内容目录。
- 独立的“辅助工具”货架从可见导航与工具页移除。
- 工作单被嵌入已经选定的资料主题、学习入口、完整学习单元或分析问题；每个语境只给一至两个动作。
- 工具完成后能够回到确切来源，而不是统一回到资源首页。

当前内容基线没有变化：8 份本站完整学习正文、3 篇开放许可完整中文译文、5 篇原创设计师案例综合，共 16 个 `authoritativeItems`（`8 + 3 + 5`）。

## 2. 当前信息架构

### 顶栏

1. 找资料
2. 方法与概念

`#path`、`#tools/<tool-id>` 与旧 `#method/resource-reading/<item-id>` 仍可刷新、分享和恢复，但不再占用一级导航。

### 找资料

首页仍只问三个问题：

1. 开始学习桌游设计
2. 从设计师角度分析一款游戏
3. 按正在解决的设计问题找资料

工作单只有在读者完成一次语境选择后才出现。当前映射覆盖：

| 语境 | 覆盖 | 规则 |
| --- | ---: | --- |
| 具体问题资源入口 | 34 / 34 | 每个入口 1–2 个工作单 |
| 完整学习内容 | 16 / 16 | 读完正文后出现 |
| 游戏分析问题 | 5 / 5 | 四步分析脚手架之后出现 |
| 学习方式入口 | 4 / 4 有显式记录 | “系统性学习”在具体单元内给工具，其目录页不重复给 |

20 种既有工作单都至少在一个明确语境中出现，没有未知工具 ID，也没有超过两个动作的语境。

### 方法与概念

默认页先显示三个普通任务：

1. 解决一个具体任务
2. 理解一种分析方法
3. 查一个设计词

进入后才显示 `专题指南 / 理论框架 / 概念词表` 三个局部标签。旧“资源怎么读”仍可通过深链恢复，但不再作为平行标签出现。

## 3. 关键路径

资源与工具主路径：

`#resources` → `#resources/problems` → `#resources/first-prototype` → `#tools/prototype-scope` → 返回 `#resources/first-prototype`

学习单元路径：

`#resources/learn/systematic-unit-04-minimum-prototype` → `#tools/prototype-scope` → 返回原单元

方法路径：

`#method` → `#method/frameworks`

直接打开旧 `#tools/<tool-id>` 时，顶栏不制造错误的当前项；如果没有来源历史，返回操作回到 `#resources`。

## 6. 仍然存在的边界

- `scripts/qa-site.cjs` 是早期全站历史脚本，仍按可见“设计路径”导航执行；它不是本阶段的权威 V2 浏览器门。当前权威脚本是 `scripts/qa-resource-v2.cjs`。
- 工具映射目前是编辑契约，没有逐条保存 `sourceGuideId` 来源谱系；以后若自动生成映射，需要先补这一字段和守卫。
- 隐藏旧入口不等于删除旧功能。后续若真正移除路由，必须另做迁移与本地数据审计。
