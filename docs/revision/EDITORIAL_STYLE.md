# 落桌双语编辑准则

本准则服务于桌游设计学习网站。目标是让第一次做游戏的人顺着例子读懂一个问题，也让有经验的读者迅速找到有用的分析。它依据本次用户反馈制定，不是对用户个人文风的模仿。

## 先让人遇见问题

开头给一个能想象或摆出来的处境：桌上有几个点子，不知道先做哪个；棋子没有移动，回合却已经过去；手里有素材，播出卡却不能再用。读者知道困惑在哪里以后，再解释“设计简报”“状态”“行动选择”。

不必每篇都以问句开头。操作、对话、一个意外结果，都能开始文章。虚构对话须用“设想”“例如”等语境说明，不能编造试玩、采访或读者反馈。

## 每一段接着上一段往前走

先摆局面，再走规则，解释为什么出现这个结果，最后看一次修改。每节承担不同工作，不机械套用四段模板。已解释过的知识只在用到时短暂提醒。

保留蛇梯棋主线、过河替代路线和各自完整规则。延伸文章可从任一路线进入，也应能独立读懂。用“选择版 C”“重掷版 R”等名称介绍不同草稿，之后尽量用有意义的名称；比较多个版本时保留字母以免混淆。

结尾留在刚讲过的例子或一个可做的动作上。章节导航已说明后续内容，正文无需每篇再写“下一章将深入探讨”。若需要收起一个变体、回到基本版，必须保留这个规则交接。

## 准确的限制，放到用得上的地方

数学计算保留假设、位置、计时范围和适用条件。真实游戏保留版本、出处、作者原意与本站分析的区分。独立规则必须自足，不能依赖读者看过前章。

避免每段都补一次“这并不证明好玩”“不是成功保证”。教学场景的身份在课程开头交代；具体场景仍用设想、摆出、试一试等措辞。谈真实测试时明确区分计划、观察、提示与解释。

不为了让文字顺口而删掉概率限制、随机独立性、每回合上限、支付时点、胜负条件或版本差异。

## 中文与英文各自写顺

一个内容版本，两种语言。保持论点、规则、人物、数字和例子一致；句子可以拆分或合并，无需逐句保持同构。

中文优先使用熟悉动词：“摆出”“选”“走完”“留下”“看看”。例如，把“检查动作的可执行性”改成“请人照说明走完这一回合”。避免把所有判断写成“提供许可”“建立可理解性”“形成闭环”。

英文以明确的人和动作作主语。优先写 “Ask someone to complete a turn”，少写 “examine whether the action is executable”。保留自然长短句，不把每句话都切成广告式短句。被动语态和限定词按语境保留，不能为工具分数而删除。

中文案例显示中文游戏名；需要辨认版本或查询出处时保留英文名和版本号。英文新主线标题统一 sentence case，游戏专名保留大小写。

## 让界面给正文让路

目录摘要说明这一章会遇到什么问题，不罗列一串研究名词。练习标题说要做什么，提示写具体步骤。正文里的练习默认收起，读者需要时展开；侧栏入口能展开并定位输入框。版本核查、工具和来源留在相应入口，避免把阅读变成流程确认。

## 本地检查

本轮使用 `ecc:article-writing` 的例子优先、每节推进、删去模板句方法，以及 `ecc:brand-voice` 的语气一致性检查。未建立个人声音指纹。

采用开源 [write-good](https://github.com/btford/write-good) 1.0.8（MIT）作编辑辅助，通过其 custom checks 接口加入中文与英文本站规则。仅作开发依赖，不进入网页运行包；不使用付费 API 或外部文本上传。

运行：

```sh
pnpm copy:style --output /tmp/luozhuo-style-review.json
```

检查覆盖两条课程、延伸文章、案例与机制资料库的中英文正文。结果是逐文件、逐行的复查清单，包含内容指纹；不是 AI 检测器，也不评价论证是否成立。未自动改写，未把所有警告视为错误。英文只开冗词、陈词与重复词检查，关闭对所有被动语态、限定词和副词的一概质疑。

文字改完后先运行 `pnpm search:index`，再运行 `pnpm copy:audit`，然后 `pnpm build`。搜索索引也参与内容指纹，顺序不能倒置。

## 投稿或后续改稿的复查顺序

1. 从开头读到结尾，确认每段引出的疑问在后面得到处理；不靠小标题勉强拼接。
2. 把例子按规则走一遍，核对关键结论是否仍成立。
3. 对照两种语言的主张、人物、数字、版本与例子，不要求句法相同。
4. 核对标题、目录摘要、练习字段及示例指向同一个任务。
5. 在桌面和手机上读一段正文，检查插入内容、标题换行和练习展开。
