# 节点文案规则

## 前台语言

- 每个节点只解释一种关系。
- 先给例子，再给术语。
- 一个段落只承担说明、示例或动作中的一种工作。
- 每个节点主动出现的概念不超过三个。
- 完成信号必须描述看得见的产出，不写“已经理解”。
- 不使用能力等级、掌握程度、经验值或综合评分。
- 来源和限制保留在折叠层，不抢占当前动作。

## 统一说法

| 方法语言 | 主线语言 |
| --- | --- |
| 反驳信号 | 什么情况说明你猜错了 |
| 冻结版本 | 记下这次使用的版本 |
| 参与者语境 | 这次是谁在玩 |
| 证据边界 | 这次还不能说明什么 |
| 单一变化轴 | 下一版只改哪一处 |
| 运行证据 | 实际发生了什么 |
| 迁移假设 | 换一个游戏后还成立吗 |

## 页面顺序

1. 当前节点与全程位置
2. 一句话思维
3. 一个具体例子
4. 当前动作
5. 一个轻量工具
6. 完成信号
7. 下一节点
8. 折叠的支线、概念、来源和限制

## 工具规则

- 轻量工具只收集完成本节点所需的一个结果。
- 完整工作台是同一工具的深入版本，不作为第二个并列任务。
- 保存节点草稿不等于完成；用户主动勾选完成后才更新进度。
- 节点进度只记录完成与当前位置，不生成质量判断。
