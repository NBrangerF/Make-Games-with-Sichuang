# 专项指南：这轮应该怎么测试

状态：review  
阶段：测试与反馈  
核心阅读：8 分钟  
关联 Claim：`claim-playtest-mode-follows-question`

## 你可能卡在这里

你知道游戏需要测试，却不知道该自己多跑几次、找熟人、去设计师社群，还是直接把规则书交给陌生人。你担心“测试方式选得不够高级”，于是不断找更多人，却没有先说清这轮要知道什么。

## 读完带走

一份测试方式决定单：本轮问题、建议方式、设计者角色、需要的测试者、停止条件，以及这轮不能推出什么。

## 先看一个具体判断

当前问题是“玩家会不会为了下一个港口保留高价值货物”。系统刚改完货舱容量，回合流程可能会断。

此时不需要规则盲测。先由设计者同时操作两方，跑到第二次交货；只要出现无法继续、无选择或货物不够，就停止修改。自测稳定后，再找两名没有参与改动的玩家，由设计者讲解并观察真实取舍。

## 五步选择

### 1. 把问题改写成可观察事件

不要写“游戏好玩吗”。写清谁在什么局面会做什么，以及什么结果会反驳你的假设。

示例：玩家在能立刻得 3 分时，会至少一次保留货物等待下一港口；若所有人总是立即交货，假设不成立。

### 2. 先判断失败成本

如果系统仍可能在几分钟内卡死、无限循环、无人有合法行动或组件数量不足，先自测。不要把尚未运行的系统交给测试者替你排错。

### 3. 决定设计者能否影响答案

- 需要随时改规则、加组件或缩短片段：设计者在场并主持；
- 需要观察玩家未经提示会做什么：设计者讲完后退到观察角色；
- 需要检查陌生人能否只靠交付包学习：进行局部或完整盲测；
- 需要知道目标受众是否能理解、触达或接受：招募具备相应语境的玩家。

### 4. 选择最低成本的足够方式

| 当前问题 | 优先方式 | 设计者角色 | 主要盲点 |
|---|---|---|---|
| 规则能否运行、循环是否卡死 | 自测 / 快速测试 | 可以暂停和改动 | 不能证明多人策略与社交体验 |
| 玩家是否出现目标行为 | 引导测试 | 讲解后观察，少提示 | 讲解可能掩盖规则书问题 |
| 不熟悉项目的人怎样理解系统 | 外部测试 | 说明目标，避免辩护 | 测试者未必是目标受众 |
| 设置、教学或查询能否自主完成 | 局部盲测 | 不解释，记录偏离 | 不能证明整局体验成立 |
| 完整交付包能否脱离设计者运行 | 整局盲测 | 不在场或保持沉默 | 成本高，太早会混入系统缺陷 |
| 极端人数、资源或策略是否破坏系统 | 极限测试 | 明确要求尝试边界 | 不代表常规玩家行为 |

### 5. 写停止条件与下一步

测试不是必须玩到结算。写清观察几次核心决定、出现什么问题立刻停止，以及下一轮回到哪种方式。

示例：三回合或第二次交货后停止；若第一回合没有合法行动，立即停止并回到自测。

## 常见误区与修复

### “盲测比自测高级，所以越早越好”

修复：把盲测理解为测试“自主使用”的方法。系统还会现场改规则时，盲测只会把系统断裂与文档断裂混在一起。

### “朋友说好玩，已经可以公开测试”

修复：熟人能帮助你度过早期断裂，但关系会影响坦率度。系统稳定后，找与项目没有投入关系的测试者。

### “一次外部测试要问完平衡、时长、规则和市场”

修复：只保留 1–3 个主问题。其余异常可以记录，但不要让它们自动改变本轮判断。

### “线上测试更方便，所以等于实体测试”

修复：先列出媒介删掉的信号。触感、视线、桌面空间、设置劳动和身体协作可能无法在线上观察。

## 20 分钟练习

选择当前版本最想知道的一件事，填完：

```text
版本：
本轮问题：
预计行为：
反驳信号：
建议方式：
设计者角色：
需要的测试者：
停止条件：
这轮不能推出：
```

示例产出：v0.4；问题是玩家是否保留货物；先双人引导测试；设计者只讲解一次；需要两名熟悉轻中策但没看过本项目的玩家；三回合停止；不能推出规则书已经清楚或四人平衡成立。

## 完成信号

- 问题描述的是可观察行为，不是总体评价；
- 选择方式的理由能回到问题和系统稳定度；
- 写清设计者在场时可以和不可以做什么；
- 有停止条件，不强制完整结算；
- 至少写出一项这轮不能证明的结论。

## 证据边界

测试分类来自 [TTGDA](https://www.ttgda.org/in-person-playtesting)、[Break My Game](https://www.breakmygame.com/codeofconduct)、[Board Game Design Lab](https://boardgamedesignlab.com/playtest-like-a-boss/) 和设计师实践的综合。它们能提供做法与反例，不能证明固定顺序或某种方式普遍更有效。本站的决策表是项目推断，需要通过新手使用测试修订。
