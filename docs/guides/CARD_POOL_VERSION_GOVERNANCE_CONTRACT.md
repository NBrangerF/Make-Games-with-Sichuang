# 卡池与版本治理契约

不要先宣布“全部兼容”。先回答：谁拿着哪一版，在什么模式里，用哪份规则，可以怎样组合，发生变更后要做什么。

## 一、给内容建立护照

为每张牌、模块或组件保存稳定 ID，并分开记录：印刷文字、当前文字、获取方式、实际出现频率、理解/桌面/战略复杂度、系统角色与强度风险。稀有度不能替代这些字段。

## 二、画兼容矩阵

行写基础版与印次，列写扩展、模块、人数、模式、语言、规则版与组件版。每格只能写：已验证、声明支持、未知、互斥、需替换、已停止支持，并连接测试记录或理由。

## 三、指定单一事实源

明确当前规则、当前卡文、FAQ/裁决、变更日志、历史归档和打印替换材料分别在哪里。每项修订标为错字、澄清、技术修复、平衡改动或功能重做，并写生效范围。

## 四、把治理画成时间线

分开写预览/发售、玩家可获得、休闲可用、赛事合法、变更生效、复查、撤回或归档日期。试行禁限或解禁必须有观察问题、回退门和结论日。

## 五、跑配置回归与迁移任务

先排除规则上无效组合，再覆盖核心路径、直接邻接组合、旧版代表配置、最高风险多项交互及教学/无障碍任务。让旧版持有者实际完成识别版本、找到当前文本、替换组件、分拣、教学和恢复游玩；每轮只修一个治理断点。

## 完成信号

- 任一组件能从稳定 ID 追到印刷版、当前版和变更理由。
- 任一组合都能看出证据状态，而不是只看到“兼容/不兼容”。
- 玩家不用在新闻、论坛和多份 PDF 中猜哪份文字当前有效。
- 试行变更有生效、复查和回退日期。
- 旧版玩家能完成一次真实迁移任务，劳动和不可覆盖事项被记录。

## 不能推出

完成契约不证明扩展平衡、值得购买、适合所有玩家或可以永久兼容；它只让承诺、证据、变更与迁移成本可见。
