# 专项指南：用一个任务记录无障碍障碍

## 你要得到什么

玩家从桌子对面读不到港口需求，请同伴代读后完成了交货。但代读同时暴露了他准备保留的私人货物。

若记录只写“在帮助下完成”，设计者会错过自主性和策略隐私已经改变。

读完本指南，你会得到一张不含总分的任务观察单：版本、媒介、具体任务、实际动作、阻碍、受影响的组件功能、协助与代价、玩家原话和复测实验。

## 1. 冻结版本、媒介和一个任务

不要测试抽象的“视觉无障碍”。写清玩家要做什么：

- 识别组件；
- 打开包装、取出组件与收纳；
- 完成设置；
- 从桌面读取公共或私人状态；
- 拿取、移动、洗牌或计数；
- 选择并执行动作；
- 查询规则或图标；
- 与其他玩家沟通；
- 完成结算。

同时记录版本、实体/线上/混合媒介、座位、光照、桌面距离、沟通节奏和相关组件精度。

线下活动还要把“抵达”当成任务：交通、入口、通道、座位与桌面、厕所和退出路径分别记录，并注明核验日期。笼统的“无障碍场地”和多年前的店家清单都不能替代当次路径资料。

海上贸易例：`v0.7 实体桌；玩家坐在长边，从自己位置读取三座港口需求并选择一座交货。`

## 2. 先写实际动作，再写障碍判断

优先记录可以回看的动作：停顿、靠近、旋转组件、误拿、询问、跳过、放弃、记忆、使用放大镜或屏幕阅读器。

写“玩家两次把港口板转向自己，靠近到约 20 厘米，仍把蓝色需求读成绿色”，不要直接写“玩家视觉能力不足”。后者既不是可验证观察，也把设计责任推给玩家。

## 3. 指出受影响的信息或组件功能

同一张卡在不同用途中会产生不同障碍：

| 功能 | 需要追问 |
|---|---|
| 公共状态 | 能否从不同座位和距离独立读取？ |
| 私人状态 | 请求帮助会不会暴露策略？ |
| 随机器 | 结果只需瞬时识别，还是要持续记住？ |
| 计数器 | 触摸或移动时是否会破坏当前数值？ |
| 空间关系 | 玩家能否定位、触达并恢复被移动的布局？ |
| 规则查询 | 信息能否被找到、暂停、重复和按需展开？ |

海上贸易例：港口板承载所有人都需从远处读取的公共状态，不是只在手中查看的私人卡牌。

接着把暂定障碍单独写出来，例如“公共状态只用相近颜色表达，且必须从长边远距离读取”。这是一条关于任务要求与当前设计错配的假设，不是对玩家能力的诊断。

## 4. 分开玩家策略、外部协助和协助代价

玩家可能先使用自己的经验、记忆、触摸、放大设备、读屏或重新摆放。不要把这些行为都写成他人帮助。

若他人提供协助，把协助者视为系统中的一个角色，继续记录：

- 谁做了什么；
- 他看见了哪些公共或私人信息，在什么时点介入；
- 是否代替玩家作出决定；
- 是否暴露私人信息；
- 是否增加等待或身体负担；
- 是否增加费用、制作、运输或寻找帮助的劳动；
- 是否改变实时压力、谈判关系或乐趣；
- 适配制作、运输和购买成本由谁承担。

协助不是天然失败，也不是天然解决。玩家主动选择共同讨论可能正是目标体验；关键是保留选择和代价。同样，免费打印文件也不等于零成本：设备、材料、技能和制作时间仍要记录。

任务是否“完成”还不够。分开检查玩家是否能进入并操作、是否保有信息与决定、是否在群体中被听见并承担想要的角色。有人替玩家完成动作或让他留在桌边旁观，不应被活动出席人数掩盖。

沟通任务还要记录谁能控制节奏、是否多人同时发言、玩家能否看见说话者、是否有语音以外的表达方式。它们不能被“音量足够”一个判断取代。

## 5. 只改一个条件并复测同一任务

把修法写成实验，而不是“提高无障碍”：

> 在港口颜色旁增加可从任意方向识别的形状；其余规则与尺寸不变。复测时，玩家无需转板或代读即可选择港口，且私人货物保持隐藏。

屏幕滤镜、自动检查和设计者启发式可以发现候选问题，但不能替代有相关生活经验的玩家。一次成功也只支持当前玩家、版本、媒介和任务。

复测时再做一次跨维度检查：解决颜色识别的语音提示是否制造沟通障碍？放大组件是否让桌面更难够到？延长时间是否改变目标中的实时压力？维度是检索入口，不是彼此隔离的通过标准。

同一结构也可能产生相反结果。轮流和共同目标可能降低部分玩家的社交含混，规则争议与过高信息负荷也可能增加冲突或让玩家错过群体线索。因此适配结论必须带玩家、版本、地点、协助安排和失败记录，不能只写“已由某类玩家测试”。

## 常见误区与修复

| 误区 | 修复 |
|---|---|
| 勾完清单后给游戏一个无障碍总分 | 保留每个任务的语境、阻碍、协助和代价 |
| 根据医学诊断猜玩家需要什么 | 邀请有相关生活经验的玩家，记录实际策略与原话 |
| 有人帮忙完成就算问题解决 | 检查协助是否代替决定、暴露信息或改变体验 |
| 所有障碍都修成更多文字 | 先判断受影响的功能，再选择形状、位置、触觉、节奏或信息结构 |
| 一项适配在当前维度有效就停止 | 用同一任务检查新的操作、沟通、认知、隐私、时间与成本代价 |

## 何时立即停止或调整

- 出现疼痛、安全、羞辱、强烈情绪或玩家要求停止时，立即停止。
- 没有目标玩家参与时只能做启发式预检，结果标为设计者假设。
- 改变计时、隐藏信息或难度的适配可以作为变体，但要明确它改变了哪些体验条件。

## 20 分钟练习：填写一张任务观察单

选择一次已经发生的设置、读取、操作、查询或沟通任务，填写：

1. 版本与媒介；
2. 任务；
3. 实际动作；
4. 阻碍维度；
5. 受影响的组件功能；
6. 暂定的障碍描述；
7. 玩家自己的策略；
8. 外部协助；
9. 协助与适配代价；
10. 玩家原话；
11. 下一次实验与成功信号。

完成信号：观察不是诊断推测；组件功能可指出；策略、协助和代价被分开；下一版只改一个条件；没有生成总分。
