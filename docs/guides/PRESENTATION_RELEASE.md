# 指南 06：把可玩的版本整理成可交付的发布包

状态：review  
阶段：呈现与发布  
核心阅读：10 分钟

## 你要得到什么

介绍页写 `v0.7`，规则书仍是 `v0.6`，打印文件来自 `v0.5`。三份文件单独都能打开，合在一起却不是一个可交付版本。

发布不是把文件上传，而是让接收者知道：这是什么、该用哪一版、怎样开始、发现问题后去哪里。

读完本指南，你会得到一个面向明确接收者、版本一致、权利可追溯、能独立开始体验的发布候选包。

## 1. 先确定接收者和他要做的决定

公开试玩者、审阅设计师、出版方与免费 PnP 玩家需要不同入口。先写希望对方做什么。

例：给公开试玩者——下载、打印、独立完成一局，并提交 `v0.7` 的盲测记录。

这条边界决定介绍页要说明什么，也决定不需要什么。投给出版方时，应以对方当前官方提交要求为准；这些规范会变化，不要把某一时期的格式写成行业定律。

## 2. 锁定一个发布候选版本

给规则、组件、玩家辅助和打印文件同一版本号与日期。列出文件清单、兼容关系和已知问题。

```text
RC 0.7
rules-0.7.pdf
cards-0.7.pdf
player-aid-0.7.pdf
已知问题：不兼容旧港口板；双面打印方向仍需复核
```

版本号不是装饰。反馈必须能回到实际使用的规则与组件，否则旧问题会混进新版本。

## 3. 组装最短进入路径

一个可测试发布包至少说明：

- 一句体验承诺；
- 玩家数、时长与复杂度预期；
- 组件与文件清单；
- 打印、裁切、设置或平台要求；
- 第一次教学与查询入口；
- 版本、已知问题和反馈渠道。

例：3–4 人、60 分钟的航线取舍游戏；先读 2 页教学，再用单页参考完成后续回合。

漂亮效果图可以帮助预期管理，却不能替代可玩的规则与组件。

## 4. 核对权利、署名与隐私

为文本、图片、字体、模板、图标和第三方素材记录作者、来源、许可与可发布范围。免费访问不等于允许复制。

本项目的课程材料只使用原创综合，不发布课件、工作表正文或专有版式。测试者引语需要同意并去除可识别信息。共同作者、学校模板和第三方图片未核清时，不进入公开包。

如果许可不确定，优先链接原始页面并写原创摘要。

## 5. 从发布入口再做一次盲测

让接收者从链接或文件夹入口开始，不另发补充说明。记录：

- 链接是否有效；
- 文件是否齐全、版本是否一致；
- 打印比例与双面方向；
- 设置和首回合的首次偏离；
- 反馈是否自动带上版本。

例：测试者下载 `RC 0.7`，按 100% 打印；发现双面翻转说明缺失。把它记录为发布阻断，而不是私聊补一句后宣告成功。

## 常见误区

| 误区 | 下一动作 |
|---|---|
| 用漂亮效果图替代可玩交付物 | 先保证规则、组件、版本与进入路径一致 |
| 不同文件各自维护版本 | 用发布清单锁定同一候选版本和兼容关系 |
| 免费资源直接复制进发布包 | 逐项核对许可；不确定时只链接并原创摘要 |
| 把测试次数写成质量证明 | 说明测试版本、问题、参与者语境与未覆盖风险 |

## 发布候选不是停止设计

严重规则、可访问性、安全或权利问题出现时，应撤回、标记并发布新版本。面向朋友的一次私人测试可以只用共享文件夹，但版本、入口和隐私边界仍要清楚。

制造、合同、税务、众筹和地区法律会随地点与平台变化。本指南只处理版本一致性、进入路径和权利记录，具体决策需要核对当前官方要求或专业意见。

## 20 分钟练习：发布候选清单

选择一个接收者，列出他从第一次看到链接到完成首局需要的全部文件、说明和权限。给它们统一版本，并标记每项权利状态与一个已知风险。

完成信号：接收者和行动明确；所有文件同版；第三方素材有权利记录；有人从发布入口独立完成下载、设置与首局。

## 证据与边界

本指南综合设计蓝图、设计师开发记录、规则信息结构和社区反馈版本管理。它不提供会随地区、平台与商业模式变化的法律、制造或众筹结论。原始资源与 Claim 由 `content/guides.json` 维护。
