# 核心指南模板

状态：stable  
用途：Phase 1 六个设计阶段的统一写作与审阅结构

## 一篇指南只做一件事

读者带着一个具体卡点进入，在 5–12 分钟内产出一份能继续设计或测试的东西。指南不是术语百科，也不承担整个阶段的所有知识。

## 必填结构

1. **问题**：用新手第一人称描述卡点。
2. **产出**：读完后会得到什么可保存、可比较或可测试的工件。
3. **具体开场**：先给规则、局面、记录或成品句子，再解释概念。
4. **3–6 个动作**：每步包含动作标签、提示和一个贯穿示例。
5. **常见误区与修复**：不能只说“不要这样”，必须给下一动作。
6. **何时不适用/故意违反**：保留分歧、类型语境和反例。
7. **短练习**：写清输入、过程和示例产出。
8. **证据边界**：说明当前内容来自学术框架、设计实践、玩家观察、教学材料还是项目推断，以及它不能证明什么。
9. **延伸资源**：只列本指南实际使用的机器可读 `resourceIds`。
10. **完成信号**：3–5 条可观察检查项，不设置总分。
11. **回退与下一步**：用稳定指南 ID 连接路径，不强迫线性完成。

## 机器字段

`id`、`title`、`stage`、`problem`、`outcome`、`coreMinutes`、`opening`、`steps`、`commonMistakes`、`whenToBreak`、`exercise`、`evidenceBoundary`、`resourceIds`、`claimIds`、`conceptIds`、`doneWhen`、`backtracksTo`、`nextOptions`、`toolIds`、`status`。

## 编辑检查

- 开头是否出现具体工件，而不是背景铺垫；
- 每一步是否推动同一份产出；
- 所有“应该”能否回到 Claim，或明确标为项目推断；
- 示例是否贯穿，而不是每段换一个无关游戏；
- 误区是否有修复动作；
- 反例是否真的限制了主张；
- 练习是否可在 20 分钟内完成；
- 是否避免复制本地课件或外部文章措辞；
- 是否没有用分数伪装客观质量；
- 页面上的资源链接是否仍由 `content/resources.json` 提供。
