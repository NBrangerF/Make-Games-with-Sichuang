# 别数做了几个，追一个判断怎样迁移

对应内容对象：`special-cross-project-learning-trace`  
阶段：测试与反馈  
核心用时：12 分钟；迁移原型另需 30–60 分钟

## 解决的问题

做完了不少原型、比赛或练习，却说不清自己的哪项设计判断改变了，也不知道上一项目的经验能否带到下一项目。

本指南不生成“设计师等级”。它把一个项目中的局部判断带进有所改变的新情境，记录它继续成立、需要适配，还是应当搁置。

## 产出

一页跨项目学习轨迹：

- 设计锚点；
- 一个行动前判断；
- 版本与行为证据；
- 修订后的适用边界；
- 只改变一个变量的迁移任务；
- 迁移结果、反向信号和继续 / 改写 / 搁置决定。

## 五步流程

### 1. 只冻结一个判断

从上一版本选一句能被行为反驳的判断，写明玩家、局面和预期结果。不要总结整个项目，也不要用“更好玩”作结果。

示例：在四人合作游戏中，每人持有一条不可直接展示的线索，会让四人在决定前都说出信息。

### 2. 分开锚点与可改项

写这次要保护的体验或责任锚点，以及可以随证据改变的问题框架、机制和表现形式。锚点也不是永远正确；安全、权利和生产硬边界可能要求重写它。

示例：锚点是让每人保有一个必要贡献；私密手牌只是可改解法，不能因沉没成本保留。

### 3. 把证据接到修订

引用具体版本、桌面行为或反例，写原判断是保留、缩小、扩大、反转还是搁置；同时写新判断不适用于什么。

示例：v0.8 中两人直接把线索交给熟练玩家代解。判断缩小为：私密信息只有在不可代办且发言权受保护时才可能分散领导。

### 4. 安排改变情境的任务

把修订判断放进新项目或微型原型，只改变一个关键变量，例如玩家年龄、关系、类型、材料、时长或团队；其余尽量固定。

示例：做一个 30 分钟亲子合作微原型，保留分散线索，只把玩家关系从成人朋友改为一名成人与一名儿童。

### 5. 比较迁移并决定出口

记录判断继续成立、需要适配还是失效，并保留一个反向信号。选择继续、改写或搁置，不累计经验值。

示例：儿童有必要信息却请成人代读，贡献仍被替代。下一版只把文本改成图形线索；若仍需代办，就搁置私密信息方案。

## 一页记录模板

```text
旧项目 / 版本：
玩家、局面与约束：

设计锚点：
原判断（如果……那么玩家会……）：
行动：
证据 / 反例：
修订：保留 / 缩小 / 扩大 / 反转 / 搁置
新的适用边界：

新情境：
唯一改变的变量：
保持不变的条件：
迁移测试任务：
反向信号：

结果：继续成立 / 需要适配 / 失效
下一决定：继续 / 改写 / 搁置
```

## 常见误区

- 用项目数、工时、版本数、参赛或名次证明成长：把数量降为背景，展示判断—证据—修订—迁移。
- 给自己贴新手、中级或专家总标签：改写成任务级描述，说明在哪个判断上能独立工作，在哪里仍需要脚手架。
- 出版后的故事讲得很顺，就认为当时因果已经清楚：分开设计中记录、测试后复盘和后来叙事。
- 把上一项目的规则原样复制到新项目：迁移带边界的判断，不复制表面配方。
- 把停止机制或项目等同失败：若证据说明不再服务锚点，记录搁置原因和复用边界。

## 何时不用或停止

- 纯休闲、关系或恢复性创作不必形成学习档案。
- 交付期限、赛事规则或合同要求先完成时，把交付评价与学习评价分开。
- 出现健康、安全、权利、歧视或团队冲突时先停止。
- 当前项目还没有可说清的局部判断时，先保存未知和下一条最小问题。
- 新旧情境同时改变太多变量时，把结果降级为新探索，不宣称完成迁移验证。

## 证据边界

这份指南来自跨设计领域的专长综述、探索性的设计教育阶段模型、职业游戏设计师访谈、学生桌游日志研究、Game Jam 系统综述与桌游 Jam 试点，以及商业设计师、新手比赛和个人挑战日记。

它们支持把学习拆成情境化判断、反思、版本和迁移，但不提供桌游设计师的通用等级、最低工时、项目数量或能力分数。职业访谈多偏数字游戏；Jam 研究多为短期、描述性或自报；设计日记受回顾与成功叙事偏差影响；中文材料主要是赛事评委视角。本页的跨项目记录结构是本站产品推论，仍需用户测试。
