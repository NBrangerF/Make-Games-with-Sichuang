# 结束契约：一页模板

更新：2026-08-20  
状态：review；对应 `special-ending-contract`

## 1. 会话时间口径

```text
原型 / 版本：
人数、队伍、座位与模式：
玩家经验：首局 / 返回 / 熟练 / 混合
可访问性、教学或现场支持：

设置：____ → ____，____ 分钟
教学：____ → ____，____ 分钟
正式游玩：____ → 触发 ____ → 最后行动 ____，____ 分钟
规则查询与错误恢复：____ 次 / ____ 分钟（是否含在游玩中：____）
结算：____ → ____，____ 分钟
收纳（如计入承诺）：____ 分钟
```

不要把不同起止口径、人数、版本或首局/熟练局直接求平均。

## 2. 节奏形状

| 阶段 | 新决定或转化 | 等待/查询/维护 | 玩家读取的结束信号 | 加速或停滞 |
|---|---|---|---|---|
| 开局 |  |  |  |  |
| 中盘 |  |  |  |  |
| 终局 |  |  |  |  |

圈出第一次出现以下事件的回合/时间：

- 玩家只执行已经决定的计划；
- 安全循环能持续而不推进结束；
- 回合外预案因共享状态变化而失效；
- 玩家必须重数他人组件才能判断剩余时间；
- 纯结算、维护或等待开始占主导。

等回合和“知道这是最后一回合”分别填写。

## 4. 拖尾观察

每位玩家在不影响当下决定的方式下，记录一次或局后回放：

| 玩家 | 认为结果已高度确定的时点 | 当时依据 | 之后仍有价值的决定/表达/排名 | 纯执行、维护或等待 |
|---|---|---|---|---|
| A |  |  |  |  |
| B |  |  |  |  |
| C |  |  |  |  |
| D |  |  |  |  |

不要用分差自动判定拖尾；也不要因为仍有动作就假定仍有决定。

## 5. 退出、投降与淘汰

分别填写，不共用一条模糊家规：

| 情形 | 谁可提出 | 同意规则 | 状态怎样处理 | 隐藏信息/旁观义务 | 重新加入或整桌停止 | 结果记录 |
|---|---|---|---|---|---|---|
| 两人认输 |  |  |  |  |  |  |
| 整桌提前结束 |  |  |  |  |  |  |
| 多人局单人退出 |  |  |  |  |  |  |
| 玩家淘汰 |  |  |  |  |  |  |

最低要求：不能因一人离桌而临场瓜分其资源、公开其秘密或重写邻接，却不记录这是新版本。

## 完成检查
