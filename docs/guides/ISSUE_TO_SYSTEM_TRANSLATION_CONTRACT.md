# “议题到系统”专题指南契约

状态：review  
更新：2026-08-21

## 用户任务

帮助已有社会、文化或教育主题的新手，把“希望玩家明白什么”改写为一次可以制作、游玩、观察和反驳的系统关系。指南不替用户决定正确立场，不生成社会影响分数，也不认证代表性或教育效果。

## 输入与输出

最低输入：一个议题、一类目标玩家、一句当前设计目标、一个准备借用或已存在的机制。  
最低输出：系统主张、团队位置与受影响者、六字段翻译、遗漏账本、一条重复决策、三层验证计划和单变量下一版。

## 五步契约

1. **系统主张**：写一句可被反驳的关系；同时记录设计者位置、直接受影响者和修改权。
2. **六字段翻译**：角色、权限、资源、约束、反馈、时间尺度分别对应动作或系统响应。
3. **遗漏账本**：记录删去内容、删去原因、误读风险、发现责任和补查节点。
4. **重复决策**：核心关系在循环中被选择、承受或观察；更名后仍能辨认，外挂问答不承担主关系。
5. **分层验证**：系统行为、玩家解释和受影响者审阅分开保存；复盘不能替系统补讲因果。

## 形成门

只有同时满足以下条件，才把草稿视为进入最小原型，而不是“观点卡面”：

- 系统主张可以被一次测试支持或反驳；
- 六字段至少形成一条动作—反馈链；
- 遗漏账本写出至少一种替代解释；
- 测试计划知道本轮收集哪一层证据；
- 下一版只准备改变一个关系字段。

这里没有规定固定条数、讲解分钟、玩家比例或通过分数；“至少一种替代解释”只是防止单一结论被当成系统事实的最低记录要求，不是质量阈值。

## 路由

- 议题与团队位置不清：返回体验意图或主题承诺复核；
- 行动—反馈链不清：进入核心系统、决定轨迹或共享决定观察；
- 原型包含太多现实细节：进入原型范围裁剪器；
- 玩家解释与系统日志冲突：进入测试计划和反馈分拣；
- 目标玩家无法读取或操作：进入任务无障碍观察；
- 需要公开课程、人物或案例：先做许可、隐私、伤害与发布责任复核。

## 证据边界

契约来自两套本地课程和 8 个公开来源的交叉综合。本地课程里的“5 分钟讲清”“70% 重玩”等数字不进入通用产品规则。汉字课程 DOCX 的中文视觉渲染不完整，具体内容依据结构提取；Pages 文件只做元数据索引。形成门验证的是文档是否可测试，不验证游戏是否准确、无害、有趣或能改变学习与态度。
