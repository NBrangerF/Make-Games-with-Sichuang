# 专项指南：把盲测拆成四个可观察任务

状态：review  
阶段：规则与信息  
核心阅读：9 分钟  
关联 Claim：`claim-blind-test-whole-delivery`

## 你可能卡在这里

你把规则书交给一组玩家，告诉自己绝不能说话。十分钟后他们摆错了港口、漏发资源，于是整局都按错误状态进行。你得到很多问题，却不知道应该改规则、组件、玩家辅助，还是核心系统。

## 读完带走

一份盲测任务单和偏离记录：本轮只测试设置、反向教学、规则查询或完整游玩中的一种，并记录第一次偏离和恢复路径。

## 盲测不是只有“完整玩一局”

### 任务一：设置测试

把规则书和全部组件交给玩家，请他们摆到“可以开始第一回合”的状态，然后停止。

观察：他们先找什么、哪些组件无法对应、桌面图是否足够、剩余组件放在哪里、何时开始猜测。

### 任务二：反向教学

请一名第一次阅读规则的玩家向另一名玩家解释目标、回合和主要例外。设计者不纠正，只记录。

观察：哪些概念被换词、遗漏或提前；目标与行动是否被连起来；示例是否被误当成规则。

### 任务三：查询测试

给出一个真实局面，例如“货舱已满但港口奖励又给一枚货物”，请玩家使用规则书或玩家辅助找到处理方法。

观察：先查看哪里、搜索用了多久、目录和术语是否匹配玩家语言、找到的答案能否执行。

### 任务四：完整盲测

陌生玩家只靠交付包从设置走到结算。设计者不在场，或在取得同意后只观察和记录。

观察：设置、教学、查询、桌面信息、结算和收尾如何共同工作。只有当系统足够稳定时，整局证据才容易解释。

## 五步执行

### 1. 冻结测试包

给规则、玩家辅助、组件表和原型同一个版本号。测试中临时口头修订要单独记录，不能悄悄替换包内规则。

### 2. 写任务，不写“看懂规则”

示例：只靠包内材料完成两人设置，并准确说明第一名玩家的三个合法行动。

### 3. 定义协助协议

提前选择：完全不回答、只给勘误表、卡死后提供最小提示，或允许玩家像查询客服一样提问。任何方式都可以，但必须记录，避免事后把被帮助的结果称为自主完成。

### 4. 记录第一次偏离

每次问题至少分成：

```text
版本与任务：
发生位置：
玩家实际做了什么：
他们查看了哪里：
需要什么协助：
偏离类别：缺失 / 顺序 / 术语 / 图示 / 组件 / 系统例外
```

### 5. 先修最早的上游问题

如果设置漏发资源导致后续所有行动错误，先修设置信息，再重新测试；不要同时重写十处下游规则。一次改动后回到同一任务，确认偏离是否消失。

## 常见误区与修复

### “规则写在那里，玩家没看到是玩家的问题”

修复：规则书是被使用的界面。位置、目录、术语、图示和组件提示共同决定信息能否被找到。

### “玩家没有提问，说明规则清楚”

修复：记录他们实际做了什么。玩家可能沉默地猜测，并在错误状态下完成整局。

### “第一次盲测失败，游戏就失败了”

修复：第一次偏离就是产出。停止下游任务、修复上游信号，再用同一任务重新测试。

### “必须等全部美术完成才能测”

修复：若测试目标是术语、设置或查询，材料只需在相应信息上达到足够精度。装饰美术不必完成。

## 20 分钟练习

从当前规则包选一个任务，不超过 20 分钟：

```text
包版本：
任务类型：设置 / 反向教学 / 查询 / 整局
任务句：
成功不是总分，而是：
允许的协助：
记录者：
停止条件：
```

示例产出：v0.6；设置测试；两名玩家只靠材料摆出三港口开局并指出第一回合起始玩家；允许查看一页勘误，不回答口头问题；第一次猜测组件用途即标记，十分钟停止。

## 完成信号

- 规则、组件和玩家辅助有同一版本号；
- 本轮只指定一种自主使用任务；
- 协助协议在测试前写清；
- 能指出第一次偏离，而不只统计总问题数；
- 下一改动针对最早的上游原因。
