# 指南 02：找到第一条值得反复测试的核心系统

状态：review  
阶段：核心系统  
核心阅读：10 分钟

## 你要得到什么

“加入手牌管理”不是核心系统。先把飞行棋的一次移动改成这条规则：

> 玩家从两张移动牌中选一张；打出的牌暂时不能再用。

输入是两张牌，选择是现在走多远，代价是失去之后的移动可能，棋盘位置随之变化。这个短循环已经可以测试。读完本指南，你会得到一条“输入—选择—代价—状态变化—反馈”的循环，以及一项带行为预测的单变量改动。

## 1. 圈出会重复发生的决定

核心不是规则总数，也不是游戏最独特的名词。先找玩家在一局中会多次遇到、且答案会随状态变化的决定。

飞行棋改造例：现在用高点数牌抢位置，还是保留它越过后面的危险格？如果无论棋盘状态如何，最高点数永远正确，这个决定就没有真正成立。

## 2. 把短循环写成一行

依次写：

```text
输入 → 选择 → 代价或约束 → 状态变化 → 玩家得到的反馈
```

例：抽到两张移动牌 → 选一张 → 用过的牌进入冷却 → 棋子位置变化 → 玩家看见下一回合的风险。

缺少反馈时，玩家可能无法从结果中学习；缺少代价时，选项可能只有名字不同；状态没有变化时，下一次决定也不会变。

## 3. 检查选项的条件，而不是只数选项

两个按钮不自动等于有意义的选择。比较它们的条件、成本、范围和后果：高点数更快，却可能错过安全格；低点数较慢，却能停在补牌位置。

这也解释了为什么只统计某类卡牌比例不足以定义派系或系统性格。真正产生差异的是效果何时可用、作用到哪里、支付什么，以及它与其他规则怎样耦合。

把“规则允许的选项”与“玩家实际考虑的选项”分开。某个选项可能合法，却因为信息入口、支付能力、认知负担、明显劣势或其他玩家的行动而根本没有进入比较。不要立即把缺失解释为玩家不会玩；先用 [单轮决定轨迹](DECISION_TRACE.md) 记录第一次分叉。

互动也不要直接写成“多”或“少”。写清谁的什么行动，经由哪条规则关系，改变了谁的状态或可行选项。共享一个随机结果可能改变所有人，却未必表示玩家彼此产生影响；直接攻击也不自动比间接竞争更好。

## 4. 一轮只改变一个轴

写下本轮改变的是移动、信息、资源、互动、主题还是胜利条件，并明确哪些核心保持不变。

飞行棋例：只改变移动决定；棋盘、轮流行动和先到终点获胜保持不变。这样失败时，你至少知道证据主要指向哪项变化，而不是面对一整款同时重做的游戏。

## 5. 从规则推到行为，再决定原型范围

预测：如果移动牌能保留，玩家会在关键位置前主动留下高点数牌。

第一版只需要能玩 1–3 回合的牌与棋盘片段。若玩家没有看见保留机会、始终打最高牌，或选择不影响后续状态，就先修复这条循环，不要用更多卡牌和精细数值掩盖它。

MDA 适合追问规则怎样形成动态与体验；5PM 适合拆一项机制中的呈现、操控物、资源、决定与目标。它们回答不同问题，也都不是质量总分。计算对局能查状态空间、分支和特定策略漏洞，却不能单独验证教学、触感、社交互动或情绪。

策略深度与可重玩性同样不能由规则量、组件量或随机变化量直接推出。深度需要长期学习和持续问题求解的证据；变化只有在改变玩家要预测、学习或权衡的关系时，才可能支持可重玩性。一个决定轨迹只能定位下一次实验，不能给整款游戏打“深度分”。

## 核心决定成立后，才进入单风险平衡

当玩家已经能反复遇到并使用这条决定，再选一种具体风险：选项支配、先手/座位优势、领先滚雪球、追赶过强、随机结果主导、经济停滞/爆炸、时长/节奏或非对称差异。

不要一次平衡完整游戏。使用 [“先定义这轮到底在平衡什么”](BALANCE_ONE_RISK.md) 把目标体验、资源流/反馈关系、数学基线、实测证据、反驳信号和下一版唯一改动连起来。期望值和胜率是针对问题的证据，不是整款游戏的总分。

## 常见误区

| 误区 | 下一动作 |
|---|---|
| 把机制名称列表当系统 | 写出玩家在什么状态下，用什么信息做什么决定，之后什么改变 |
| 一次加入多项机制 | 保留大部分规则，只改一个轴并预测影响 |
| 用更多内容掩盖循环没有张力 | 用少量重复组件验证决定是否因状态改变 |
| 核心未成立就追求精细平衡 | 先确认玩家看见、理解并使用这个决定，再调数值 |

## 何时故意违反

随机性不等于没有选择。关键是玩家能否在随机结果前后读取信息、承担风险或改变后续状态。熟悉机制也不是缺乏原创性；可迁移的规则块能降低学习成本，原创性可以来自它与目标、关系和反馈的组合。

短循环同样不是整款游戏。长局经济、谈判关系、叙事弧线和组件可用性需要另外的测试问题。不要因为第一条循环工作，就宣告完整体验已经成立。

## 20 分钟练习：熟悉游戏单变量改造

1. 选择一款你能不查规则就讲清的简单游戏。
2. 写下哪些核心保持不变。
3. 从移动、信息、资源、互动、主题或胜利条件中只选一个变化轴。
4. 写成一条玩家可执行的规则。
5. 预测玩家会做什么不同决定，再写一个测试问题。

完成信号：一行循环包含输入、选择、代价、状态变化和反馈；至少一个选项会随状态改变价值；本轮只改一个轴；行为预测可以被实际游玩推翻。
