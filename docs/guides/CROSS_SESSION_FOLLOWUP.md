# 跨局测试与延迟回访

更新：2026-08-19  
对应专题：`special-cross-session-follow-up`

## 这份指南解决什么

首局能发现设置、教学、查询和第一印象，却不能证明熟练后仍有空间，也不能说明同一组会形成怎样的惯例，更不能把“想再玩”直接当成真的回来。

这份指南不规定至少玩几局。它帮助设计者把一个需要时间才能回答的问题，拆成可比较的跨局序列。

## 一页记录结构

### 1. 序列头

- 游戏、版本、日期、场地与媒介
- 唯一研究问题
- 固定条件
- 只允许改变的一项条件
- 预定停止或回访点，以及选择理由
- 安全、隐私、退出与资料删除协议

### 2. 三种玩家轨道

| 轨道 | 适合回答 | 不能单独回答 |
| --- | --- | --- |
| 新玩家 | 设置、教学、查询、首次有意义决定 | 熟练后的深度、重复劳动、长期惯例 |
| 回流玩家 | 规则内化、策略发展、重复劳动、版本比较 | 当前版本真实首局是否清楚 |
| 同组历史 | 共同语言、指导、策略传播、角色固化、退出 | 换一组后是否仍出现相同行为 |

同一玩家可以同时属于回流轨道和固定组；记录时保留两层标签，不合并成“熟练”。

### 3. 每局最多三个片段

局中只捕捉：

- 时间点或回合
- 规则、局面或触发事件
- 一个关键词
- 可选照片或语音编号

例如：`第 3 回合／第二次查卸货／先翻玩家辅助／照片 02`。

局后再补：实际发生什么、玩家先做什么、谁介入、与上一局哪里相同或不同。片段不是完整观察；涉及快速动作、身体风险或信息传递时，应在同意前提下增加观察或录像。

### 4. 局后变化

不要重复问总体好不好玩。问：

1. 这局主要注意什么？
2. 什么因为熟悉变容易？什么变成重复、无聊或更难？
3. 学到或借用了谁的什么做法？
4. 下一局准备尝试什么？
5. 如果有机会是否愿意再玩？需要什么条件？

第 5 题只记录为再玩意向。

### 5. 延迟回访

间隔由研究问题决定，不使用统一天数。记录：

- 是否真的再次游玩
- 是自发成局、研究安排还是设计者邀请
- 没发生时的兴趣、时间、人数、拥有、场地、设置、规则遗忘或其他阻碍
- 还能否复述上次准备尝试的策略
- 哪些记录字段太重、太私密或没有价值
- 是否继续参加，以及资料保留选择

没有再玩不是自动的负面评分；真正要解释的是行为与机会条件。

## 版本分支规则

以下任一关键条件改变时，结束或分支原序列：

- 核心规则、计分、组件功能或信息结构
- 玩家构成或固定组关系
- 实体/线上媒介、场地或重要辅助方式
- 战役进度、剧透暴露或 Legacy 改造状态

研究可以专门比较版本前后，但改变必须被标为自变量，不能把它画成同一版本的第二局、第三局熟练曲线。

## 缺失不是一个状态

至少分开：

- 漏记
- 跳过某题
- 拒绝回答
- 退出研究
- 没有再玩
- 失联
- 资料删除

如果只保留坚持填完的人，记录协议会把最忙、负担最高或最不舒服的参与者筛掉。缺失本身可能在说明方法太重。

## 最小练习

安排两局和一次延迟回访：

1. 选一个会随重复改变的问题。
2. 标记新玩家、回流玩家和同组历史。
3. 每局只预设一至三个触发片段。
4. 写四个局后变化问题和一个再玩意向问题。
5. 选择回访时间并说明理由。
6. 写清什么变化会建立新版本分支。

完成标准不是跑满局数，而是能区分：学习、策略传播、群体惯例、版本变化、意向、实际行为和记录负担。

## 证据边界

方法依据来自玩家体验日记、纵向 HCI、日记反应性实验、多方法三角验证、模拟桌游体验采样、包容性教育桌游测试、专业用户研究文章和桌游设计日志。多数纵向研究以数字游戏或一般 HCI 为对象；实体桌游证据仍偏案例。因此本站不提供通用局数、间隔、样本或留存标准，三轨道与片段协议仍需要真实用户测试。
