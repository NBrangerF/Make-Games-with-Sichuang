# 市场状态转移契约

## 适用问题

当玩家说“市场卡住了”“价格失控”“先手把便宜货买光”“我不知道补货后多少钱”时，不要先改价格步幅。先把市场写成可执行、可观察的状态转移。

## 五步契约

1. **目标与失败边界**：市场要制造等待、抢购、囤积、转售、阻断还是适应？写一种不可接受的经济失败和一种参与失败。
2. **对象与补货**：列槽位、容量、供给来源、进入顺序、补货时点、轮换/淘汰、组件耗尽、人数与阶段调整。
3. **交易顺序**：写资格、商品、数量、容量检查、价格读取、支付/收款、库存变化、价格移动、触发、补货与交接。注明统一价或逐件边际价。
4. **单位流与异常**：追踪一个单位从来源到消耗；演一次短缺、过剩和滞销，并检查囤积与后手选项。
5. **事件记录与单变量改动**：记录交易前后状态、价格时点、库存、补货、下一位选项和理解错误；下一版只改一项。

## 最小记录表

| 字段 | 记录内容 |
|---|---|
| 市场前态 | 槽位、数量、价格、滞销年龄 |
| 行动 | 玩家、买/卖/跳过、商品、数量 |
| 结算 | 单价、总价、统一/边际、收款者 |
| 状态变化 | 库存、持有量、容量、价格移动 |
| 补货 | 来源、数量、位置、时点、失败条件 |
| 交接 | 下一位合法选项与可见信号 |
| 理解 | 犹豫、误读、漏步骤、协助方式 |
| 下一版 | 只改一项；支持与反驳信号 |

## 常见误判

- “买涨卖跌已经足够明确”：仍缺批量价格、移动时点、补货和交接。
- “公开市场人人都看得懂”：高频轮换、远座、空间数值和交叉计算仍会制造负担。
- “滞销就自动刷新”：刷新会改变供给遍历、成本归属和后手收益。
- “加补贴就能解决买不起”：补贴可能提高净收益，却不一定提供前置支付能力。
- “四人补货量是两人的两倍即可”：还需验证行动间市场事件数、控制感、先后手和读表负担。

## 完成条件

- 陌生玩家能执行一笔交易直到下一位开始，无需设计师补口头规则。
- 短缺、过剩、滞销、组件耗尽和容量已写规则或证明不可能发生。
- 玩家能从真实座位说出当前价、成交价、交易后价和补货后状态。
- 记录能还原一件货物与一笔资金去了哪里。
- 下一版只有一个市场参数变化，且预先写了反驳信号。
