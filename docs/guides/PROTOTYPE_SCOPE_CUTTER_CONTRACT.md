# 原型范围裁剪器契约

日期：2026-08-21  
对应核心指南：`guide-minimum-prototype`  
对应工具：`prototype-scope`

## 用户任务

用户已经有一个设计方向或当前版本问题，但不知道这一轮应该做哪些组件、做到多真实、玩到哪里停，也容易在测试前继续增加完整内容。

## 五步映射

| 指南步骤 | 工具动作 | 必须产出 |
|---|---|---|
| 先写测试问题 | 写问题、风险/体验、推翻信号与非目标 | 一个可在本轮观察的问题；至少一个非目标 |
| 按功能列材料 | 选择最多两个证据过滤维度 | 每个维度为何必须出现；初始材料功能 |
| 决定哪里必须真实 | 分别配置材料、分辨率、范围 | 每维“替代/近似/必须真实”与理由；代理边界 |
| 裁成最短可玩片段 | 写玩家、起始状态、重复与停止 | 不依赖完整胜负的可运行切片 |
| 写明确不做清单 | 写排除项、时间盒与重做信号 | 能阻止范围回流、触发重做的版本门 |

## 非目标

- 不生成保真度、成熟度或质量总分。
- 不推荐固定组件数、回合数、参与者数或制作时长。
- 不把低成本、纸面或实体媒介排成通用优先级。
- 不声称短片段替代完整局、长程经济、联盟、叙事或学习曲线测试。
- 不把主持人代运转当作没有代价的自动化替代。

## 保存与导出

- 草稿保存在当前浏览器本地，字段变化后自动保存。
- “保存范围快照”冻结一条带时间戳的记录，不覆盖历史快照。
- JSON 导出包含方法边界；导出成功不代表原型范围已经验证。
- 清空草稿需二次确认，不删除已保存快照。
