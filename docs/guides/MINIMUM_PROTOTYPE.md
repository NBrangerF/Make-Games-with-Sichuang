# 指南 03：只做这一轮问题需要的原型

状态：review  
阶段：最小原型  
核心阅读：9 分钟

## 你要得到什么

如果这一轮只问“玩家会不会为了未来航线放弃眼前得分”，你需要三座港口、几枚货物、一个有限货舱和能触发两次交货的短航线。

你不需要完整世界地图、四十张事件卡或最终插画。

原型不是缩小的成品，而是给一个问题搭的实验。读完本指南，你会得到一份原型范围单：必须真实的功能、可以替代的组件、明确不做的内容和停止条件。

## 1. 把测试问题写在材料清单上方

每个组件都要回答一句：“它怎样帮助我回答这个问题？”

海上贸易例的问题是：玩家会为下一港口主动保留货物吗？若一个天气事件不会改变货物取舍，这一轮就不需要天气牌。若终局计分不会在三回合内出现，这一轮也不需要把它做完。

“最低成本”不是固定的卡牌数或玩家数。Daniel Piechnick 的短时、两人原型是他的实用流程，不是所有设计的通则。真正稳定的判断是：范围由问题决定。

## 2. 先列功能，再找物件

不要先写“需要 30 张卡”。先列公开状态、私人信息、资源数量、空间关系、随机结果、计时或谈判权限。

海上贸易例：

- 货舱容量：纸上三个空格；
- 港口需求：三张便签；
- 货物类别：不同颜色方块；
- 航线先后：一条纸带；
- 对手意图：不需要额外组件，保留玩家选择即可。

家里的硬币、方块、旧游戏零件和索引卡很适合表示功能，因为改变成本低。它们不必像产品，却必须让玩家分辨当前状态。

## 3. 决定哪里必须接近真实

“越粗糙越好”会误导设计者。若问题涉及触感、触达、可见度、图标、颜色、拿取动作或设置流程，相应部分必须有足够精度。

测试货舱取舍时，地图美术可以省略；测试港口信息能否被全桌看见时，字号、位置和对比度就不能省略。测试隐藏信息时，纸片背面不能透出内容。测试拿取动作时，数字平台不能代替实体组件。

这也是为什么无障碍不适合压成总分。应描述具体任务、障碍、所需协助和协助代价，并让原型在该任务上足够真实。

## 4. 裁成最短可玩片段

只保留足以重复核心决定两三次的玩家、回合和内容，并写下何时停止。

海上贸易例：两名玩家、三座港口、三回合；第二次交货后停止。完整胜负暂时不是必要条件。短片段让你更快看到决定是否存在，也更容易在同一天改完再测。

但短片段不能代表所有问题。长局经济、背叛、谈判、合作权力或叙事积累需要完整局或专门的极限测试。先用短片段排除局部断点，再扩大时间尺度。

## 5. 写“不做”清单

把本轮诱人但无关的工作明确写出来：

- 不做事件牌；
- 不做最终计分；
- 不做正式规则书；
- 不做历史插画；
- 不做四人平衡。

它们不是永远不做，而是没有资格挤进这一轮。若测试发现核心取舍根本没有发生，完整内容只会提高丢弃成本。

## 常见误区

| 误区 | 下一动作 |
|---|---|
| 把原型当作低配成品 | 从问题反推必要功能，而不是把最终组件等比例缩小 |
| 把“越粗糙越好”当定律 | 只让无关部分粗糙；与问题有关的触感、空间和信息必须真实 |
| 做完全部内容再开始平衡 | 用少量重复内容确认核心决定存在，再扩分布 |
| 只在线上验证实体体验 | 写下媒介盲点，并安排实体复核 |

## 线上、自动化与实体各自能回答什么

线上平台适合快速换规则、远程招募和减少重做成本，但会遮蔽触达、设置、身体动作和细微社交互动。自动对局适合找形式规则冲突、参数异常或特定策略漏洞，却不能证明教学清楚、触感合适或玩家产生目标情绪。

选择媒介时不要问“哪一种最好”，要问“这一轮要看见什么证据”。

## 20 分钟练习：原型范围裁剪单

1. 写一个测试问题。
2. 列出必须表现的功能。
3. 为每个功能选最便宜的替代物。
4. 限定玩家数、回合数和停止条件。
5. 写至少三项本轮不做。

完成信号：每个组件都能指回问题；必须真实与可以替代的部分已分开；原型有停止条件；不做清单真实地删掉了工作。
