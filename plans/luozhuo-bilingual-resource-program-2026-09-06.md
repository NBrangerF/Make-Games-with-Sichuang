**3. 网站内容怎样组织。** 建议首页以“推荐阅读＋按主题找文章”为主要内容，提供明显的“从零开始”和“搜索资料”入口。“边玩边学”与设计工具从相关正文进入。知识主题和项目阶段是两套可同时使用的分类，不把它们混成一条必修线。

文章类型先控制为四种：解释一个问题的原创文章、比较不同观点的专题综述、围绕具体局面的案例分析、帮助选读的资源导读。授权译文单独标明；不能把“导读”“完整译文”“原创综述”混用。

读者公开看到：可独立阅读的正文、关键概念、原创图解、简明出处与延伸阅读。研究者内部看到：完整证据卡、方法限制、引文位置、权利记录与编辑历史。文章末尾最多提供一个可选小活动和少量延伸资料。

**5. 从资源到原创文章的工作流。** 每个阶段都保存一个可复用产物；下一次写文章时重新检索这些产物，而不是把全部资料再读一遍。

| 步骤 | 输入 → 输出 | 主要执行方式 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 接收与登记 | 文件／官方链接 → 来源记录 | 本地脚本，编辑核对 | 书名、作者、版本、格式、来源与获取情况可追溯 |
| 权利分流 | 来源记录 → 使用范围与许可证据 | 规则检查＋人工判断 | 区分内部研究、允许转载、允许改编、待确认；不以“免费阅读”代替许可 |
| 提取与质量检查 | PDF／EPUB → 带位置的结构化文本 | 普通解析优先，必要页 OCR | 页序、段序可用；抽查目录、普通页、复杂页 |
| 文献地图 | 目录、导言、结论、抽样 → 章节问题地图 | 轻量模型协助，保留原文定位 | 知道哪些章节回答哪些问题，标明未读部分 |
| 深读 | 当期相关章节 → 证据卡与论证图 | 有界的研究任务 | 主张、依据、条件、反例、不同意见与原文位置齐全 |
| 专题综合 | 多份独立来源＋读者问题 → 研究简报 | 较强模型辅助，编辑判断 | 说明共识、分歧、证据空缺和本站打算提出什么 |
| 原创写作 | 研究简报 → 原创中文稿＋图解草案 | 编辑主导，AI 辅助成稿 | 有独立问题、论证、例子和结构；不是逐章压缩替代原著 |
| 复核 | 草稿＋引用位置 → 修订稿 | 事实核对、编辑、必要时权利专业复核 | 关键主张可查、语境未失真、原创贡献可说明 |
| 双语表达 | 稳定中文稿＋术语表 → 英文版本 | 翻译／本地化，双语校核 | 数值、规则、论证强度、限制条件与引用对应 |
| 发布与维护 | 已审内容包 → 公开白名单与更新记录 | 自动检查＋发布决定 | 公开产物只含获准内容；旧版本可追踪、可回退 |

深读不能退化成“一章一个摘要”。每一份重点分析至少回答：作者试图解决什么问题；关键术语在文中是什么意思；论据是实验、案例、经验还是理论推演；有哪些假设与限制；哪些说法存在张力；迁移到桌游、新手或儿童场景时还缺什么证据。目录、摘要和模型记忆不能冒充全文证据。

证据卡的最小字段：主张 ID、来源 ID、作品版本、章节、印刷页／PDF 页／EPUB 内部路径与锚点、必要的内部短摘录、自写释义、证据类型、适用范围、反例、复核人／方式、复核时间、可支持的文章。没有页码就明确使用段落或锚点，不生成虚构页码。

专题综合以读者问题为单位，例如“为什么运气不一定削弱策略”。先核对相关来源是否独立、是否引用同一原始研究，再比较结论。建议重要专题有两到四个互补来源；这是一项编辑经验值，既不是硬凑数量，也不是版权安全门槛。

写作与原文核查分成两个动作：先按研究简报设计文章结构和原创例子，再回到来源检查事实与表达距离。研究简报本身也可能保留原作表达，因此不能将这套流程视为自动消除侵权风险的机制。

**6. 每篇一个版本、中文和英文两种语言。** 按用户最新确认，每篇只维护一套内容，不制作年龄版本、儿童版或额外陪伴阅读卡。不同年龄的新手共同阅读同一篇文章；具体局面、清楚的短句、必要术语解释、图解和适用条件都是正文的一部分。

阅读测试可以覆盖不同年龄与经验，但不据年龄另开内容分支。不以自动可读性分数宣称适合所有年龄；测试发现理解障碍时，优先改进共同正文。文章可以有简短摘要和必要的深入段落，仍属于同一内容版本。

每篇原创文章拥有一个稳定 ID，中文与英文共享它，并各自记录版本、审校状态和最后修改时间。中文可以作为首轮编辑主稿，英文是落桌自己文章的英文表达，不能拿原书英文当作本站英文版。需要时可基于同一研究简报重写不自然的英文段落。

从既有 287 个概念中先核对试点实际用到的 30–50 个词，补中文首选词、英文词、别名、例句和禁混用说明，例如 mechanics／mechanisms、agency、balance、randomness。不能为了术语一致把不同作者的不同含义压成一种。

双语复核优先检查否定词、条件、数值、概率、规则顺序、论证强度、引文和来源位置。中文主张改动后，关联英文段落标记待同步；简单标点调整不触发整篇重译。公开语言切换不应跳到不同文章。技术实现时检查页面 `lang`、独立语言地址、缺失语言提示和搜索体验。

**7. 版权与内部资料怎样处理。** 原创综合是合适的主要方向，但“分析过”“改写过”“引用很多来源”不自动赋予发布权。著作权法分别规定翻译、改编和信息网络传播等权利；适当引用也有条件。这里采用编辑与发布的风险管理方案，不把它写成对每项具体使用的法律批准。[国家版权局：著作权法](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

| 素材情况 | 默认处理 |
| --- | --- |
| 权利未明确的商业书、文章 | 保留书目与原站入口；研究时核对获取和处理条件；公开原创文章需另做表达与引用审核 |
| 明确允许改编的开放许可 | 按具体版本和条件使用，保留署名、许可、修改说明；第三方图像或引用另核对 |
| 含 ND 的许可 | 不依赖该许可发布译文或实质改编；是否存在其他授权或例外另行判断 |
| 含 NC／SA 的许可 | 分别核对商业使用范围和改编作品许可要求；不能将受限制的改编统一改贴本站许可 |
| 书面授权 | 逐项记录文本、图片、中英文、改编、商业用途、媒介、地域与期限 |
| 本站原创案例与图解 | 保存创作过程；标明构造案例，不能捏造真实测试、用户原话或研究发现 |

例如 Game Design Concepts 官方页面明确标注 CC BY 3.0 US，因此存在按条件制作译文的路径；不能把“所有来源都不能翻译”作为总规则。ND 与翻译、改编的关系以具体许可及适用法律判断。[课程许可](https://gamedesignconcepts.wordpress.com/about/)、[Creative Commons FAQ](https://creativecommons.org/faq/)

不设“改写百分比”或统一引用字数作为合规保证。人工复核要同时看句子、论证顺序、独特比喻、案例组合、练习与图表。重绘一张图并不当然取得图的使用权。参考书可以启发独立的解释，但不能做足以替代原作的逐章精缩。

新增书籍先核对获取来源与允许的处理方式；文件存在不证明拥有复制、云端上传或公开权利。“内部使用”也不是所有使用方式的豁免。首轮先用本地处理与已核实可用材料跑通，不把整个书库上传到外部知识库。

公开网站和内部研究至少在构建输入与存储权限上分离。正文进入浏览器前就应按公开清单筛选；内部原文、摘录、草稿和搜索索引不进入前端包、静态目录、源映射或公共接口。内部检索即使以后采用向量库，也不能直接提供给公众问答。搜索结果、缓存、导出与预览同样遵守边界。`robots.txt` 和 `noindex` 只影响收录，不是访问控制。

发布前优先完成三项具体修正：梳理现有十六份正文的 import 链；让公开构建仅接收已批准正文与资产；在生成物中验证内部测试标记和受限文件缺席，并核对当前托管的构建。若确认已暴露，再处理线上内容与历史构建。当前这份计划没有自行改动部署。

**8. 最小工具组合。** 初期只需要文件管理、可靠提取、结构化笔记和编辑辅助。优先复用已有代码，把每一类记录放在一个明确位置。

| 工具或项目 | 建议 | 能节省的工作与限制 |
| --- | --- | --- |
| 项目现有 JSON／Markdown／Git | 现在使用 | 保留资源与主张 ID、正文、版本记录；避免另造平行内容库 |
| Zotero | 值得采用，尚未在本任务配置 | 管理书目、作者、版本、附件与笔记，辅助查重；不把自动元数据视为权利证据，也不要求先购买云存储 |
| bundled Python、`pypdf`／`pdfplumber` | 普通文字 PDF 首选 | 本轮已使用现有 bundled runtime 提取逐页文本并抽查渲染；无需新增环境或订阅 |
| EPUB 原生目录与 HTML 解析 | 必需的新增小能力 | 使用 EPUB 自带章节结构与锚点，避免先转 PDF 再 OCR；不必先建设复杂服务 |
| Docling | 复杂文件按需采用 | 处理版面、阅读顺序和结构较复杂的文档；先用困难样本验证收益，避免每本书都走重处理 |
| 本地文件检索／SQLite FTS5 | 文件规模增长后增加 | 可追踪的关键词检索；中文需验证分词或 n-gram 策略，不能假定英文默认配置就够用 |
| Codex 与已有写作能力 | 现在使用 | 有界任务：选章、证据卡、专题比较、草稿、核查；每个任务读取有限材料 |
| 现有 React／Vite 站点 | 首轮沿用 | 补文章、语言和发布清单。公开推广前再验证可索引正文、稳定语言 URL 与预渲染方案 |
| Astro | 后续有条件评估 | Content Collections 可支持类型化内容；只有文章发布成为主要维护负担、预渲染需求明确时再比较迁移成本 |

工具依据：[Zotero 基础](https://www.zotero.org/support/quick_start_guide)、[Zotero 查重](https://www.zotero.org/support/duplicate_detection)、[pdfplumber](https://github.com/jsvine/pdfplumber)、[Docling](https://docling-project.github.io/docling/)、[SQLite FTS5](https://www.sqlite.org/fts5.html)、[Astro 内容集合](https://docs.astro.build/en/guides/content-collections/)。

资料记录的分工：Zotero 如被采用，负责书目与附件；项目来源清单保存对应 ID 与编辑用字段；证据卡保存研究判断；文章文件保存成稿；网站从公开清单生成内容。数据单向导出或明确字段归属，避免 Zotero、表格、JSON 和笔记同时修改同一字段。

NotebookLM 等阅读辅助、Dify／RAGFlow 等知识库服务，可以在出现明确需求后作为可替换辅助界面。当前没有证据表明维护这些平台比直接检索证据卡更省成本；也不把其自动摘要作为引文依据。复杂向量数据库、多代理编排、全天候爬虫、付费 CMS、实时翻译和公众 AI 问答均不属于首轮必需项。

**9. 现有 skills 与需要补的规范。** skill 的作用是固定输入、产物与质量要求，不是越多越好。已有 skill 的模型价格或阈值示例不能当成当前报价直接抄用。

| 可复用 skill | 本项目用途 | 使用边界 |
| --- | --- | --- |
| `ecc:content-hash-cache-pattern` | 文件不变时复用解析成果 | 解析配置和版本也加入缓存键；不是只比较文件名 |
| `ecc:cost-aware-llm-pipeline` | 任务分级、费用日志、重试和预算控制 | 不按篇幅单独决定模型能力；复杂性与出错成本也参与判断 |
| `ecc:knowledge-ops` | 去重、来源关联、权威记录位置 | 只采用适合当前仓库的必要层次，不照搬多层记忆与同步系统 |
| `ecc:article-writing` | 原创结构、具体例子、删冗余与证据约束 | 需增加桌游教学与双语要求；其默认“operator”文风不直接用于儿童或新手 |

已阅读这些 skills 的说明。商业文案、社交传播等 skills 不适合直接承担本项目的文献分析。`dbs-deconstruct` 有特定商业／哲学框架，也不作为桌游知识体系的总框架。

建议从三份项目内模板开始，样稿流程稳定后再封装成定制 skills：

1. 资源分析模板：来源定位、论证结构、证据类型、条件、反例、缺口与权利记录。
2. 原创综合模板：读者问题、互补来源、分歧矩阵、本站判断、独立例子、拟用图解、核查清单。
3. 双语与阅读支持模板：术语对应、语言版本、事实对齐、难度支持、图文关系、审校与过期状态。

未来可以将它们称为 `luozhuo-source-analysis`、`luozhuo-original-synthesis`、`luozhuo-bilingual-editor`；这些是拟建设能力，不是当前已安装的 skills。无须先开发插件。资源筛选、深读、写作、复核是可顺序执行的角色，不要求常驻多个 agent。

**10. 资源与费用控制。** 节省预算最有效的做法是缩小需要重复推理的材料范围，并减少错误成稿后的返工。

| 控制点 | 首轮规则 |
| --- | --- |
| 范围 | 当前五书全部主要章节做主题分析；Building Blocks 203 条建索引、各章至少三条精读；不受原三篇样稿选章上限限制 |
| 解析 | 可读取文本直接提取；只对无文本或抽样失败的页 OCR；云端不可用或文件未下载时记录状态，不无限等待 |
| 缓存 | 使用文件内容指纹＋解析器版本＋配置；分析缓存再包含文本片段、任务模板、模型与输出结构版本 |
| 上下文 | 每次只给相关章节、证据卡和稿件；需核对事实时回取原文，不反复携带全项目对话 |
| 模型 | 文件统计、校验、引用 ID 和链接结构由脚本做；轻量模型处理初筛；复杂分歧与重要事实使用较强能力并回源核对 |
| 重试 | 网络暂时错误有限重试；无权限、坏文件和输入错误直接入待处理队列；内容最多两轮集中修订后转人工判断 |
| 在制品 | 同时最多一份研究简报和两篇待审稿；未审稿堆积时暂停新生成 |
| 图像 | 每篇至多一到两张确实帮助理解的原创图，优先简单示意；先不做视频、配音和装饰图批量生成 |
| 维护 | 只重新核验被更新来源影响的主张与文章；稳定来源不每次写作重复联网读取 |

本轮不使用另行计费 API，不新增订阅或常驻多代理系统。记录本地解析时间、缓存复用、核查工作与可观测模型用量；不可取得的 token、额度或现金成本明确标记不可观测，不套用旧价格或虚构单篇成本。

API 成本按实际输入、缓存输入、输出用量乘当日单价计算；调用前预估该次上限并预留并发预算，结束后回写实际值。预算不足时停止新调用并保存断点，不能先超支再记账。

试点需要测出五个数字：每篇双语合格稿的现金成本、人工分钟数、来源核查命中率、返工次数、证据复用比例。扩张预算＝剩余篇数 × 试点实测平均成本，再加维护和不确定性余量；不要把成稿速度当成质量证据。

**11. 首轮三篇样稿及六至八周安排。** 时间按一位负责人每周约 8–12 小时、AI 辅助的情景估计；真实材料、外部审校和读者招募会改变进度。验收门优先于日期。

| 样稿 | 要验证的问题 | 研究与原创产物 |
| --- | --- | --- |
| 为什么选项很多，玩家仍然没什么可想？ | 能否从不同设计观点形成直观、准确的原创解释 | 决策与信息证据包；自制“选项多但选择弱”的对照局面；中英文正文 |
| 运气为什么有时让游戏更有策略？ | 能否保留条件、分歧与反例，不写成简单口诀 | 随机时点、信息与应对能力比较；原创图解；中英文正文 |
| 没轮到你时，游戏里还发生了什么？ | 能否从桌面共同体验扩展到等待、注意与互动 | 桌面体验与行动结构研究；构造案例；中英文正文 |

题目是编辑方向，最终论点取决于读到的证据，不能先指定想要的结论再挑材料支持。

| 阶段 | 预计安排 | 交付物 | 验收门 |
| --- | --- | --- | --- |
| A：基线与隔离 | 第 1 周 | 14 份来源记录、16 项现有正文状态核对、公开构建隔离方案／修正 | 原文和内部稿与公共构建边界可验证；版本与来源缺口明确 |
| B：五书研究（当前独立批次） | 按逐书验收推进，替代旧第 2 周选章上限 | 5 份主题报告、跨书综合、来源与覆盖记录、证据卡、12 选题与 3 简报 | 全部主要章节有真实正文覆盖；关键归因回源；索引与精读分开；成本可回查 |
| C：双语样稿（后续） | 研究简报收口后重新估算 | 3 组中英文正文、3–6 张原创图、30–50 词术语表 | 每篇一个内容版本；事实、表达、双语和发布范围复核；阅读可独立成立 |
| D：读者验证与网站接入 | 第 5 周 | 小样本反馈、修订稿、语言切换、主题入口与来源页 | 读者能找到、读懂、迁移一个概念；公共产物只含已批准内容 |
| E：扩至小型首发 | 第 6–8 周 | 依试点产能争取新增 3–5 组双语文章，形成总计 6–8 组 | 以实测成本决定产量，不为凑数绕过审核；覆盖至少四个知识主题 |

样稿正文起始目标为中文约 1,500–2,500 汉字、英文按完整表达确定长度，复杂问题可以另有深读内容。这个长度是试写控制，不作为好文章的充分条件。

角色分工：负责人确定读者价值、取舍、例子和最终成稿；AI 协助查找、整理、比较和语言处理；双语读者核查表达与关键事实；真实目标读者提供理解反馈。存在实质授权疑问的稿件再集中请相关专业人士处理。首轮不需要组建大型团队或多代理系统。

**12. 如何判断试点值得继续。** 找六至八位参与者开展形成性测试，兼顾不同年龄的新手与英文读者，角色可以重叠；使用同一内容版本。人数是发现问题的安排，不足以证明所有年龄群有效；未成年人招募与记录沿用项目已有同意流程。

给参与者三个简单任务：找到一篇能回答自己问题的文章；读完后用自己的话解释一个概念；用新的局面判断该概念是否适用。记录耗时、卡住的位置与误解，避免只问“喜不喜欢”。

继续扩张的最低条件：

- 三组文章的关键事实与引用全部能回查；正式引用不能只有书名而没有定位。
- 没有未解决的重大误导、规则矛盾或发布范围问题；不能用平均评分抵消这类问题。
- 每种语言至少经过一名熟悉该语言的读者反馈；机器翻译自检单独标注，不冒充人工审校。
- 小样本中大多数参与者能完成解释与迁移任务；不同年龄与经验读者的问题分别记录，用于改善共同正文，不只看总平均。
- 没有阅读前必须做项目、填表、登录、购买指定游戏的阻断。
- 双语同步、来源更新与内部资料隔离均可复现检查；事实／教学质量仍由编辑与读者验证。
- 人工与机器成本已有实测，能据此决定下一批三篇的规模。

若这些条件未成立，先修样稿与流程，不新增几十篇待审文章。网站页面浏览量、资源数量、自动校验通过数只作为辅助信号。

**13. 长期维护与近期决策。** 每次批量成稿后做一次来源与语言状态检查；来源变动时标记受影响的证据卡、文章和译文，不自动重写已发布内容。维护一个待办表即可：本周主题、待补证据、待审稿、阻断原因、实际费用、下一动作。不要为每篇创建另一套平行计划。

每个公开页面标明作者／编辑责任、AI 辅助方式、发布日期、更新日期、来源和纠错入口；拟采用的本站原创内容许可与第三方素材许可分开决定，不自动对全站套用一种许可。定期备份正文与台账，保留可回退版本。

本轮已确定五书研究范围和不新增付费 API 的约束；后续写作再按编辑时间与读者反馈安排三组双语样稿。当前顺序是：**五书主题研究与证据核查 → 跨书综合与研究简报 → 后续原创写作、双语复核与读者验证。**
